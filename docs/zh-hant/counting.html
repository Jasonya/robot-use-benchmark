這幾個名詞，各自定義什麼

來源名錄條目

登記一項benchmark、含評測的資料資源或其版本，保留原文及來源關係。

143是這一層的名錄條目數，含版本／衍生資源；不表示143個完整資料集已下載或彼此獨立。

原作定義／設定索引

從原作清單、程式或資料檔提取的一筆可追溯條目，可是任務ID、活動定義、模板、註冊、配對或協定。

5,349是本版已提取索引總數，包含robot任務、資訊題型、人類活動及其他設定；不代替場景、共同任務或題目總量。

任務環境定義

一份可互動評測規格，明訂世界與機體、觀測與動作、初態生成及狀態變化、任務目標、過程限制與判分規則。

按完整規格與來源／別名關係識別後計數。只有名稱、task ID或生成器設定時先保留為索引。定義可以先收錄，是否已載入、執行或驗證另記。

場景／layout

房間、工作站或場地的空間配置、設施與幾何資產。

同一廚房可支援多個任務環境；更換目標或評分規則不會自動增加物理場景數。

測例

固定任務環境或評測規格，再指定一個有效初態、輸入／歷史、介入條件與評分約定。

同一任務環境可產生多個有效測例。初態或觀測條件變化通常在這一層計數；必須實際建立並確認適用性，不能直接把任意引數乘積當已完成測例。

原始資料樣本

原作提供的影片、QA pair、episode、示範或軌跡等資料單位。

依樣本型別、版本、split與來源重疊分項統計；原作公佈量、已取得量、已整合量分開。

一次評測執行

某個方法在一個固定測例上執行一次。

多個方法或重複執行會增加trial數，保留其與測例的關係。

G與T各自代表什麼

G：在數哪一層。T：在測哪種能力。 本計畫採用的整理編號，概念來自研究與評測實務；不是所有前作共同使用的G／T標準。

G · Granularity

領域、家族、規格、例項、測例、一次執行。

T · Evaluation track

理解、記憶、預測、規劃、執行、恢復、協作、世界模型。

G0–G5：規模的計數層級

G是granularity（粒度）標記，回答正在計數哪一層單位。 應用領域與任務家族是交叉分類；同一摺疊家族可出現在居家或旅宿。

什麼時候能登記為任務環境定義

這是本計畫採用的整理約定。可以把原作任務及其可互動世界封裝成task environment，並保留下面四組規格：

  1. 世界與機體：場景／layout、物件、材料與機器人，或可追溯的原作定義。
  2. 觀測與動作：模型能看什麼、能操作什麼，以及介面與控制約定。
  3. 狀態規則：如何初始化、有效初態範圍、動作造成哪些狀態變化。
  4. 任務與判分：目標、必要過程、限制、完成條件與評分。

原作已提供這些內容時，可以先收集和對齊規格；未取得的部分標待補。影片、活動名稱或生成器設定仍保留在來源索引，另外建立它們到環境規格的對應。離線QA／預測保留其評測型別。

已有索引 → 來源已連結 → 規格完整 → 身份／別名已對齊

執行驗證狀態

未測試 → 載入已核對 → 軌跡已核對 → 判分已核對

兩組狀態分開儲存。本機尚未跑過，不會把來源或環境定義從目錄刪掉；同時，已有定義也不直接標成已驗證可執行。

假設算例 · 非已建資料或實驗結果

一間廚房，可以有多個任務環境

假設使用同一間廚房，分別定義「收杯子」「開櫃門」「倒出指定水量」三個任務環境。它們共用場景，但目標與判分規則不同。

1場景／layout
3任務環境定義
100每個定義的有效測例
300總測例數

3 × 100 = 300

改變有效測例數，會增加測試量；場景仍是1個、任務環境定義仍是3份。規則或互動系統有實質改變時，另建立版本／繫結並審核其差異。這個算例不增加本庫實際計數。

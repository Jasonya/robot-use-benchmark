CHAPTER 07 / 14

示範、標註、資料切分與有效性

約 5 分鐘·資料快照 2026-09-21設計階段 Q0
先掌握這三件事
  • 先以原始活動或錄製 session 分組，再產生 clips 與 QA。
  • 示範與 robot 的配對可能只有共同目標，不能假設幾何一致。
  • 資訊不足的題目應補線索或允許詢問，不能當成難題。

1. 來源與配對

來源 可支援內容 必須另確認
頭戴／胸前影片 第一人稱目標、手物互動、歷史和人類未來 相機、時間、遮擋、目標充分性、來源使用條件
外部／多視角影片 程式、全身、手部、視角轉移 無校準時只能宣稱語義對齊，不能假定3D
VLOG／教學剪輯 多領域活動、步驟、敘述和工具 剪接、變速、旁白對齊與遺漏資訊
模擬robot示範 動作、物理狀態、接觸、可控失敗 不可標成人類第一人稱影片
多session／互動 歷史、角色、意圖、詢問和恢復 身份、時間線、來源隔離及合作方模型

配對分為 same_scene_calibrated、same_objects_semantically_aligned、same_goal_only。第三種不是精確重建，不能直接使用跨機體軌跡距離。來源使用條件及必要參與者同意資料，是收集／發布前需記錄的欄位，不假定公開影片皆可再分發。

來源設定可重疊，例如頭戴影片也可被剪成VLOG。分別記錄相機安裝、agent來源、時間包裝、語言與sensor，不從Ego命名推斷攝影機位置。

2. 五層標註

  1. 來源：活動、錄製session、人物／角色、相機／時間、剪輯來源、場景和物件身份。
  2. 語義：目標、合法替代、步驟、依賴、必要順序、錯誤和恢復。
  3. 幾何／物理：可見性、接觸、姿態、材料、座標系；有根據才填值。
  4. 知識：已知什麼、需哪段歷史、是否有唯一答案、何時可詢問。
  5. 執行／結果：contract、軌跡、觸發、結果證據、量測有效性與evaluator版本。

錯誤需區分錯目標、程式、接觸／機構、材料狀態、未完成、錯誤恢復與不可判定。人類做錯下一步時，T3預測其實際行為，T4可要求提出正確下一步。

3. 目標有效性

成對目標共享robot初態；示範與答案同步更換，獨立標註者應能辨別且專家都能完成。

例項化時記錄初態是否已滿足目標。主操作測試不能混入大量直接停止就成功的初態；辨認已完成、允許不動作可另成診斷條件。也要檢查兩個目標在物件對稱、身份重新命名或允許對齊後，是否其實變成同一個結果。

若外觀相同杯子被隨機交換，歷史和當前觀測都不提供身份對映，這是不可辨識，不是高難度記憶。須補線索、接受合法目標集合或改測詢問。

無影片、單幀、時間打亂和遮擋是診斷對照。打亂時序可能產生不可能過程，剪去關鍵資訊會改變答案集合。不能一律保留舊答案，將不再可解樣本算模型失敗。

4. 切分順序

原始活動／錄製／場景身份
→ source-group split
→ clips、QA、plans、prediction labels、sim pairs
→ 額外object/material/composition holdouts

追蹤原始session與相鄰clips、人物與場地、物件／衣物身份、mesh和改色版本、功能替代／擾動指令碼、teacher示範及衍生標籤。

跨人物、跨場景與跨材料是不同主張；每個split列出隔離軸和重用軸。不同資料集名不保證獨立來源：EgoSchema衍生自Ego4D；RoboReward沿用OXE／RoboArena。WatchAct使用LIBERO環境，則不等於所有人類影片也相同。

5. 預訓練與生命週期

分為控制資料、宣告外部資料、固定few-shot support、明訂online adaptation tracks。無法審核完整預訓練資料時，標未知／開放條件，不宣稱完全無汙染。

普通trial清空跨trial隱狀態，記憶track保留明訂session範圍。不能讓成對目標的上一個答案洩漏到下一個trial。

另保留LIBERO／Meta-World等工作啟發的學習設定軸：凍結策略、離線調適、固定few-shot、線上互動、連續任務學習。連續學習需預先排定回測舊任務，儲存「學到第幾個任務×被測任務」的成功率矩陣，辨識保留和遺忘；這不是T2的推理時記憶。

跨機體轉移需同時確認來源和目標profile的可解性、共享語義目標、adapter和目標資料預算。不能把不同DOF或action space的raw success直接混比，也不能假設人手3D軌跡可直接當robot joint actions。

6. 品質與發布

抽查可推斷性、標註分歧、校準誤差、合法替代、失敗／近失敗和目標對無關線索，公佈排除理由。開發版可提供候選spec；正式結果須經Q1–Q4，包含資料、assets、simulator、policy、config、evaluator及case版本／hash。

收集前先固定一份 data card

每一個來源活動需儲存來源 ID、session、人物／角色、相機安裝、時間與剪輯方式、物件／場景身份、使用條件與可發布範圍。每組 human–robot 配對必須說明是校準同場景、同物件語義對齊，還是隻有同一目標。

沒有校準的第三視角影片可以用來測語義理解，不應填入推測的 3D 座標。沒有保留真即時間的 VLOG 可以測程式圖，但未必能測接觸時間。沒有合法身份對映的記憶題要補資料或改變答案集合，不能用 hidden ground truth 製造不可解題。

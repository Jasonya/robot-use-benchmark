CHAPTER 12 / 14

工程實作、資料格式與發布

約 5 分鐘·資料快照 2026-09-21設計階段 Q0
先掌握這三件事
  • 先建立 registry、instance builder、adapter、evaluator 與結果紀錄。
  • 共同 API 不代表不同模擬器有相同動力學。
  • 本網站提供公開研究檔案；正式評測和平臺代跑仍待實作。
v0.4：任務規模與廣度共同驗收

完整任務庫初始目標為 2,000–3,000 個 G2；任務數與有效覆蓋各以最大可比基準至少 2 倍為目標。新增場域、家族、材料與機體的支撐配額。180 個藍圖保留為設計種子，原 100–140 預算屬歷史方案。

系統模組

  1. Registry：場域、家族、情境、能力、來源、變化與readiness。
  2. Instance builder：assets、引數、A/B目標、reset與觀測。
  3. Data builder：來源配對、時間／幾何／語義標籤與packets。
  4. Simulator adapter：reset、step、允許觀測、私有state、擾動和snapshot。
  5. Policy adapter：輸入、action contract、history lifecycle和預算。
  6. Evaluator：目標、過程、觸發和量測有效性。
  7. Aggregator：eligibility、權重、分組不確定性和結果包。
  8. Release／網站：版本、來源、方法卡、核驗狀態及下載。
build_instance(scenario, assets, config, contract) -> validated instance
reset(instance, seed) -> policy_observation, evaluator_initial_state
step(action) -> observation, termination_info
get_evaluator_state() -> private state, events, validity
inject_disturbance(trigger_spec) -> delivery record, state validity
export_trace() -> actions, observations, state/event evidence, hashes

相同seed不保證跨GPU、引擎或controller位元級一致。儲存版本、數值設定、實際初態hash和重跑容差。跨引擎是另一條件，不預設物理等價。

Backend 審核候選

剛體／機構可審核LIBERO／robosuite／RoboCasa或ManiSkill；布料／靈巧手可審核GarmentLab、DexGarmentLab、SoftGym；複閤家務／流體可審核OmniGibson／BEHAVIOR；導航／協作可審核Habitat、PARTNR、Assistax。

這是文獻導出的候選，不是已安裝、整合或跑通清單。數位到實體先採限定工具API／裝置狀態機，不宣稱開放網路或真實裝置泛化。

驗收關卡

層級 產物 通過要求
Q0 語義規格與來源 計數清楚、目標／近失敗／輸入／metric明確
Q1 場景例項 assets、目標、控制、reset、觸發、量測完整
Q2 專家執行 同介面可解、合法替代被接受、初態有效
Q3 判分器 成功／近失敗、過程缺失、量測故障與擾動有效性審核
Q4 重現基線 provenance、split、方法配置、重跑與統計可追蹤

網站或case IDs不替代Q1–Q4。Pilot以原16個候選池及M1重選結果為起點；不支援的布料或其他情境保留Q0，不以物件動畫假裝完成physics。

每個pilot須有A/B示範與可推斷性、專家解與合法替代、典型近失敗、版本化條件、自然失敗與注入失敗來源標記，以及evaluator獨立抽查。

共同 adapter 不是跨引擎等價

先固定一個可運作的 backend 和 profile，驗證 reset、step、允許觀測、私有 evaluator state、介入和 trace。後續加入第二引擎時，重新檢查接觸、材料、控制與判分；共同 API 不表示動力學一致。

數位到實體先採版本化的本地查詢 API／裝置事件模型，世界模型先固定 action adapter。兩者都需儲存工具／轉換器版本，防止把它們的差異算成 policy 能力。

評測資料流

registry / source lineage
→ native task / asset / controller reuse audit
→ canonical spec + scene builder
→ Q1 instance → Q2 expert solvability → Q3 evaluator audit
→ source-group split + valid typed cases
→ frozen release + policy adapter + trials
→ trace / validity / outcome evidence
→ macro aggregation + paired uncertainty + verified result package

正式 case 不應由未繫結的 symbolic predicates 直接生成。Policy 可見資訊、evaluator 私有答案和完整 state 要分層；公開網站與下載包不能攜帶 private split 答案。

三種上線階段

階段 使用者能做什麼 現在狀態
設計／檔案網站 閱讀來源、規格、候選清單與下載 研究檔案已提供網站閱讀；正式評測服務尚未推出
下載評測與結果提交 本地跑固定 release，提交 traces、hash、coverage 與方法卡 尚無可執行正式 release
平臺代跑模型 上傳／指定 checkpoint，由平臺排程並核驗 private test 尚未實作；需要 runtime、配額、資源與提交格式

結果狀態分為 submitted_unverified、reproduced_verified、rejected_or_incompatible。使用者自行回報不能標成平臺重跑。若選定公開服務方式，先在實際可重現子集完成發布，再擴大。

完整 episode template、欄位含義、規劃器與建置檔案索引列在附錄 H。完整報告 可獨立說明設計；真正重跑仍需原始程式、資產與之後完成的實作。

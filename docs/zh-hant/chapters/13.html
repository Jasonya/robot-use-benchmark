論文流程與 milestones

約 5 分鐘·資料快照 2026-09-21設計階段 Q0
先掌握這三件事
  • v0.4 先固定共同分類、參照集與廣度配額，再驗證跨 backend 閉環。
  • 每批 250／500／1,000 都同時檢查數量、場域、家族、機制、材料與機體支撐。
  • 規模與廣度共同達標後凍結主實驗；原 24 週示例不作本版承諾。
規模與廣度共同驗收；開發執行已有新證據

全庫初始目標為 2,000–3,000 G2，任務數／有效覆蓋各以至少最大可比基準 2× 為目標。現已完成50個Meta-World原生任務的開發執行，本次新初態測試 1,250 次；它們不等於新造或跨作去重後的G2。180個藍圖與原100–140預算保留為歷史種子／方案。

10. Milestones 重新對齊整體目標

階段 主要交付 驗收重點
S0 來源盤點 完整 native records、版本、單位與 lineage 本輪已有 5,020 筆靜態紀錄；不算成正式任務數
S1 共同分類與缺口 G2 規則、參照集、F/K 分類、場域矩陣與配額定版 確定兩個相對門檻的分母；不能只挑較小對照
S2 跨 backend 閉環 代表性 6–8 個 anchors、例項、專家解與判分 驗證介面和量測；不是論文規模上限
S3 批次擴張 250／500／1,000 個驗證任務及其 bindings 每批同時看 N_task 和各廣度配額，避免只擴容易的一類
S4 達雙門檻 向 2,000–3,000 與更多有效覆蓋推進 任務規模及 coverage ratio 同時達標，核心場域／材料／機體支撐足夠
S5 凍結與主實驗 固定測例、完整 eligible 集合、基線、oracle／ablation 所有正式結果能回查版本、cases 和 traces；測試後不挑題
S6 發布與論文 code、data、evaluator、核驗結果與完整稿件 「更多、更廣、統一」每個主張都有相應證據

設計網站和階段性 beta 可以持續公開；只有通過共同門檻的正式版本，才能標示已達成「規模與廣度優勢」。未達時公開進度並繼續擴充，不以換單位或降標準代替成果。

11. 論文最後要怎麼呈現

主表同時列出：native counts、正規化 G2、有效場域／家族／機制格子、材料與機體支撐、G3、typed G4、實際 G5，以及資料來源量。

與對照工作的完整資源、可取得部分、已例項化部分和實驗 subset 分欄。原生 task、資料 episodes、影片 QA 和 benchmark wrappers 不能直接混加。

論文的主實驗須回答：擴大的任務庫與覆蓋是否帶來穩定、可解釋的新評測證據；哪些領域、材料、流程與來源仍是瓶頸；新增任務相對原作聯集有何真正差異。統一介面本身已有相關工作，不單獨當作新穎性。

目前實際進度

已有50個Meta-World原生任務的MuJoCo執行器。Forward-consistent訓練池與測試共有750個原生初態；最新測試250個新初態、五方法、1,250次執行。另保留早期介面與reset診斷，累計記錄4,286次開發執行。

這是state＋明示目標、單Sawyer手臂、剛體／關節任務的開發證據。正式G2去重、全域／材料／機體覆蓋、人類影片執行與通用基準release仍待完成。

第一個具體驗收包

  1. 一頁 paper pitch：主問題、兩三個假設、最接近工作、計數單位。
  2. 20–30 列復用審核：原 repo／commit／task ID、assets、示範、controller、evaluator、取得／使用條件、改造需求。
  3. 原生 ID → family／G2 → instance → typed case 的 crosswalk，環境 seed 與 policy repeat 分開。
  4. 選出 6–8 個情境，在同一介面完成專家 A/B 解、合法替代與有效 reset。
  5. 判分器接受成功，拒絕部分完成、錯物、錯順序與暫態假成功；儲存 trace 與獨立審核。
  6. 選定 pilot 的資料來源、基線路線與成本量測方法，才啟動擴張。

目前位置是 M0 的文獻與設計材料已具備；尚未通過 M1。完整平臺可保留 12／48／180 的發展方向，第一篇論文則以經驗證且能回答主問題的核心集合為準。

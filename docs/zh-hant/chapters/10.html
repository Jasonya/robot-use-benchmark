CHAPTER 10 / 14

難度如何量化

約 3 分鐘·資料快照 2026-09-21設計階段 Q0
先掌握這三件事
  • 難度屬於某個例項加上完整評測條件，不屬於論文名稱。
  • 十維人工向量是設計註記；經驗難度需要固定 agent panel。
  • 全模型失敗時，先排除不可解任務和錯誤評分器。

難度的單位是 instance 加上完整評測 contract。同一條毛巾、同一目標，在不同手部能力、觀測、controller、示範量和時間限制下，難度會改變。不相容或不可解的配置應標為不適用／無效，不能當作高難題。

設計難度：十維向量

維度 0 的錨點 2 的錨點 4 的錨點
H 依賴長度 一個獨立 primitive 數個因果依賴步驟 長分支、多個持續承諾
C 組合／因果 直接對應 選擇／排序已知子目標 新組合、多約束與依賴
O 觀測／記憶 相關狀態現在可見 遮擋或短歷史 隱藏狀態需長／跨 session 歷史
P 接觸／精度 不需接觸 中等容差的穩定接觸 窄容差、動態、柔順或密集接觸
D 形變 剛體狀態 中等材料形變 重大形狀／拓撲、自遮擋、混合材料
B 機體協調 單末端、固定底座 雙末端或底座與手臂協調 全身／多末端強耦合
G 泛化差異 匹配訓練分佈 held-out instances／scenes 新類別、組合、材料或機體組合
U 不確定性 目標／合法動作已知 多種可能解釋 需觀測／詢問的目標與結果不確定性
R 恢復需求 沒有注入擾動 一個可恢復擾動 多個相互影響的失敗與重規劃
S 社會協調 單獨執行 共享時序／輪流 意圖相關協作與變動對方行為

每維 0–4，中間值 1／3 由相鄰錨點判定。需保留完整向量，unknown 不填 0，並由獨立標註者檢查一致性。以下等權公式只是舊報告中的透明設計摘要：

D_design = 2.5 × (H + C + O + P + D + B + G + U + R + S)

它不是公認難度標準，不能拿來排列 168 篇論文，也不能跨 QA 和實體操作比較。專門的高精度任務可能很難，卻因沒有社交／記憶需求而總分低。舊報告的十個假設評分例子保留在附錄 H，沒有套到 180 個情境上。

經驗難度：固定 agent panel 後再估

D_empirical(t) = 100 × [1 − Σ_m w_m × P(success | m,t,contract)]
Σ_m w_m = 1

需要相同模組、相容 contract、固定方法群、多次實驗和不確定性區間。這只是該 panel 下的相對難度；換模型群就可能改變。少數共享 checkpoint／controller 的系統也不是大量獨立方法。

保留 method×task 的結果矩陣，先檢查是否存在足夠的成功／失敗差異，再考慮 IRT 或多維／階層模型：

P(success | m,t) = logistic[a_t × (ability_m − difficulty_t)]

需要檢查識別性、資料量、residual dependence、模型家族敏感性與 held-out-agent 預測；fit 成功不等於量尺有效。更新題庫時保留 anchor items，但重新驗證版本影響。tinyBenchmarks 是相鄰領域的方法啟發，Rliable 提供 agent 評測的統計方法參考；都不自動證明這套機器人難度量尺有效。P159 P160

難度、診斷力和重要性分開

全模型都失敗，可能是難，也可能是不可解、label 錯或 adapter 壞。先用專家、oracle 與判分器審核排除錯題。全模型都成功的題仍可重要，但對當前排序的鑑別力有限。

影片長度、子目標數、物件數、A/B/C 實作階段都不能直接取代實測難度。EgoSchema 的時間證據觀點提醒我們：應測「必須看多少歷史」，不只是「影片有幾分鐘」。P028

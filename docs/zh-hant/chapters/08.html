CHAPTER 08 / 14

評測協定、指標與比較方法

約 8 分鐘·資料快照 2026-09-21設計階段 Q0
先掌握這三件事
  • 終態成功、完整合規成功、配對目標成功分開報告。
  • 恢復要同時列全 episode、擾動施加率與條件式成功。
  • 模型在相同資訊、控制、資料和預算下比較。

1. 一個 episode 的共同約定

固定：

  • task family 與 release version；
  • robot profile、action interface、觀測；
  • 示範／文字輸入 track；
  • 訓練、線上適應與推理預算；
  • simulator、資產、控制／物理步進設定；
  • reset seed、初始狀態與驗證摘要；
  • 成功 predicate、必要過程、時間和幹預規則。

相容的模型在同一評測 contract 下比較。不同機體、輸入、oracle 資訊與 adaptation regime 分榜。

goal_spec、私有測試答案、精確 evaluator state 和正式測試 seed 不得作為 policy input。公開的任務家族說明與訓練案例可以存在，但不等於公開正式測試 instance。

2. 成對目標測試

對同一 task family、同一 initial scene、同一 generalization／disturbance 條件和 seed，建立 A/B 兩個有效目標。使用兩個示範分別指定 A 和 B。

要求：

  1. 初始可觀測狀態匹配，不能只靠場景猜答案。
  2. 示範改變時，ground-truth 目標同步改變。
  3. A/B 都可解，而且可以客觀區分；若終態可以同時成立，另定互斥要求或換一組目標。
  4. 配對示範的無關因素應匹配或平衡。
  5. 不能讓 task filename、public ID、長度或提示模板洩漏目標。

定義：

valid_success(e) =
    required_final_predicates(e)
    AND required_trace_constraints(e)
    AND no_disallowed_intervention(e)
    AND within_declared_budget(e)

pair_success(p) =
    valid_success(p.A) AND valid_success(p.B)
    AND both_outcomes_follow_the_corresponding_demonstration

若評分器還輸出另一目標是否成立，應檢查兩個目標的區分。不要假定 pair success 的 chance level 固定為 25%；它取決於動作空間、目標結構與模型先驗。

no_video 對照用來量測先驗或場景捷徑，不能假裝它也獲得同樣的目標資訊。oracle_goal 是診斷上界，不是正式模型排名。

3. 2×2 條件與變化型別

Seen-Clean：已見例項，無擾動
Unseen-Clean：未見例項，無擾動
Seen-Disturbed：已見例項，執行中擾動
Unseen-Disturbed：未見例項，執行中擾動

「未見」依 track 具體定義為 object identity、geometry、material parameter 或合法功能替代；不得在不同方法間改定義。每個條件內包含多個真實有效的變化例項，不以重複 seed 冒充新物體。

材料子研究需記錄可比幾何、摩擦、質量／密度、彎曲與拉伸引數、引數取值依據和 simulator 適用範圍。若沒有校準物理材料，結論僅能針對「模擬引數變化」。

不要把這四個條件當成必然遞增的難度級別；難度需由結果檢查。

4. 擾動與恢復：避免分母偏差

主測試在完整 episode 中，在預定的語義 checkpoint 注入擾動。checkpoint 應對合法策略公平；不能只獎勵某一種軌跡，或阻擋本來允許的替代解法。

必須記錄：

  • 是否到達 checkpoint；
  • 是否真的注入擾動；
  • 觸發事件／時間、擾動引數；
  • 擾動後狀態是否有效；
  • 最後是否成功、額外時間／動作數。

分開報告：

Full success rate =
    完整成功 episodes / 全部有效起始試驗

Trigger delivery rate =
    確實注入擾動 episodes / 全部有效起始試驗

Conditional recovery success =
    擾動後完整成功 episodes / 確實注入且狀態有效的擾動 episodes

最後一個量受模型能否到達 checkpoint 影響，不能單獨拿來排序整體能力。未能到達 checkpoint 的模型不應因為少進入難案例而獲得更好的總榜分數。

若合法策略完成了任務卻沒有經過觸發點，應修正觸發定義或將它標為未施加介入的試驗；不可把它宣稱為恢復成功。

可以另外建立固定失敗快照診斷集，讓模型從同一組狀態與同一個可用歷史重新規劃。該結果標為 snapshot_replanning，不可與 online_recovery 混成一個量。

模擬器故障、無效 reset、evaluator 感測缺失要記錄並按預定規則處理。模型 crash、超時、控制失敗通常是方法結果，不應為了提高分數而丟掉。所有排除事件及數量都要公開。

5. 真正完成與表面完成

每個 task family 須有：

  • 成功解及至少一種合法替代解；
  • 部分完成反例；
  • 錯物體／錯位置反例；
  • 必要過程未完成但終態看似正確的反例；
  • 過渡性成功但最終不穩定的反例；
  • evaluator 無法可靠量測時的處理規則。

布料摺疊不能只用面積或緊密度；至少檢查指定摺法對應的拓撲／邊緣關係、幾何與最後位置。具體量測方法與容差在物理 backend、資產與獨立評分樣本上校準，再凍結。

過程約束只包含使用者任務真的需要的事件。不能為了讓題目變難而要求逐幀模仿示範，除非 track 明確評測軌跡模仿。

6. 聚合與不確定性

先在固定 case 的重跑內平均，再按 instance／spec／family 和場域的預先公佈權重聚合。場域與家族交叉時須明確分配權重，不能讓同一家族只因跨場域重複出現便無限制加權。成對目標和同一來源／物件／變化 instance 的關聯要保留。

報告內容：

  • full valid success、pair success；
  • 四個條件的成功率；
  • 每個領域與變化型別的分佈；
  • trigger delivery 和 conditional recovery；
  • final-only 與 trace-valid 判定差異；
  • 時間、動作、幹預與排除試驗；
  • 相容任務覆蓋與未支援格子；
  • 不確定性與 trial 數。

模型比較採相同 case 的配對分析。Bootstrap／階層模型要對應實際抽樣單位，避免把同一影片的 clips 或同一物體的 seeds 當成大量獨立證據。很少的任務家族只能支撐 pilot 結論。

不先設計一個把正確性、時間、風險等任意加權的「universal intelligence score」。正式排行榜可以有主要成功率，但必須同時顯示覆蓋與分項。

八模組的計分分界

1. 成功的層次

GoalSuccess = required_final_goal_predicates_at_valid_termination
CompliantSuccess =
    GoalSuccess AND required_process_constraints
    AND within_budget AND no_disallowed_intervention

兩者同時報告。過程約束只包含任務明訂需求，不要求逐幀模仿。SafeVLA-Bench、OopsieVerse和Embodied Agent Interface是相關先例。

平均子目標分數不能代替完整成功：在籃內不表示摺法正確；兩站都送到不表示必要順序正確；面板復位不表示程式曾執行。

2. 各模組的計分邊界

  • T1：答案、定位、關係與狀態分開。
  • T2：記憶答案、證據和幹擾曲線；行動成功另列。
  • T3：固定horizon與K。2D／3D、序列、接觸和時間分開；有效時間和座標標籤是前提。
  • T4：語義計畫有效與物理可行分開，用固定executor和oracle診斷。
  • T5：固定機體、輸入、動作與資料條件。
  • T6：diagnosis、online recovery和snapshot replanning分開。
  • T7：共同結果、時序、協議、延遲；模擬代理量不當成真實人類滿意度。
  • T8：視覺品質、狀態一致性與固定adapter下可執行性分開。

剪輯影片不能直接以播放秒數計物理接觸時間。軌跡要宣告座標、尺度與有效frames；best-of-K不單獨證明機率校準。

40 個候選指標在附錄 D 逐項列出名稱、單位、分母／標籤需求、解讀限制和來源。這 40 項不是每題都要算，也不應任意加成一個 universal score。

基線與必要對照

路線／控制 主要用途 比較時固定什麼
資訊對照：無影片、單幀、完整影片、匹配文字 檢查模型是否使用任務相關資訊，以及場景捷徑 資訊不足時重審可解性；無影片不是等資訊條件
影片／語言理解與規劃模型 測 T1–T4 的推理與證據 輸入、history、tools、label 與預算
模組式 video → goal／plan → controller 區分上游與控制瓶頸 共用 executor；以 oracle goal／plan／state 分別診斷
直接 visuomotor imitation，如 ACT／Diffusion Policy 建立動作學習參考 示範與訓練資料、觀測、action interface、訓練預算 P130 P138
通用策略／VLA 參考 測開放或受控資料設定下的泛化 checkpoint、外部資料、適應方式、profile 相容性 P134 P135 P136 P137
記憶／恢復消融 檢查 history、diagnosis、replanning 的作用 相同 case、觸發、可用歷史和計算預算
特權 state／專家／oracle 驗證可解性並定位瓶頸 明確標為診斷上界，與一般方法分欄

這是方法路線規劃，不是已確認所有 checkpoint 都能讀取人類影片或使用同一雙臂 controller。M1–M2 要先確認相容性；不相容的模型不得暗換輸入或控制器後放進同一欄比較。

主實驗需要回答的問題

  1. 示範改變時，行為是否跟隨 A/B 目標？無影片與單幀可解釋多少捷徑？
  2. 在分開控制物件、材料、場景、替代與任務組合後，哪些變化造成下降？
  3. GoalSuccess 與 CompliantSuccess 的差距有多大，哪些近失敗會被終態判分漏掉？
  4. FullEpisodeSR、TriggerDelivery、ConditionalRecovery 和 snapshot replanning 是否給出不同診斷？
  5. Oracle goal／state／plan 解除哪個瓶頸？上游 QA 好是否真的預測執行好？
  6. 排序對家族／場域權重、樣本選擇、模型家族和不確定性有多敏感？

這些是假設與分析計畫，不預設一定顯著。主測試凍結後不應根據模型表現挑題；改判分器時升版本，重跑受影響比較。

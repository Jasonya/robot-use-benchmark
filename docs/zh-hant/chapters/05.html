表中的「設計啟發」是研究方向，不是已證明原作沒有的功能。沒有列出某項能力，也不能當作原作不支援。真正的新穎性仍需具體 task／data／evaluator 審核和 matched experiments。

是否全部用之前的 benchmark 整理就好

可以大量復用，但整理本身只完成文獻地圖與候選設計。 要成為 benchmark paper，需要讓既有資源在共同定義下形成可驗證的任務、資料與評測，並用實驗證明它回答了有價值的問題。

復用方式 可以沿用 必須補的部分
原協定重現 原始任務、資產、示範、評分器與 split 固定版本、執行驗證、真實原生計數；可用來建立參考成績
任務／資產移植 場景、物件、controller 或子技能 新 backend 的接觸、reset、觀測／動作和判分重新驗證
評測條件擴充 已可解的 base tasks 人類示範 A/B、歷史、擾動、替代、必要過程與新 labels
多來源整合 不同 suite 的合法子集 G2 對映、source lineage、相容性、去重、權重與結果分層
新物理情境 既有 mesh／流程可作起點 真正 physics、量測、專家解、合法替代與近失敗；不能靠動畫補齊

不能只改 task 名稱或把多套排行榜拼在一起。若觀測、控制器、robot、資料和評分不同，合併平均會把方法差異與評測差異混在一起。

LIBERO 的實際粒度示例

固定官方 commit 8f1084e3132a39270c3a13ebe37270a43ece2a01 的 manifest 有 130 個不同 native task IDs：spatial 10、object 10、goal 10、libero_10 10、libero_90 90。這次只抽查其中 10 個 BDDL goal 欄位，沒有執行模擬。

三個 spatial 任務的完整 goal expression 相同，但 instruction 的位置／關係指涉不同；三個 object 任務的物件名稱不同，運算形狀都是 In(object, basket)。抽樣出現 5 種粗粒度 goal patterns，不代表它們正式等於 5 個 canonical tasks，也不代表整個 LIBERO 只有 5 種任務。必須連指涉、機構、reset 和 evaluator 一起核對。完整例子與固定來源在附錄 F。

CHAPTER 02 / 14

用一個例子理解整套系統

約 3 分鐘·原稿快照 2026-09-21歷史設計原稿
先掌握這三件事
  • 文獻分類回答「研究測什麼」，任務規格回答「機器人要做什麼」。
  • 以摺毛巾走過家族、任務、例項、測例與一次執行。
  • 問答、預測、規劃和物理完成需要不同證據。
先看代號：G是計數粒度，T是評測模組。

例如G2是任務規格、G4是一個測例；T3是預測、T5是實際執行。這些是本計畫的整理編號，數字不代表難度，也不要求依T1→T8順序執行。

G0–G5完整定義 →T1–T8完整定義 →與任務環境的關係 →

以前面的「文獻 taxonomy」和「任務 ontology」為例：前者像圖書館的分類，告訴我們研究在測影片理解、預測、操作還是恢復；後者像正式考試的出題規格，定義機器人究竟要做什麼、看到什麼、怎麼判分。

看見很多摺衣論文，不代表要按它們佔全部文獻的比例出題。兩篇論文也可能使用同一批影片或同一模擬環境。研究篇數、獨立資料量和實際任務量必須分開。

G2 正規化 task spec 指定摺法的目標、指涉、必要過程與有效性 需要可審核的正式任務定義；目前 TBD
G3 instance 某個 mesh、材料引數、桌面、實際初態與 robot 有資產、引數與 state hash 的具體例項
G4 case 給頭戴示範、固定觀測與預算，抓持後施加指定滑脫 一個有合法輸入、標籤和 evaluator 的測例
G5 trial 某模型在此 case 跑一次 才會產生軌跡、成功／失敗、時間與證據

由同一個 instance 可以產生不同的測例：T1 問哪條邊對齊、T3 預測下一接觸、T4 規劃摺法、T5 實際摺疊、T6 滑脫後恢復。每個模組仍需要自己的資料與答案；不能直接把一個情境乘八就當作八種已完成評測。

三個容易混淆的情況

改顏色或位置通常增加 G3 的例項變化；沒有改變任務語義時，不增加 G2。從摺好改成摺好後存入籃子、而且保持摺法可能改變 G2。同一題以五個 policy seeds 重跑只增加 G5；若 seed 改變物理初態，則增加 G3／G4 的 realization。

「摺得很緊」、「外形像長方形」、「已在籃子裡」都不能單獨證明指定摺法正確。必須把邊緣對應、層／拓撲關係、幾何、釋放後穩定性與收納要求分別寫清楚。第 09 章有完整案例。

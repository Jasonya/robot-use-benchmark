EmbodiedMemory-Bench: Benchmarking Embodied Memory for Long-Horizon Embodied Tasks

返回逐篇總表核心內容已核讀 benchmark／資料／評測主來源原作 ↗ 用途與原生規模依據

核讀快照 2026-10-11。已讀範圍限所列片段；本輪未執行上游程式。

循官方 project 搬移頁確認 ZJU-OmniAI/Embodied-Omni 的 embodied_memory/ 為本篇公開程式，已追 manifest loader、history sanitization、simulator runner、四家族具體 success／ERR 與 macro 分母。HF 有 frozen release，但公開 loader 與發布路徑不一致；code 亦將任一 ERR 視為不能成功，與 paper 的可恢復終態 SR 有實質差異。

版本與身份

code 固定 f0409a8ecd858acd1f53c69f6424e0c4af83737b，只核 embodied_memory 子專案。HF 固定 3b45bd3f3a67a23b09b78d27c3ab563a700e832a；README 說公開 episode-level 名稱／描述／probe instructions 已英文化並更新 hash，原語言 revision 為 28694bf83b78049ac96ba01c9ffb13aeac7eaef9，不能混用。HF canonical manifest SHA256=6c69644b9fc4755065830e4884a12898e3ed0db32c1825dbecf623c37b9b1bc2 是發布者 metadata 宣告，本輪未下載 full2554 逐例重播驗算。

pinned arXiv:2609.28236v1 題名及 Lizhou Liang 等作者與 embodied_memory/README 一致。PDF 原始 ZJU-OmniAI project 轉址到 Embodied-Omni/EmbodiedMemoryBench，新頁直接連官方 monorepo 與 lzLiang/EmbodiedMemoryBench；不將參考文獻的 OpenBMB/MiniCPM-V 當成 benchmark。只核本篇 embodied_memory 子樹，未擴讀同 monorepo 的 reasoner／navigator。

領域
居家整理與清潔
環境
AI2-THOR 單房間組合的多房間脈絡與 ProcTHOR 場景；論文 Table 9 報 1,118 個 globally unique source scene IDs、四 room types，不能加總各家族重疊 scene counts。當前 env 以 probe.scene reset，使用 500×500 RGB、visible_objects、agent_state、available_actions 與高階離散目標動作。原生 x/y/z、objectId、rotation_y（0–360）及相機角度須保留；不把 Navigate／PickUp 等介面當連續機器人關節控制。
任務
manifest 四家族 l2_passive、l2_dynamic、l2_interaction、l3_owner_habit 分別對應 Passive Observation、Dynamic Tracking、Interaction Failure、Experience Generalization。probe_retrieve／probe_track_location 要到記憶位置並拾取目標；probe_avoid_failure 要選非已知鎖定容器存放物品；owner_habit 以先前 correction 對新物件選擇合規 receptacle。construction schema 的 L0–L3 enums 不等於四個發布家族。
題數與資料
data.load_manifest 讀 JSONL 的 id、family、source.episode_path、source.episode_sha256；拒絕重複 id，先依 family／per_family 選擇，再檢查 episode 檔與可選 SHA256。run 另以 source.probe_id 精確配對一個 probe。episode JSON loader 是 json.load；schema 含 episode_id/name/difficulty、sessions[].context_trajectory.steps[] 的 step_id/image_path/visible_objects/agent_state/action/feedback、micro_probe 或 macro_probe，以及 hidden_rules／memory_cues／expected_actions／evaluation_hooks。時間原生單位是有序 session／step，非影片秒。paper 與 HF metadata／audit report 同報 2,554=1,036+1,052+263+203、split=all；本輪僅機械清點小型 experience_generalization manifest 的 203 個唯一 id，未重新驗證全部 2,554 episodes。
評估方式
實際鏈為 CLI evaluate→load_manifest→run.evaluate→env.step→EpisodeEvaluator.evaluate_probe。env 為每次 action 嘗試記 success／feedback，無效動作及 Done／Stop 也計入 actual_steps；預設 8-step budget 覆蓋 schema 的 30／60 預設。success 讀 simulator world_state 的持物／parent／狀態並核對成功執行的導航或放置；L2 可接受原生指定的同類且同記憶容器物件，owner_habit 保留 executable receptacle alias。ERR 只比對成功動作的 frozen triggers，L2 是先去不同 receptacle type、interaction 是重複已知錯誤 action–target、owner_habit 是違規放置；每 subtask ERR=min(1,觸發數/max(1,required_memory_integration 數))，probe 對 subtasks 平均。run.summarize 以每家族 task_completed 布林值／已記錄 rows 計 SR，再對實際出現家族等權 macro；ERR 同樣先家族平均。不能將 smoke 選樣或中止前 summary 當 Full-2554。InvalidPhaseOutput 保留作該例失敗，infra exception 寫錯誤並中止，不產生新的完整 summary。RAR/AES/MAE 是附帶 diagnostics，不等於 paper 主 metric。

怎麼接入我們的benchmark

可重用

官方 frozen manifest 身分／family／hash、episode schema、session-step 脈絡、模型可見欄位過濾、動態 action registry、trace 與具體 state／ERR evaluator 可重用；case、probe、action attempts 需分開。

需要轉換

source 同時記 paper v1、GitHub commit 與 HF revision；domain／environment 保留 room type、host simulator、scene provenance 與重用關係。task 維持四家族／probe 規則；case key 用 manifest id 及 episode_id+probe_id，另以 organized_view 建可攜 execution_path，不覆寫原研究路徑或 lineage。history/action/feedback、model-visible context 與 evaluator-only rules 分開對映；evaluator 儲存 terminal-state SR 與此版 ERR-veto SR 差異、逐類分母、8-step／80-per-session budget、grounding repair 與實際 world-state。

仍需補齊

修正 published manifest→loader 路徑橋接、核對 ERR-veto 與論文 scorer、全 release hashes／素材／scene reset 閉合、完整 runtime 及同一預算重現。單一 nested episode 嘗試超過本輪 512 KiB 小文字上限，已停止且保留 receipt；不把該檔視為已讀或不存在，亦未下載 RGB／模型／simulator。

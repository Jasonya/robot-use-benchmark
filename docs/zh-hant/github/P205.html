CapMem: A Benchmark for Caption-Based Episodic Memory in Egocentric Video

返回逐篇總表實作尚未確認 benchmark／資料／評測主來源原作 ↗ 用途與原生規模依據

核讀快照 2026-10-11。已讀範圍限所列片段；本輪未執行上游程式。

CapMem 的 pinned paper 有完整標註、單一 evaluation split、caption／frame 協定與 retrieve-and-verify 規則，Appendix G 亦宣稱發布程式；但已收錄 PDF／project／搜尋來源未提供可確認的本篇 GitHub release。未把同名記憶遊戲或 CapMemUtils 當成實作，也未假造 loader／scorer 檔案。

版本與身份

全篇依 pinned 2609.17688v1 與既有 2026-10-10 搜尋／project cache；沒有已確認 repo commit 可記。論文 p.24 的 release 宣告不能替代可讀原始碼。沒有新批次搜尋、模型執行或資產下載。

核對 arXiv:2609.17688v1（2026-09-15），Dingli Liang、Yiqiao Xie 等九位作者。project_candidates 的本篇沒有 project 或 repo；既有 CapMem egocentric 搜尋為 0，廣義 CapMem 搜尋的前 8／10 個結果未建立作者或論文對應。因此狀態是尚未確認程式倉庫，不是證明全網無 code 或 repository 404。

領域
居家整理與清潔、寵物照護與動物活動
環境
75 段既有公共人類第一人稱影片，共 33.7 小時，來源為 Ego4D、EgoLife、EgoPet、EPIC-KITCHENS、HoloAssist、ENIGMA-51、CASTLE2024。四用途是 Daily Life & Domestic、Outdoor & Mobility、Work & Procedural、Pet Related；16 scenario labels 不等於 16 個已去重可執行世界。
任務
主題是 Episodic Memory Video Caption QA；CleanQA（僅問題／選項）、Direct VideoQA（抽樣影格）、CaptionQA（時間化文字記憶）是同題三種資訊條件。Ego／Exo × Who／What／Where／When／How 為問題分類，50 templates 是出題樣板；Object、Attribute、Spatial、Action 為可重疊標記，不是額外物理任務。
題數與資料
論文 Appendix E 的 2,109 人工 candidates 經雙 reviewer 留 1,276，文字捷徑 filter 刪 352 後剩 924，再復核恢復 76，得到 1,000 題。Appendix G 指定每題包含 question identifier、父資料／影片 ID、四選項與正解、evidence timestamps、domain／scenario、Ego／Exo、4W1H、evidence-location、多視覺 tags；此為論文所述內容，沒有實際檔案可驗證 JSON key 名稱或 loader。單一 1,000-question evaluation split，無獨立 dev；來源影音／原庫標註不重發。影格 cache 是 1 fps，full-coverage caption 用連續 30／60 秒窗；caption 完成後以文字回答同影片各題。
評估方式
論文用四選一 QA accuracy（正確題／實際評測題）及每題 token 成本；主設定 N=1,000，Gemini 3 Flash Direct VideoQA 僅 N=786，相關配對比較須對齊這 786 題。duration 子集 208／792 題，evidence-location 子集 348／507／145 題；multi-label tags 的分母重疊。CleanQA 15%–35% 是 model 進入主評測的 gate，不是 case 成功門檻。Direct 的 InternVL／Qwen frame caps 為 128／768；full-caption 無 video-level cap，六 Qwen 的 frame-aligned control 才用與 direct 相同的 frames。Appendix D 的 retrieve-and-verify 最多三 seed、neighbor=1、NMS 45 秒，最多三段各四個影格驗證；僅 strong 視覺支援、合法字母且無 clock-time cue 才覆蓋原 CaptionQA。該 override policy 在全 benchmark 錯誤分析後選定，作者明示屬 post-hoc proof of concept。未取得 concrete scorer，答案 parser、無效輸出、例外／遺漏題入分母方式及實際 filter 實作均未核實。

怎麼接入我們的benchmark

可重用

可重用原生用途／題型／多標籤、單一 evaluation split 的論文統計、公開 prompt 文字、input-budget 對照與 post-hoc 限制。

需要轉換

source 綁 paper v1 並保留七個父媒體來源；domain／environment 保留四用途與 scenario labels。case 用 CapMem QA ID 關聯 parent video／evidence 與選項，三種資訊條件及 30／60 秒 caption 版本作同題條件；evaluator 儲存 matched question IDs、完整或 786 子集、frame IDs／captioner／QA model、caption 一次性成本與逐題攤提成本。retrieve-and-verify 另記 override／wrong→correct／correct→wrong，不能與無視覺 CaptionQA 混記。

仍需補齊

作者可驗證 release URL、官方 annotations／question IDs／split manifest、JSON schema、reader、caption cache 索引、各協定實際 scorer 與可追溯排除清單；還需獨立 dev／held-out policy 驗證。未取得的 LICENSE-DATA／LICENSE-CODE 僅是論文宣告，不列成已讀檔案。

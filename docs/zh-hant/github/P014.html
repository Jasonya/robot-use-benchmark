P014 · Ego-Exo4D

Ego-Exo4D: Understanding Skilled Human Activity from First- and Third-Person Perspectives

返回逐篇總表核心內容已核讀 benchmark／資料／評測主來源原作 ↗ 用途與原生規模依據

核讀快照 2026-10-10。已讀範圍限所列片段；本輪未執行上游程式。

Ego-Exo4D 的主檔案、姿態、步驟與視角關係倉庫分工明確。已核對共享步驟 ID、姿態有效關節／座標以及具體評分；挑戰年份與論文任務清單不能混為一談。

版本與身份

已釘選檔案的 challenge 頁為 2026，但 pose 倉庫 README 仍列 2024；不能把當年開放的 2 項挑戰當整個 benchmark 覆蓋量。body loader 排除含 bouldering 名稱的 take 並依相機／標註可用性篩選，應儲存實際納入清單。relation README 的 translation 仍寫 Coming Soon，不能只憑此推定 tree 完全無相關程式。

領域
餐飲與烹飪、個人照護、交通移動與車輛維修、休閒與運動、音樂與表演、穿戴互動與動作介面
環境
同時拍攝第一／第三人稱的熟練活動，檔案舉運動、音樂、舞蹈、腳踏車維修。以 take_uid 連多相機與標註，camera 數不等於環境數，scenario 是活動分類。
任務
步驟辨識／程式理解、穿戴者身體／手部 3D pose、ego-exo 物件 correspondence 等分成子挑戰。taxonomy 的 step_id 僅 scenario 內唯一；跨 scenario 共用步驟以 step_unique_id 表示，不能逐 scenario 直接加總。
題數與資料
keystep JSON 有 annotations/taxonomy/vocabulary，含 take_uid、scenario、segments 的 start/end_time、step_id、step_unique_id、is_essential。body loader 讀 takes.json、camera_extrinsics、annotation／automatic 與可見旗標，提供 global／aria／當前相機座標選項。hand GT 以 take_uid/frame_number/right或left_hand_3d 及 hand_valid_3d 索引。
評估方式
手姿態要求 21×3、將公尺轉毫米，僅有效關節計 MPJPE；PA-MPJPE 使用平移／旋轉／尺度對齊，逐手影格誤差再平均。offset 模式加回 GT wrist，須列成不同條件。細粒度步驟以 ego_segment_name 對齊 label_id，缺預測報錯，計 top-1。correspondence 提供邊界 F 與輪廓中心距離／影像對角線正規化；完整聚合入口尚未驗證。

怎麼接入我們的benchmark

可重用

take／步驟全域 ID、階層 taxonomy、姿態有效性旗標和手部 evaluator。

需要轉換

環境保持實體場景／take／相機多層關聯；scenario→task 用原生 taxonomy，step_unique_id 保留跨 scenario 共用。姿態與視角關係以獨立 profile 記錄 frame、座標、米／毫米、pseudo/manual、GT wrist 條件與對齊方式。

仍需補齊

尚未取得多視角影片與校準、執行 pose／keystep evaluator，或完整核讀程式理解／proficiency 的實作。fine_grained/eval_json.py 使用 os.path 卻未 import os，為靜態發現的整合問題；需在 adapter 測試時修正並保留差異。

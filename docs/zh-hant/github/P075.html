P075 · VIMA

VIMA: General Robot Manipulation with Multimodal Prompts

返回逐篇總表核心內容已核讀 benchmark／資料／評測主來源原作 ↗ 用途與原生規模依據

核讀快照 2026-10-10。已讀範圍限所列片段；本輪未執行上游程式。

VIMA-Bench提供任務、資料與成功判定，VIMA倉庫提供模型與互動範例。已核讀多模態prompt、四級partition、T+1/T資料對齊，以及visual_manipulation與without_touching的具體checker；primitive步數不能當低階控制步數。

版本與身份

train與L1 YAML整檔相同（SHA256 bf577e269939b6b9850f1d4fe1deb4e532b1badae6711cb4c74b9f438c611322）；泛化須靠不同初始化，不能把相同YAML當已固定test cases。VIMA example.py一直重設seed42，reset失敗才加seed；顯示範例設hide_arm_rgb=False，README benchmark預設True。其TimeLimit是oracle_max_steps+2，並非完成全級評測的統計指令碼。

對應arXiv:2210.03094v2（2023-05-28／ICML 2023），收錄年份2022是首版年。兩個官方倉庫都連同一arXiv；VIMABench固定97e0af11e126fd477c9d81eeabfb6c739021c680，VIMA固定8449837aa453f8ec9ba229cb956e3bbef5c796ea。

領域
居家整理與清潔、通用物件與機動作業
環境
PyBullet／UR5桌面，前方與俯視RGB＋segmentation；基礎physics為240 Hz。位置bounds為x=[0.25,0.75]、y=[−0.5,0.5]公尺。吸盤pick-place或spatula push是完整primitive，一次env.step內含多個移動、接觸與settle步。
任務
全庫17個模板；train/L1/L2各13、L3為12、L4為4個模板，不能直接算17×4套獨立任務。L4是sweep_without_touching、novel_adj_and_noun、follow_motion、same_texture。visual_manipulation的goal含objects/matches/target poses/metric/params/max_progress；影像placeholder與語言由generate_prompt共同生成，不能把prompt_assets丟掉後稱為同一任務。
題數與資料
發布說明為650K成功訓練軌跡，非測試case總量且本輪未重新清點資產。每trajectory含rgb_front/<t>.jpg、rgb_top/<t>.jpg、obs.pkl（segm/ee）、action.pkl、trajectory.pkl（prompt/prompt_assets/steps/success/failure及seed、物件對映、action_bounds等meta）。writer明確儲存T個actions與T+1個observations；loader將JPEG HWC轉CHW。action為pose0/pose1各2D位置＋xyzw四元數，模型範例另執行位置反正規化與quaternion範圍轉換。
評估方式
env.step→task.update_goals→具體check_success→info.success/failure；reward固定0，done也可能來自失敗或primitive timeout。visual_manipulation設定pos_eps=0.1公尺，is_match只比xy距離，忽略z與旋轉；完成的goal逐一移除，誤把distractor當目標／物件亦失敗。without_touching每50個physics steps檢查物件點集與禁止區域重疊，一次違規即鎖定failure，最後還需完成精確目標數；不是逐接觸事件的檢查。

怎麼接入我們的benchmark

可重用

模板class、版本化partition/YAML參照、prompt_assets、obs/action時序、seed與具體幾何／過程checker。

需要轉換

case ID需含template、partition、seed、物件/材質及prompt媒體；保留T+1/T對齊、2D雙pose primitive、oracle-only goals、違規記憶與50-frame檢查頻率。任務模板、軌跡量及rollout數分欄。

仍需補齊

正式eval seed/case manifest及跨task聚合設定、其餘checker逐一覆核、全部示範／prompt媒體閉合，以及policy checkpoint與視覺資訊條件驗證。

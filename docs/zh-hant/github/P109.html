REFLECT: Summarizing Robot Experiences for Failure Explanation and Correction

返回逐篇總表核心內容已核讀 benchmark／資料／評測主來源原作 ↗ 用途與原生規模依據

核讀快照 2026-10-10。已讀範圍限所列片段；本輪未執行上游程式。

REFLECT/RoboFail公開失敗設定、歷史摘要與修正執行流程；LLM對子目標的Yes判斷和修正後的模擬狀態成功是兩種不同證據。

版本與身份

原columbia-ai-robotics/reflect已轉址real-stanford/reflect，屬同一來源。README含舊commit示例連結；本筆固定c2f9db9，未執行LLM或模擬器。

領域
居家整理與清潔、餐飲與烹飪
環境
AI2-THOR FloorPlan場景和另附真實感測資料；RGB-D、聲音、robot state形成scene graph，GT detection與感知模型模式需區分。
任務
失敗原因／時刻辨識、執行錯誤與規劃錯誤、生成恢復計畫及執行檢查。tasks.json的scenario會共用task_idx，但failure設定／原計畫不同。
題數與資料
name/task_idx/scene/actions/success_condition、chosen_failure/params、gt_failure_reason/step；GT時間可能字串或list，轉換需原video_fps。events/step_i.pickle與nav_actions/interact_actions及L1/L2摘要有共同時間關係。
評估方式
run_reasoning以ans.split(", ")[0]=="Yes"解析子目標，輸出prediction和GT並列於reasoning.json，GT不可迴流模型。修正後另用check_task_success讀THOR物件狀態；例如task_idx=5檢查乾淨mug裝有coffee，未檢查countertop位置。原checker並非完整自然語言目標所有條件，自建規則須另版，不覆寫原分數。

怎麼接入我們的benchmark

可重用

scenario/parent task、失敗注入、感測時間鏈、原子actions及實體狀態checker。

需要轉換

同一case分診斷/恢復protocol，隔離GT原因與時間；保留parser、LLM版本、history截止、預算及原checker範圍，新加目標條件以derived-rule標記。

仍需補齊

全量感測資產與物件對映、GT/感知模式公平性、文字診斷一致性、任務自然語言與程式predicate差異審核。

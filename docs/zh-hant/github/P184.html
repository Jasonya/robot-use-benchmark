DLO-Lab: Benchmarking Deformable Linear Object Manipulations with Differentiable Physics

核讀快照 2026-10-11。已讀範圍限所列片段；本輪未執行上游程式。

已核讀8-task registry、原生RL/DiffRL action與時間約定、coiling/lifting/wrapping的具體reward、trajectory aggregation，以及LeRobot匯出／讀取。原生episodic return、存活到horizon的diagnostic success及論文影片人工success三者不同；生成示範的過濾也只排除absorbing，不證明任務完成。

領域
裝配與生產作業
環境
Genesis衍生的Taichi differentiable rod simulator，ROD material可設E/G、segment radius/mass、接觸friction與塑性；場景配Franka、cones/posts、rings等。coiling具體為60個rod vertices、間距0.02 m、radius0.01 m與固定cone，control_idx=[1]在reset直接attached_to_gripper，不能視為已包含自由抓取成功。scene dt=0.001 s、substeps=5；一次policy action跨steps_interval個scene steps，須另保留此數與split，不以影片fps推控制頻率。
任務
registry正好8個固定horizon任務：coiling、gathering、lifting、separation、slingshot、unknotting、wiring_post、wrapping。論文第6頁另列Letter Art與Wiring-ring，屬DLO agent的長時程分解實驗，未在此8-task registry中，分開建task來源／協定。grasp候選、rod nodes、posts、robot arms與rollout次數都不是task數；未取得固定case manifest，案例總數不填虛構值。
題數與資料
RL privileged observation按(rope vertices+additional objects)×6+grasp points×14，包含位置／速度、末端pose及arm joints；RL action每control point 6D，先乘_act_magnitude、clip、L2限制，再拆xyz／rotation，Pink controller預設translation=m、rotation=degrees。DiffRL只有每point3D translation並從rope vertex反傳，不能共享同一action schema。資料匯出另統一為observation.state float32[16]、action[12]、action.joint[18]，單臂左側zero padding；action排列[right_xyz,left_xyz,right_rot,left_rot]。相機front/wrist_right/wrist_left，單臂wrist_left為黑圖，不是第三個真實視角。timestamp=step_idx×scene.dt×n_substeps_per_step；初frame有zero action，之後capture在step之後，末frame action/action.joint又複製前frame，必須保留原對齊。匯出data/chunk-000/file-000.parquet、meta/info.json/stats.json/tasks.parquet、meta/episodes/...與videos/chunk-*/observation.images.<cam>/episode_*.mp4，split只宣告train。filter reader只讀consolidated file-000；需保持其前置條件。
評估方式
coiling reward=exp(−0.1Σv||v−(0,0,0.15)||)，是距離proxy而非繞圈成功。lifting reward=5×兩環高度和+rope相對抬高項−0.5×rope到兩環最近距離−100×末端距環小於0.08 m的penalty；loss_criterion另外含stretch loss，不能當相同分數。wrapping以xy-plane角度和／2π的絕對winding、與1圈的平方誤差及到三柱最近距離超出0.015 m的penalty計reward。coiling eval_traj累加substep reward，另回final_reward及forward_time，NaN/failed final用survival_ratio−100；CMA可選cum或final做最佳化。PPO儲存undiscounted return及末reward，diagnostic success_rate=(episode_length==n_outer_steps)，只是未提前失效。論文主表報固定budget內最大episodic return、3 seeds；附錄影片人工success用每RL方法15條、GD1條、CMA最佳checkpoint的top15條。這些不是同一個自動success metric。

怎麼接入我們的benchmark

可重用

8-task registry、具體reward/loss、scene／material／control-point引數、macro/micro-step約定、LeRobot欄位與frame/video reader。

需要轉換

source儲存此Genesis衍生commit及外部dependency／asset來源；environment按DLO拓樸、材料、fixture、robot/grasp attachment建立；task儲存原goal文字與reward program。case儲存seed、randomization、grasp indices、horizon、algorithm、sampling budget及checkpoint；evaluator分cum_return/final_reward、simulation-survival及人工task success。資料另記arm_present／camera_present mask、原raw action及縮放後物理action、前後state/action對齊，task名稱去重不靠生成episode數。

仍需補齊

assets與Mushroom-RL/Pink等依賴的完整pin／驗證；論文影片success rubric／標註及top15選擇名冊；完整task checker覆蓋；LeRobot產生資料的action-time與SHAC格式驗證；data generation僅依absorbing過濾且在n_envs>1時用obs0選action後tile給各env，不能直接視為獨立閉迴路成功示範。

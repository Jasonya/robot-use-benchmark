P081 · ARNOLD

ARNOLD: A Benchmark for Language-Grounded Task Learning With Continuous States in Realistic 3D Scenes

返回逐篇總表核心內容已核讀 benchmark／資料／評測主來源原作 ↗ 用途與原生規模依據

核讀快照 2026-10-11。已讀範圍限所列片段；本輪未執行上游程式。

ARNOLD已追到NPZ重建、兩階段策略、具體joint／pickup／orientation／water checker及score聚合。水量實作是cup world-AABB內粒子比例，成功還需連續穩定；normalized訓練state不可直接當checker原生target。checkpoint選擇有list.argmax靜態錯誤，且GT輔助結果必須獨立儲存。

版本與身份

固定arnold-benchmark/arnold@40ad6861f45b676bf538b7a0e180d81c8d454823（2024-04-01），晚於論文v2，README另含CVPR 2024 Challenge公告；不能混用Challenge與ICCV paper的case/split。P077/P078方法在此的軸、單位、keypoint及checker均已改寫，需標為重用方法的另一實驗版本。未執行Isaac Sim、policy、Cython或上游shell。

固定論文為Gong、Huang等人的ARNOLD: A Benchmark for Language-Grounded Task Learning With Continuous States in Realistic 3D Scenes，arXiv:2304.04321v2（2023-09-11）。PDF第7頁直接指arnold-benchmark/arnold，README作者、題名與arXiv相符。此repo含benchmark與改寫的PerAct/6D-CLIPort基線；它們是P077/P078方法的重用，不是原倉庫資料或同一評測協定。

領域
居家整理與清潔、通用物件與機動作業
環境
Isaac Sim／USD、Franka與五相機front/base/left/wrist_bottom/wrist（配置128×128）。load_task將stage設為y-up、1單位=0.01m、gravity=(0,-1,0)且magnitude=981；physics設120Hz。場景／機器人／物件／material USD依NPZ info重建，路徑改寫假設原始路徑含VRKitchen2.0或指定materials字串。README的20 scenes／40 objects／10k demos是來源宣告，未以本地asset／NPZ列舉驗證。
任務
8個原生task為pickup_object、reorient_object、open/close_drawer、open/close_cabinet、pour_water、transfer_water。訓練樣本分act1抓取／act2操作，sample_weights=0.2/0.8；一般四keyframes（初態、預抓、抓住、終態），water六幀並混合frame3位置與frame4姿態作第二動作。二次policy決策不等於3或6個planner stages。7個split需保留train/val/test/novel_object/novel_scene/novel_state/any_state；預設eval只跑後五者。
題數與資料
每case是.npz，gt為keyframe物件序列，info包含scene_parameters、robot_parameters、objects_parameters及robot_shift。gt使用instruction、robot_base、position_rotation_world、gripper_joint_positions、images；每camera有rgb、semanticSegmentation、depthLinear、camera內參／pose。Reader把position/finger由cm除100成m、wxyz轉xyzw，以機器人前方0.5m為中心；PerAct點雲維持y-up，CLIPort heightmap換軸成z-up。depthLinear先clip到[0,10]，Cython反投影乘100到cm、世界變換後再除100；不能把raw depth直接當cm。target_points註解寫[6]，實際concat xyz+xyzw是7D（rot=None才3D）。parse_state從檔名取標籤：pickup目標/40、reorient角度/180、pour為(100-p)/100、transfer為p/100，其他直接取浮點；runtime CheckerParameters.target_state另取info中的cm／度／比例／百分點原生單位。尚未讀任何示範NPZ內容，欄位證據來自reader。
評估方式
eval→load_task→OpenDrawer或PourWater/TransferWater.step→120Hz physics callback→具體Checker.start_checking→BaseChecker。joint把位置按lower/upper化為0–100%，必要時翻轉target，要求比例差<0.1且每physics-step百分點差<0.05；pickup要求相對初始y高度誤差<5cm且每step y位移<0.1原生單位；orientation要求物件y軸相對世界y的角度誤差<20度，穩定性檢查同樣是y位移，不是角速度。water用所有粒子落在cupShape世界AABB的比例，誤差<10百分點、受約束杯偏離直立<30度，transfer另需兩杯外spill<10%；pour只看原杯殘餘量。各條件需連續success_steps>steps_per_second*2，失敗清零；末planner stage完成後最多再step 300次讀success，callback已從reset啟動，並未在末階段重新開始2秒計時。horizon=2400是planner主迴圈tick預算，額外gripper等待及success period另計。eval寫stats[fname]=1/0/-1、score=correct/total（0–1），-1包含timeout及捕捉到的例外並留在分母；console另乘100。0gt/1gt/2gt與use_gt旗標必須區分。

怎麼接入我們的benchmark

可重用

NPZ欄位／USD物理設定、語言與native continuous target、四類checker、兩階段policy／多stage planner、task/split/case成功記錄。

需要轉換

source綁v2+commit；case保留NPZ檔名、object/scene/state split、raw info和asset引用。建立cm↔m、wxyz↔xyzw、y-up↔z-up的明確轉換，normalized learning goal與runtime target分欄。evaluator儲存每步穩定性單位、hold ticks、planner耗時、GT介入、checkpoint及-1原因，水量保留particle-AABB proxy名稱。

仍需補齊

ckpt_selection.py 204產生Python list、205直接.argmax()，在此靜態路徑不能完成best checkpoint挑選，需協調者處理且保留修補版本；本輪未執行確認。缺USD/material/fluid資產及實際NPZ manifest、其餘具體task stage覆寫的逐項核對。water AABB不是精確杯內幾何或真實體積，須保留限制。GT log名稱對任意use_gt組合未全區分；bare except把不同錯誤壓成-1且已有score會跳過整個split，需追加設定hash／錯誤分類。README尚列demonstration generator為TODO。

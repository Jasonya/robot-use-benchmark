FactCheck: Feasibility-aware Long-term Action Anticipation with Multi-agent Collaboration

返回逐篇總表實作尚未確認 方法／綜述參考原作 ↗

核讀快照 2026-10-11。已讀範圍限所列片段；本輪未執行上游程式。

已核FactCheck原作的Observe–Plan–Verify流程、資料與mAP設定，並找到通訊作者列出的同篇IET Software論文；該條目僅連Paper，尚無confirmed官方方法repo。本文的Verifier是LLM推理模組，報告的mAP是未來類別集合評測，不能當成實體可行性驗證或機器人成功率。

版本與身份

cached repository query「FactCheck action anticipation」為0筆；arXiv摘要及PDF連結抽取沒有method code連結，Qwen/Grok連結屬模型引用。通訊作者同篇publication條目只列期刊Paper。一次依該連結讀取Wiley得到HTTP403 Forbidden，共享network.py沒有標成rate_limited，未重試；期刊版code/data availability仍未核到，另列為待查來源，不能把403當repo不存在。技術結論限固定arXiv v1；未確認全球不存在程式。

FactCheck: Feasibility-aware Long-term Action Anticipation with Multi-agent Collaboration；Rui Cao、Jiannong Cao、Bo Yuan、Zhiyuan Wen、Mingjin Zhang。固定核讀arXiv:2606.14778v1（2026-06-10）；首頁的Journal 2023與DOI xxx/xxxx是模板內容。通訊作者Zhiyuan Wen的publications頁列同五位作者及IET Software 2026、DOI 10.1049/sfw2/7118691。此FactCheck是動作預測方法，非同名新聞／文字事實查核專案。

領域
方法／綜述參考，未另作來源用途歸納。
環境
離線EPIC-KITCHENS-55與EGTEA Gaze+人類第一人稱廚房活動。Observer由已觀測片段的辨識結果重建物件狀態，並非從robot simulator取得真實狀態。§5.4的長程操作及人機協作屬未來應用構想，沒有本篇實體robot評測環境。
任務
§3以M個action segments構成影片、N=floor(αM)個歷史片段預測Z=floor(βM)個未來verb–noun動作；α為25/50/75%，β≤1−α。Observer產生歷史動作、意圖／環境摘要及圖；Planner生成有序草稿；Verifier依Object Availability、Affordance Validity、State Consistency修正。三個agent是推理角色，不是三臺robot，也不是三個獨立benchmark。§5.1.1實際評測取剩餘影片中的動作類別集合，須保留「序列生成、集合計分」差異。
題數與資料
§4.1與§5.1.3：每action segment均勻抽4影格，以凍結CLIP-ViT-L/14-336px加訓練分類head辨識verb/noun；抽樣是每片段4張，非4 FPS。History Action Abstract是一句生成文字。圖的noun node儲存Attr(n)=(v,t_start,t_end)，edge weight計歷史轉移頻率；時間單位未明列。Table3提供示意JSON的nodes[].id/state/history及edges[].src/tgt/w；§5.1.3另稱圖序列化為JSONL，未取得真正檔案或parser，不能將示例當已驗證schema。Planner用Qwen2.5-3B/7B-Instruct與QLoRA；摘要及Verifier用grok-4-1-fast-reasoning，Verifier prompt含3個人工few-shot範例。母庫的EK-55 39.6K segments／125 verbs／352 nouns及EGTEA 86 videos／10,325 action instances／19 verbs／53 nouns，不是本篇測試case數。精確split ID、完整提示與範例、生成輸出及資料reader均缺。
評估方式
§5.1.1按α=25/50/75%的觀測比例，對剩餘(1−α)部分的未來類別做mAP-All／mAP-Freq／mAP-Rare；Freq/Rare沿EGO-TOPO分組，這裡未提供類別表或頻率門檻。未核到實際sequence→class score轉換、重複動作處理、AP積分／空positive類別及各α平均方式。沒有獨立的物理可行性真值、constraint violation rate或robot rollout；Table3是定性修正案例，不能作scorer。§5.1.1稱沿用train/test split，§5.2.1卻將EK-55結果稱validation；§3的floor與79動作案例「50%=40個observed」亦不一致，須以原始case生成器釐清。

怎麼接入我們的benchmark

可重用

可重用三角色流程、歷史資訊可見性、三種feasibility約束、圖示意欄位、每segment4影格與多觀測比例，以及mAP-All/Freq/Rare的原生名稱。未取得作者可執行checker或dataset reader。

需要轉換

source保留arXiv v1及作者頁所列journal關係；domain/environment歸人類影片預測。task同時儲存有序生成目標與無序集合計分。case應保留video/segment、α/β、observed recognized labels、生成摘要／圖、draft與refined outputs，並與GT分離；evaluator記類別與頻率分組、提示／模型版本及取樣預算。圖中的狀態為推斷記憶，不升格成已確認的實體世界狀態。

仍需補齊

官方method repo與commit、完整graph schema／讀寫器、觀測切點及split manifest、sequence-to-score與mAP實作、三個few-shot範例及API設定。需釐清noun node與文中action edge的連結語義、JSONL和表中JSON示例的對應、floor邊界及test/validation稱法；若要評機器人可行性，還缺獨立狀態真值與執行判準。

HOT3D: Hand and Object Tracking in 3D from Egocentric Multi-View Videos

返回逐篇總表核心內容已核讀 benchmark／資料／評測主來源原作 ↗ 用途與原生規模依據

核讀快照 2026-10-11。已讀範圍限所列片段；本輪未執行上游程式。

HOT3D 官方 toolkit 同時服務完整 VRS 序列與 HOT3D-Clips 子集；已核讀 schema、DataProvider 和 BOP 轉換，不把工具可讀取誤寫成已完成評測。 2026-10-11 補讀官方連結的 hand_tracking_toolkit 提交、GT writer 與實際指標 caller；BOP evaluator 仍未核讀。

版本與身份

VERSIONS.md 列 v2 修正 MANO 拇指、v3 更新 visibility，metadata.json 的 version 需隨資料保留。Clips README 對 T_world_from_object 的文字方向與欄位名不一致，已用實際 converter 確認為 model→world 再轉 camera，不直接複製文字說明。 官方專案頁區分 2024 whitepaper／ECCV 2024 hand challenge 與 CVPR 2025 完整論文；此補讀固定 hand_tracking_toolkit@bc628e9286c18444b47a0971a89d075ea6f00747，不宣稱今日 snapshot 就是 2024 伺服器提交或論文全部實驗。README 的 pose 欄名和 run_evaluation.par 與程式的 mano_theta／run_evaluation.py 不同，以已讀 caller/writer 為準；資料 v1–v3、論文 edition 與 evaluator commit 分開儲存。

領域
居家整理與清潔、餐飲與烹飪、辦公與教育、穿戴互動與動作介面
環境
Aria／Quest3 頭戴裝置記錄的手與物件互動；sequence、participant、clip、device、stream 分層。HOT3D-Clips 為同一資料的 5 秒／150 frame 子序列，多個 image streams 不是獨立環境。
任務
3D 手／物件追蹤與姿態、手形估計；BOP object pose 與手部 pose/shape challenge 使用不同 GT 可見性。動態 object onboarding 只給首影格 GT，靜態 onboarding 每影格給 GT。
題數與資料
完整資料用 VRS+CSV providers；clip tar 含 image_STREAM、cameras/hands/hand_crops/objects/info JSON，__hand_shapes 跨 frame 共享。clip_definitions 連原 sequence/device/timestamp；clip_splits 有 train、test_ht_pose、test_ht_shape，test_bop 是兩個 test 的聯集。相機有 fisheye 模型、projection_params、wxyz quaternion，時間為 ns。 2026-10-11 補讀：實際 pose JSON 使用 sequence_name、frame_id、mano_theta[15]、wrist_xform[6]、hand_side（0 左／1 右）；wrist 前三項送 global_orient，後三項是米制平移。shape JSON 用 mano_beta[10]，GT writer 每 clip 只存一份左右手共用 shape。HOT3D README 規定 frame_id=0,10,20…；GT writer 的 --every-n-frames 預設 1，須顯式對齊 challenge 抽樣。
評估方式
已核公開格式轉換及hand_tracking_toolkit所列pose／shape評分鏈；完整BOP評分器不在本篇列出的閱讀範圍。BOP converter 實際以 inverse(T_world_from_camera) @ T_world_from_object 得模型到相機姿態，平移乘 1000 成毫米，XYXY 轉 XYWH；visib_fract 取 modeled/predicted 可見性的最小值。不在 stream 範圍的物件以 -1 pose、空 mask、0 visibility 佔位，不能當真實姿態。 Hand tracking的實際呼叫鏈為 scripts/run_evaluation.py→evaluate→compute_overall_*→compute_pose_metrics/compute_shape_metrics。pose 用 GT mano_beta 搭配預測 pose／wrist 做 MANO FK，20 點移除 wrist 後評 19 點並乘 1000 成毫米；實際回傳 MPJPE、PCK_AUC、FINGERTIP_PCK_AUC，沒有 docstring 所列的 MPVPE。PCK 用誤差≤閾值，0–50 mm 共 101 點，曲線乘 100 後以梯形面積除 50，保留 0–100 尺度；五指尖另算。pose 依 GT landmarks 列數（手／影格樣本，未必是唯一影格數）加權；shape 在零 pose／零 wrist 的左手模型算 MPVPE(mm)，再等權平均序列。未提交某 dataset 的整份結果檔會略過，不是零分。

怎麼接入我們的benchmark

可重用

VRS/clip schema、物件／手模型、同步時間、GT 可見性 split 與 BOP 轉換。 可另接手部提交 writer、原生 19 點／指尖 PCK 和 canonical shape MPVPE；各自保留聚合單位。

需要轉換

保留 full→clip→frame→stream ancestry，BOP scene_id 映回 clip_id 而非新增實體場景。座標轉換記明方向、米／毫米、相機畸變模型和 visibility 來源；測試缺 GT 依 track 顯式標 unknown，不填零。 手部 case 保留 clip/sequence_name、frame_id、hand_side、抽樣步長、GT shape 是否已知、PCA pose／wrist 向量格式及 mm/AUC 尺度；不與 BOP 物件姿態合成共同成功率。

仍需補齊

尚未取得 VRS、tar、物件／MANO 模型、外部 BOP／手評測套件或執行。需為外部 evaluator 另釘選提交，驗證相機畸變、時間同步和 -1 佔位規則。 更新：手 evaluator 的選定原始碼已取得並釘選，但隱藏 GT、MANO 資產、BOP 套件與執行仍未完成。caller 僅按 sequence_name 分組及 frame_id 排序後逐列相減，未顯式按 frame_id/hand_side join；接線須驗證缺列、重複影格與同影格左右手順序。本地自選 train 子集也不是官方 validation split。

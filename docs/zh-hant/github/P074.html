P074 · RoboTwin 2.0

RoboTwin 2.0: A Scalable Data Generator and Benchmark with Strong Domain Randomization for Robust Bimanual Robotic Manipulation

返回逐篇總表核心內容已核讀 benchmark／資料／評測主來源原作 ↗ 用途與原生規模依據

核讀快照 2026-10-10。已讀範圍限所列片段；本輪未執行上游程式。

RoboTwin 2.0 的50項任務清單與逐task步數上限可直接核對；現行main已有XPolicyLab評測及新版HDF5。已閉合Lift Pot的幾何checker、seed篩選、action計數、資料時間對齊與影像解碼，須與2025論文版區分。

版本與身份

XPolicyLab實際gitlink為fa431ecd893ee706883e64fe5fe1464ec8cd928d；.gitmodules的branch=main不是版本pin。本次只讀RoboTwin端整合與本地codec。具體schema風險：save_freq用作每N個控制步抽幀，卻原值寫入frequency；還另插入端點幀，不能據此重建固定Hz時間軸。extrinsics_matrix優先寫cam2world_gl，缺少時才寫extrinsic_cv，座標方向不由欄位名保證。JPEG有legacy色序與XPL-RGB1兩制，不能無條件再交換RGB/BGR。

對應arXiv:2506.18088v2（2025-08-27），題名／作者以固定PDF為準。官方README連同一arXiv，並記錄2025-08論文更新；本次main commit ea8b21121ebb3cd201ff5b3fe361944ac94eda3f則是2026-09-24的後續整合版。

領域
居家整理與清潔
環境
SAPIEN桌面雙臂，論文正式設定為Aloha AgileX。現行clean與randomized不是兩個生活場域；randomized包含clutter、背景、光照，table_z_bias實際抽[-0.03,0]公尺，並改用unseen語言。兩份YAML都將depth/pointcloud關閉，不能把論文DP3使用的完美點雲當所有方法共同輸入。
任務
all_tasks與step-limit檔各列50個原生task；左右／數量變體按原清單保留。Lift Pot從兩個060_kitchenpot模型抽樣；成功需世界z>0.82公尺、兩TCP各距指定contact point<0.03公尺，以及pot區域性z軸與世界z軸內積>0.8。此check不另測雙臂接觸力或持續時間。
題數與資料
原生PKL仍是observation/joint_action/endpose字典；關節讀值來自drive targets，非real_jointState。現行轉檔輸出HDF5 data_format_version="v1.0"、instructions JSON字串、additional_info/frequency、state/action與vision；state=values[:-1]、action=values[1:]，只保留N−1組。joint欄位用left/right_arm_joint_states及left/right_ee_joint_states，pose用left/right_ee_poses；vision含cam_head/cam_left_wrist/cam_right_wrist的colors定長JPEG bytes、shape、可選depths與矩陣。線上adapter用單數joint_state鍵，且EE/TCP有不同原點。
評估方式
main→eval_remote_policy→take_action→lift_pot.check_success→eval_success；逐task成功數除以test_num（預設100）。從100000×(1+seed)往後找候選；expert_check預設開啟，先play_once且要求plan_success與checker通過，再重置同seed評policy。unstable、setup錯誤及首個action前的rollout錯誤會被略過；因此100是有效試驗數，不是連續100個初態。期限按take_action_cnt而非physics frames；每次action內部再規劃／插值，達條件即鎖定成功。論文50 clean示範訓練、Easy/Hard各自100rollouts的結果不由本輪執行重現。

怎麼接入我們的benchmark

可重用

50 task IDs、逐task步數、clean/randomized設定、物件contact-point資料模型、具體checker與seed篩選loop。

需要轉換

source固定主repo及XPolicyLab gitlink；case存embodiment、語言分割、隨機化、被接受／略過seed、action計數與checkpoint。分開PKL命令、HDF5 t/t+1配對、線上單數鍵，保留EE/TCP、pose/quaternion與JPEG marker約定。

仍需補齊

2025論文對應的程式／asset版本閉合、所有50 checker逐項覆核、XPolicyLab與policy模型依賴取得、正式accepted-seed manifest及時間／座標schema驗證。

VLABench: A Large-Scale Benchmark for Language-Conditioned Robotics Manipulation with Long-Horizon Reasoning Tasks

返回逐篇總表核心內容已核讀 benchmark／資料／評測主來源原作 ↗ 用途與原生規模依據

核讀快照 2026-10-10。已讀範圍限所列片段；本輪未執行上游程式。

VLABench 有互動VLA評測與離線VLM技能序列評測兩條不同鏈。已追到select_fruit的容器幾何、progress實作、HDF5 writer/reader及DSL匹配；metric.py的pass不代表全庫沒有評分器，但現行總分與CLI確有靜態缺陷。

版本與身份

VLM get_final_score雖宣告0.4/0.4/0.1/0.1，實際total_score只加前兩項，因此完美匹配上限80；get_final_score_dict呼叫get_result_save_path時漏eval_dim。evaluate_vlm.py引用未宣告的task_list_json/save_dir。互動Evaluator捕捉episode例外後不加入task_infos，均值分母會縮小；必須另列請求、完成、失敗及錯誤數。README的舊CLI拼字/引數也不等於現行parser。這些是靜態檢查結果，未執行上游。

固定論文為arXiv:2412.18194v1（2024-12-24），README引用相同題名與11位作者。固定程式cf588fe60c0c7282174fe979f5913170cfe69017（2025-11-11）已有2025評測軌道與資料更新，不能視作2024預覽版的原封快照。

領域
居家整理與清潔、餐飲與烹飪、辦公與教育、實驗室操作、休閒與運動
環境
MuJoCo/dm_control依scene、components、robot及MJCF資產組裝；select_fruit_series具體使用studyroom_0與table。觀測依模型的ncam迭代，不能把樣例四視角當所有任務固定相機數。物理步、NUM_SUBSTEPS=100與policy步數分開；影片10 fps不是通用控制頻率。
任務
論文100項（60 primitive＋40 composite）；原生task、config_manager與condition以註冊名連線。select_fruit的seen類別為apple/banana/orange/pear，unseen為peach/lemon/kiwi/mango；contain檢查物件worldbody位置點落在Plate的平面範圍及預設0–0.1公尺上方，不檢查整個物件bbox或穩定接觸。PourCondition只比較top/bottom site高度，是姿態代理，不代表液體流動。
題數與資料
HDF5為data/<時間名>/observation、meta_info、trajectory、instruction；observation可含rgb uint8、depth/q_state/q_velocity/q_acceleration/ee_state及點雲float32。meta_info儲存entities、target_entity、episode_config字串；writer略過segmentation、instrinsic、extrinsic等欄位，點雲補零且未另存有效點數。trajectory為8維xyz/Euler/兩指gripper；指令碼只從xyz減robot_position，不能宣稱已做含旋轉的完整座標轉換。VLM題目則是task/exampleN/input的input.png/input_mask.png/instruction.txt與output/operation_sequence.json，GT為skill_sequence[{name,params}]。
評估方式
互動鏈：Evaluator→load_env→dm_control終止→ConditionSet→ContainCondition→Plate/FlatContainer.contain；success取timestep.last。未提供episode_config時用42+i seeds；預設最多200個policy步，可由task_config覆蓋。當前API分別平均success、intention、progress；intention是歷史最小eef距離<0.1公尺，primitive progress將當前已滿足condition與曾抓握target計數合併，沒有實作論文0.2/0.8加權PS。離線VLM鏈用技能/引數多重集合recall、技能引數聯合recall及DAG節點匹配百分比；這些0–100分數不能轉稱物理成功率。

怎麼接入我們的benchmark

可重用

原生task/config/condition、確定性episode_config、HDF5與DSL case結構、分開的物理checker及圖匹配metric。

需要轉換

同一source保留互動與離線兩種case/evaluator；對映name/params/target_entity_name/target_container_name時儲存圖依賴模式、few-shot、CoT及資訊可見性。保留8維Euler waypoint、9維joint＋gripper控制與觀測四元數各自語義，不依維度誤併。

仍需補齊

大型track JSON與外部vlm_evaluation_v1.0的完整case清單尚未取得，不能填全庫episode數；仍需修正CLI/metric、固定model與dm_control版本、資產閉合，以及逐task驗證進度支援。

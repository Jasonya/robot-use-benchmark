EgoLife: Towards Egocentric Life Assistant

返回逐篇總表核心內容已核讀 benchmark／資料／評測主來源原作 ↗ 用途與原生規模依據

核讀快照 2026-10-10。已讀範圍限所列片段；本輪未執行上游程式。

EgoLife、EgoIT、EgoGPT、EgoRAG 是資料／訓練集／模型／方法的不同角色。已核讀 EgoRAG 的 QA schema、記憶查詢、證據與精確選項評分。

版本與身份

主 README 中早期 arXiv-on-hold 等訊息仍保留，身份以實際論文標題／arXiv ID 為準。EgoGPT 檔案對其他 EgoSchema/EgoPlan/EgoThink 的結果是外部測試，不算 EgoLife 原生題目。

領域
居家整理與清潔、餐飲與烹飪、休閒與運動、社交與溝通
環境
六位參與者一週的真實生活觀測，包含 Aria、外部相機與 mmWave；本次核心程式處理人物/日期/影片的記憶序列，不代表所有感測 modality 都已進入每道題。
任務
長期記憶、人物／事件／習慣等 QA，以 query_time 和過去證據答四選一。EgoIT-99K 是九個既有 ego 資料的 instruction tuning 混合，不是新增 99K EgoLife 測試題。
題數與資料
QA 有 ID、query_time 的 DAY/time 字串、type、need_audio/need_name、question、choice_a–d、answer、target_time、keywords、reason。caption DB 以 date/start/end/video_path/text 建記憶片段；parse_query 實際使用 keywords。時間為來源自訂8位編碼，需保留原字串再建立經核驗的時間換算。
評估方式
calculate_accuracy 只對已進 answers 的 model_option 與 metadata.answer strip 後精確比較；query_all/main 遇例外 continue，故漏題可能不進分母。get_answer 遇 API 字串 error 會隨機選 A–D；須另列失敗 fallback。主入口 extract_evidence 實際 modality=text，EgoGPT 是可換的 caption/視覺模型，不能把此設定報成每題直接看影片。

怎麼接入我們的benchmark

可重用

人物／日期／query time、題目與證據 schema、記憶資料庫與四選一評分。

需要轉換

case 保留本人、query timestamp、合法 past cutoff、是否提供 keywords，以及 target_time/reason 的 GT 身份。cache/DB 對應 caption model/version、影片範圍與讀取記錄；完整預定題清單與已答題清單並列，漏題、隨機回退、解析失敗分開。

仍需補齊

尚未下載完整一週影片、EgoIT、建立 DB 或呼叫模型。需核驗每層摘要／retrieval/filter 的時間截止與 evidence 完整性，並固定 keyword 可用條件；不同人物和同時攝影不能直接計成獨立環境。

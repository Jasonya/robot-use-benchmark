P080 · DexArt

DexArt: Benchmarking Generalizable Dexterous Manipulation with Articulated Objects

返回逐篇總表核心內容已核讀 benchmark／資料／評測主來源原作 ↗ 用途與原生規模依據

核讀快照 2026-10-11。已讀範圍限所列片段；本輪未執行上游程式。

DexArt已追到四個具體RL task的state／success、底層contact、物件annotation reader與paper評測入口。原生success是episode內曾達is_eval_done的比例；bucket的成功比early_done寬鬆，laptop reset又隨機抽物件，不能將eval_per_instance名稱當每個物件精確等量試驗的證據。

版本與身份

固定d6ab75e1a0b81384d1ac918cbfd4d97b1f230149（2026-05-11），晚於2023v1；README的2023-11checkpoint發布也晚於論文。所讀門檻只代表此commit；無論文精確experiment lock或assets版本對照，不宣稱重現paper表格。未執行PPO、感知預訓練或SAPIEN。

固定論文為Bao、Xu、Qin、Wang的DexArt: Benchmarking Generalizable Dexterous Manipulation with Articulated Objects，arXiv:2305.05706v1／CVPR 2023。README 1–13和171–176吻合完整題名、作者及arXiv，確認Kami-code/dexart-release為官方模擬環境／訓練程式；不是同名搜尋命中即視為官方。DexPoint及vendored Stable-Baselines3是重用實作。

領域
居家整理與清潔
環境
SAPIEN articulated objects與xArm6腕接Allegro手；create_env預設frame_skip=10，已讀laptop scene timestep=0.004s，即該配置每control step為0.04s。policy相機64×64，另外1000×1000的viz_only相機不算policy觀測。四task各有point-cloud裁切bound和rand_pos/rand_degree；例如laptop位置擾動為每軸[0,0.1)m、yaw±60度，不是對稱±0.1m。基底pose、物件scale、摩擦、handle與joint annotation都是case重建依賴。
任務
四個原生task labels是faucet、bucket、laptop、toilet；TRAIN_CONFIG的seen/unseen ID數分別11/7、11/8、11/6、17/11（共82個配置中的物件ID），不是82個task或實測episodes。*_half只是訓練物件子集。laptop reader讀assets/sapien/{id}/mobility.urdf與mobility_v2.json的joint欄位，結合annotation/laptop_scale.json、laptop_joint_annotation.json中left/middle及robot-relative position。外部asset包未下載，僅核對程式期待的欄位，未聲稱這些JSON內容已讀。
題數與資料
BaseRLEnv.step依序控制、update_cached_state、更新robot imagination、讀觀測、算reward與done。action為[-1,1]的robot.dof向量：前六維還原Cartesian速度，Jacobian IK得arm速度並裁至±π，再積分成joint target；後段對映到hand joint位置limits，不能當全向量都是joint velocity。obs含state/oracle_state（所讀laptop為joint qpos+palm線/角速度+位置+step/horizon）、instance_1-point_cloud(512,3)、instance_1-seg_gt(512,4)及imagination_robot。點雲由camera轉robot座標後裁切，少點時重複第一點，空雲補零；四mask順序handle/instance_body/hand/arm。pretrain生成器把512個感知點及96個robot imagination點組成(608,7)樣本，儲存{task}/{train|val|test}_{id}.npy，再np.load合併；seen同時產生train與val，unseen產生test。其內容是random-action／random-joint-state感知樣本，不是成功操作軌跡或固定時間同步action標籤。
評估方式
入口examples/evaluate_policy.py→create_env→BaseRLEnv.step→task.update_cached_state→sim contact checker。contact以scene contact的sum(abs(impulse))>=1e-2認定。laptop：progress=1-|q-middle|/(|left-middle|-init_open_rad)，需>0.95且palm距handle<=0.2m、至少兩指及palm接觸；toilet相似progress>0.95，但距離<=0.1m、兩指接觸即可。faucet需|hinge qpos|>1.5rad，距離<=0.2m及兩指+palm接觸。bucket eval需progress>0.7且base-link升高>0.25m；early_done則>0.9、state=3及>0.3m，且is_done實際只看250步horizon。四個task的horizon均250；faucet、laptop、toilet在各自成功條件成立時提早結束。主迴圈只要任一步is_eval_done為真就鎖定episode成功，即使bucket之後落下仍記成功。最終印mean(success_list)，shaped reward另累加但不作該成功率。通用SB3 evaluate_policy回mean/std reward，不能替代此入口。

怎麼接入我們的benchmark

可重用

四task checker、contact門檻、native object ID/split、物件annotation loader、robot/point-cloud觀測profile與episode-any-success聚合。

需要轉換

task記動作目標；environment綁SAPIEN、robot、資產/annotation版本；case記task+object ID+split+初態+seed，不以渲染幀或pretrain樣本數當case。evaluator分開is_eval_done、early_done、reward、done、any_step_success及horizon；保留每task不同的角度／progress／接觸與高度門檻。點雲、seg_gt、imagination及可選previous觀測需標示來源與policy可見性。

仍需補齊

外部assets的URDF、scale、joint left/middle及relative-position JSON尚未閉合或驗證，須固定asset版本／hash。eval_per_instance預設10、README示例100，總數為該值×instance_list長度；但已讀laptop reset用random.randint抽ID，沒有逐ID均衡控制或per-ID結果儲存，需記實際抽樣頻數。程式stdout只有總成功率，缺trial明細與失敗／落下後狀態。BaseRLEnv在horizon處因task.is_done已為True而寫TimeLimit.truncated=False，需協調者分離超時與成功，不能把done當成功。

CaptainCook4D: A Dataset for Understanding Errors in Procedural Activities

返回逐篇總表核心內容已核讀 benchmark／資料／評測主來源原作 ↗ 用途與原生規模依據

核讀快照 2026-10-10。已讀範圍限所列片段；本輪未執行上游程式。

CaptainCook4D 主倉庫是入口；已追到官方 annotations 與 error_recognition 程式，核讀原始步驟 JSON、mug cake 圖、loader 及實際 step/sub-step metrics。

版本與身份

Error-Dataset/annotations 轉向 CaptainCook4D/annotations；2023 初版與 2024 最終 baseline／2025 衍生工作分開。主 repo 無 Python 不能推定整項無程式，實作在其明確連結的子倉庫。

領域
餐飲與烹飪
環境
真實廚房中遵循食譜或刻意誘發錯誤的錄製。recording、recipe、person、environment split 分別管理；同一食譜多錄製是 case，不自動增加獨立任務。
任務
error recognition、early error recognition、多步定位／程式學習；task_graph 的 steps/edges 可保留先後與選擇限制。loader 另有五類錯誤 one-vs-rest 標籤及 has_errors，未出現／負時間步驟不當作已觀察完成。
題數與資料
step_annotations 以 recording_id 連 steps 的 step_id、start/end_time、description、has_errors；error_annotations 另連多個 errors.tag。ImageBind 特徵按 2 秒索引，其他 backbone 按 1 秒；floor/ceil 後切片，同一 step 多次出現會串接。early 只取前半特徵；recording 12_6 在 ImageBind 分支因無特徵跳過。
評估方式
base.py sub-step 以 sigmoid>.5 算 accuracy/P/R/F1，ROC-AUC 用連續分數，但 PR-AUC 實際餵二值預測。step 層取每個 loader batch 的平均分數，再可選全測試集 min-max 正規化，以 threshold 判斷；GT 平均>.95 才當 error。README 報 step split=.6、recording=.4，core/evaluate.py 目前掃 .5/.6，需固定原作條件。

怎麼接入我們的benchmark

可重用

24 份 recipe graph 的路徑清單、逐步錯誤 schema、split 型別及 error／early 的資料流程。mugcake.json 作為已逐項閱讀的 task graph 範例；其他 graph 不能據此宣稱內容全審。

需要轉換

case ID 用 recording+step+occurrence，保留完整秒數、重複片段及合併規則；source 關聯原始影片、特徵與 graph。error labels、early prefix、step/recording/person/environment split 分欄；評分儲存閾值、min-max、batch_size 和二值 PR-AUC 的原始行為。

仍需補齊

尚未取得影片／特徵、執行評分或核讀 zero-shot/multi_step_localization 全實作。step 切分內 phase=test/val 對應片段命名互換，應以實際索引存檔；batch 必須維持單一步驟，否則 collate 後 batch 被當 step。程式保留作者絕對路徑、手選 epoch 表和 start-end>1 條件，均需 adapter 驗證與差異記錄。

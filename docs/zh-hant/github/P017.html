HOI4D: A 4D Egocentric Dataset for Category-Level Human-Object Interaction

返回逐篇總表核心內容已核讀 benchmark／資料／評測主來源原作 ↗ 用途與原生規模依據

核讀快照 2026-10-10。已讀範圍限所列片段；本輪未執行上游程式。

HOI4D 有可直接利用的 room、layout、物件與任務路徑，原生任務表也已核讀；後續 semantic/action segmentation challenge 的張量與類別空間需獨立儲存。

版本與身份

三倉庫均引用同一 HOI4D 論文；兩個 challenge 倉庫同時引用後續 PPTr，不表示這些程式和首版論文的所有協定完全相同。task 表的 T1–T6 是來源內編碼，與本計畫舊 T 模組無關。

Instructions 的精確標題／作者／官方專案連結及兩個 challenge README 的同題引用、hoi4d.top 指向一致；保留各自 repo 角色。

領域
居家整理與清潔
環境
路徑 ZY/H/C/N/S/s/T 分別代表 camera、human、object class、object instance、room、room layout、task。S 與 s 才提供實體房間／佈局身份，T 不可計為新環境。
任務
task_definitions.csv 按 16 個物件類別列 T1–T6，含取放、開關、切割、倒水、收納、裝訂等；有 N/A 和相同文字重複欄位。T 編號僅在物件類別內有意義，不能把列×欄或動作 segmentation label 當通用任務總數。
題數與資料
align_rgb/depth、objpose JSON、action/color.json、raw_pc/label.pcd、相機 output.log、motion masks 與 MANO pose 各自保留。CAD 的 canonical frame 定義物件姿態；MANO 轉米時除 1000。action challenge HDF5 讀 pcd/center/label，與原始 RGB-D 資料是加工關係。
評估方式
semantic test_seg.py 去掉輸出 channel 0/1、回加 label offset=2，再聚合各類 intersection/union；跳過 0/1 與 GT 無樣本類，計 macro accuracy/mIoU。action train_p4.py 用 frame accuracy、segment edit 與 F1@.1/.25/.5，結果還依 batch 聚合。公開 challenge 輸出形狀分別 (892,300,8192) 與 (892,150)，是序列×時間×點或序列×時間，不能當任務類別數。

怎麼接入我們的benchmark

可重用

room/layout/task 身份、原生任務表、CAD articulation／pose 及 semantic/action 評分。

需要轉換

保留 C+T 複合 task ID 並以 parent source 追溯，N/A 不計數，重複語義僅提出待核對關係。environment 用 S/s，case 記原始序列→challenge HDF5 row 的對映、點取樣與 label mapping；3D/4D segmentation、動作分割與人體姿態分 profile。

仍需補齊

尚未取得 RGB-D、CAD、HDF5 或執行 CUDA baseline；需要 release.txt 和 challenge row-order／sampling 對映、標註時間單位與原生 challenge evaluator 版本核對。不能把具有人類取放標籤的影片當已可執行的機器人題。

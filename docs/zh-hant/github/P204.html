P204 · S-EMBER

S-EMBER: A Large-Scale Benchmark for Streaming Egocentric Memory Retrieval

返回逐篇總表核心內容已核讀 benchmark／資料／評測主來源原作 ↗ 用途與原生規模依據

核讀快照 2026-10-11。已讀範圍限所列片段；本輪未執行上游程式。

官方 S-EMBER 已有具體 JSONL reader、五選一 scorer、temporal IoU 與 optional Gemini judge；核讀專用 sember task 及兩條模型／API 路徑。此 commit 預設只回報 MCQ accuracy 或 mIoU，尚未實作 paper v2 的完整 clean／overall／hallucination／R@1／GQ 協定；另有缺片降為純文字與 judge 非同步錯配等整合問題。

版本與身份

固定 code 18db1323a60c86f50d9cf91df2083237a9895c50（2026-07-08）早於 paper 2607.02689v2（2026-08-26）。pyproject 標 lmms_eval 0.7.1、task metadata 0.2；Qwen runner 預設 uniform_nframes=768、fixed_frame_pixels=786432，而 paper v2 主表是 open models 128 frames。此讀取範圍不是整個繼承 framework 或所有外部 decoder 已核。

pinned arXiv:2607.02689v2 首頁直接指定 facebookresearch/S-EMBER 與 facebook/S-EMBER dataset；README 題名、作者及 arXiv 對應一致。倉庫包含 lmms-eval 的其他 task，但本篇只追 lmms_eval/tasks/sember 與其直接呼叫；沒有把 FALCONBench 等繼承 task 當成本篇資料。

領域
居家整理與清潔、餐飲與烹飪、零售與購物
環境
613 名使用者以 Ray-Ban Meta 錄下日常人類第一人稱、visual-only 觀測。論文的 2,090 fine-grained scenario labels 合併為 33 activity categories，均非可執行場景資產或去重實體場所數。
任務
原生八類為 location_trace、sequential_action、counting_objects_events、visual_detail_recall、temporal_ordering_recognition、time_duration、object_comparison、spatial_aware_reasoning。兩個 task entry 是 sember_mcq（五選一）與 sember_grounding（答案＋證據時間段）；同題三種 verbosity 參考答案及 MCQ 變體不產生三倍獨立 case。
題數與資料
兩個 YAML 以 datasets.load_dataset(path="json", data_files={test: data/sember_*.jsonl}) 載入 test split。程式按 SEMBER_VIDEO_DIR/<video_id>.mp4 取影片，忽略 HF 的 video 路徑欄；doc_to_visual 產生 {video_path, video_end: question_time}。MCQ 使用 question_id、question、options、correct_letter（scorer 可 fallback correct_index）、question_category；grounding 使用 answer、answers[].answer_text、answer_start_time／answer_end_time，並保留 memory_recency、answer_range、duration、video_category。question_time、證據區間及 duration 以原片秒為單位；未做跨影片共用時間軸。論文／README 報 9,448 QA、3,141 videos、388 小時，本輪未下載 HF JSONL／影片，未把這些數字宣稱為本地驗算。
評估方式
MCQ parser 優先接受單一 A–E，否則取第一個獨立字母；空白／不可解析為錯。aggregate = 100×答對數／所有傳入結果，另印每類 accuracy／parsed 數，並非八類 macro。grounding 只解析 Answer: 與 Time:[非負數,非負數]；IoU = max(0,min(end)−max(start))／(max(end)−min(start))，缺 GT、無法解析或 union≤0 均為 0。mIoU = 100×IoU 總和／所有結果，未解析仍在分母，未裁到 question_time／duration。API summary 同樣把 FAILURE 留在分母；--max-samples 限制後只對該子集計分。optional judge 收集 answer 與 answers[].answer_text，以任一可接受答案匹配；CORRECT／WRONG／UNPARSED／ERROR 均入 total，僅 CORRECT 入分子。paper v2 的 Acccl、Accov、hallucination union-check、R@1≥τ 及 GQ@τ 並未在上述專用公開 scorer 實作；其論文主表以原始 IoU 0–1 報告，而程式回傳 0–100。

怎麼接入我們的benchmark

可重用

可重用原生八類、兩個 task YAML、JSONL loader、per-question logs、五選一 parser／deterministic IoU 作待修正的原生 evaluator；保留完整／缺片子集與 API／local 路徑。

需要轉換

source 記 paper v2、repo commit、HF 另行固定的資料版本及 lmms-eval 衍生關係；domain／environment 從 video_category_broad／video_category 分層，不能將 2,090 labels 當 scene assets。case 以 question_id 關聯 video_id、question_time、options／answer variants 與多 reference intervals，MCQ／grounding 共用 parent QA。evaluator 各自儲存 score unit、全分母、parsed／failed／缺片數、可見 prefix、frame/pixel budget；追加 paper v2 的各分項與同題 joint GQ，保留和舊版 scorer 的差別。

仍需補齊

HF 原生題目／影片 manifest 及資料 revision、有效題數驗算、缺片一致處置、strict schema／timestamp validation、judge ID 對齊與 parser 修正、完整 paper v2 metrics 接線。Qwen 的實際解碼委派 qwen-vl-utils>=0.0.14，未固定精確版本；需另驗證取樣時間／外部 reader 的 cutoff，不宣稱已完成 runtime 重現。

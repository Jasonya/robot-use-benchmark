P240 · ANTICIPATR

Rethinking Learning Approaches for Long-Term Action Anticipation

返回逐篇總表核心內容已核讀 方法／綜述參考原作 ↗

核讀快照 2026-10-11。已讀範圍限所列片段；本輪未執行上游程式。

已沿ANTICIPATR的TSV/feature reader→instance-set預測→timeline／集合前處理→evaluator核讀。其future比例以剩餘影片為基準，與P236/P237的全影片比例不同；公開commit的scorer鏈還有會阻止合法計分的變數、shape與case鍵錯誤，不能宣稱直接重現論文結果。

版本與身份

固定 a7f0af215f50680e6b784df195a17884cb520bbf（2023-04-06）。論文§4與附錄A.1.3定義remaining-length protocol及dense重建，與其引用的全長比例benchmark需分項對待。主評測應保留模型提出的instance集合；loss配對不是scorer，loss_segment/loss_siou以跨rank平均target instance數（至少1）正規化，不是case成功率。僅核核心source區段與小型原生文字資料，未安裝、載入pickle／checkpoint或跑上游模型。

Rethinking Learning Approaches for Long-Term Action Anticipation，Megha Nawhal、Akash Abdu Jyothi、Greg Mori，ECCV 2022；快取arXiv:2210.11566v1（2022-10-20）。PDF p.3直接連Nmegha2601/anticipatr，README列同題名作者。原生方法是兩階段Anticipation Transformer；不是固定20個verb–noun的Ego4D LTA。

領域
方法／綜述參考，未另作來源用途歸納。
環境
離線人類活動：Breakfast/50Salads第三人稱烹飪；EK55/EGTEA Gaze+第一人稱廚房。此release的stage2 build_dataset只註冊bf與ek，50Salads/EGTEA雖有pretraining名單及論文結果，不能視為stage2已接通。
任務
預測未來action instance集合，每instance是(label,start,end)，query數是最多預測槽數，不是任務數。stage1 snippet anticipation、stage2以凍結snippet encoder配合video encoder/decoder是論文方法關係，本次核心核讀以stage2資料／計分為主。Breakfast時間條件dense timeline評測；EK55時間無關future-label presence評測。固定Breakfast詞表48類含SIL；EK示例容量125 verbs/352 nouns/3806 actions，many-shot檔實際26 verbs/71 nouns，不能照ek.py的舊註解32 nouns。
題數與資料
名為.csv的split實際無header、tab分隔：video_path,start_frame,end_frame,verb_id[,noun_id]；另*_nframes.csv是video_path與全長frame數。DatasetSegmentRecord.num_frames=end-start+1。外部feature pickle是video→frame_index→2048維向量，reader不載RGB；目前切取range(start-31,end+31)中存在的key，會涵蓋觀測終點之後至+30的feature index，須驗證提特徵的時間支援域。區域性fps=1只是idx模數，不能解讀為1Hz；CLI fps預設60。target含video_id、labels_onehot、instance labels、label_mask、segments、duration、prediction_duration、observation_duration、ratio_idx、prediction_idx、observation_positions、fps；segments=(native_start/end-observation_duration)/prediction_duration，duration以秒存，observation/prediction_duration仍是frame數，單位混用不能抹平。EK action ID依各自CSV中的verb/noun頻率另建int_to_idx，可能造成train/val ID漂移。
評估方式
實際入案：只取end<=t的完整past與start>t的future，且各至少3個action；Breakfast future另需end<=pred_t，跨邊界action被排除。EK α=.25/.5/.75預測全部remaining；Breakfast α=.2/.3、β=.1/.2/.3/.4/.5，pred_t=t+int(β*(T-t))，論文表只報β=.1/.2/.3/.5。以固定val_S1文字檔依相同條件作結構重算（未載features）：Breakfast252影片/1548segments只產生12個視窗、5個video keys；EK67影片/7742segments產生172視窗、60個video keys。這是入案邏輯統計，非成功跑分。模型輸出pred_logits[B,Q,C+1]及pred_segments[B,Q,2]；後者實作ReLU+0.1，並未保證<=1或end>=start。get_unrolled_timeline將segment乘prediction_duration，重疊處逐類取最大softmax，去no-action後argmax；卻把整個future multi-hot label複製到所有時間位置當GT，未重建instance的逐格GT。get_mAP再把timeline presence加總clip至0/1，外層預定呼叫sklearn average_precision_score macro/micro；get_accuracy預定用1-hamming_loss按class平均×100，不能等同論文的class-normalized逐格MoC。snapshot的get_accuracy寫acc[k]但k未定義，get_AP_perclass未初始化preds[k_ap]/targets[k_ap]便append，get_accuracy_perclass對1D陣列argmax(axis=1)；所以沒有可認定正確的實際評測分母／合法輸出。engine更以video name為唯一key覆寫不同α/β視窗；單process下前述12/172視窗最多隻留5/60筆。

怎麼接入我們的benchmark

可重用

版本化TSV與length table、dataset-specific video_id、instance(label,start,end)、觀測／future比例及原生query輸出介面；普通temporal IoU函式可作原生定義參照。

需要轉換

source記paper/commit及EgoTopo/MS-TCN feature來源；domain/environment保留view與dataset；task分instance-set模型、dense timeline與future-label set評測；case鍵必須包含dataset/split/video/α/β與有效視窗，而不只video。frame、秒、normalized-future座標分欄，native inclusive標註與rasterizer [start,end)保留差異；global action mapping與many-shot mask另版本化。evaluator必須重建合法GT timeline與每類正確/總GT格數，或儲存per-case presence及score以計AP；β剩餘長度協定不可直接換算成P236/P237表格同一格。

仍需補齊

優先修復criterion/evaluator未定義變數、mask形狀、GT timeline與engine視窗覆寫，再確認macro/micro／空類／frequent/rare的分母。須固定global action ID，noun分支instance["nouns"]與建立時"noun"也不一致。確認末端+30 feature索引是否越界可見、實際feature pickle及stage1 checkpoint版本、min-three入案排除，並取得50Salads/EGTEA的stage2 reader/scorer。build_matcher永遠回GreedyMatcher，CLI hungarian未接；generalized_segment_iou只算普通IoU；greedy將targets依長度排序後未還原原索引，需對照label配對。以上靜態疑點尚未執行驗證，不可把程式已下載當可重現。

P078 · PerAct

Perceiver-Actor: A Multi-Task Transformer for Robotic Manipulation

返回逐篇總表核心內容已核讀 方法／綜述參考原作 ↗

核讀快照 2026-10-11。已讀範圍限所列片段；本輪未執行上游程式。

PerAct 是使用 RLBench 的方法參考，不另建18任務／249 variations的新任務庫。已讀replay與keypoint定義，並沿作者peract分支的reader、open_drawer condition、YARR rollout及accumulator閉合一條具體評測路徑；test可為每個task載入不同的val最佳checkpoint。

版本與身份

主倉庫02fb87681c5a47be9dbf20141bedb836ee2d3ef9（2024-05-09），README明說論文DataParallel改為公開版DDP。補讀依賴固定RLBench ad991951bc53e4f3b73b803a75cf4b7d55295cf7與YARR 8d0f2e228b97efa207eeccedfc6dac9334342ba3。P077 PyBullet、P062較新RLBench與本版資料／checker各有版本邊界；本輪只審所列區段。

論文為Shridhar、Manuelli、Fox的Perceiver-Actor: A Multi-Task Transformer for Robotic Manipulation，arXiv:2209.05451v2（2022-11-11）。README題名、作者、arXiv與peract.github.io相符；84–109明指MohitShridhar/RLBench及MohitShridhar/YARR的peract分支，不是P062的stepjam/RLBench現行快照。兩fork是執行／計分依賴。

領域
方法／綜述參考，未另作來源用途歸納。
環境
作者fork的RLBench/CoppeliaSim 4.1／PyRep桌面操作，EndEffectorPoseViaPlanning後接Discrete gripper。policy取front/left_shoulder/right_shoulder/wrist四個128×128 RGB與世界點雲；配置不直接輸出depth/mask，loader仍讀depth產生點雲。場景界限[-0.3,-0.5,0.6,0.7,0.5,1.6]為公尺，100³ voxel在此配置每格1cm。Franka真實實驗的teleop ZIP及Drive資料是外部附件，未取得／未驗證。
任務
18個task是README 232–249手選RLBench subset；249是論文v2的variations，不是task或trial數。已讀open_drawer的bottom/middle/top三variation，成功條件為指定joint相對初態位移>0.15m。task、variation_number、語句、demo初態各自存放；其餘17個checker未逐一選讀。
題數與資料
路徑為{split_root}/{task}/all_variations/episodes/episodeN，包含low_dim_obs.pkl、variation_number.pkl、variation_descriptions.pkl與camera/%d.png。24-bit depth除DEPTH_SCALE後以near+depth*(far-near)還原公尺，結合intrinsics/extrinsics產生點雲。reader即使僅啟用四視角，仍檢查全部五相機RGB/depth影格數與low_dim_obs一致。fill_replay按自然序讀demo、取第一句description；keypoint為gripper_open改變、末幀或joint_velocities在0.1容差內停止，stopped_buffer=4。action為xyz公尺+xyzw+gripper共8D；保留拼法trans_action_indicies／rot_grip_action_indicies，rotation是xyz Euler+180後5度bin。replay另含ignore_collisions、rgb/point_cloud/矩陣、task、lang_goal、1024D sentence embedding、77×512 token embedding及demo。low_dim_state是gripper_open、兩指位置及[-1,1]決策進度。末keypoint的100 reward為合成訓練標籤；增廣replay條目數不能當demo/case數。
評估方式
eval→IndependentEnvRunner→_run_eval_independent→RolloutGenerator→CustomMultiTaskRLBenchEnv→RLBench TaskEnvironment.step→Task.success→open_drawer JointCondition。demo index=eval_from_eps_number+ep，variation與初態自檔案恢復。範例checker成功時RLBench回1並terminal，PerAct乘100；reward<1歸零，IK／path／invalid-action錯誤直接失敗終止；預設25決策後timeout。SimpleAccumulator對episode累積reward取mean，稀疏0/100協定的eval_envs/return/{task}數值等於百分比成功率，但保留return名稱及scale，不泛推到有reward shaping的task。預設每task25 episodes；method seed另記。best模式每task依val CSV獨立選現存checkpoint、平手取最後，因此test不保證同一權重。YARR依weight是否dict決定test_data.csv檔名，仍需另核對demo_path實際split。

怎麼接入我們的benchmark

可重用

作者fork reader／demo reset、18-task subset、variation/description、keypoint生成、planner與具體condition、YARR return aggregation。

需要轉換

source記P078方法與P062 RLBench重用關係並儲存三個commit；case以split+task+episode+variation+Demo初態hash識別。raw sensor、policy observation、連續pose與voxel/Euler標籤分層；保留原始frame到keypoint的對映、augmentation起點與碰撞旗標。evaluator另存task→checkpoint、decision/trial budget、return scale、error/timeout。

仍需補齊

README只鎖peract分支，補pin不能證明是論文實驗版本。尚需五相機影像／TTM／Demo資產閉合、其餘17 checker核對與實機附件版本。不能套用P062現行RLBench reader。YARR pop只在>1個完成episode時輸出，單case試讀不保證有CSV指標。

P208 · DYAD

DYAD: A Multimodal Dataset of Co-Located Human Assistance

返回逐篇總表實作尚未確認 benchmark／資料／評測主來源原作 ↗ 用途與原生規模依據

核讀快照 2026-10-11。已讀範圍限所列片段；本輪未執行上游程式。

DYAD pinned paper 將資料與 benchmark code 列為規劃中的 controlled-access research release；已收錄 PDF／project／GitHub 搜尋沒有可確認的本篇倉庫。已核三個 endpoint 的標註與分母，但沒有公開 reader 或 concrete scorer 可讀，不能把同名 app builder／其他 dyadic dataset 當成來源。

版本與身份

來源固定為 2609.09023v1 與既有 2026-10-10 discovery/search caches；未確認 repo 就不造 commit 或 source path。851 assistance events、528 step intervals、611 requests、829 mode cases、256 response test pairs、感測影格均為不同單位；數字來自已核 paper，沒有本地 release 逐列驗算。

核對 arXiv:2609.09023v1（2026-09-08），Akhil Ajikumar、Mahya Qorbani、Sakib Reza、Sean Andrist、Mohsen Moghaddam。paper p.3 Table II 明示 planned release，正文說 will provide annotations/manifests/benchmark code under controlled access；未附本篇 release URL。既有 DYAD co-located assistance 搜尋成功回傳 0；DYAD 廣義搜尋前 8／1,197 結果不足以證明全網無倉庫。

領域
裝配與生產作業、協助、交接與陪伴
環境
單一 gearbox 組裝工作站的同地人類 performer–helper 協作；20 名 HoloLens 2 佩戴者各一 session，同一受訓 helper 遵循先言語引導、等待自我修正、必要時實體幫助的規則。六 pilot 不計正式 20 sessions／5 小時 58 分鐘。人類示範不是已執行機器人協作。
任務
三個分開評測的 reference endpoints：因果組裝步驟辨識、已知將有介入時的 verbal／physical mode anticipation、給 oracle 脈絡的 helper response generation。八個 step labels 是 Gear on shaft、Bearing in holder、Second holder、First holder、Part search、Shaft assembly in post、Attach crank、Verify rotation。九 trigger labels 是 out of reach、cannot find part、cannot decide next step、wrong part、ordering violation、wrong orientation、wrong screwdriver、stabilization needed、missed screw；null trigger 表示分類外需要，不能當沒有介入的負例。
題數與資料
論文 Table II 的觀測為 ego RGB 24–30 Hz／896×504、depth 5 Hz／320×288 16-bit、gaze 30 Hz 3D origin/direction、hands 20 Hz 每手 26 joints／4×4 poses、head 30 Hz 4×4 transform、Kinect RGB-D 15 Hz（RGB 1280×720 JPEG）。音訊不在規劃釋出範圍，使用去識別逐字稿。三層標註各有 task step（step/objects/tool）、request（utterance/confidence）、assistance（onset/offset、mode、initiation、hard stop、trigger、objects、helper utterance、outcome）。全部轉 session-relative clock 並儲存 null；兩場原始絕對式 hour 欄需保留各自 origin，不能當 elapsed hours。這些是論文 principal fields／單位，尚未核到實際 JSON keys、檔案佈局、reader 或同步轉換程式。
評估方式
mode 的論文清點是 export 852→刪一重複 851→有 mode label 850→完整 pre-onset RGB window 829（610 verbal／219 physical）；window=[onset−3.5s,onset−0.5s]。五 fold 各 12/4/4 performers，合併 829 個唯一 OOF events 算 binary macro-F1、physical-class AUPRC，四 seeds 為 0/1/2/42，2,000 participant bootstrap replicates 不能算新 cases。當次 trigger／initiation／outcome／speech／step label 等不得作輸入。step track 是 5 validation／15 test sessions，1 Hz 因果 RGB、四 frame lookback；segment F1@IoU0.1、collapsed-sequence edit、temporal mAP@0.1、frame mAP 與 MoF 分別保留，528 intervals 中一筆 null 不能擅自丟成零標籤。response 將 request end 前5秒至後15秒內最近的 verbal assistance 配對，376 pairs=120 dev+256 held-out test；oracle 提供先前步驟、10輪真實對話、10次介入及 CAD 圖，當次 trigger 不提供。每 query 一次生成、100-token cap；Claude Opus 4.5 依正確性、完整性、脈絡相關性、可行動清晰度、簡潔度與整體各評0–5，另 BERTScore P/R/F1。以上均為 paper protocol；segment matcher、judge prompt／parser、null／例外處理、aggregation 程式未找到，沒有宣稱本輪算過成績。

怎麼接入我們的benchmark

可重用

可重用三層事件結構、八步驟／九 trigger 原生詞表、單 helper policy、三 endpoint 的資訊邊界與原生分母；規劃 release 與實際可用素材分開記。

需要轉換

source 儲存 v1 與 controlled-access-planned 狀態；domain 記組裝／協作，environment 記 workstation、performer、helper policy。case 將 session、step interval、request、assistance event 與各 endpoint 的 eligible sample 建關聯，保留原始時鐘／session origin／同步率／nullable 欄。evaluator 分開 mode OOF、step sequence／frame 與 response pair，各自保留 split、seed、可見資訊及分母，三 endpoint 沒有共同成功分數。

仍需補齊

官方 release／access 流程及程式 URL、native annotation／manifest、同步 clock reader、829 OOF IDs、step null-policy、response 配對與評分實作。沒有 non-intervention negatives，不能接成 assistance-need detector；827 個有 outcome 標籤的事件中 812 個為 effective，這種高度偏態是作者不設 outcome prediction 的原因，不能以所有 851 events 當此 endpoint 分母。

Embodied Agent Interface: Benchmarking LLMs for Embodied Decision Making

返回逐篇總表核心內容已核讀 benchmark／資料／評測主來源原作 ↗ 用途與原生規模依據

核讀快照 2026-10-10。已讀範圍限所列片段；本輪未執行上游程式。

EAI統一四種決策模組，但BEHAVIOR與VirtualHome各有具體評分程式。目標理解的JSON錯誤處理不同，不能只因同名F1就合併成一個分數。

版本與身份

原embodied-agent-eval repo現轉址embodied-agent-interface/embodied-agent-interface，屬同一倉庫身份。這次深入核對goal interpretation，其他模組僅確認介面與來源角色，未宣稱全codebase或所有模組已跑通。

領域
居家整理與清潔、餐飲與烹飪、辦公與教育
環境
重用BEHAVIOR/iGibson與VirtualHome環境／狀態圖。形式goal、PDDL problem或語言題不自動新增物理場景。
任務
goal interpretation、subgoal decomposition、action sequencing、transition modeling四種資訊／決策評測；同一底層家務任務可接受不同資訊及要求，應建立不同case protocol。
題數與資料
BEHAVIOR以demo identifier連goal conditions、objects、instruction與LLM輸出；VirtualHome以scene_id、script/file_id連狀態／動作目標。保留node goals/edge goals/action goals與原形式語法，不能直接flatten丟掉順序／備選完成方式。
評估方式
已核讀goal interpretation：BEHAVIOR精確比對conditions，對備選目標取命中最多option，累計TP/FP/FN；解析失敗代空預測。VirtualHome JSON解析失敗直接continue並記format error，幻覺物件另記錄；跨環境F1分母與失敗規則需分開。transition env.step呼叫抽象control，不能宣稱真實機器人成功。

怎麼接入我們的benchmark

可重用

原goal/schema、scene/demo/script身份、模組介面、細粒度錯誤與evaluator。

需要轉換

同一父task連多protocol case；state/可見物件名/語言與reference答案分開；保留環境特定parser、備選goal及micro計數，不扁平為通用accuracy。

仍需補齊

其餘3模組各具體checker逐一接線、原始資產、判分分母完整性、形式規劃器與物理執行的比較界線。

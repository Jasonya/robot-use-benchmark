RoboRecover: Benchmarking Robot Policy Recovery under Execution Deviations

返回逐篇總表核心內容已核讀 benchmark／資料／評測主來源原作 ↗ 用途與原生規模依據

核讀快照 2026-10-11。已讀範圍限所列片段；本輪未執行上游程式。

公開程式是 LIBERO／RoboTwin 的恢復起點、固定 split 與回放後推論 overlay。已核讀 JSON reader、回放／新推論預算、LIBERO 成功傳遞與 RoboTwin 入櫃任務的具體 checker；完整2,000個 scenario JSON 的託管仍待發布，兩個 example 並非完整資料集。

版本與身份

固定 RoboRecover 089b942；LIBERO 延伸核讀恰為 lock 指定8f1084e。lock 所有 historical_revision_verified 均為 false；README 指 LIBERO MuJoCo3.3.2／robosuite1.4.x、RoboTwin SAPIEN3.0.0b1，不可用 upstream 最新版代換。RoboTwin FastWAM／LingBot-VA recovery adapters 仍 pending；論文六政策結果不等於倉庫六個可用 adapter。

收錄論文為 arXiv:2609.28952v1，PDF 第1頁直接連至 RUCKBReasoning/RoboRecover；README 的雙平臺、action-prefix recovery 與論文一致。README 第78行仍使用 CuteClaire/RoboRecover 複製網址，保留為別名待確認，不另算來源。

領域
居家整理與清潔
環境
LIBERO 的 MuJoCo 桌面任務與 RoboTwin 2.0 的 SAPIEN 雙臂場景各自重用原 benchmark。LIBERO 依 suite/task_id 找 BDDL、episode_idx 找原生 init state；RoboTwin 依 task_name/task_config/seed、embodiment 與 camera YAML 初始化。scenario 是同一任務執行偏離後的起點，不另計為新的 environment 或 task。
任務
論文定義 Recovery Stage=Approach/Contact/Move/Place，Deviation Type=Wrong Target/Wrong Pose/Stage Rollback/Scene Change；實際兩個 test CSV 都有9種 stage–type 組合，不是4×4皆存在。靜態解析各200個不重複 test sample_id，LIBERO 含38個 task_name、RoboTwin 含34個；論文另述 train 涵蓋40／42個任務。2,000是恢復 scenarios，兩平臺各800 train／200 test，不是2,000項技能。
題數與資料
split CSV 欄位為 sample_id/path/sha256/original_sha256/actions/replay_prefix_steps/task_name/s_stage/d_stage；兩個 example 的實際 SHA256 各匹配該平臺 test 第一列。LIBERO JSON 包含 task_suite_name/task_id/episode_idx/seed、initial_state.xyz/quat/rpy/gripper、actions；RoboTwin 包含 task_name/task_config/instruction、initial_state.joint_vector/left_endpose/right_endpose/left_gripper/right_gripper 及 annotation_meta.frame_index/video_fps。驗證器接受 LIBERO 7D、RoboTwin 14或16D action，qpos／ee 應另存 action_type；不可把 gripper 或正規化 action 一律當公尺。reader 只在長於 annotated_step+1 時擷取，不補短 prefix。LIBERO 模型輸入是兩視角 RGB、末端位置／axis-angle／gripper state；annotation video_fps=10 的 example 不代表所有控制頻率。
評估方式
先以原 reset 重建，再回放 prefix、清空推論歷史並給新的 S 步預算；正式設定 post-replay wait=0，prefix 不扣推論額度。LIBERO suite 預設預算 spatial/object/goal/10/90 分別220/280/300/520/400；RoboTwin 以原 task.step_lim 和可選 max_infer_steps 取較小值。LIBERO native done 來自 goal predicates；RoboTwin Base_Task 將具體 check_success 鎖存至 eval_success，所讀入櫃 checker 要求 |dx|、|dy|各<0.05，物件比初高0.007至0.12且對應夾爪張開（原生模擬長度單位）。論文 Overall RSR 是每 scenario 成功數／排定 trials 後等權平均；Macro-9 再對9個 stage–type group 等權平均。程式 build_summary 按 task/error_type 直接累加 trial 並使用 eval_success_at_end，可能包含 replay_already_done；不能原封當成論文 RSR。LIBERO _to_summary 主要輸出 status_counts，effective_failure 只加 timeout_failure/env_crash，亦不等於完整失敗分母。

怎麼接入我們的benchmark

可重用

固定 split／逐檔雜湊、JSON schema、upstream task/reset 關係、stage–type 標籤、replay/infer 分段與具體成功 checker。

需要轉換

source 保留兩層 commit；environment 指向原生模擬器／資產；task 仍用平臺與 native task key；case 用平臺+split+sample_id，儲存 reset 引用、prefix、原指令及偏離來源；evaluator 另記 step budget、repeat、scheduled/invalid/status。domain 只按任務內容對映。從 results.jsonl 重算 scenario 等權 RSR、Macro-9，將回放已完成與 state mismatch 保留為獨立有效性狀態。

仍需補齊

完整 scenario archive／資料授權及 simulator assets；各 adapter 完整環境驗證；原論文歷史 upstream revision 證實；正式排定 trial 名冊及 replay_already_done 的統一處置；各 task checker 全覆蓋。本輪只核讀代表性核心路徑，未跑模型或模擬。

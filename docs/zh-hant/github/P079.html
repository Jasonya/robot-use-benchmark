P079 · FMB

FMB: a Functional Manipulation Benchmark for Generalizable Robotic Learning

返回逐篇總表核心內容已核讀 benchmark／資料／評測主來源原作 ↗ 用途與原生規模依據

核讀快照 2026-10-11。已讀範圍限所列片段；本輪未執行上游程式。

FMB有真實Franka資料轉RLDS與策略rollout，但環境step固定回reward=0、done=False；成功需依官方實物評測程式另行記錄。已追到combined／insert-only builder、ResNet reader與robot action，發現state/peg_id欄位不相容、負ID轉uint8、primitive過濾後episode邊界未重算等具體整合問題。

版本與身份

固定rail-berkeley/fmb@d4da6ce044a9806f41e58bf7423b5a3c05289925（2024-05-28），早於論文v3（2024-09-03）；不能認定涵蓋v3所有實驗。官方procedure是以SHA256固定的網站文字快照，無與paper/commit同版的證明。combined、single、multi、insert-only TFDS builders是不同schema／subset，不能僅因均1.0.0合併；本輪選讀combined與insert-only。

固定論文為Luo、Xu等人的FMB: a Functional Manipulation Benchmark for Generalizable Robotic Learning，arXiv:2401.08553v3（2024-09-03）。PDF及README均指functional-manipulation-benchmark.github.io，README 136–140列相同作者與arXiv；繫結中的專案Code連結指rail-berkeley/fmb。此repo是控制器／資料builder／baseline，CAD與資料壓縮包另行發布。

領域
裝配與生產作業
環境
真實Franka Panda、兩個側面與兩個腕部RGB-D相機、抓取區、reorientation fixture及插入板。論文單物體位置隨機於20×20cm、板於35×35cm；多物體抓取區20×30cm，板固定。控制器預設10Hz；gripper切換會另等待，影片以20fps寫出，均不能用來推定原始資料有精確等間隔timestamp。形狀／顏色／長短／大小是物件屬性，板號或相機數不等於environment/case數。
任務
原生任務含single_object_manipulation及三種multi_object assembly；combined builder的primitive有grasp、place_on_fixture、regrasp、rotate、move_up、go_to_board、insert。論文Table 1的六種分段標籤與程式中的過渡primitive不強制一對一合併。22,550為論文統計的分段軌跡（single 15,350、multi 7,200），不等於完整任務episodes：論文另列2,700個single全流程、4,050個額外insert及每assembly150個multi全流程。本輪未下載檔案，無實際落地case計數。
題數與資料
combined builder 1.0.0讀.npy dictionary：actions(T,7)、primitive[T]、obs/{side_1,side_2,wrist_1,wrist_2及_depth,q,dq,tcp_pose,tcp_vel,tcp_force,tcp_torque,gripper_pose}，single另有object_info。RLDS steps.observation為256×256 JPEG RGB、float32 depth、joint_pos/vel(7)、eef_pose(7)、eef_vel(6)、eef_force/torque(3)、state_gripper_pose及object/shape/color/size/length；episode_metadata保留file_path、episode_task與生成語句，USE embedding為512D。depth僅astype，未提供raw depth到公尺的scale；size/length為類別字串。action是base-frame xyz增量（m）、左乘的xyz Euler增量（rad）及gripper 0=open/1=close；env裁剪前六維至±0.06m／±0.25rad。builder只有train，ResNet reader預設train[:95%]/train[95%:]，不是物件held-out benchmark split。reward在原始最後步硬設1、discount全1，不能作量測成功標籤。
評估方式
callchain：ResNet simulate_policy→rollout→FrankaFMB.step；env固定回(obs,0,False,{})，rollout亦丟棄reward/done、可按Esc停止，只存observation/action與影片。N=100是程式呼叫引數，不是官方protocol；grasp/regrasp 60步、insert/place_on_fixture 100步、rotate 200步、long_horizon 300步，action chunk可能跨越外層上限。官方procedure另定grasp/rotate/place/regrasp各50 trials（5 seen+5 unseen物件各5次）、insert 45（9 shapes各5次）、single multi-stage 10、每multi-object assembly 10（5初態各2次）。成功依牢固抓持、fixture上斜放、rotate ±15度、底面完全插入正確孔等實物條件；multi-object需全部插入。未找到此路徑的機器自動量測或success JSON，必須保留人工／外部判讀地位。
原作數字：保留論文的單位與頁碼

怎麼接入我們的benchmark

可重用

raw→RLDS欄位、primitive語句與object屬性、父軌跡file_path、控制器delta-action定義、官方逐skill初態／trial／成功準則。

需要轉換

source同時綁paper v3、repo commit與TFDS dataset名稱/1.0.0；task區分完整assembly與primitive；case保留父episode、原始frame index、board/object ID、切分後segment及protocol trial。物件泛化split需另存held-out清單，不沿用95/5切片。把raw depth scale、force/torque frame、gripper及action正規化作profile欄位；evaluator單列合成demo reward與實物成功判讀。

仍需補齊

combined及insert-only builder均無observation.state/peg_id，但ResNet decoder 137–140無條件讀state，peg filter/shape_vec又用peg_id；需版本化adapter，不能宣稱可直接串接。combined把-1 ID sentinel轉uint8後成255，schema文字卻仍說-1。insert-only過濾後仍用原始i標is_first/is_last，可能沒有first或terminal步。README說舊checkpoint force/torque在base frame、新dataset預期eef frame，不能只按同名欄位合併。尚缺深度尺度、物理資產／相機校正、protocol附圖座標、實際trial結果與觀察者判讀記錄。

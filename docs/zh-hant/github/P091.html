P091 · UniFolding

UniFolding: Towards Sample-efficient, Scalable, and Generalizable Robotic Garment Folding

返回逐篇總表核心內容已核讀 benchmark／資料／評測主來源原作 ↗ 用途與原生規模依據

核讀快照 2026-10-11。已讀範圍限所列片段；本輪未執行上游程式。

已核讀 UniFolding 的 VR HDFStore、runtime YAML/NPZ/PLY、動作與標註格式、模擬幾何計分及真機狀態機。真機 SUCCESS 是流程狀態：fold1/fold2 條件以最後 action 型別推定，並無成品幾何驗收；原始論文10步內按摺法完成的成功率需另保留評閱證據。

版本與身份

固定2024-10-18 commit，晚於2023論文。核讀限Python資料／task／metric與控制流程，未核讀所有電機控制／Unity外掛底層，未執行上游程式、連線標註資料庫／通知或下載模型與大型資產。 已補讀VR-Garment c9014f62的收集與回放資料契約；它本是GarmentTracking工具，UniFolding引用作Stage0上游。未使用VR硬體或執行Unity。

README 明示官方 CoRL 2023 程式，完整題名、六位作者與 arXiv:2311.01267 相符。RFUniverse、CLOTH3D、VR-Garment 與 ClothFunnels 各有重用角色，不把框架／母資料集當成本篇新benchmark。

領域
衣物與洗護
環境
模擬是Unity 2022.3 LTS上的RFUniverse，README要求另取得Cloth Dynamics 2.0.9 beta；CLOTH3D衣物依category meta與instance filter載入。真機是雙Flexiv Rizon 4、AG-95與Photoneo MotionCam3D＋MindVision RGB。Unity左手系先轉Open3D右手系，再轉virtual/world/左右robot frames；virtual以z為高度，配置另有particle_scale=100與time_scale=4，不能直接沿用FleX的y-up或將步數當秒。
任務
兩種衣物tshirt_long／tshirt_short的展開→fold1→fold2流程；附錄C先同時摺兩袖，再對半摺本體，精確抓放點由VR人類示範生成。ActionTypeDef包含FLING/DRAG/FOLD_1/FOLD_2/PICK_AND_PLACE/DONE及恢復／HOME等，是動作enum而非同數量任務。ExperimentVirtual.execute_action只實作FLING，random_fold用於初態，不能宣稱runtime模擬提供完整摺衣動作集。論文60件真衣物以2:1分割，20件held-out各10trials＝200次測試；2432是訓練sample、每sample16次人類偏好比較，不是測試cases。
題數與資料
VR data.h5 的Pandas df以instance_id/video_id/sample_id標識，讀pcd_path_frame1→NumPy Nx6 xyz/rgb、nocs_path_frame1、coverage_frame1/2、左右gripper_point/theta_frame1/2、action_type、folding_step、is_smoothed/is_smoothing。raw fold依folding_step映為fold1/fold2；pose內部順序為左pick、左place、右pick、右place，角度wrap至±π。VR依instance_id打亂切分，所讀stage1 config為8/1/1；runtime real/virtual卻依sample打亂，不能等同論文物件held-out split。runtime metadata按namespace記pcd.processed.begin、processed_nocs.begin、pose_virtual、reward.begin/end及episode_idx/trial_idx/action_step；NPZ鍵為points/nocs，real另接受PLY。annotation.action_poses原順序左pick、右pick、左place、右place，reader重排後將角度全設0；虛擬fling place亦用0佔位，應儲存validity而非當有效目標。偏好0/1/2/3分別為左對優／右對優／相等／不可比較，經label smoothing後監督分數模型。 VR-Garment補查：PoseData包含dualHandPoses（position／Euler／手勢）、localParticles（solver renderable positions／normals）、左右grasp solver indices、solver／actor local-to-world矩陣和Time.time。Record名義每0.04秒呼叫，應保留實際timestamp而非假設等間隔。JSON錄製再回放輸出AnimationData及color/depth/mask影像引用的BSON；四個隨機相機視角共用同一段示範。
評估方式
虛擬get_deformable_reward以canonical初態粒子覆蓋面積作max_coverage，在virtual XY平面用100×100粒子網格；IoU另外把兩組XY點共同縮放至0–99並畫半徑2圓，以點陣交集/聯集計算，不是RGB影像mask IoU。reward.py沿用ClothFunnels分解形式，但此版把z歸零、同頂點SVD配準5次、映象取min，距離除sqrt(初態粒子覆蓋面積)，stage2權重0.7；與P090用長×寬正規化不同。runtime學習用begin−end的l2/icp改善量；VR則用同instance的coverage_frame1最大值正規化、stage1以max(tanh(2Δcoverage+coverage_after),0)給fling標籤，fold等固定0.8、done為0，均非實測成功率。真機state machine把fold成功設為最後action_type==FOLD_1/FOLD_2，garment_fling_drag_success固定True且有TODO；operable只看mask面積上限、reachable看mask橫向均值，沒有成品摺法驗收。step_idx>max_num_steps非全域強制終止，部分轉移還要求不可操作，lift與fold前drag迴圈不按每個物理動作累加。論文要求10動作內按規則完成，這與狀態機SUCCESS需分欄。 VR收集工具的開始／清除／儲存由手勢或按鍵觸發，超過maxFrameCount僅提示；錄完不表示通過摺疊成功判分。ClothImitation2／AnimationImitation2是錄製與回放場景，不能加成兩個新任務；四視角不加成四段獨立示範。

怎麼接入我們的benchmark

可重用

原生動作／觀測／annotation dataclasses、frame pairs與偏好、instance與sample索引、模擬幾何metric及真機流程狀態。

需要轉換

source固定commit並標記VR-Garment/CLOTH3D/ClothFunnels重用；environment儲存Unity/Open3D/virtual/world/robot座標鏈；task儲存衣物類與兩段摺法；case保留完整garment/trial/step、checkpoint、split粒度；evaluator分模擬距離、VR訓練reward、preference target、真機流程狀態及獨立成品成功。保留特權粒子/NOCS，勿當真機可觀測量；人類VR示範須經primitive與校正adapter才能成為robot命令。 VR原生Unity／solver座標、Euler順序、BSON/JSON與視角／timestamp對應須保留並校驗；不得直接視為米制robot命令。

仍需補齊

VR→UniFolding前處理與data.h5/NPZ/annotation/instance清單閉合；物件held-out真機200trials的逐次成品評閱；嚴格10物理action budget；pure evaluation入口與網路／barrier相依隔離；Unity付費外掛／CLOTH3D／硬體校正取得與執行驗證。

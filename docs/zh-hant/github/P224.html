EMPIRE: Explicit Manipulation Planning as a Learnable Intermediate Representation for Egocentric Hand-Motion Forecasting

返回逐篇總表核心內容已核讀 benchmark／資料／評測主來源原作 ↗ 用途與原生規模依據

核讀快照 2026-10-11。已讀範圍限所列片段；本輪未執行上游程式。

已追完EMPIRE的index/episode reader、30→12FPS取樣、混合MANO動作表示及best-of-8 joint scorer。公開庫有核心程式，但EMPIRE-651K資料與前處理明示尚未發布；650,910訓練視窗與111活動標籤為論文數字，未由實際dataset逐筆驗證。

版本與身份

固定commit bea74bb146baa750b02f291754cafd5ed6cd0bfe。標準StageII配置與predicted_plan ablation使用預測plan；ground_truth_plan另列。直接執行eval_mse的預設K=5、COT_GENERATE_THEN_CONDITION=0，可能使用GT plan suffix；正式shell才設定K=8與online生成，因此兩入口不可混同。online分支重讀raw image/coarse instruction而不用GT suffix，但資料載入仍依賴reference-plan存在；不能宣稱是完全無標註部署封裝。所有內容僅靜態核讀，未執行資料前處理、模型、MANO或評測。

arXiv:2608.22449v1，Wen Wang、Ruibing Hou、Hong Chang、Shiguang Shan、Xilin Chen，EMPIRE: Explicit Manipulation Planning as a Learnable Intermediate Representation for Egocentric Hand-Motion Forecasting。PDF第1頁直接連wangwen-banban/EMPIRE，README題名/arXiv一致。VITRA為程式與資料格式基礎，EgoDex為母資料，Being-H0為比較baseline，三者不能另算本篇新資料。

領域
穿戴互動與動作介面
環境
EgoDex/Apple Vision Pro的人類桌面操作第一人稱影片，RGB、相機內外參、雙手追蹤骨架轉MANO、task caption與per-hand plan。reader在query frame的camera座標表示整段未來姿態；公開FrameDataset只支援human，不提供robot互動環境。
任務
從current RGB、初始雙手狀態與caption生成操作plan，再預測雙手未來motion；plan描述不是可執行robot技能。論文650,910個5秒train windows、6,836個test windows、111個活動標籤需分開計數。Part1 ablation另以訓練任務重疊定義26 seen tasks/1,247 windows與85 unseen tasks/5,589 windows；並非全五partition訓練的預設unseen切分。task summary從episode名稱或obj_class/video_name解析label，再對指定training annotation snapshot比對，沒有封閉111-task registry。
題數與資料
preferred layout為dataset/episode_frame_index.npz（index_frame_pair[N,2]=episode_index/frame_index、index_to_episode_id[E]）、episodic_annotations/id.npy及statistics.json；legacy .npy字典/processed_episodes_vitra_format也可讀。episode含video_name、video_decode_frame、intrinsics、extrinsics及left/right的beta、kept_frames、global_orient_worldspace、transl_worldspace、hand_pose、joints_worldspace、text/anno_type；caption→instruction、plan→cot只是alias。標準設定source_fps=30、target_fps=12，step=2.5，以np.rint取整，並可依此過濾index rows；future=59建立含current的60個window位置，再取next-state而產生60個未來action。OOB雖clip索引，但被mask剔除，60個slots不保證60個有效影格。text範圍採[start,end)，plan匹配卻允許end且取最近範圍。每hand51維為逐步腕平移m、腕旋轉xyz Euler-radians及下一步絕對15×3手指Euler；use_rel=false仍保留腕部relative分量。兩手102維action補到288；原state122維含betas，padding移除betas後補到296。predicted plan ABI為schema_version=1.0、plans[episode_id:frame_index]，主StageII配置明確讀該sidecar。
評估方式
run_full_eval預設REPEAT_TIMES=8、ONLINE_PLAN=1、save_repeated_samples；model config為flow matching 4步。eval_mse先依mask選正規化動作MSE最小者，分母為有效action scalar數，這不是論文MPJPE。compute_egodex_metrics優先讀sampled_actions[N,K,T,D]，逐候選反正規化並recon_traj：累加腕平移、左乘腕旋轉、手指使用絕對角，再以MANO重建21關節；beta固定0、左手套軸修正，剔除初始state，只評未來。mask為hand/frame有效性，非獨立joint可見性。每window MPJPE=全部有效hand-frame之21-joint Euclidean均值；等價分母21×有效hand-frame數。選該MPJPE最小的同一候選來算wrist joint0與finger-relative（扣wrist後只取其餘20關節），不可各指標另挑best。FDE為每個有GT手最後有效frame的joint均值，再對手平均。最終對非NaN windows的metric等權nanmean，再m×1000轉mm；num_samples仍包含無有效手而為NaN的records，須另報有效分母。若NPZ沒有sampled_actions，scorer把pred_actions當K=1，無法恢復best-of-8。shard merge按sample_positions排序並檢查連續性；task summary再分組，並不將總分改成task-macro平均。

怎麼接入我們的benchmark

可重用

重用versioned schema/resolver、canonical sample ID、plan sidecar、FPS/mask邏輯、MANO adapter、step重建、best-of-K MPJPE與task provenance摘要；保留EgoDex/VITRA lineage。

需要轉換

分開source/domain/environment/task/window/evaluator；case鍵為dataset revision+episode_id+frame_index，儲存source/video/target FPS及np.rint後實際indices。將51維混合action、102有效維、288/296 padding及mean/std明確分層；保留anchor-camera與xyz-radians、公尺/mm轉換。evaluator儲存K、4步設定、全部sampled_actions、選中best_k、21/20 joint定義、每window有效hand-frame及NaN分母。

仍需補齊

未發布的index/episodes、骨架→MANO擬合與caption/plan前處理、資料/統計/sidecar/weights/MANO資產尚未閉合；不能驗證650,910/6,836筆或真正split無洩漏。需核對eval dataset statistics.json與scorer STATISTICS_PATH均使用對應training normalization，避免反正規化版本不同。須鎖定ONLINE_PLAN、各shard皆保留sampled_actions、真正K與完整case coverage；資料格式稱HF-compatible不代表已確認HF dataset repo/revision。

REBOOT: From Failure to Recovery - A Dataset and Benchmark for Precision Assembly

返回逐篇總表核心內容已核讀 benchmark／資料／評測主來源原作 ↗ 用途與原生規模依據

核讀快照 2026-10-11。已讀範圍限所列片段；本輪未執行上游程式。

已核讀 REBOOT 的 depth reader、frame／video 對齊、phase.json 裁切讀取與通用 evaluator。原生18任務及人工五階段判定主要定義於論文；所查固定版本未提供 REBOOT 專用自動 phase scorer。另實查官方 RCA recovery 資料 metadata，確認僅30 episodes、train split 且沒有 meta/phase.json，不能直接把論文2,160段視為已閉合的公開資料。

版本與身份

固定 depth 分支269d539，不以 upstream LeRobot 最新版替代；HF實查固定fb4e5c5。README 的『2,160 bimanual』與論文83段實際協作需分開解讀；論文1-based phase公式、範例tau_0=0及程式0-based slice 也要保留來源差異。未下載 parquet/video，未安裝或執行上游程式。

arXiv:2609.22591v1 第16頁及作者 nanayawoa 的專案頁均連至此 fork；README 自稱 LeRobot (REBOOT fork)，承接 Trossen fork、LeRobot v0.4.3 與 depth PR2604。這是資料錄製／讀取支援倉庫，不是18項組裝任務的完整模擬器。

領域
裝配與生產作業
環境
實體 NIST Assembly Task Board #1，Trossen WidowX AI 兩支6關節 follower 與 leader teleoperation；四臺 RGB-D 視角為 high、low、left_wrist、right_wrist。論文物件初位在名義位置周圍3–6 cm 變動，目標板固定。雙臂硬體／14D state 不等於每段雙臂協作：論文第10頁只有83／2,160段屬雙臂，且主要為 recovery_install。
任務
依第23頁表10保留9種物件各 install/remove，共18項：M12、USB-A、USB-C、RJ45、NEMA 1-15P、HAN10E、RCA、16mm bar/cylinder。每 task 保留 C1/C2/continuous symmetry、clearance（mm）、precision tier。共同五階段是 Align(pick)、Engage(pick)、Transport、Align(place)、Engage(place)，不是90個獨立任務。論文每 task 有60 expert+60 recovery，總2,160；第7頁『10 types』與具體9列 inventory 不一致，採表10列舉並標記差異。
題數與資料
論文 action/state 為兩臂各6 joint+1 gripper 的14D絕對目標／狀態，30 Hz；保留關節及夾爪原生尺度，不推定全部維度為角度。實查 REBOOT26/rca_recovery_install@fb4e5c5：info.codebase_version=v3.0、30 episodes、26,939 frames、1 task、splits.train='0:30'；action/observation.state 為 float32[14]，RGB 為480×640×3 video、四個 *_depth 為480×640×1 depth。data/chunk-*/file-*.parquet 與 videos/{video_key}/chunk-*/file-*.mp4 透過 episode metadata 的 chunk/file/from_timestamp 連線；reader 裁定 delta_indices 不跨 episode，另輸出 *_is_pad。相機程式以 z16 讀 uint16，docstring 稱 mm，但資料 info 未提供 depth scale，仍需校準資訊。論文 phase schema 含 repo_id/task_id/episode_index、phase_boundaries.tau_0…tau_5、failure.originating_phase/failure_mode/t_f/t_r/t_s；trim reader 則要求外層 episodes[]，按 failure.<cut-key>（預設t_r）取 [start,stop)。抽查的 RCA dataset file inventory 未含 meta/phase.json；其他38個 API 列出專案未逐一查資料，不能斷言全部缺標註。
評估方式
論文以人工標記的 last-completed phase／first failure phase 形成每階段分佈及最終成功率，不能由 clearance 單欄推導自動成功。正文第7頁寫20 rollouts/task/policy，第8頁與附錄A.5寫15，後者18×3×15=810；須釐清實際使用名冊。公開 lerobot_eval.py 讀 info.final_info.is_success 或 info.is_success，缺值用False，沿 episode 合併為 any(success)，再平均成 pc_success（百分比），同時計 reward；它不判斷 connector engagement 或 phase 邊界，不能代替 REBOOT grader。失敗詞彙也有版本差：第6頁四類，附錄與第7頁另含 slip。裁切器會移除 dtype=depth／名稱結尾_depth 的 feature，重新產生 index/timestamp，未重對映 phase/failure 時間，不能直接把其輸出當原版完整 recovery case。

怎麼接入我們的benchmark

可重用

14D通道名稱、四相機／depth schema、LeRobot v3 episode 索引讀取、原生 task inventory、人工 phase/failure 表達及裁切窗解析。

需要轉換

source 分別保留程式 commit 與每個 HF dataset revision；environment 記硬體／board；task 用 object+install/remove；case 用 dataset revision+episode_index，另存 expert/recovery 與雙臂旗標；frame/time 用30 Hz與原 offset 連線。保留 source_frame_index 與 trim offset，重新對映 phase/t_f/t_r/t_s，避免刪 depth；evaluator 獨立儲存人工階段判定與通用 rollout success，不合併。

仍需補齊

36個理論 task×episode-type 分組與官方實際38個資料 repo／分片的對照及去重；完整 episode 與 phase annotation 名冊；RCA 本次固定版本僅30段及缺phase的原因；15/20 rollout 協定釐清；原生 joint/gripper/depth 校準尺度；公開 REBOOT 專用 grader 或人工評分流程。

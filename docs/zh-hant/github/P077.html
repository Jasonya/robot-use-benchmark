P077 · CLIPort

CLIPort: What and Where Pathways for Robotic Manipulation

返回逐篇總表核心內容已核讀 benchmark／資料／評測主來源原作 ↗ 用途與原生規模依據

核讀快照 2026-10-11。已讀範圍限所列片段；本輪未執行上游程式。

CLIPort已追到Ravens/PyBullet的bowl／rope任務、示範讀寫與Task.reward/is_match。mean_reward可含部分分數；bowl文字目標與checker有一對一配對落差，且eval沒有按episode seed重設Python random，不能保證完全重建示範語義變體。

版本與身份

本輪固定cliport/cliport@2be5c47b5bb9bb7040ad90693288b87b1e18e7ad（2023-05-22），晚於2021v1；未取得論文實驗的逐項commit對照。README承認部分seen/unseen train相同、多工Google物件訓練集較小及旋轉augmentation與方向語句衝突。記錄的是所列選讀區段；不聲稱全倉庫／完整資料／實機實驗已驗證。

固定論文為 Shridhar、Manuelli、Fox 的 CLIPort: What and Where Pathways for Robotic Manipulation，arXiv:2109.12098v1／CoRL 2021。PDF 的 code-availability 指向 cliport.github.io；倉庫 README 1–9 同時吻合題名、三位作者、arXiv 與專案網址，足以確認 cliport/cliport 為本論文官方程式。openai/CLIP 與 Ravens 是重用依賴，不能另算 CLIPort benchmark。

領域
包裝、倉儲與物流、通用物件與機動作業
環境
PyBullet 桌面 UR5／預設吸盤；agent有三個480×640無噪RGB-D視角，oracle另有俯視影像與segmentation。示範與評測入口將physics設為480Hz，但每筆資料是完成pick/place primitive並等待物體靜止後的決策步，不能當480fps影片。工作區x=[0.25,0.75]、y=[-0.5,0.5]公尺；Task bounds的z上限0.3，dataset/action bounds為0.28，需按用途保留。實機Franka結果不等於此UR5環境可直接重播。
任務
任務檔案的10個goal-conditioned家族需與seen/unseen/full屬性子集及seq流程分開。已讀PutBlockInBowl：隨機1–3個碗、1至碗數個block、6個distractor，語言指定兩種顏色；goal=(objects,matches,target_poses,replace,rotations,metric,params,max_reward)，步數重設為blocks+1。seen與unseen類別在train均取TRAIN_COLORS，unseen只在非train改EVAL_COLORS。AlignRope是20節繩／四種邊方向、可正反向匹配；節數、語句變化與生成seed均不能當新增任務數。
題數與資料
RavensDataset把同一episode寫成color/depth/action/reward/info五個目錄下的{episode_id:06d}-{seed}.pkl；color為uint8、depth為float32公尺。序列元素為(obs,act,reward,info)，最後一筆act=None；reward是到達該obs的前一步回饋。act.pose0/pose1各是(position_xyz公尺,quaternion_xyzw)；info含lang_goal及object_id→(pos,rot,dimensions)特權狀態。讀入後以3.125mm/pixel融合成320×160×6 RGB+重複三次height，p0_theta固定0、p1_theta為相對負yaw（弧度）。seq以i+1為goal，其他任務用末幀。train seed從0每次+2，val從1、test從10001每次+2；只儲存oracle總reward>0.99，實際case數須列舉落地檔案，不能用要求生成的n或README估計值替代。
評估方式
callchain：eval.main→ds.load(i)/seed→env.reset（Python random非逐case重設）→最多task.max_steps次env.step→Task.reward→is_match或zone點覆蓋。pose逐object在可配對target中找到任一匹配即加max_reward/objects；is_match只看XY距離與對稱性處理的z-yaw，不看高度，bowl容差0.05m、rope0.02m。zone算區域性座標點落入矩形範圍且低於z上限的比例。reward為累計完成度差值，完成當前goal後彈出相應語言；done是goals空或_rewards>0.99，primitive timeout也會直接done=True且reward=0。結果JSON儲存episodes=(total_reward,last_info)與mean_reward；預設n_demos=100、n_repeats=1，test_best依val mean_reward選模型（未找到則last.ckpt）。因此不得把done、mean_reward與二元success混用。

怎麼接入我們的benchmark

可重用

重用task class與原生屬性切分、goal tuple、語言順序、episode seed、相機與pose-action欄位、具體reward/checker。

需要轉換

source綁paper edition+commit；environment綁資產／相機／物理設定；task保留家族及seen/unseen/full/seq；case以task+mode+seed+示範檔案識別並儲存五檔引用；evaluator分列delta_reward、total_reward、done及終止原因。把世界座標、公尺、xyzw、heightmap投影和特權info可見性寫入profile；同一train資料的seen/unseen別名記reuse關係。

仍需補齊

尚未閉合Google Scanned Objects修改COM後資產、所有case檔與實機採集格式。PutBlockInBowl註解要求每block放不同碗，goal也設replace=False，但reward丟棄replace並逐物件獨立匹配，不消耗target；加上只驗XY，需協調者明列原生checker限制，不能宣稱嚴格一對一裝碗或3D落碗驗證。val_best只取目錄第一個匹配results-val檔，且n_repeats共用同checkpoint／case seed，需固定檔案與replicate定義才能可比較。另有seed再現性缺口：demos.py同時以episode seed重設np.random與Python random；eval.py只在repeat開始用train_run呼叫utils.set_seed，逐case僅重設np.random及env.seed，而env.seed只建立self._random。PutBlockInBowl等任務的random.sample顏色未按case重設，因此存下seed不等於已驗證同一示範場景／語句；需儲存或修訂完整RNG協定。

P083 · RoboDojo

RoboDojo: A Unified Sim-and-Real Benchmark for Comprehensive Evaluation of Generalist Robot Manipulation Policies

返回逐篇總表核心內容已核讀 benchmark／資料／評測主來源原作 ↗ 用途與原生規模依據

核讀快照 2026-10-11。已讀範圍限所列片段；本輪未執行上游程式。

RoboDojo與XPolicyLab分別提供sim任務／計分與policy／data adapter。已閉合stack_bowls、push_T的checker、RewardManager、EvalEnv及summary，並讀HDF5→RGB→LeRobot reader。success_rate與partial score不同；unstable/abandoned layout不在相同分母，summary還有embodiment鍵遺失與layout排序問題。

版本與身份

RoboDojo固定cb2a37d58dbbeb2777b0c2b30e97ecb8ab91095c（2026-10-08），不同於舊inventory 726e9aabfaa642203722eb126f5eaf0f37f3e1ad；XPolicyLab固定de9b445e4e46388542c412e406c73d359a5802fd（2026-10-10）。RoboDojo README記9月16–17日get_obs單幀與RGB修正、HF資料更新及swap_T assets修正，要求XPolicyLab bb9a0b5f5136a74503b679af830bfd0a3a837d5c或後續；未獨立驗證本兩pin的完整runtime相容性。7月paper、9月資料修訂、10月程式與8月XPolicyLab paper須分開建版本，不把政策數當benchmark task數。未啟動server、sim、policy或遠端評測。

固定RoboDojo論文為Chen等人的完整sim-and-real benchmark，arXiv:2607.04434v3（2026-07-08）。PDF第1頁直接連兩repo，主README題名/arXiv吻合。XPolicyLab現行README另引用2608.09892（2026年8月的獨立工具論文）；本P083只審其RoboDojo adapter角色，不把那篇的政策數或新功能倒算成7月RoboDojo benchmark。

領域
居家整理與清潔、衣物與洗護、裝配與生產作業、通用物件與機動作業
環境
Isaac Sim／Isaac Lab配置化場景，TaskEnv由sim/scene/robot/camera/task YAML建立，可有target雙臂與support arm。選讀stack_bowls從8個bowl asset ID中選3個同類物件，xlim[-0.45,0.45]、ylim[-0.25,0.07]相對Table；評測改讀已存Eval_Layout。主README此版為sim eval-only，真實ARX X5/Piper/Piper X的18 tasks使用RoboDojo-RealEval另行部署；本輪未取得真實trial影片、三人評分或隱藏驗證layout。
任務
summary DIMENSIONS確列42個base tasks：Generalization12、Precision8、Long-Horizon8、Memory6、Open8；12個*_random是對應base task的泛化設定，不另算42以外新canonical任務。stack_bowls完整成功需三碗軸向<45度、最低碗<7度、相鄰中心XY距離<=0.04m且高度差>=0.005m、target robot回原位（每座標差<=0.15m、旋轉<=20度）。此stack checker不驗接觸且未設最大垂直間隔。process score為兩碗階段15、三碗階段100，要求gripper開度>=0.8；transition每action最多推進一階，100仍須完整成功gate。push_T以quat差<7度、XY距離<0.007m及robot回原位成功；is_lift相對初態>0.01m的query允許次數0，觸發即失敗；不是IoU評測。
題數與資料
case來源為Assets/Eval_Layout/RoboDojo/{config_name}/{eval_seed}/{task}_N.json。SeedManager按N排序後重新以0..len-1編ordinal，該ordinal才是程式layout_id；未取得外部layout JSON，不能用檔名suffix直接替代。runtime obs含data_format_version='v1.0'、instruction、additional_info.frequency、vision/state/action及env_idx；RGB為HWC，float depth保持距離，approximate_depth=clip(raw*1000,0,65535).uint16。實際ObsManager寫extrinsic_matrix，與XPolicyLab README宣稱runtime extrinsics_matrix不同。XPolicyLab load(RoboDojo,v1.0)遞迴讀HDF5、解析instruction/subtasks JSON，colors經decode_image_bit；pose為xyz+qwqxqyqz。legacy JPEG及有XPL-RGB1 COM marker的新JPEG可共存，decoder只對有marker者做BGR→RGB。LeRobot v2.1 converter取state/action下left_arm_joint_states、left_ee_joint_states、right_arm_joint_states、right_ee_joint_states依序串接；三相機映到cam_high/left_wrist/right_wrist，缺相機補黑，各arm補到共同最大維度。paper的3500 trajectories=34訓練tasks各100+100 DLC輔助（Open無task-specific訓練），1859602 frames及25Hz是paper統計，未下載重新點算。
評估方式
policy deploy→update_obs/get_action→EvalEnv.take_action→robot control→RewardManager.step→Func_Parser→is_episode_end。check按列表順序移除已完成stage，巢狀list交替OR/AND，query計事件次數；完整reward只回0/1。stack_bowls上限800個take_action，push_T600，非physics ticks；capture frequency另由dt與collect_freq決定。EvalEnv完整成功記episode score=1，失敗若有process score則/100；_result.json含details{record_index:{layout_id,success,score}}、success_rate（0–1）、score（0–100平均）、eval_time（已計數episodes，不是秒）。無效、unstable及部分PhysX broken layouts被排除／補樣，abandoned另存resume manifest；要求50不能當50次嘗試。summary採每task/policy/embodiment/seed最新timestamp結果；獨立task前50筆，Generalization合base25+random25，三seed0/1/2共126個完整cell。先平均每維tasks，再五維等權平均，seed標準差為population std；未完成cell留空，overview可顯示已完成部分平均。真實paper協定每task10 trials、三位評分者分別打成功與substeps後平均，不能以sim RewardManager替代。

怎麼接入我們的benchmark

可重用

42-task capability mapping、base/random關係、layout replay與seed排程、具體幾何／事件／階段checker、逐trial success/score及HDF5／JPEG reader。

需要轉換

source同時鎖RoboDojo與XPolicyLab commit；case鍵包含paper/code版、task、base/random、embodiment、config、eval_seed、layout ordinal和實際檔案hash，record_index另存。evaluator區分success、process score、末階段gate、unstable/abandoned與實際分母；按五維聚合而非所有task混平均。資料profile保留v1.0容器、JPEG marker、pose wxyz、觀測／動作對齊、相機缺失與padding mask、原頻率及LeRobot版本。

仍需補齊

尚缺固定layout/robot/object資產包、原始HDF5樣本、真實評分資料與hidden-layout驗證。summary load_entries其實按details字典record key排序而非payload.layout_id；main又將(policy,embodiment,seed)寫入data[policy][task][seed]，多embodiment同名結果可能互相覆蓋。latest timestamp還會跨不同checkpoint/action_type選最後結果，須額外綁run配置。LeRobot轉換合併多頻率來源時以max_fps建立dataset，convert_one逐原幀寫入無resampling，需儲存原時間軸或分流。geometry-only stack條件、runtime extrinsic鍵差異、score gate與unstable排除均需協調者在schema／protocol層明示。

P237 · Gated Temporal Diffusion

Gated Temporal Diffusion for Stochastic Long-Term Dense Anticipation

返回逐篇總表核心內容已核讀 方法／綜述參考原作 ↗

核讀快照 2026-10-11。已讀範圍限所列片段；本輪未執行上游程式。

已核 GTDA 的 Breakfast/50Salads 與 Assembly101 loader、DDIM inference 及 Mean/Max MoC／Frame Diversity。三個指標有不同分母：candidate-pooled class accuracy、逐 case/β oracle 選樣後 class accuracy，以及候選兩兩 frame disagreement；不可折成共同 success 或把 Top-1 當部署模型選出的最佳預測。

版本與身份

固定 010bad63c802e1666f64943dd098f3ac7be13118（2025-05-29），晚於ECCV 2024。readme所稱 precomputed_<dataset> 命名與實際 predict_precomp_bf_prob.sh 不同。論文對Breakfast/Assembly用50 DDIM steps，50Salads用10；不能把兩個已讀指令碼的50套全資料集。paper p.14 明指ANTICIPATR協定不同，不應與P240數值直接合併。僅讀核心區段及小型split/label來源，未跑模型或載入pickle／大資產。

arXiv:2407.11954v1（2024-07-16），Olga Zatsarynna、Emad Bahrami、Yazan Abu Farha、Gianpiero Francesca、Juergen Gall；PDF p.1 直接給 olga-zats/GTDA，README 引同一 ECCV 2024 論文。GTD 是 stochastic diffusion、GTAN 是其 deterministic backbone；同 repo 兩個模式不增加獨立來源數。

領域
方法／綜述參考，未另作來源用途歸納。
環境
離線烹飪（Breakfast、50 Salads）及玩具車組裝／拆解（Assembly101）。Assembly CSV 含固定 RGB 相機與頭戴 HMC view，程式按存在的 numpy feature 過濾，沒有隻選 Ego view 的條件；視角欄位必須留在 case，不能把所有來源標第一人稱。
任務
以 α=0.2/0.3 的觀測預測 β=0.1/0.2/0.3/0.5 的逐格動作標籤。Breakfast mapping=48類含 SIL；50Salads mapping=19類（17動作+action_start/action_end）；Assembly 使用 coarse action_cls/action_id，附帶 actions.csv 有202類，不是全部細粒度 action 組合。每訓練 video/view 衍生 α=.2/.3/.5 的3個 observation case，另有40%機率改為 .15+.25U；這些不是3支新增影片。
題數與資料
Breakfast/50s 為 D×T 的 .npy、逐行 label .txt、mapping.txt、split bundle。sample 回傳 features、classes、classes_all、classes_one_hot、mask_past、mask_future、vid_len、file_name；feature 只取 [:int(αT)] 並 [::sample_rate]，collate 在未來／padding補零，label padding=C+1。--part_obs 將 prediction span設為全影片的 .5，所需長度仍源自完整 GT T。Assembly CSV 為 video_id,view,action_type,video_start_frame,video_end_frame；coarse_labels/{action_type}_{video_id}.txt 每行 tab 分隔 start,end,label（尾空欄依實作），依 end-start 展開，程式註明 @30fps；TSM_features/{video_id}/{view}/features.npy 用 [start:end] 裁切。feature缺檔、空segment或無長度會跳過，lmdb分支未實作。固定 split4 bundle 1136 train／576 test unique video keys，無交集；這是名單數。Assembly train/val CSV 4684/1424列、204/61個 video_id，各16種view；尚非有效執行case數。儲存預測 pickle 以 action_type_video_id_view 或 Breakfast file_name 為key，值為K組復原逐格預測，gt_ 字首是全長GT。
評估方式
線上 validate 強制 batch_size=1，stochastic 用 EMA 產生 K=25 候選；Breakfast示例 sample_rate=3，Assembly=6，預測每個取樣位置重複該倍數回原格。對 [int(αT):int((α+β)T)] 計 n_T/n_F。Mean MoC 先把所有影片、全部K候選的每GT類別正誤格數相加，再對有GT的類別平均 T/(T+F)，輸出0..1；不是每影片MoC的平均。Max/Top-1 MoC 對每影片及每β依GT挑該範圍MoC最高的一個候選，累積其類別計數後再宏平均，同影片不同β可選不同候選。precomputed Frame Diversity 對每case取 K(K-1)/2 配對的 [1-相同frame數/該future窗長] 平均，再等權平均case。完整K=25對應300配對；test_num_samples 預設1會除零，不能沿用其預設。eval_file 另算 normalized segment Levenshtein error，但目前 MoC caller 丟棄該回傳，不能當正式主指標。程式把 x_0 GT傳到 predict，但底層只用 zeros_like取得形狀，生成值起於高斯噪聲；仍依賴GT長度，與GT action值洩漏需分辨。

怎麼接入我們的benchmark

可重用

原生 mapping、split與view身份、coarse-to-frame規則、TP/FN累積、候選pickle結構及Frame Diversity程式。

需要轉換

source 記paper/repo/data-feature revision，domain/environment依烹飪或組裝與view分類；task區分deterministic GTAN／stochastic GTD；case=(dataset revision,fold或train/val,video,action_type,view,α,β)，candidate_index屬case內試樣。保留annotation frame reference、sample_rate、GT-length protocol、K、EMA/checkpoint、diffusion T/D；evaluator標明Mean MoC／oracle Top-1 MoC／pairwise diversity各自分母與0..1尺度，不能直接對齊P236的百分比或P240的mAP。

仍需補齊

固定TSM/I3D及Assembly coarse annotation版本、實際feature存在清單，驗證start/end與view長度裁切。線上stochastic分支沒有累加frame error/num_frames卻仍輸出Acc，會得到0/0，應列為無效欄位。precomputed讀取硬編碼 /home/user/diff_results/final，與writer的 ./diff_results 不同；predict_precomp_bf_prob.sh未傳mapping_file；Assembly的main_diff_evaluate把actions_dict設空，eval_file會以零長類別陣列索引，須修復後才能重評。固定test_num_samples>=2並檢查候選數／長度、有效GT窗；原程式min(pred_len,GT_len)可能縮短評測分母。尚未閉合50Salads的示例指令碼／checkpoints與完整跨fold聚合。

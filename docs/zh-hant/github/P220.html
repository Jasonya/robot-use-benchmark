P220 · VISTA（Ego4D STA）

VISTA: Technical Report for the Ego4D Short-Term Object Interaction Anticipation at EgoVis 2026

返回逐篇總表核心內容已核讀 方法／綜述參考原作 ↗

核讀快照 2026-10-11。已讀範圍限所列片段；本輪未執行上游程式。

已核讀精確VISTA repo的STA reader、split設定、submission序列化與具體Top-5 mAP程式。公開train設定使用train+大部分val，僅24個holdout且每次只跑1個batch的proxy；最終ensemble預設version 2.0，庫內scorer卻只接受1.0，整合時須顯式處理。

版本與身份

讀取commit 62e39d137426e12f30fe4efd12122f8c188b4b33。初始prediction writer回傳version 1.0；dynamic_metric_head_ensemble與包裝shell預設最終version 2.0，而本地validate_results_json拒絕非1.0。ensemble/proxy使用無+1的連續IoU，scorer使用+1畫素IoU；ensemble的IoU匹配可含0.5，scorer嚴格>0.5；論文寫TTC<0.25，程式為≤。README的scaffold稱呼不代表只有README，亦不代表已完整重現官方submission。

arXiv:2605.20901v1，Qiaohui Chu等人的 VISTA: Technical Report for the Ego4D Short-Term Object Interaction Anticipation at EgoVis 2026，PDF第1頁直接指向CorrineQiu/VISTA；README與8張2FPS影片、Faster R-CNN still branch、四prediction heads相符。不是其他同名VISTA專案，也不是FROST-STA。

領域
方法／綜述參考，未另作來源用途歸納。
環境
Ego4D v2人類第一人稱影片之STA query；資料被預先拆成train／val／test_unannotated sample directories，每例含短片歷史影格與最後高解析影格。沒有robot rollout或simulation場景。
任務
預測每個query下一互動的active-object box、noun、verb、TTC及score；一例可有多個GT物件。類別不是固定新任務清單：build_label_maps_from_roots掃train+val中有效noun/verb ID，排序重編成連續index，輸出時再還原；須保留mapping與母資料taxonomy版本。
題數與資料
reader掃排序後的label.json，讀uid、split、video_uid、frame、observation.history_frames[*].file與last_history_frame_highres_file；GT優先future_prediction_target.objects，fallback raw_annotation.objects，讀box_xyxy/box/bbox、noun_category_id/noun_id、verb_category_id/verb_id、time_to_contact/ttc。train/val排除空標註與所有框無效的樣本；test仍需label.json但不要求GT。history_frames保留既有順序，超過8取最後8，不足8以前端第一張補齊，並不在reader內由fps重建時間戳。論文/設定為8張2FPS、影片384×384；still short-side train640–800、eval800，max1333。框隨影像縮放，dump依orig_size還原xyxy畫素，TTC秒不縮放；可改讀split/uid.pt的1664維JEPA cache。train_include_val=true時以有效樣本排序後前24個作holdout，其餘val併train，並非take-disjoint的新split。
評估方式
run_official_metric_only.py是真正本地scorer：以uid對齊，CLI要求所有GT uid都有results（可空list）；無GT物件的query不入評分。IoU面積使用(x2-x1+1)(y2-y1+1)，框須IoU>0.5，TTC條件為絕對誤差≤0.25秒。每query按score貪婪一對一匹配各metric的GT；Top-5不是截前5，而是每個metric忽略排序前4×該query GT數的FP。Noun／Noun+Verb／Noun+TTC／Overall皆按noun類別分組：recall分母是全評測集中該noun的GT物件數，AP以precision envelope對recall積分乘100，再只對出現GT的noun做macro平均。compute_proxy_hits則只查score前5，只要任一GT匹配就給該query一個hit，分母為batch中有GT的query；eval.py以batch size加權再跨rank平均，與mAP不同。預設train max_val_batches=1、run_official=false、best_metric_source=proxy；test設定只產生每head最多100個hypotheses，四headensemble再保留100。論文5.40為test server結果，本輪未重跑或證明本地Lite實作與server完全等價。

怎麼接入我們的benchmark

可重用

重用STASampleDirItem及label.json reader、noun/verb雙向map、UID submission schema、具體STAMeanAveragePrecisionLite與head ensemble引數，保留其來源commit。

需要轉換

case鍵為Ego4D版本+split+uid，video_uid/frame另存；框保留原影像畫素xyxy、orig_size與resize比例，時間以TTC秒與實際history-frame序列描述。evaluator分開記proxy query-hit與noun-macro Top-5 mAP，儲存FP-budget=4×GT、IoU+1、比較邊界與head/top100預算。

仍需補齊

原始影片至sample label.json的可驗證製作流程、實際manifest/hash與frame時間戳仍需補齊；未取得資料、features、weights，無法報有效case總數。需固定24個holdout身份並按完整benchmark split評分；須對齊ensemble version 2.0與scorer要求1.0、以邊界例核驗本地scorer/server差異，不能只改字串便宣稱等價。

Real Garment Benchmark (RGBench): A Comprehensive Benchmark for Robotic Garment Manipulation featuring a High-Fidelity Scalable Simulator

返回逐篇總表核心內容已核讀 benchmark／資料／評測主來源原作 ↗ 用途與原生規模依據

核讀快照 2026-10-11。已讀範圍限所列片段；本輪未執行上游程式。

這是服裝模擬fidelity評測，不是學習policy的task-success榜。已核讀98-capture registry、processed CSV／PCD reader、PyBullet fixed-point回放、具體Chamfer／stability計算與兩階段聚合；GarmentDynamics本體仍只有外部import插槽及已發布baseline數字。

版本與身份

固定2026-07-30的5cc3d072。公開來源是evaluation harness加asset子集，不能將paper『Ours／mujoco_style3d』baseline當成此repo可跑的普通MuJoCo。比較指令碼掃描所有timestamp run且aggregate時丟robot、按garment/action/simulator/mode平均，重複sample會被重複加權。n_samples亦非處處3。現有cloth params依GarmentDynamics擬合，跨sim使用須保留校準協定。未下載6.7GB資料、checkpoint或執行sim。

arXiv:2511.06434v2（2025-11-12）首頁 → rgbench.github.io → hwk0809/RGBench；README的AAAI2026題名與作者相符。網站模板eliahuhorwitz/Academic-project-page-template與Nerfies不算benchmark來源。

領域
衣物與洗護
環境
真實雙臂衣物操弄capture與同一動作的cloth simulator配對。公開資料檔案列Piper／RealSense D455，固定PDF則描述Piper或JAKA K1／RealSense L515，應儲存各版本capture硬體證據。fixed_point以錄製末端位置驅動mesh anchors；robot mode包含robot tracking/contact。所讀PyBullet wrapper在grasp/fold讀取position並把grabber orientation固定identity，不能直接宣稱完整6DoF姿態精確重放。普通MuJoCo僅fixed_point；GarmentDynamics不等於普通MuJoCo wrapper。
任務
Grasp、Fling、Fold三種原生動作；native case key=(garment,action,robot,sample_id)。靜態解析完整experiment_library得到9 garment keys、98 entries、98個不重複data_subfolder。baseline CSV有105行：fixed_point三動作各21行，robot的fold/grasp各21行，缺robot-fling的21個cells；runner也明示fling只支援fixed_point。baseline只有7件衣物，grey_sunwear／khaki_blazer的資料仍有但未入baseline。PDF6k+ mesh assets=4k+自有工業assets+2k+ ClothesNet來源，不是6,000個task或capture；mesh解析度variants亦不增加衣物數。
題數與資料
每capture含calibration/world_to_camera_transform.json、兩臂joints/*joint_states_and_end_pose.csv、segment_pcds/pointcloud_<absolute_timestamp>_segmented.pcd；mesh另由HF來源供應。實際load_processed_data要求time、pos_1…pos_gripper，或pos_x/y/z、orn_w/x/y/z；檔案列header.stamp.secs/nsecs及JSON position/name是另一層ROS輸入約定，不可直接餵此reader。pose輸出quaternion=wxyz，base_rotation_quat輸入給SciPy用xyzw，位置以R_base_to_world.apply(local)+translation組合。PCD由camera_to_world=inv(world_to_camera)轉世界座標，timestamp減master_start_time。main逐一遍歷PCD，再用target_time+camera_delay+fling_prepare_time+fling_wait_time推進sim；不是重取樣成共同FPS。保留原seconds、delay、sim step大小、record/calculation windows與point/vertex數。
評估方式
compute_cost輸出單向Chamfer L1 sim→real及real→sim、L2 sim→real、雙方向one-sided Hausdorff、sim_stability_score及兩點雲平均z差絕對值。Chamfer L1是每source point找Manhattan nearest distance後平均；L2用Euclidean距離而非平方距離，單位維持m。CPU/GPU對Nx3路徑同義，但batch輸入CPU只取[0]、GPU平均batch，不能未驗證就擴成batched evaluator。stability實際將同一frame vertices[1:-1]與相鄰vertex-index三點均值作L2偏差，再除總vertex數N，並非跨時間穩定性。HD委派point-cloud-utils且未傳norm，PDF公式卻寫L1；pyproject只限>=0.30，本輪未鎖定/核讀該依賴版本的HD實作，norm一致性列為缺件。record window決定計算哪些frame，calculation window再按sim_time取mean/std；benchmark primary fidelity metric為cd_l1_r2s。空sim mesh frame會跳過，低於z門檻的vertices函式只警告仍原樣返回。這些誤差不能轉成操作success率。

怎麼接入我們的benchmark

可重用

98個capture registry／每case時間窗、world calibration、CSV pose與PCD reader、BaseEnvWrapper到具體sim stepping、方向性Chamfer與result schema。

需要轉換

source分capture dataset、工業asset subset、ClothesNet重用與code commit；environment儲存sim engine/version/mode、robot／sensor、mesh/material；task記動作primitive；case用capture key，simulator/mode/mesh resolution是trial條件。evaluator分direction/norm/unit、raw frame errors、window mean/std及跨sample mean。儲存case frame coverage、camera delay與calibration SHA；不要把105列baseline或不同sim run倍增case。raw ROS→processed CSV明示轉換，保持wxyz/xyzw與base-transform方向。

仍需補齊

HF capture／mesh與校準檔的實際revision及完整性驗證；GarmentDynamics本體、完整工業library與不同component條款；HD norm／依賴pin；spatial vertex-order stability的指標命名或實作釐清；資料檔案與processed CSV／capture硬體版本對齊；重跑sample去重、mean/std尾列存在性與跳過frame的coverage檢查。

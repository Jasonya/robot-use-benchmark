SoftVTBench: A Deformation-Aware Visuo-Tactile Dataset and Benchmark for Deformable-Object Manipulation

返回逐篇總表核心內容已核讀 benchmark／資料／評測主來源原作 ↗ 用途與原生規模依據

核讀快照 2026-10-11。已讀範圍限所列片段；本輪未執行上游程式。

核讀的是舊v0.1的四suite task/config、HDF5 reader、具體goal checker、FEM Kabsch變形計算、per-object calibration及正式softvtbench_metrics。它與收錄論文的資料規模、asset清單及90th-percentile門檻不同，且runtime停用了drop termination；本筆是有版本限制的程式核讀，不代表已重現4,000示範版DSR。

版本與身份

固定58056111f（2026-07-22）。repo身分由PDF明鏈與相同作者確認，但README的2607.04234、1,628/33、pi05-only、半最大值calibration都屬舊版；PDF為2608.18701、4,000/50+、Diffusion/π0.5/FastWAM、90th-percentile。另有README NoDrop敘述與正式code不一致，以及deprecated global-threshold scorer，全部分開記錄。未執行任何模擬或上游模型。

arXiv:2608.18701v1 第1頁直接連至此repo，作者與README的Bowen Jing、Mingxin Wang等一致，故為第一方來源。但2026-07-22固定commit的README／專案頁仍連2607.04234並使用Safety-Aware舊題名；不能據此改寫收錄PDF身分或當作新paper版本已完整發布。

領域
通用物件與機動作業、餐飲與烹飪
環境
Isaac Sim／Isaac Lab，Franka Panda及雙指GelSight Mini，FEM deformable物件、剛性對照與tactile proxy；與Tabero／LIBERO有重用關係。task JSON分fixtures、objects、regions、robot_base_pos／wxyz orientation、obj_of_interest與tactile_targets，soft／rigid twin及場景variation要各自保留，不將舊LIBERO BDDL檔名當作當前soft task身分。
任務
Object-Soft、Spatial-Soft、Object-Rigid、Spatial-Rigid是2×2 matched suites，核心為pick-and-place。收錄論文每suite10 tasks／1,000 demos，另500 ID evaluation episodes／suite（50/task），soft suites各9種單因子OOD條件、每suite/config合計900 OOD trials。程式的generic softvtbench_tasks.json另列libero_10/spatial/object/goal各0–9，不能直接當四個soft/rigid suite mapping。實查object_soft config有10 tasks；task0為取white swirled soft pastry放basket，其asset soft_pastry001與舊alphabet_soup BDDL並存。
題數與資料
PDF宣稱4,000 demonstrations、50+ assets；README舊v0.1是1,628 demonstrations（500/500/421/207）與33 assets，均非本輪實際下載數。20 Hz同步第三人稱／腕部RGB、左右tactile RGB/marker motion、proprioception、language及binary/continuous gripper；FEM為evaluator-only。所讀HDF5使用data/demo_*、actions、obs/eef_pose（xyz+wxyz）、obs/gripper_pos、states/deformable_object/<asset>/nodal_pos_w與soft_extras。assembly保留original_demo_id並按(task_id,demo_id)去重；缺success attr預設True，匯入需額外驗證。7D converter以xyz+axis-angle+單指gripper為state，接受7D或legacy8D action，13D force-in-action需另一converter；較短影片路徑有隨機drop state/action再切video的分支，不能宣稱與PDF『無重取樣』完全一致。模型7D、legacy8D、13D及server padded32D不可混為一種action space。
評估方式
goal checker逐個goals合取xy距離與(|Δz|−height_diff)<height_threshold；IN/ON尚共用此公式，force條件只在enable_force_threshold='True'且sensor存在時啟用。task0閾值xy=0.2、height=0.2、force=0.05（原生模擬尺度），soft asset建置會跳過該rigid contact sensor。client預設30次推論×10動作、8連續success steps；但正式JSONL scorer取最後success_now，須核對其與experiment_success一致，且成功／terminated會在debug記錄前break。FEM正式metric_id=fem_rms_rigid_aligned_bbox_pct_v1，以首個節點狀態作reference，proper Kabsch禁止reflection，D(t)=100×RMS位移／reference bbox diagonal，D_peak=max_t D(t)。程式SafeSuccess=GoalSuccess且D_peak≤tau，未另檢NoDrop，harness也停用*_dropped；不能宣稱符合PDF的drop即停。舊calibrator用0.5×max stable peak；例如soft_pastry001 tau=0.44692%，PDF表9的90th-percentile tau為7.6%，差異不是單純改名。正式scorer重算HDF5 nodes、檢JSONL metric ID；goal rate分母是已知goal episodes，safe rate分母是全部episodes，未知safety保留n_safe_unknown且不算safe。strict通過且分母一致前，goal_safe_gap不具有PDF TSR−DSR的精確語義。rigid診斷可令safe=goal，公表仍應保留N/A／適用性。

怎麼接入我們的benchmark

可重用

具體task/config、native HDF5與影片索引、policy/evaluator通道分離、Kabsch FEM公式、per-asset門檻及explicit metric ID。

需要轉換

source綁PDF v1與程式v0.1兩個版本；environment記solver／scene／tactile assets；task以suite+native task_id+asset identity建立；case分demo、ID trial、OOD trial並儲存paired seed／initial state。evaluator保留TSR/DSR與程式Goal/Safe label的版本關係，另記tau生成方法、reference nodes、百分比尺度、成功horizon及drop規則。domain依實際pick/place用途對映。附加force的squeeze=2min(|fLz|,|fRz|)，applied-force z扣除成對squeeze，*_max是非零Top5%均值，不映成物理peak。

仍需補齊

對應2608.18701的4,000版release／split manifest、90th-percentile calibration與rescorer、soft_stw_cuboid_hq等新版asset對照；drop termination及300-step協定閉合；terminal debug／sustained goal的對齊；資料與USD／Tabero tactile runtime資產取得驗證；原生HDF5 success型別、跨root重複JSONL/HDF5及影片時間對齊。

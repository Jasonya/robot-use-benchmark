P232 · Diff-IP2D

Diff-IP2D: Diffusion-Based Hand-Object Interaction Prediction on Egocentric Videos

返回逐篇總表核心內容已核讀 方法／綜述參考原作 ↗

核讀快照 2026-10-11。已讀範圍限所列片段；本輪未執行上游程式。

Diff-IP2D 重用 OCT／EPIC 的軌跡與接觸標註，但實際軌跡入口評的是 WDE／FDE。逐段追到 runtime caller 後，已把它和 repo 內沿用但未在該路徑呼叫的 OCT evaluator 分開；不能只看檔名就判斷評估方式。

版本與身份

原生程式 import 了 evaluate_traj_stochastic，但所讀實際軌跡路徑使用 compute_wde／compute_fde；OCT wrapper 的名稱對調不能直接套到此主結果。固定版本的來源差異均保留。

領域
方法／綜述參考，未另作來源用途歸納。
環境
來源影片與人工評測 labels 重用 EPIC-KITCHENS／OCT；論文也包含其他 Ego 資料實驗，README 的當前完整部署僅 EK100，EK55／EG 發布仍列待補。
任務
未來 2D 雙手 waypoint 與 object affordance/contact hotspot；典型 10 個過去 token→4 future 點。改 diffusion 架構不是新增語義任務，沿用 label 要連回 OCT 父來源。
題數與資料
features／bbox／有效性、uid／raw frame 與 homography 均有原生欄位。training loader 會加 future features，evaluation loader 不加；manual-merged annotations 不等同 OCT 原始 annotation folder。各外部檔案與 checkpoint 要固定 hash／split，不能只記 repo commit。
評估方式
主迴圈將預測轉 numpy 後呼叫 compute_wde：4 未來點權重 0.25／0.5／0.75／1.0，求和未除以權重總和；FDE 為末點，normalized image 單位。tensor 分支反而為普通平均，但不是此路徑。輸出先按 batch 的有效手平均，再跨抽樣／batch／rank 平均，與全資料有效手池化不同。heatmap SIM/AUC-J/NSS 沿用 OCT，仍需按 uid 配對、NaN 分母明示；原始 metrics rank equal-average 也要保留。

怎麼接入我們的benchmark

可重用

重用 OCT lineage、native labels／split、真正在主迴圈呼叫的 WDE／FDE 與熱圖 evaluator。；保留 full／fast diffusion 與 sample_times，不能將 10 次抽樣當 10 道題。

需要轉換

source 同時記 paper version、code commit、data archive hash；canonical case 禁止 training-only future features 出現在評測輸入。；原生 WDE、FDE、heatmap 各列公式和有效分母；若改為 sample-weighted global mean，需新增 evaluator 版本。；以父 participant/video/time 去重；EPIC55/100、OCT／Diff-IP2D 保留 overlap 關係。

仍需補齊

未下載 weights／features 或執行，README checkpoint links 與其他資料部署仍需逐一取得。；已有函式不等於已有完整測試任務，case metadata 與 raw video 許可權尚未整合。

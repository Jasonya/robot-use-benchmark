P082 · RoboVerse

RoboVerse: Towards a Unified Platform, Dataset and Benchmark for Scalable and Generalizable Robot Learning

返回逐篇總表核心內容已核讀 benchmark／資料／評測主來源原作 ↗ 用途與原生規模依據

核讀快照 2026-10-11。已讀範圍限所列片段；本輪未執行上游程式。

RoboVerse官方repo已確認，但2026固定commit的MetaSim、trajectory reader與generalization level均有版本變化。已閉合maniskill.pick_cube config-port的初態→PositionShiftChecker→IL SuccessOnce聚合，另讀Zarr產生／載入鏈。發現NaN可令整批checker成功、L2/L3與paper定義錯位，以及trial尾批／normalizer切分問題。

版本與身份

固定RoboVerseOrg/RoboVerse@5f3ec0185d2d3bcb59d53b0bd1f5b0f8a6f2ce14（2026-09-08），對應paper 2504.18904v1（2025-04-26）的官方延續repo，而非paper原始實驗pin。README如今把MetaSim與RoboVerse分成同tag發行的兩套package；trajectory v2/v3、native/config ports與generalization protocol各自記版本。舊usage的RandomizationCfg不可直接作現行DRConfig schema；本輪只選讀所列task／data／evaluator。

固定paper為Geng等人的RoboVerse: Towards a Unified Platform, Dataset and Benchmark for Scalable and Generalizable Robot Learning，arXiv:2504.18904v1（2025-04-26）。PDF指roboverseorg.github.io，README 134–141題名、作者與arXiv一致，確認RoboVerseOrg/RoboVerse為官方平臺。本文不等於較早同名RoboVerse環境，也不把整合的RLBench、ManiSkill、LIBERO、ARNOLD等資料算成新獨立來源。

領域
居家整理與清潔、衣物與洗護、裝配與生產作業、通用物件與機動作業
環境
平臺把task/robot/scene內容放roboverse_pack，模擬核心在packages/metasim/metasim。已讀範例是Franka提起4cm紅cube，ScenarioCfg與runtime backend共同決定物理／相機／控制時間；不能賦予全平臺單一FPS。eval建立camera0的256×256 RGB/depth並依task選pose。此maniskill.pick_cube是跨simulator config port，該基類檔案明分它與*_native/SAPIEN3 official-demo port；未獨立驗證任何跨引擎parity。
任務
pick_cube alias與maniskill.pick_cube共用一個task，目標cube比reset初態沿z移動>=0.1m，最大250原生步；不要求抓持或放置。traj_filepath指roboverse_data/trajs/maniskill/pick_cube/v2/franka_v2.pkl.gz，下載helper在constructor被呼叫，本輪未執行。全平臺registry條目、object variants、來源task、demo與benchmark trial必須分開；本輪未聲稱現行registry總數等於paper task數。
題數與資料
legacy v2內容為{robot_name:[{init_state,actions,states?},...]}，init/state是entity→pos/rot/dof_pos；actions支援dof_pos_target/dof_vel_target/dof_effort_target。v3轉換只是把state分objects/robots、action包上robot名稱；缺states仍可回初態+actions，但不能做state-anchored replay。現行get_traj按內容辨識、拒v1，遇roboverse.episode會要求load_episode另一API，不能只改副檔名。TensorState儲存objects/robots/cameras；root/body state為[pos,quat,lin_vel,ang_vel]13維，joint資料與body_names需繫結，部分backend欄位可None。另一路data2zarr讀demo_NNNN/metadata.json及各camera.mp4（head_camera可退到rgb.mp4），用joint_qpos、joint_qpos_target或robot_root_state/robot_ee_state(_target)生成state/action；EE為robot-local xyz+wxyz+兩指共9D，delta_ee另有相對quat。輸出data/{camera,state,action}與meta/episode_ends，保留downsample/padding/action-space設定。RobotImageDataset從Zarr抽episode內sequence、相機值除255。未取得外部traj、MP4或Zarr，case數應依實際episode_ends／檔案manifest，而非metadata要求處理的num_episodes。
評估方式
DefaultRunner.evaluate→get_task_class→ManiskillBaseTask→get_traj(v2→v3)→env.reset/checker.reset→BaseTaskEnv.step→handler.set_dof_targets/simulate/get_states→_terminated→PositionShiftChecker.check→util.get_pos。正常checker以reset差值z>=0.1m且總位移<=100m回bool，base reward仍為0，timeout另回。runner每個outer step執行joint action一次、EE action兩次，僅讀最後一次success；SuccessOnce是outer steps上的OR，SuccessEnd是末步，TimeOut只累積不停止個別env；全batch曾成功或max_step耗盡才退出。final_stats為SuccessOnce成功數/總完成數，並儲存demo索引、DR level/mode/seed。選取demo靠task_id_range_low/high及max_demo，並沒有自動套用paper90/10索引。現行DRManager確為L1 scene+material、L2加light、L3加camera，與paper／舊usage檔案的L2 camera、L3 light/reflection不能同名比較。

怎麼接入我們的benchmark

可重用

官方native task ID／aliases、ScenarioCfg、typed state/action、v2 parser和v3轉換、metadata→Zarr鏈、具體checker及SuccessOnce/End結果。

需要轉換

source保留paper v1與2026 code snapshot；task標config_port或native_port並連回ManiSkill等上游。case儲存robot、task、原demo index、asset/初態hash、backend、控制步長及DR實際factor，不只存level數字。明分v2磁碟trajectory、v3記憶體state、roboverse.episode與IL Zarr四種介面；保留joint名稱／單位、wxyz、camera座標及EE local/delta語義。

仍需補齊

PositionShiftChecker 219–221只要cur_pos任何元素NaN就回整批True，沿此task鏈會被SuccessOnce計成功，需先修補並標版本。尾批demo_end_idx只截到num_demos、不截到要求的low+max_demos，SuccessOnce分母固定num_envs，需核對超額或不滿批處理。RobotImageDataset normalizer.fit吃全buffer而非train mask；get_validation_dataset取downsample後train_mask的補集，可能把未選訓練episodes納入val，需固定真正paper split。尚缺2025實驗commit/資產/90-10 case清單及舊L2/L3到現行factor對照；v1資料已明示不支援。

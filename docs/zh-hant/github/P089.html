SpeedFolding: Learning Efficient Bimanual Folding of Garments

返回逐篇總表核心內容已核讀 benchmark／資料／評測主來源原作 ↗ 用途與原生規模依據

核讀快照 2026-10-11。已讀範圍限所列片段；本輪未執行上游程式。

已核讀 SpeedFolding 的真機流程、SQLite/PNG 格式、BiMaMa 資料 reader、摺線指令與具體 coverage reward。evaluation.py 只記錄事件／時間，folded 事件也不是獨立成功判定；論文摺衣成功須保留三位人類評閱者多數決。公開版本另有 reader／writer 介面不一致。

版本與身份

固定2023-12-11 commit，晚於2022論文；README已明示硬體相依參考程式。未連線資料庫、相機或YuMi，未下載15.2GB資料集或執行模型。

README直接連結 arXiv:2208.10552 與 pantor 官方專案頁，明示 IROS 2022／ABB YuMi＋PhoXi 的硬體相依參考實作。

領域
衣物與洗護
環境
實體ABB YuMi雙臂平行夾爪、海綿工作面、PhoXi頂視灰階／深度，以及額外webcam coverage。軟體包含OMPL與PhoXi C++ wrappers，README明示不易直接執行。pixel_to_transform從校正point cloud取xyz、以theta設定gripper姿態；影像位姿不能直接當已校正機器人動作。
任務
流程是先平整衣物，再依使用者摺線／2-second heuristic／fling-to-fold完成摺衣。shirt.json有兩種順序、每種三條摺線，屬同一目標的候選程式，不是6個任務。loader的fling、fling-to-fold、pick-and-hold、drag、done為訓練primitive類別。論文每組實驗15 trials，4300訓練action records含1500複製重標；不能把records、物理操作、完整摺衣trial及任務名稱混算。
題數與資料
SQLite actions(id,episode_id,action_id,data JSON)與images(episode_id,action_id,scene,camera,hash)；PNG路徑為collection/episode_id/{action_id}-{scene}-{camera}.png，scene含before/after，camera可為color/depth/ortho-color/ortho-depth。JSON儲存type、poses[{x,y,theta}]、reward、needs_annotation、is_human_annotated、is_self_supervised。Saver把0.85–1.25m深度反向線性對映0–255並裁切，0深度先改1.25m，不能把PNG值當公尺。BiFoldingDataset讀灰階與量化深度兩通道，按1032×772來源尺寸crop後resize到256×192、theta為弧度及20個離散方向。預設以episode_id的SHA256低16bit閾值做約80/20 train/test，非衣物物件切分；run.py每個action新建Episode，因此該ID未必代表整個物理trial。
評估方式
reward.segment以灰階閾值90、形態學與最大輪廓產生mask；calculate_reward為tanh(64×A_before×(A_after−A_before))，A為mask畫素佔比。另一個coverage＋confidence reward函式存在，但run.py呼叫前者。Experiment.take_coverage用校正webcam、閾值130並回傳輪廓面積/影像面積。done是模型分類的Sufficiently Smoothed停止決策；執行摺線後直接記folded事件，不代表成品合格。Evaluation記相對啟動秒數及profile duration，未實作三人投票或完整FPH。論文成功要求10動作內且三位評閱者多數通過，排除motion-planning早退；表I duration只平均成功trial，cycle time/FPH包含成功與失敗。程式CLI horizon預設3，README實驗設10；run.py horizon限制平整迴圈，後續摺線及move另外執行，須明訂共同action budget。

怎麼接入我們的benchmark

可重用

摺線JSON＋template、影像／action DB索引、primitive執行脈絡、coverage reward及事件計時。

需要轉換

source綁commit；environment綁YuMi工作站與相機校正；task綁衣物與摺執行緒序；case新增完整trial_id、garment_id與初態，連到多個action record；evaluator分smoothing confidence、grasp failure、coverage、成品人評與duration/cycle/FPH，明列排除及分母。重標記錄保留來源action關係，量化depth需用尺度／缺測mask解碼。

仍需補齊

人評票決與完整trial成品影像／耗時表；去除重標後的資料lineage及物理trial切分；公開reader/writer相容性修正；硬體／template／weights資產與校正接線。

P012 · HD-EPIC

HD-EPIC: A Highly-Detailed Egocentric Video Dataset

返回逐篇總表核心內容已核讀 benchmark／資料／評測主來源原作 ↗ 用途與原生規模依據

核讀快照 2026-10-10。已讀範圍限所列片段；本輪未執行上游程式。

HD-EPIC 的標註包含動作、物件移動、凝視、食譜／營養與音訊；VQA 原始 schema 支援多影片／片段。已追到主程式實際使用的 BaseVLM 與 LlavaVideo 評分，而非把舊單影片 Dataset 當作全部介面。

版本與身份

固定提交檔案已新增 MP4 對齊的中介 calibration／pose／gaze；不得假定與原論文首發資產同版。檔案明列 mask 與 bbox 由不同團隊標註可能不一致；YouTube 版本只供觀看，不作復現輸入。

vqa-eval README 自述為 HD-EPIC CVPR2025 benchmark 程式，指向官方 annotations；已核對專案名稱和實際資料路徑。

領域
居家整理與清潔、餐飲與烹飪
環境
佩戴 Aria 眼鏡的真實廚房活動及對應 digital twin／fixture。video、participant、capture、fixture、3D 場景的 ID 分開，不把多個感測流計成新環境。
任務
以每個 JSON 的 question prototype 管理五選一 VQA；動作、物件關聯、凝視 priming、食譜和聲音是標註層，各自不自動成為可執行任務。
題數與資料
敘述含 unique_narration_id、秒制 start/end_timestamp、另列 narration_timestamp、多個 verb/noun pairs 與 main_actions；assoc_info 連到 mask_info 的 0-based MP4 frame、XYZ、XYXY bbox、fixture。音訊以 48kHz sample index 標示。VQA 含 inputs/question/choices/correct_idx（0-based），保留多個 input 的 id 與時間窗。
評估方式
主程式呼叫模型 run_eval；核讀 LlavaVideo 的 answer==correct_idx，再由 run_benchmark 對結果平均。BaseVLM 取回覆第一個大寫字母轉選項索引；invalid 回 -1。analyse_output 按 prototype 字首分組，另列 invalid／failure。輸入會按模型 max_video_length_seconds 降取樣，須一併報告 input_total_seconds 與 input_subsampled_seconds。

怎麼接入我們的benchmark

可重用

原始標註層關聯、五選一題目、時間／框 tag 解析、同輸入題目分組及正確率流程。

需要轉換

用原生 question ID 建 case，inputs 保留多影片與框；同一次 capture 的多感測／多題重用同一環境記錄。保留完整毫秒時間和原始座標，另記 native adapter 對時間取整秒、框轉 0–1000 的行為；模式 visual_text／narration 與取樣預算入 evaluator 約定。

仍需補齊

尚未下載數 TB 感測資料、校準／digital twin 或執行模型。各模型 wrapper 的 parsing／API 版本仍需個別驗證；data/vqa_dataset.py 只支援單影片且舊欄位與正式 VQA 不同，不能直接通用。

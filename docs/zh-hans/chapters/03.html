CHAPTER 03 / 14

规模的六个 granularity levels

约 4 分钟·数据快照 2026-09-21设计阶段 Q0
先掌握这三件事
  • Domain、family、task spec、instance、case、trial 分六层报告。
  • v0.4 添加 task–context 与 execution bindings，分开估计覆盖和工程量。
  • 同一任务跨场域、换机体或重跑，不会自动增加全球 G2 数量。
v0.4：任务规模与广度共同验收

完整任务库初始目标为 2,000–3,000 个 G2；任务数与有效覆盖各以最大可比基准至少 2 倍为目标。添加场域、家族、材料与机体的支撑配额。180 个蓝图保留为设计种子，原 100–140 预算属历史方案。

阅读整体设计、配额、架构与 milestones →
Level／单位 定义与去重依据 不能混入
G0 application domain 固定 ontology version／分类深度下的应用节点；与家族交叉分类 能力维度、test suite、场景资产
G1 task family 依明订共同语义／技能结构分组；需 family ontology 和 mapping 规则 对象改色、换领域名称就算新家族
G2 task specification typed goal、指涉规则、operator graph、必要过程、机构／角色／有效性 未审核的 native task IDs 或标题
G3 task instance task spec＋bindings＋物理场景与 agent 实际初态；保存内容与 state hash 仅规划 ID、未加载的 asset 名称
G4 typed evaluation case instance 或来源证据＋输入／观测／介入／预算／label／scoring robot_control 与 video_qa 混成一个能力总题数
G5 evaluation trial 方法／checkpoint 在某 case 的一次运行；policy seed／repeat 与配置 训练示范、环境资产或重复的 case ID

哪些数字另外列

单位 报告内容 本计划目前
B0／B1 情境 blueprint／probe template 180／24，设计而非数据
R-scene／R-object environment、layout、object mesh、material variant 未创建正式资产 manifest
R-source 活动、人物／场地、recording session 未收集；需先分组切分
R-video videos、clips、hours、frames，保留原始单位 实际本计划配对来源 0
R-demo demonstration pairs／robot trajectories 已收集 0
R-label QA、contact、trajectory 等标注；与 G4 链接 题型已设计，实际 labels 未收集
Coverage facets 能力、模块、profile、传感、材料、condition 不直接乘成题数

视频、clips、hours、frames 必须保留原作者的定义；提高 FPS 不会增加语义覆盖。示范 trajectories 是数据资源，模型测试 rollouts 是计算／实验量。168 篇文献是研究依据，不是 168 份训练数据。

如何创建 G2 的共同标准

一个范式 task specification 至少包含：

task_kind
+ typed goal/reference rules
+ normalized goal predicate/operator graph
+ required temporal/process constraints
+ critical role/mechanism/affordance requirements
+ task-level admissibility and termination semantics

需要读取原始 instructions、reset 规则与 runtime evaluator；光看标题、embedding 或相同终态 predicate 不够。例如两个任务都把杯子送到同一区域，但其中一个必须找到「先前使用过的杯子」，它的目标指涉规则已不同。

对象名称可参数化，不代表机构功能可以任意抹除。旋盖、抽屉、可替代工具和固定容器的操作需求，须保留真正影响可解性与成功语义的部分。规则要先冻结，再做独立抽样审核。

改变 通常增加的层级 条件
同义句／改 task 名称 prompt variant 或不增加 保留 native ID，不能当新语义
新对象、颜色、尺寸、位置、折轴参数 G3 若改变关键机构／任务逻辑，再审 G2
添加真正必要的目标／顺序 G2 例如折好后收纳且保持折法
从明确指物改成找历史使用物 G2 可能不同 goal-reference rule 不能被终态 predicate 抹除
换视角、视频、history、介入或预算 G4 重新检查可回答性／可解性
固定物理 case，只改 policy seed G5 没有改变 G3／G4
reset seed 改初态 G3 realization → G4 若 case 定义成分布，另报 distribution case 与 realization
seen 改标成 unseen 本身不增加 相对于特定 training pool 的 membership

跨工作比较的共同要求

论文建议用三张表：semantic breadth（domain／family／spec）、evaluation coverage（instance／typed case／split）、data and compute（来源／示范／标注／trial）。每列都保留原作者 native count 和共同规则下的 canonical count。

尚未范式填 TBD；这次来源中未取得填 NR；不适用填 NA；已确认没有才填 0。目前 48 是我们的作者分组，G2 仍为 TBD，G3–G5 实际数量为 0。

同层数字也要对齐 type、scope、版本与范式方法，才有意义。训练 corpus、整个资源库、公开测试、私有测试、榜单子集要分开。若比较性能，还需一致或明确分层的观测、动作、数据、控制器、适应和时间预算。

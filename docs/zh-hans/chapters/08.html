CHAPTER 08 / 14

评测协定、指针与比较方法

约 8 分钟·数据快照 2026-09-21设计阶段 Q0
先掌握这三件事
  • 终态成功、完集成规成功、配对目标成功分开报告。
  • 恢复要同时列全 episode、扰动施加率与条件式成功。
  • 模型在相同信息、控制、数据和预算下比较。

1. 一个 episode 的共同约定

固定：

  • task family 与 release version；
  • robot profile、action interface、观测；
  • 示范／文字输入 track；
  • 训练、在线适应与推理预算；
  • simulator、资产、控制／物理步进设置；
  • reset seed、初始状态与验证摘要；
  • 成功 predicate、必要过程、时间和干预规则。

兼容的模型在同一评测 contract 下比较。不同机体、输入、oracle 信息与 adaptation regime 分榜。

goal_spec、私有测试答案、精确 evaluator state 和正式测试 seed 不得作为 policy input。公开的任务家族说明与训练案例可以存在，但不等于公开正式测试 instance。

2. 成对目标测试

对同一 task family、同一 initial scene、同一 generalization／disturbance 条件和 seed，创建 A/B 两个有效目标。使用两个示范分别指定 A 和 B。

要求：

  1. 初始可观测状态匹配，不能只靠场景猜答案。
  2. 示范改变时，ground-truth 目标同步改变。
  3. A/B 都可解，而且可以客观区分；若终态可以同时成立，另定互斥要求或换一组目标。
  4. 配对示范的无关因素应匹配或平衡。
  5. 不能让 task filename、public ID、长度或提示模板泄漏目标。

定义：

valid_success(e) =
    required_final_predicates(e)
    AND required_trace_constraints(e)
    AND no_disallowed_intervention(e)
    AND within_declared_budget(e)

pair_success(p) =
    valid_success(p.A) AND valid_success(p.B)
    AND both_outcomes_follow_the_corresponding_demonstration

若评分器还输出另一目标是否成立，应检查两个目标的区分。不要假定 pair success 的 chance level 固定为 25%；它取决于动作空间、目标结构与模型先验。

no_video 对照用来量测先验或场景捷径，不能假装它也获得同样的目标信息。oracle_goal 是诊断上界，不是正式模型排名。

3. 2×2 条件与变化类型

Seen-Clean：已见实例，无扰动
Unseen-Clean：未见实例，无扰动
Seen-Disturbed：已见实例，运行中扰动
Unseen-Disturbed：未见实例，运行中扰动

「未见」依 track 具体定义为 object identity、geometry、material parameter 或合法功能替代；不得在不同方法间改定义。每个条件内包含多个真实有效的变化实例，不以重复 seed 冒充新物体。

材料子研究需记录可比几何、摩擦、质量／密度、弯曲与拉伸参数、参数取值依据和 simulator 适用范围。若没有校准物理材料，结论仅能针对「模拟参数变化」。

不要把这四个条件当成必然递增的难度级别；难度需由结果检查。

4. 扰动与恢复：避免分母偏差

主测试在完整 episode 中，在预定的语义 checkpoint 注入扰动。checkpoint 应对合法策略公平；不能只奖励某一种轨迹，或阻挡本来允许的替代解法。

必须记录：

  • 是否到达 checkpoint；
  • 是否真的注入扰动；
  • 触发事件／时间、扰动参数；
  • 扰动后状态是否有效；
  • 最后是否成功、额外时间／动作数。

分开报告：

Full success rate =
    完整成功 episodes / 全部有效起始试验

Trigger delivery rate =
    确实注入扰动 episodes / 全部有效起始试验

Conditional recovery success =
    扰动后完整成功 episodes / 确实注入且状态有效的扰动 episodes

最后一个量受模型能否到达 checkpoint 影响，不能单独拿来排序整体能力。未能到达 checkpoint 的模型不应因为少进入难案例而获得更好的总榜分数。

若合法策略完成了任务却没有经过触发点，应修正触发定义或将它标为未施加介入的试验；不可把它宣称为恢复成功。

可以另外创建固定失败快照诊断集，让模型从同一组状态与同一个可用历史重新规划。该结果标为 snapshot_replanning，不可与 online_recovery 混成一个量。

模拟器故障、无效 reset、evaluator 传感缺失要记录并按预定规则处理。模型 crash、超时、控制失败通常是方法结果，不应为了提高分数而丢掉。所有排除事件及数量都要公开。

5. 真正完成与表面完成

每个 task family 须有：

  • 成功解及至少一种合法替代解；
  • 部分完成反例；
  • 错物体／错位置反例；
  • 必要过程未完成但终态看似正确的反例；
  • 过渡性成功但最终不稳定的反例；
  • evaluator 无法可靠量测时的处理规则。

布料折叠不能只用面积或紧密度；至少检查指定折法对应的拓扑／边缘关系、几何与最后位置。具体量测方法与容差在物理 backend、资产与独立评分样本上校准，再冻结。

过程约束只包含用户任务真的需要的事件。不能为了让题目变难而要求逐帧模仿示范，除非 track 明确评测轨迹模仿。

6. 聚合与不确定性

先在固定 case 的重跑内平均，再按 instance／spec／family 和场域的预先公布权重聚合。场域与家族交叉时须明确分配权重，不能让同一家族只因跨场域重复出现便无限制加权。成对目标和同一来源／对象／变化 instance 的关联要保留。

报告内容：

  • full valid success、pair success；
  • 四个条件的成功率；
  • 每个领域与变化类型的分布；
  • trigger delivery 和 conditional recovery；
  • final-only 与 trace-valid 判定差异；
  • 时间、动作、干预与排除试验；
  • 兼容任务覆盖与未支持格子；
  • 不确定性与 trial 数。

模型比较采相同 case 的配对分析。Bootstrap／阶层模型要对应实际抽样单位，避免把同一视频的 clips 或同一物体的 seeds 当成大量独立证据。很少的任务家族只能支撑 pilot 结论。

不先设计一个把正确性、时间、风险等任意加权的「universal intelligence score」。正式排行榜可以有主要成功率，但必须同时显示复盖与分项。

八模块的计分分界

1. 成功的层次

GoalSuccess = required_final_goal_predicates_at_valid_termination
CompliantSuccess =
    GoalSuccess AND required_process_constraints
    AND within_budget AND no_disallowed_intervention

两者同时报告。过程约束只包含任务明订需求，不要求逐帧模仿。SafeVLA-Bench、OopsieVerse和Embodied Agent Interface是相关先例。

平均子目标分数不能代替完整成功：在篮内不表示折法正确；两站都送到不表示必要顺序正确；面板复位不表示程序曾运行。

2. 各模块的计分边界

  • T1：答案、定位、关系与状态分开。
  • T2：记忆答案、证据和干扰曲线；行动成功另列。
  • T3：固定horizon与K。2D／3D、串行、接触和时间分开；有效时间和座标标签是前提。
  • T4：语义计划有效与物理可行分开，用固定executor和oracle诊断。
  • T5：固定机体、输入、动作与数据条件。
  • T6：diagnosis、online recovery和snapshot replanning分开。
  • T7：共同结果、时序、协议、延迟；模拟代理量不当成真实人类满意度。
  • T8：视觉品质、状态一致性与固定adapter下可运行性分开。

剪辑视频不能直接以播放秒数计物理接触时间。轨迹要声明座标、尺度与有效frames；best-of-K不单独证明概率校准。

40 个候选指针在附录 D 逐项列出名称、单位、分母／标签需求、解读限制和来源。这 40 项不是每题都要算，也不应任意加成一个 universal score。

基线与必要对照

路线／控制 主要用途 比较时固定什么
信息对照：无视频、单帧、完整视频、匹配文字 检查模型是否使用任务相关信息，以及场景捷径 信息不足时重审可解性；无视频不是等信息条件
视频／语言理解与规划模型 测 T1–T4 的推理与证据 输入、history、tools、label 与预算
模块式 video → goal／plan → controller 区分上游与控制瓶颈 共用 executor；以 oracle goal／plan／state 分别诊断
直接 visuomotor imitation，如 ACT／Diffusion Policy 创建动作学习参考 示范与训练数据、观测、action interface、训练预算 P130 P138
通用策略／VLA 参考 测开放或受控数据设置下的泛化 checkpoint、外部数据、适应方式、profile 兼容性 P134 P135 P136 P137
记忆／恢复消融 检查 history、diagnosis、replanning 的作用 相同 case、触发、可用历史和计算预算
特权 state／专家／oracle 验证可解性并定位瓶颈 明确标为诊断上界，与一般方法分栏

这是方法路线规划，不是已确认所有 checkpoint 都能读取人类视频或使用同一双臂 controller。M1–M2 要先确认兼容性；不兼容的模型不得暗换输入或控制器后放进同一栏比较。

主实验需要回答的问题

  1. 示范改变时，行为是否跟随 A/B 目标？无视频与单帧可解释多少捷径？
  2. 在分开控制对象、材料、场景、替代与任务组合后，哪些变化造成下降？
  3. GoalSuccess 与 CompliantSuccess 的差距有多大，哪些近失败会被终态判分漏掉？
  4. FullEpisodeSR、TriggerDelivery、ConditionalRecovery 和 snapshot replanning 是否给出不同诊断？
  5. Oracle goal／state／plan 解除哪个瓶颈？上游 QA 好是否真的预测运行好？
  6. 排序对家族／场域权重、样本选择、模型家族和不确定性有多敏感？

这些是假设与分析计划，不预设一定显著。主测试冻结后不应根据模型表现挑题；改判分器时升版本，重跑受影响比较。

CHAPTER 02 / 14

用一个例子理解整套系统

约 3 分钟·数据快照 2026-09-21设计阶段 Q0
先掌握这三件事
  • 文献分类回答「研究测什么」，任务规格回答「机器人要做什么」。
  • 以折毛巾走过家族、任务、实例、测例与一次运行。
  • 问答、预测、规划和物理完成需要不同证据。

以前面的「文献 taxonomy」和「任务 ontology」为例：前者像图书馆的分类，告诉我们研究在测视频理解、预测、操作还是恢复；后者像正式考试的出题规格，定义机器人究竟要做什么、看到什么、怎么判分。

看见很多折衣论文，不代表要按它们占全部文献的比例出题。两篇论文也可能使用同一批视频或同一模拟环境。研究篇数、独立数据量和实际任务量必须分开。

从折毛巾走到一次评测

研究地图文献 taxonomy视频／理解／预测／操作…
出题规格D × F → SC场域 × 家族 → 情境蓝图
具体化Spec → Instance目标、资产、材料与初态
有效评测Case → Trial合法信息、介入、方法运行
可核验结果T1–T8 → Evidence分项指针、轨迹与不确定性
层次 折毛巾例子 这一步多了什么
文献依据 SpeedFolding、UniFolding、GarmentLab 提供任务、物理与量测参考，不表示资产已取得
G0 应用场域 居家 D01／旅宿 D08 任务发生的应用背景
G1 作者定义家族 F21 指定折叠；F22 折叠后收纳 共通的语义结构
B0 情境蓝图 SC-H15：依示范沿指定方向折毛巾 初态、A/B 目标、近失败与验收构想
G2 范式 task spec 指定折法的目标、指涉、必要过程与有效性 需要可审核的正式任务定义；目前 TBD
G3 instance 某个 mesh、材料参数、桌面、实际初态与 robot 有资产、参数与 state hash 的具体实例
G4 case 给头戴示范、固定观测与预算，抓持后施加指定滑脱 一个有合法输入、标签和 evaluator 的测例
G5 trial 某模型在此 case 跑一次 才会产生轨迹、成功／失败、时间与证据

由同一个 instance 可以产生不同的测例：T1 问哪条边对齐、T3 预测下一接触、T4 规划折法、T5 实际折叠、T6 滑脱后恢复。每个模块仍需要自己的数据与答案；不能直接把一个情境乘八就当作八种已完成评测。

三个容易混淆的情况

改颜色或位置通常增加 G3 的实例变化；没有改变任务语义时，不增加 G2。从折好改成折好后存入篮子、而且保持折法可能改变 G2。同一题以五个 policy seeds 重跑只增加 G5；若 seed 改变物理初态，则增加 G3／G4 的 realization。

「折得很紧」、「外形像长方形」、「已在篮子里」都不能单独证明指定折法正确。必须把边缘对应、层／拓扑关系、几何、释放后稳定性与收纳要求分别写清楚。第 09 章有完整案例。

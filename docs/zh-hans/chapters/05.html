CHAPTER 05 / 14

和既有 benchmark 比，哪些可以复用

约 7 分钟·数据快照 2026-09-21设计阶段 Q0
先掌握这三件事
  • 先保留原作者单位，再对齐 domain、task、case 和数据量。
  • 既有任务、资产和评分器可复用，但要重新审核兼容性。
  • 视频到动作、折衣、恢复都有先例，新贡献需要实验支持。
v0.3：主攻规模与覆盖优势

完整任务库初始目标为 2,000–3,000 个范式 G2，并要求至少最大可比基准 2 倍。180 个蓝图是设计种子；原 100–140 情境预算不再代表全库规模。

我们：v0.2 情境种子 12 labels／48 families／180 blueprints G0／G1 authored；B0 G2 TBD；G3–G5 实际 0
我们：v0.3 规模目标 2,000–3,000 个 G2 任务；至少最大可比基准 2 倍 范式任务的研发目标 尚未达成；以共同 ontology、scope、来源去重与验证后的实绩比较

例如 EgoPlan-Bench2 的 Work 大类包含 lab work、blacksmith、mechanic、farmer 等细类，可能横跨我们的工坊、实验室和户外。不能用「12 对 4」宣称广三倍。RoboDojo 的 42 sim 与 18 real 任务未做语义去重前，也不能宣称 60 种独立任务。

上述为先前已核对来源的版本快照，不是本次重新查核的实时榜单。每笔数字的版本、native term、对应尺度、scope 和解读限制完整列在附录 F。

The Imitator Game 多领域示范到运行与功能替代，包含衣物 A/B与多替代配置的动机 不能靠折衣或功能替代本身称新

表中的「设计启发」是研究方向，不是已证明原作没有的功能。没有列出某项能力，也不能当作原作不支持。真正的新颖性仍需具体 task／data／evaluator 审核和 matched experiments。

是否全部用之前的 benchmark 整理就好

可以大量复用，但整理本身只完成文献地图与候选设计。 要成为 benchmark paper，需要让既有资源在共同定义下形成可验证的任务、数据与评测，并用实验证明它回答了有价值的问题。

复用方式 可以沿用 必须补的部分
原协定重现 原始任务、资产、示范、评分器与 split 固定版本、运行验证、真实原生计数；可用来创建参考成绩
任务／资产移植 场景、对象、controller 或子技能 新 backend 的接触、reset、观测／动作和判分重新验证
评测条件扩充 已可解的 base tasks 人类示范 A/B、历史、扰动、替代、必要过程与新 labels
多来源集成 不同 suite 的合法子集 G2 映射、source lineage、兼容性、去重、权重与结果分层
新物理情境 既有 mesh／流程可作起点 真正 physics、量测、专家解、合法替代与近失败；不能靠动画补齐

不能只改 task 名称或把多套排行榜拼在一起。若观测、控制器、robot、数据和评分不同，合并平均会把方法差异与评测差异混在一起。

LIBERO 的实际粒度示例

固定官方 commit 8f1084e3132a39270c3a13ebe37270a43ece2a01 的 manifest 有 130 个不同 native task IDs：spatial 10、object 10、goal 10、libero_10 10、libero_90 90。这次只抽查其中 10 个 BDDL goal 字段，没有运行模拟。

三个 spatial 任务的完整 goal expression 相同，但 instruction 的位置／关系指涉不同；三个 object 任务的对象名称不同，运算形状都是 In(object, basket)。抽样出现 5 种粗粒度 goal patterns，不代表它们正式等于 5 个 canonical tasks，也不代表整个 LIBERO 只有 5 种任务。必须连指涉、机构、reset 和 evaluator 一起核对。完整例子与固定来源在附录 F。

CHAPTER 12 / 14

工程实作、数据格式与发布

约 5 分钟·数据快照 2026-09-21设计阶段 Q0
先掌握这三件事
  • 先创建 registry、instance builder、adapter、evaluator 与结果纪录。
  • 共同 API 不代表不同模拟器有相同动力学。
  • 本网站提供公开研究文件；正式评测和平台代跑仍待实作。

系统模块

  1. Registry：场域、家族、情境、能力、来源、变化与readiness。
  2. Instance builder：assets、参数、A/B目标、reset与观测。
  3. Data builder：来源配对、时间／几何／语义标签与packets。
  4. Simulator adapter：reset、step、允许观测、私有state、扰动和snapshot。
  5. Policy adapter：输入、action contract、history lifecycle和预算。
  6. Evaluator：目标、过程、触发和量测有效性。
  7. Aggregator：eligibility、权重、分组不确定性和结果包。
  8. Release／网站：版本、来源、方法卡、核验状态及下载。
build_instance(scenario, assets, config, contract) -> validated instance
reset(instance, seed) -> policy_observation, evaluator_initial_state
step(action) -> observation, termination_info
get_evaluator_state() -> private state, events, validity
inject_disturbance(trigger_spec) -> delivery record, state validity
export_trace() -> actions, observations, state/event evidence, hashes

相同seed不保证跨GPU、引擎或controller比特级一致。保存版本、数值设置、实际初态hash和重跑容差。跨引擎是另一条件，不预设物理等价。

Backend 审核候选

刚体／机构可审核LIBERO／robosuite／RoboCasa或ManiSkill；布料／灵巧手可审核GarmentLab、DexGarmentLab、SoftGym；复合家务／流体可审核OmniGibson／BEHAVIOR；导航／协作可审核Habitat、PARTNR、Assistax。

这是文献导出的候选，不是已安装、集成或跑通清单。数字到实体先采限定工具API／设备状态机，不宣称开放网络或真实设备泛化。

验收关卡

层级 产物 通过要求
Q0 语义规格与来源 计数清楚、目标／近失败／输入／metric明确
Q1 场景实例 assets、目标、控制、reset、触发、量测完整
Q2 专家运行 同界面可解、合法替代被接受、初态有效
Q3 判分器 成功／近失败、过程缺失、量测故障与扰动有效性审核
Q4 重现基线 provenance、split、方法配置、重跑与统计可追踪

网站或case IDs不替代Q1–Q4。Pilot以原16个候选池及M1重选结果为起点；不支持的布料或其他情境保留Q0，不以对象动画假装完成physics。

每个pilot须有A/B示范与可推断性、专家解与合法替代、典型近失败、版本化条件、自然失败与注入失败来源标记，以及evaluator独立抽查。

共同 adapter 不是跨引擎等价

先固定一个可运作的 backend 和 profile，验证 reset、step、允许观测、私有 evaluator state、介入和 trace。后续加入第二引擎时，重新检查接触、材料、控制与判分；共同 API 不表示动力学一致。

数字到实体先采版本化的本地查找 API／设备事件模型，世界模型先固定 action adapter。两者都需保存工具／转换器版本，防止把它们的差异算成 policy 能力。

评测数据流

registry / source lineage
→ native task / asset / controller reuse audit
→ canonical spec + scene builder
→ Q1 instance → Q2 expert solvability → Q3 evaluator audit
→ source-group split + valid typed cases
→ frozen release + policy adapter + trials
→ trace / validity / outcome evidence
→ macro aggregation + paired uncertainty + verified result package

正式 case 不应由未绑定的 symbolic predicates 直接生成。Policy 可见信息、evaluator 私有答案和完整 state 要分层；公开网站与下载包不能携带 private split 答案。

三种上线阶段

阶段 用户能做什么 现在状态
设计／文件网站 阅读来源、规格、候选清单与下载 研究文件已提供网站阅读；正式评测服务尚未推出
下载评测与结果提交 本地跑固定 release，提交 traces、hash、coverage 与方法卡 尚无可运行正式 release
平台代跑模型 上传／指定 checkpoint，由平台调度并核验 private test 尚未实作；需要 runtime、配额、资源与提交格式

结果状态分为 submitted_unverified、reproduced_verified、rejected_or_incompatible。用户自行回报不能标成平台重跑。若选定公开服务方式，先在实际可重现子集完成发布，再扩大。

完整 episode template、字段含义、规划器与建置文件索引列在附录 H。完整报告 可独立说明设计；真正重跑仍需原始程序、资产与之后完成的实作。

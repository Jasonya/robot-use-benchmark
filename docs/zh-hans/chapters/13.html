CHAPTER 13 / 14

论文流程与 milestones

约 5 分钟·数据快照 2026-09-21设计阶段 Q0
先掌握这三件事
  • M0–M2 先验证研究问题、可解性与评分可靠性。
  • M3 冻结测试集合，M4 才跑主实验与消融。
  • 24 周是调度示例，不是投稿或交付保证。

能否发表，取决于 benchmark 的有效性、添加诊断价值、比较的公平性与可重现证据。扩充清单有助规划，但不能单独证明论文贡献。目前适合进入研究实作；还没有足够实验支持一篇已完成的 benchmark 结果论文。

范例调度

以下示例假设 4–6 位主要研究／工程人员，内核数据与计算资源可取得，并优先复用既有资源。24 周不是交付保证；M2 后以实测成本重估。第 1 周从正式启动此计划起算。

Milestone／示例时间 研究与工程成果 规模目标 可验收产物
M0 定位与主张
周 1–2		 定义主问题与 2–3 假设；保留完整候选库但不宣称验证覆盖。 候选库 12／48／180；实际 0
（场域／家族／蓝图）		 一页paper pitch、related-work矩阵、主要研究问题
通过：能对照最近工作说清楚评测回答什么；不是只比任务数

（场域／家族／蓝图）		 20–30候选的repo/task ID审核；可运作backend/profile
通过：计入的情境有同界面专家解、有效reset及近失败检查

每一部分文章在什么时候形成

文章部分 对应阶段 需要的证据
Introduction／主张 M0 草稿，M5 重写 一个清楚问题、最接近先例、实验实际支持的贡献
Related work／taxonomy M0–M3 168 篇来源地图、native／canonical 比较、任务与来源相依
Problem setting M1–M2 机体、观测、action、数据、时间与介入约定
Benchmark／Dataset M3 实际验证的 G0–G4、来源、标注、split、coverage、readiness
Evaluation protocol M1 起草，M3 冻结 成功／过程／近失败、可解性、分母、evaluator 可靠性
Experiments M4 固定 subset 的 baselines、oracles、消融、共同条件与 uncertainty
Analysis／Difficulty M4–M5 视频必要性、泛化、恢复、排序、瓶颈与经验校准
Limitations／Reproducibility M5–M6 模拟范围、proxy、缺口、来源未知、版本、原始证据

这些是拟定的呈现方式，没有预先填入不存在的结果。若某个模块在 pilot 后没有足够有效数据，就调整内核范围并明确保留为扩展工作。

第一个具体验收包

  1. 一页 paper pitch：主问题、两三个假设、最接近工作、计数单位。
  2. 20–30 列复用审核：原 repo／commit／task ID、assets、示范、controller、evaluator、取得／使用条件、改造需求。
  3. 原生 ID → family／G2 → instance → typed case 的 crosswalk，环境 seed 与 policy repeat 分开。
  4. 选出 6–8 个情境，在同一界面完成专家 A/B 解、合法替代与有效 reset。
  5. 判分器接受成功，拒绝部分完成、错物、错顺序与暂态假成功；保存 trace 与独立审核。
  6. 选定 pilot 的数据源、基线路线与成本量测方法，才启动扩张。

目前位置是 M0 的文献与设计材料已具备；尚未通过 M1。完整平台可保留 12／48／180 的发展方向，第一篇论文则以经验证且能回答主问题的核心集合为准。

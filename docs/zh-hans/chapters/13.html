论文流程与 milestones

约 5 分钟·数据快照 2026-09-21设计阶段 Q0
先掌握这三件事
  • v0.3 改用完整来源盘点、共同去重、界面验证与批量扩展的阶梯。
  • 依序验证 250／500／1,000，朝 2,000–3,000 个 G2 和 2× 参照门槛推进。
  • 达规模与品质门槛才冻结主实验；原 24 周示例不作本版承诺。
v0.3：主攻规模与覆盖优势

完整任务库初始目标为 2,000–3,000 个范式 G2，并要求至少最大可比基准 2 倍。180 个蓝图是设计种子；原 100–140 情境预算不再代表全库规模。

9. Milestones 改成规模与有效性的验收阶梯

阶段 交付 通过条件
S0 完整来源盘点 官方来源、固定版本、完整 native IDs、型态与 lineage 提取规则可重跑；混合单位与来源重复不被隐藏
S1 共同比较与去重 baseline task sets、G2 mapping、分歧审核、覆盖矩阵 能确定最大可比基准及本版增量；正式目标依结果调整
S2 跨 backend 最小闭环 代表性刚体、机构、布料、移动／协作 anchors 初始 6–8 个 anchors 只验证界面与判分，不作论文规模上限
S3 批量扩展到 250／500／1,000 每批已绑定、可解、可评分的 G2 与实例 每批同时通过品质与来源检查，公布实际成功移植率与成本
S4 规模门槛 朝 2,000–3,000 个 G2 推进，完成 relative-size 与 coverage checks 达共同口径的 2× 门槛，或据实记录尚未达成并继续扩展
S5 冻结与全规模实验 固定 release、baseline、成本与分层结果 所有正式数字能回查 spec、case、trace 与版本；测试后不挑题
S6 论文与公开发布 论文、数据／程序／评分器、可核验平台 对「更多、更广、all-in-one」的每个主张都有相应证据

10. 论文的主比较表

主表同时列：

  1. 原作者 native counts 与共同范式 G2 counts。
  2. 完整资源库、可取得部分、已实例化部分、正式评测 subset。
  3. 领域／家族／交互机制覆盖，以及同一 G2 在多机体实作的情况。
  4. inherited、modified、genuinely new specs 的来源与判定规则。
  5. human-observation-conditioned tasks 的实际数量与配对品质。
  6. G3、typed G4、G5 和数据资源量。

主实验应包括全库与各来源／领域的 macro 结果、held-out 语义／对象／材料条件、规模增加后的排序稳定性、以及视频／过程／恢复诊断。不能用大量相似取放样本掩盖其他机制的弱项。

11. 目前已完成与仍未完成

本次完成的是规模主线重设、官方来源版本盘点、可追溯原生纪录提取与网站规划更新。静态来源纪录可作为构建大型任务库的输入。

目前仍没有共同范式后的完整 G2 计数、实际 instance、已验证 cases 或 simulator rollouts。因此本版不宣称已建成最大 benchmark，也不把来源库条目自动登记为本计划完成的任务。

本版的承诺是把规模与覆盖优势作为主要验收目标，并沿完整任务库路线推进。

能否发表，取决于 benchmark 的有效性、添加诊断价值、比较的公平性与可重现证据。扩充清单有助规划，但不能单独证明论文贡献。目前适合进入研究实作；还没有足够实验支持一篇已完成的 benchmark 结果论文。

每一部分文章在什么时候形成

文章部分 对应阶段 需要的证据
Introduction／主张 M0 草稿，M5 重写 一个清楚问题、最接近先例、实验实际支持的贡献
Related work／taxonomy M0–M3 168 篇来源地图、native／canonical 比较、任务与来源相依
Problem setting M1–M2 机体、观测、action、数据、时间与介入约定
Benchmark／Dataset M3 实际验证的 G0–G4、来源、标注、split、coverage、readiness
Evaluation protocol M1 起草，M3 冻结 成功／过程／近失败、可解性、分母、evaluator 可靠性
Experiments M4 固定 subset 的 baselines、oracles、消融、共同条件与 uncertainty
Analysis／Difficulty M4–M5 视频必要性、泛化、恢复、排序、瓶颈与经验校准
Limitations／Reproducibility M5–M6 模拟范围、proxy、缺口、来源未知、版本、原始证据

这些是拟定的呈现方式，没有预先填入不存在的结果。若某个模块在 pilot 后没有足够有效数据，就调整内核范围并明确保留为扩展工作。

第一个具体验收包

  1. 一页 paper pitch：主问题、两三个假设、最接近工作、计数单位。
  2. 20–30 列复用审核：原 repo／commit／task ID、assets、示范、controller、evaluator、取得／使用条件、改造需求。
  3. 原生 ID → family／G2 → instance → typed case 的 crosswalk，环境 seed 与 policy repeat 分开。
  4. 选出 6–8 个情境，在同一界面完成专家 A/B 解、合法替代与有效 reset。
  5. 判分器接受成功，拒绝部分完成、错物、错顺序与暂态假成功；保存 trace 与独立审核。
  6. 选定 pilot 的数据源、基线路线与成本量测方法，才启动扩张。

目前位置是 M0 的文献与设计材料已具备；尚未通过 M1。完整平台可保留 12／48／180 的发展方向，第一篇论文则以经验证且能回答主问题的核心集合为准。

论文流程与 milestones

约 5 分钟·数据快照 2026-09-21设计阶段 Q0
先掌握这三件事
  • v0.4 先固定共同分类、参照集与广度配额，再验证跨 backend 闭环。
  • 每批 250／500／1,000 都同时检查数量、场域、家族、机制、材料与机体支撑。
  • 规模与广度共同达标后冻结主实验；原 24 周示例不作本版承诺。
v0.4：任务规模与广度共同验收

完整任务库初始目标为 2,000–3,000 个 G2；任务数与有效覆盖各以最大可比基准至少 2 倍为目标。添加场域、家族、材料与机体的支撑配额。180 个蓝图保留为设计种子，原 100–140 预算属历史方案。

10. Milestones 重新对齐整体目标

阶段 主要交付 验收重点
S0 来源盘点 完整 native records、版本、单位与 lineage 本轮已有 5,020 笔静态纪录；不算成正式任务数
S1 共同分类与缺口 G2 规则、参照集、F/K 分类、场域矩阵与配额定版 确定两个相对门槛的分母；不能只挑较小对照
S2 跨 backend 闭环 代表性 6–8 个 anchors、实例、专家解与判分 验证界面和量测；不是论文规模上限
S3 批量扩张 250／500／1,000 个验证任务及其 bindings 每批同时看 N_task 和各广度配额，避免只扩容易的一类
S4 达双门槛 向 2,000–3,000 与更多有效覆盖推进 任务规模及 coverage ratio 同时达标，内核场域／材料／机体支撑足够
S5 冻结与主实验 固定测例、完整 eligible 集合、基线、oracle／ablation 所有正式结果能回查版本、cases 和 traces；测试后不挑题
S6 发布与论文 code、data、evaluator、核验结果与完整稿件 「更多、更广、统一」每个主张都有相应证据

设计网站和阶段性 beta 可以持续公开；只有通过共同门槛的正式版本，才能标示已达成「规模与广度优势」。未达时公开进度并继续扩充，不以换单位或降标准代替成果。

11. 论文最后要怎么呈现

主表同时列出：native counts、范式 G2、有效场域／家族／机制格子、材料与机体支撑、G3、typed G4、实际 G5，以及数据源量。

与对照工作的完整资源、可取得部分、已实例化部分和实验 subset 分栏。原生 task、数据 episodes、视频 QA 和 benchmark wrappers 不能直接混加。

论文的主实验须回答：扩大的任务库与覆盖是否带来稳定、可解释的新评测证据；哪些领域、材料、流程与来源仍是瓶颈；添加任务相对原作联集有何真正差异。统一界面本身已有相关工作，不单独当作新颖性。

12. 目前进度与下一个具体产物

目前已完成研究文件、网站、规模主线、来源盘点与本版整体设计。既有 5,020 笔静态纪录来自 20 个官方程式库、21 个版本来源；它们仍未完成共同 G2 去重。

目前 G2 正式总数为 TBD，已实例化任务、已验证测例、实际模拟运行和本计划收集的人类视频 pairs 均为 0。

下一个具体产物是 G2／task–context／机制的审核表及缺口清单：每列连回原定义，记录合并／拆分理由、资产与界面需求、可行性，以及它补足哪个广度格子。依这份表安排实作批量，并同步审核可用 backend 与 profile。

能否发表，取决于 benchmark 的有效性、添加诊断价值、比较的公平性与可重现证据。扩充清单有助规划，但不能单独证明论文贡献。目前适合进入研究实作；还没有足够实验支持一篇已完成的 benchmark 结果论文。

每一部分文章在什么时候形成

文章部分 对应阶段 需要的证据
Introduction／主张 M0 草稿，M5 重写 一个清楚问题、最接近先例、实验实际支持的贡献
Related work／taxonomy M0–M3 168 篇来源地图、native／canonical 比较、任务与来源相依
Problem setting M1–M2 机体、观测、action、数据、时间与介入约定
Benchmark／Dataset M3 实际验证的 G0–G4、来源、标注、split、coverage、readiness
Evaluation protocol M1 起草，M3 冻结 成功／过程／近失败、可解性、分母、evaluator 可靠性
Experiments M4 固定 subset 的 baselines、oracles、消融、共同条件与 uncertainty
Analysis／Difficulty M4–M5 视频必要性、泛化、恢复、排序、瓶颈与经验校准
Limitations／Reproducibility M5–M6 模拟范围、proxy、缺口、来源未知、版本、原始证据

第一个具体验收包

  1. 一页 paper pitch：主问题、两三个假设、最接近工作、计数单位。
  2. 20–30 列复用审核：原 repo／commit／task ID、assets、示范、controller、evaluator、取得／使用条件、改造需求。
  3. 原生 ID → family／G2 → instance → typed case 的 crosswalk，环境 seed 与 policy repeat 分开。
  4. 选出 6–8 个情境，在同一界面完成专家 A/B 解、合法替代与有效 reset。
  5. 判分器接受成功，拒绝部分完成、错物、错顺序与暂态假成功；保存 trace 与独立审核。
  6. 选定 pilot 的数据源、基线路线与成本量测方法，才启动扩张。

目前位置是 M0 的文献与设计材料已具备；尚未通过 M1。完整平台可保留 12／48／180 的发展方向，第一篇论文则以经验证且能回答主问题的核心集合为准。

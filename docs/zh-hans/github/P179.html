REBOOT: From Failure to Recovery - A Dataset and Benchmark for Precision Assembly

返回逐篇总表内核内容已核读 benchmark／数据／评测主来源原作 ↗ 用途与原生规模依据

核读快照 2026-10-11。已读范围限所列片段；本轮未运行上游程序。

已核读 REBOOT 的 depth reader、frame／video 对齐、phase.json 裁切读取与通用 evaluator。原生18任务及人工五阶段判定主要定义于论文；所查固定版本未提供 REBOOT 专用自动 phase scorer。另实查官方 RCA recovery 数据 metadata，确认仅30 episodes、train split 且没有 meta/phase.json，不能直接把论文2,160段视为已闭合的公开数据。

版本与身份

固定 depth 分支269d539，不以 upstream LeRobot 最新版替代；HF实查固定fb4e5c5。README 的『2,160 bimanual』与论文83段实际协作需分开解读；论文1-based phase公式、范例tau_0=0及程序0-based slice 也要保留来源差异。未下载 parquet/video，未安装或运行上游程序。

arXiv:2609.22591v1 第16页及作者 nanayawoa 的项目页均连至此 fork；README 自称 LeRobot (REBOOT fork)，承接 Trossen fork、LeRobot v0.4.3 与 depth PR2604。这是数据录制／读取支持仓库，不是18项组装任务的完整模拟器。

领域
装配与生产作业
环境
实体 NIST Assembly Task Board #1，Trossen WidowX AI 两支6关节 follower 与 leader teleoperation；四台 RGB-D 视角为 high、low、left_wrist、right_wrist。论文对象初位在名义位置周围3–6 cm 变动，目标板固定。双臂硬件／14D state 不等于每段双臂协作：论文第10页只有83／2,160段属双臂，且主要为 recovery_install。
任务
依第23页表10保留9种对象各 install/remove，共18项：M12、USB-A、USB-C、RJ45、NEMA 1-15P、HAN10E、RCA、16mm bar/cylinder。每 task 保留 C1/C2/continuous symmetry、clearance（mm）、precision tier。共同五阶段是 Align(pick)、Engage(pick)、Transport、Align(place)、Engage(place)，不是90个独立任务。论文每 task 有60 expert+60 recovery，总2,160；第7页『10 types』与具体9列 inventory 不一致，采表10枚举并标记差异。
题数与数据
论文 action/state 为两臂各6 joint+1 gripper 的14D绝对目标／状态，30 Hz；保留关节及夹爪原生尺度，不推定全部维度为角度。实查 REBOOT26/rca_recovery_install@fb4e5c5：info.codebase_version=v3.0、30 episodes、26,939 frames、1 task、splits.train='0:30'；action/observation.state 为 float32[14]，RGB 为480×640×3 video、四个 *_depth 为480×640×1 depth。data/chunk-*/file-*.parquet 与 videos/{video_key}/chunk-*/file-*.mp4 透过 episode metadata 的 chunk/file/from_timestamp 连接；reader 裁定 delta_indices 不跨 episode，另输出 *_is_pad。相机程序以 z16 读 uint16，docstring 称 mm，但数据 info 未提供 depth scale，仍需校准信息。论文 phase schema 含 repo_id/task_id/episode_index、phase_boundaries.tau_0…tau_5、failure.originating_phase/failure_mode/t_f/t_r/t_s；trim reader 则要求外层 episodes[]，按 failure.<cut-key>（预设t_r）取 [start,stop)。抽查的 RCA dataset file inventory 未含 meta/phase.json；其他38个 API 列出项目未逐一查数据，不能断言全部缺标注。
评估方式
论文以人工标记的 last-completed phase／first failure phase 形成每阶段分布及最终成功率，不能由 clearance 单栏推导自动成功。正文第7页写20 rollouts/task/policy，第8页与附录A.5写15，后者18×3×15=810；须厘清实际使用名册。公开 lerobot_eval.py 读 info.final_info.is_success 或 info.is_success，缺值用False，沿 episode 合并为 any(success)，再平均成 pc_success（百分比），同时计 reward；它不判断 connector engagement 或 phase 边界，不能代替 REBOOT grader。失败词汇也有版本差：第6页四类，附录与第7页另含 slip。裁切器会移除 dtype=depth／名称结尾_depth 的 feature，重新产生 index/timestamp，未重映射 phase/failure 时间，不能直接把其输出当原版完整 recovery case。

怎么接入我们的benchmark

可重用

14D通道名称、四相机／depth schema、LeRobot v3 episode 索引读取、原生 task inventory、人工 phase/failure 表达及裁切窗解析。

需要转换

source 分别保留程序 commit 与每个 HF dataset revision；environment 记硬件／board；task 用 object+install/remove；case 用 dataset revision+episode_index，另存 expert/recovery 与双臂旗标；frame/time 用30 Hz与原 offset 连接。保留 source_frame_index 与 trim offset，重新映射 phase/t_f/t_r/t_s，避免删 depth；evaluator 独立保存人工阶段判定与通用 rollout success，不合并。

仍需补齐

36个理论 task×episode-type 分组与官方实际38个数据 repo／分片的对照及去重；完整 episode 与 phase annotation 名册；RCA 本次固定版本仅30段及缺phase的原因；15/20 rollout 协定厘清；原生 joint/gripper/depth 校准尺度；公开 REBOOT 专用 grader 或人工评分流程。

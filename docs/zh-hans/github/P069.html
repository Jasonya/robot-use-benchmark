robosuite: A Modular Simulation Framework and Benchmark for Robot Learning

返回逐篇总表内核内容已核读 benchmark／数据／评测主来源原作 ↗ 用途与原生规模依据

核读快照 2026-10-10。已读范围限所列片段；本轮未运行上游程序。

robosuite 提供可配置任务与状态判定；论文的 SAC 图表来自另一个 v1.0 benchmark 仓库。已核读 Lift、示范串行化及 return 统计链，不能把现行 v1.5 环境直接当原实验版本。

版本与身份

主程序固定5ce6643f3092639d08f7b0f90ed1c6a84f50552c；SAC固定b229f7442f3590dd0e0cad21dc6ae52f410a34bc，依赖rlkit b7f97b2463df1c5a1ecd2d293cfcc7a4971dd0ab。SAC requirements 只写robosuite>=1.0.1，却使用mujoco-py/Gym旧API。notebook第89–100行把Wipe与Door都写成NutAssemblyRound；Door示例variant为2000 epochs，论文／文件为500。加载variant后，乱数初始化仍取CLI args.seed，不能只相信JSON seed。

对应 arXiv:2009.12293v3（2025-01-18），题名与作者以固定论文首页为准；虽收录年份为2020，本 PDF 明述 v1.5。PDF 第15页直接连到 robosuite-benchmark；主仓库 README 指回同一论文。

领域
居家整理与清洁、装配与生产作业、通用对象与机动作业
环境
MuJoCo 的 robot＋arena＋objects 组合。已读 Lift 使用0.8×0.8公尺桌面，桌高0.8公尺；cube 的 xy 初态在桌面原点附近各±0.03公尺抽样。模型数、任务数与初始化 case 数分开。
任务
论文九个标准环境；实验细化到 PickPlaceCan、NutAssemblyRound 等子型，双臂设置另存。Lift 的具体 checker 只要求 cube 中心 z 大于桌面 z＋0.04公尺；不额外要求持续抓握或停留。其余八个 checker 未逐一核读。
题数与数据
原生 observation 是具名传感 dict；Lift 有 cube_pos、公尺制相对位置与 xyzw cube_quat，传感率跟 control_freq。HDF5 data/demo_N 存 states、actions 与 model_file XML；data attrs 存 env、env_info、repository_version、date/time。写入前删掉最后一笔 state 以对齐 actions，只收成功示范；此格式本身不含 RGB。20 Hz 是已读基线设置，动作维度／缩放须保留各 controller 设置。
评估方式
基线链为 train→experiment→MdpPathCollector→CustomBatchRLAlgorithm._log_stats→get_custom_generic_path_information→eval_util。Returns 是每回合 reward 总和，ExplReturns 截至 exploration horizon；统计函数的 reward_scale 参数没有运行除法，缩放在环境端。例示 run 每epoch收2500步、每回合500步，通常为5回合；论文另对5个训练 seeds 报均值与标准差。现行 base.done 是 horizon 条件且 info 为空，不能当 task success。

怎么接入我们的benchmark

可重用

任务 class、版本化 controller/env 设置、初态抽样、HDF5 模型／状态与具体 checker，以及原生 return 统计。

需要转换

source 保存论文v3与两仓库commit；environment 保存robot/arena；task 保存子型；case 保存seed、初态、horizon/control_freq；evaluator 分列二元checker、shaped reward、episode return。模型XML与资产引用需闭合。

仍需补齐

原实验所用 robosuite 精确commit仍未锁定；尚需其余任务checker、控制器动作约定及资产／重播验证，不能宣称已重现原图。

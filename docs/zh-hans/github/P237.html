P237 · Gated Temporal Diffusion

Gated Temporal Diffusion for Stochastic Long-Term Dense Anticipation

返回逐篇总表内核内容已核读 方法／综述参考原作 ↗

核读快照 2026-10-11。已读范围限所列片段；本轮未运行上游程序。

已核 GTDA 的 Breakfast/50Salads 与 Assembly101 loader、DDIM inference 及 Mean/Max MoC／Frame Diversity。三个指针有不同分母：candidate-pooled class accuracy、逐 case/β oracle 选样后 class accuracy，以及候选两两 frame disagreement；不可折成共同 success 或把 Top-1 当部署模型选出的最佳预测。

版本与身份

固定 010bad63c802e1666f64943dd098f3ac7be13118（2025-05-29），晚于ECCV 2024。readme所称 precomputed_<dataset> 命名与实际 predict_precomp_bf_prob.sh 不同。论文对Breakfast/Assembly用50 DDIM steps，50Salads用10；不能把两个已读脚本的50套全数据集。paper p.14 明指ANTICIPATR协定不同，不应与P240数值直接合并。仅读内核区段及小型split/label来源，未跑模型或加载pickle／大资产。

arXiv:2407.11954v1（2024-07-16），Olga Zatsarynna、Emad Bahrami、Yazan Abu Farha、Gianpiero Francesca、Juergen Gall；PDF p.1 直接给 olga-zats/GTDA，README 引同一 ECCV 2024 论文。GTD 是 stochastic diffusion、GTAN 是其 deterministic backbone；同 repo 两个模式不增加独立来源数。

领域
方法／综述参考，未另作来源用途归纳。
环境
脱机烹饪（Breakfast、50 Salads）及玩具车组装／拆解（Assembly101）。Assembly CSV 含固定 RGB 相机与头戴 HMC view，程序按存在的 numpy feature 过滤，没有只选 Ego view 的条件；视角字段必须留在 case，不能把所有来源标第一人称。
任务
以 α=0.2/0.3 的观测预测 β=0.1/0.2/0.3/0.5 的逐格动作标签。Breakfast mapping=48类含 SIL；50Salads mapping=19类（17动作+action_start/action_end）；Assembly 使用 coarse action_cls/action_id，附带 actions.csv 有202类，不是全部细粒度 action 组合。每训练 video/view 衍生 α=.2/.3/.5 的3个 observation case，另有40%概率改为 .15+.25U；这些不是3支添加视频。
题数与数据
Breakfast/50s 为 D×T 的 .npy、逐行 label .txt、mapping.txt、split bundle。sample 回传 features、classes、classes_all、classes_one_hot、mask_past、mask_future、vid_len、file_name；feature 只取 [:int(αT)] 并 [::sample_rate]，collate 在未来／padding补零，label padding=C+1。--part_obs 将 prediction span设为全视频的 .5，所需长度仍源自完整 GT T。Assembly CSV 为 video_id,view,action_type,video_start_frame,video_end_frame；coarse_labels/{action_type}_{video_id}.txt 每行 tab 分隔 start,end,label（尾空栏依实作），依 end-start 展开，程序注明 @30fps；TSM_features/{video_id}/{view}/features.npy 用 [start:end] 裁切。feature缺档、空segment或无长度会跳过，lmdb分支未实作。固定 split4 bundle 1136 train／576 test unique video keys，无交集；这是名单数。Assembly train/val CSV 4684/1424列、204/61个 video_id，各16种view；尚非有效运行case数。保存预测 pickle 以 action_type_video_id_view 或 Breakfast file_name 为key，值为K组复原逐格预测，gt_ 前缀是全长GT。
评估方式
在线 validate 强制 batch_size=1，stochastic 用 EMA 产生 K=25 候选；Breakfast示例 sample_rate=3，Assembly=6，预测每个采样位置重复该倍数回原格。对 [int(αT):int((α+β)T)] 计 n_T/n_F。Mean MoC 先把所有视频、全部K候选的每GT类别正误格数相加，再对有GT的类别平均 T/(T+F)，输出0..1；不是每视频MoC的平均。Max/Top-1 MoC 对每视频及每β依GT挑该范围MoC最高的一个候选，累积其类别计数后再宏平均，同视频不同β可选不同候选。precomputed Frame Diversity 对每case取 K(K-1)/2 配对的 [1-相同frame数/该future窗长] 平均，再等权平均case。完整K=25对应300配对；test_num_samples 预设1会除零，不能沿用其预设。eval_file 另算 normalized segment Levenshtein error，但目前 MoC caller 丢弃该回传，不能当正式主指针。程序把 x_0 GT传到 predict，但底层只用 zeros_like取得形状，生成值起于高斯噪声；仍依赖GT长度，与GT action值泄漏需分辨。

怎么接入我们的benchmark

可重用

原生 mapping、split与view身份、coarse-to-frame规则、TP/FN累积、候选pickle结构及Frame Diversity程序。

需要转换

source 记paper/repo/data-feature revision，domain/environment依烹饪或组装与view分类；task区分deterministic GTAN／stochastic GTD；case=(dataset revision,fold或train/val,video,action_type,view,α,β)，candidate_index属case内试样。保留annotation frame reference、sample_rate、GT-length protocol、K、EMA/checkpoint、diffusion T/D；evaluator标明Mean MoC／oracle Top-1 MoC／pairwise diversity各自分母与0..1尺度，不能直接对齐P236的百分比或P240的mAP。

仍需补齐

固定TSM/I3D及Assembly coarse annotation版本、实际feature存在清单，验证start/end与view长度裁切。在线stochastic分支没有累加frame error/num_frames却仍输出Acc，会得到0/0，应列为无效字段。precomputed读取硬编码 /home/user/diff_results/final，与writer的 ./diff_results 不同；predict_precomp_bf_prob.sh未传mapping_file；Assembly的main_diff_evaluate把actions_dict设空，eval_file会以零长类别数组索引，须修复后才能重评。固定test_num_samples>=2并检查候选数／长度、有效GT窗；原程序min(pred_len,GT_len)可能缩短评测分母。尚未闭合50Salads的示例脚本／checkpoints与完整跨fold聚合。

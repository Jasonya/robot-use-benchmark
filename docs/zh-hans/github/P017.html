HOI4D: A 4D Egocentric Dataset for Category-Level Human-Object Interaction

返回逐篇总表内核内容已核读 benchmark／数据／评测主来源原作 ↗ 用途与原生规模依据

核读快照 2026-10-10。已读范围限所列片段；本轮未运行上游程序。

HOI4D 有可直接利用的 room、layout、对象与任务路径，原生任务表也已核读；后续 semantic/action segmentation challenge 的张量与类别空间需独立保存。

版本与身份

三仓库均引用同一 HOI4D 论文；两个 challenge 仓库同时引用后续 PPTr，不表示这些程序和首版论文的所有协定完全相同。task 表的 T1–T6 是来源内编码，与本计划旧 T 模块无关。

Instructions 的精确标题／作者／官方项目链接及两个 challenge README 的同题引用、hoi4d.top 指向一致；保留各自 repo 角色。

领域
居家整理与清洁
环境
路径 ZY/H/C/N/S/s/T 分别代表 camera、human、object class、object instance、room、room layout、task。S 与 s 才提供实体房间／布局身份，T 不可计为新环境。
任务
task_definitions.csv 按 16 个对象类别列 T1–T6，含取放、开关、切割、倒水、收纳、装订等；有 N/A 和相同文字重复字段。T 编号仅在对象类别内有意义，不能把列×栏或动作 segmentation label 当通用任务总数。
题数与数据
align_rgb/depth、objpose JSON、action/color.json、raw_pc/label.pcd、相机 output.log、motion masks 与 MANO pose 各自保留。CAD 的 canonical frame 定义对象姿态；MANO 转米时除 1000。action challenge HDF5 读 pcd/center/label，与原始 RGB-D 数据是加工关系。
评估方式
semantic test_seg.py 去掉输出 channel 0/1、回加 label offset=2，再聚合各类 intersection/union；跳过 0/1 与 GT 无样本类，计 macro accuracy/mIoU。action train_p4.py 用 frame accuracy、segment edit 与 F1@.1/.25/.5，结果还依 batch 聚合。公开 challenge 输出形状分别 (892,300,8192) 与 (892,150)，是串行×时间×点或串行×时间，不能当任务类别数。

怎么接入我们的benchmark

可重用

room/layout/task 身份、原生任务表、CAD articulation／pose 及 semantic/action 评分。

需要转换

保留 C+T 复合 task ID 并以 parent source 追溯，N/A 不计数，重复语义仅提出待核对关系。environment 用 S/s，case 记原始串行→challenge HDF5 row 的映射、点采样与 label mapping；3D/4D segmentation、动作分割与人体姿态分 profile。

仍需补齐

尚未取得 RGB-D、CAD、HDF5 或运行 CUDA baseline；需要 release.txt 和 challenge row-order／sampling 映射、标注时间单位与原生 challenge evaluator 版本核对。不能把具有人类取放标签的视频当已可运行的机器人题。

P074 · RoboTwin 2.0

RoboTwin 2.0: A Scalable Data Generator and Benchmark with Strong Domain Randomization for Robust Bimanual Robotic Manipulation

返回逐篇总表内核内容已核读 benchmark／数据／评测主来源原作 ↗ 用途与原生规模依据

核读快照 2026-10-10。已读范围限所列片段；本轮未运行上游程序。

RoboTwin 2.0 的50项任务清单与逐task步数上限可直接核对；现行main已有XPolicyLab评测及新版HDF5。已闭合Lift Pot的几何checker、seed筛选、action计数、数据时间对齐与图像解码，须与2025论文版区分。

版本与身份

XPolicyLab实际gitlink为fa431ecd893ee706883e64fe5fe1464ec8cd928d；.gitmodules的branch=main不是版本pin。本次只读RoboTwin端集成与本地codec。具体schema风险：save_freq用作每N个控制步抽帧，却原值写入frequency；还另插入端点帧，不能据此重建固定Hz时间轴。extrinsics_matrix优先写cam2world_gl，缺少时才写extrinsic_cv，座标方向不由字段名保证。JPEG有legacy色序与XPL-RGB1两制，不能无条件再交换RGB/BGR。

对应arXiv:2506.18088v2（2025-08-27），题名／作者以固定PDF为准。官方README连同一arXiv，并记录2025-08论文更新；本次main commit ea8b21121ebb3cd201ff5b3fe361944ac94eda3f则是2026-09-24的后续集成版。

领域
居家整理与清洁
环境
SAPIEN桌面双臂，论文正式设置为Aloha AgileX。现行clean与randomized不是两个生活场域；randomized包含clutter、背景、光照，table_z_bias实际抽[-0.03,0]公尺，并改用unseen语言。两份YAML都将depth/pointcloud关闭，不能把论文DP3使用的完美点云当所有方法共同输入。
任务
all_tasks与step-limit档各列50个原生task；左右／数量变体按原清单保留。Lift Pot从两个060_kitchenpot模型抽样；成功需世界z>0.82公尺、两TCP各距指定contact point<0.03公尺，以及pot局部z轴与世界z轴内积>0.8。此check不另测双臂接触力或持续时间。
题数与数据
原生PKL仍是observation/joint_action/endpose字典；关节读值来自drive targets，非real_jointState。现行转档输出HDF5 data_format_version="v1.0"、instructions JSON字符串、additional_info/frequency、state/action与vision；state=values[:-1]、action=values[1:]，只保留N−1组。joint字段用left/right_arm_joint_states及left/right_ee_joint_states，pose用left/right_ee_poses；vision含cam_head/cam_left_wrist/cam_right_wrist的colors定长JPEG bytes、shape、可选depths与矩阵。在线adapter用单数joint_state键，且EE/TCP有不同原点。
评估方式
main→eval_remote_policy→take_action→lift_pot.check_success→eval_success；逐task成功数除以test_num（预设100）。从100000×(1+seed)往后找候选；expert_check预设打开，先play_once且要求plan_success与checker通过，再重置同seed评policy。unstable、setup错误及首个action前的rollout错误会被略过；因此100是有效试验数，不是连续100个初态。期限按take_action_cnt而非physics frames；每次action内部再规划／插值，达条件即锁定成功。论文50 clean示范训练、Easy/Hard各自100rollouts的结果不由本轮运行重现。

怎么接入我们的benchmark

可重用

50 task IDs、逐task步数、clean/randomized设置、对象contact-point数据模型、具体checker与seed筛选loop。

需要转换

source固定主repo及XPolicyLab gitlink；case存embodiment、语言分割、随机化、被接受／略过seed、action计数与checkpoint。分开PKL命令、HDF5 t/t+1配对、在线单数键，保留EE/TCP、pose/quaternion与JPEG marker约定。

仍需补齐

2025论文对应的程序／asset版本闭合、所有50 checker逐项覆核、XPolicyLab与policy模型依赖取得、正式accepted-seed manifest及时间／座标schema验证。

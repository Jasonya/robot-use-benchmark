P071 · RoboCasa365

RoboCasa365: A Large-Scale Simulation Framework for Training and Benchmarking Generalist Robots

返回逐篇总表内核内容已核读 benchmark／数据／评测主来源原作 ↗ 用途与原生规模依据

核读快照 2026-10-10。已读范围限所列片段；本轮未运行上游程序。

RoboCasa365 应从 TASK_SET_REGISTRY、split 建环境、LeRobot extras 和具体 task checker 读起。现进程式的 all_tasks 来自数据registry而非365项完整任务名册；论文与后续文件的trial数、horizon也已不同。

版本与身份

主仓库同时残留旧eval_utils的PandaMobile/B split；365应沿env_utils＋Gym读取。Gym预设split="test"，create_env只接受None/all/pretrain/target，因此调用时需明设split。LeRobot playback拒绝filter_key；--use_abs_actions没有进入use_actions分支，而底层get_episode_actions(abs_actions=True)也明确未实作。README要求robosuite master，LeRobot与policy runner版本尚未固定；本次没有宣称运行兼容。

对应 arXiv:2603.04356v1（2026-03-04／ICLR 2026），四位作者及题名与README的RoboCasa365引用一致。与P070共用官方仓库，但这份笔记固定365时代main：456174f62b89b8fca99eaaf33949c29fec9cfc2a。

领域
居家整理与清洁、餐饮与烹饪
环境
pretrain由layout 11–60与style 11–60交叉组成2500组；target只用(1,1)…(10,10)十组，不是10×10。create_env同时切换obj_instance_split。Kitchen会再排除任务不支持的layout/style；2500不能保证每task都有2500个有效场景。
任务
论文365＝65 atomic＋300 composite；target50明列18 atomic-seen、16 composite-seen、16 composite-unseen。固定registry经AST计数为65 atomic＋252 composite＝317个key，all_tasks直接串接这两表；pretrain300与target50联集316，另外一个key是PlaceOnDishRack。这是数据／评测入口的覆盖差异，不以317覆盖论文365，也不推论未列者没有环境实作。
题数与数据
get_ds_meta输出path/horizon/filter_key/task/split/source；human预设pretrain100、target500 demos，MimicGen一般10000但OpenCabinet特例5000。缺folder回None，soup会略过。LeRobot读data/*/episode_NNNNNN.parquet的action，按meta/modality.json重排；重播另需extras/dataset_meta.json的env_args，及每episode的states.npz、model.xml.gz、ep_meta.json。ep_meta保留layout_id/style_id/object_cfgs/fixture_refs/cam_configs/lang及底盘初态。action原始顺序为eef平移3、旋转3、gripper1、base/torso4、mode1；Gym提供三个video.*视角、state.*与annotation.human.task_description，不能直接按LeRobot字段字典顺序拼接。
评估方式
Gym.step→Kitchen.reward／具体_check_success；PickPlaceCounterToCabinet要求bbox位于某一柜内区域且eef离对象>0.25公尺。obj_inside_of仍在未范式轴投影使用0.05，非固定5公分容差。Gym将checker转为reward 0/1与info.success；ignore_done=True且truncated固定False，registry的horizon必须由policy runner另行取用。论文§G.2每task30 trials、期限内曾成功即算成功、跨task平均；现行文件改50 rollouts且v1.0.1把horizon增至1.5倍。

怎么接入我们的benchmark

可重用

有版本的task sets、pretrain/target分割、LeRobot modality及extras、场景／对象生成设置与具体bool checker。

需要转换

source记论文v1及commit；task全集、数据覆盖、target集合分栏。case记split、layout/style pair、对象分割、seed、控制频率及实际horizon；evaluator保存trial数、期限内成功与跨task平均，禁止和P070或不同horizon结果直接合并。

仍需补齐

365任务与317个数据key的完整对照、正式policy runner依赖commit／seed清单、per-frame subtask标注的实际文件schema，以及LeRobot视频／extras／资产的闭合验证。

P081 · ARNOLD

ARNOLD: A Benchmark for Language-Grounded Task Learning With Continuous States in Realistic 3D Scenes

返回逐篇总表内核内容已核读 benchmark／数据／评测主来源原作 ↗ 用途与原生规模依据

核读快照 2026-10-11。已读范围限所列片段；本轮未运行上游程序。

ARNOLD已追到NPZ重建、两阶段策略、具体joint／pickup／orientation／water checker及score聚合。水量实作是cup world-AABB内粒子比例，成功还需连续稳定；normalized训练state不可直接当checker原生target。checkpoint选择有list.argmax静态错误，且GT辅助结果必须独立保存。

版本与身份

固定arnold-benchmark/arnold@40ad6861f45b676bf538b7a0e180d81c8d454823（2024-04-01），晚于论文v2，README另含CVPR 2024 Challenge公告；不能混用Challenge与ICCV paper的case/split。P077/P078方法在此的轴、单位、keypoint及checker均已改写，需标为重用方法的另一实验版本。未运行Isaac Sim、policy、Cython或上游shell。

固定论文为Gong、Huang等人的ARNOLD: A Benchmark for Language-Grounded Task Learning With Continuous States in Realistic 3D Scenes，arXiv:2304.04321v2（2023-09-11）。PDF第7页直接指arnold-benchmark/arnold，README作者、题名与arXiv相符。此repo含benchmark与改写的PerAct/6D-CLIPort基线；它们是P077/P078方法的重用，不是原仓库数据或同一评测协定。

领域
居家整理与清洁、通用对象与机动作业
环境
Isaac Sim／USD、Franka与五相机front/base/left/wrist_bottom/wrist（配置128×128）。load_task将stage设为y-up、1单位=0.01m、gravity=(0,-1,0)且magnitude=981；physics设120Hz。场景／机器人／对象／material USD依NPZ info重建，路径改写假设原始路径含VRKitchen2.0或指定materials字符串。README的20 scenes／40 objects／10k demos是来源声明，未以本地asset／NPZ枚举验证。
任务
8个原生task为pickup_object、reorient_object、open/close_drawer、open/close_cabinet、pour_water、transfer_water。训练样本分act1抓取／act2操作，sample_weights=0.2/0.8；一般四keyframes（初态、预抓、抓住、终态），water六帧并混合frame3位置与frame4姿态作第二动作。二次policy决策不等于3或6个planner stages。7个split需保留train/val/test/novel_object/novel_scene/novel_state/any_state；预设eval只跑后五者。
题数与数据
每case是.npz，gt为keyframe对象串行，info包含scene_parameters、robot_parameters、objects_parameters及robot_shift。gt使用instruction、robot_base、position_rotation_world、gripper_joint_positions、images；每camera有rgb、semanticSegmentation、depthLinear、camera内参／pose。Reader把position/finger由cm除100成m、wxyz转xyzw，以机器人前方0.5m为中心；PerAct点云维持y-up，CLIPort heightmap换轴成z-up。depthLinear先clip到[0,10]，Cython反投影乘100到cm、世界变换后再除100；不能把raw depth直接当cm。target_points注解写[6]，实际concat xyz+xyzw是7D（rot=None才3D）。parse_state从文件名取标签：pickup目标/40、reorient角度/180、pour为(100-p)/100、transfer为p/100，其他直接取浮点；runtime CheckerParameters.target_state另取info中的cm／度／比例／百分点原生单位。尚未读任何示范NPZ内容，字段证据来自reader。
评估方式
eval→load_task→OpenDrawer或PourWater/TransferWater.step→120Hz physics callback→具体Checker.start_checking→BaseChecker。joint把位置按lower/upper化为0–100%，必要时翻转target，要求比例差<0.1且每physics-step百分点差<0.05；pickup要求相对初始y高度误差<5cm且每step y位移<0.1原生单位；orientation要求对象y轴相对世界y的角度误差<20度，稳定性检查同样是y位移，不是角速度。water用所有粒子落在cupShape世界AABB的比例，误差<10百分点、受约束杯偏离直立<30度，transfer另需两杯外spill<10%；pour只看原杯残余量。各条件需连续success_steps>steps_per_second*2，失败清零；末planner stage完成后最多再step 300次读success，callback已从reset启动，并未在末阶段重新开始2秒计时。horizon=2400是planner主循环tick预算，额外gripper等待及success period另计。eval写stats[fname]=1/0/-1、score=correct/total（0–1），-1包含timeout及捕捉到的例外并留在分母；console另乘100。0gt/1gt/2gt与use_gt旗标必须区分。

怎么接入我们的benchmark

可重用

NPZ字段／USD物理设置、语言与native continuous target、四类checker、两阶段policy／多stage planner、task/split/case成功记录。

需要转换

source绑v2+commit；case保留NPZ文件名、object/scene/state split、raw info和asset引用。创建cm↔m、wxyz↔xyzw、y-up↔z-up的明确转换，normalized learning goal与runtime target分栏。evaluator保存每步稳定性单位、hold ticks、planner耗时、GT介入、checkpoint及-1原因，水量保留particle-AABB proxy名称。

仍需补齐

ckpt_selection.py 204产生Python list、205直接.argmax()，在此静态路径不能完成best checkpoint挑选，需协调者处理且保留修补版本；本轮未运行确认。缺USD/material/fluid资产及实际NPZ manifest、其余具体task stage覆写的逐项核对。water AABB不是精确杯内几何或真实体积，须保留限制。GT log名称对任意use_gt组合未全区分；bare except把不同错误压成-1且已有score会跳过整个split，需追加设置hash／错误分类。README尚列demonstration generator为TODO。

P082 · RoboVerse

RoboVerse: Towards a Unified Platform, Dataset and Benchmark for Scalable and Generalizable Robot Learning

返回逐篇总表内核内容已核读 benchmark／数据／评测主来源原作 ↗ 用途与原生规模依据

核读快照 2026-10-11。已读范围限所列片段；本轮未运行上游程序。

RoboVerse官方repo已确认，但2026固定commit的MetaSim、trajectory reader与generalization level均有版本变化。已闭合maniskill.pick_cube config-port的初态→PositionShiftChecker→IL SuccessOnce聚合，另读Zarr产生／加载链。发现NaN可令整批checker成功、L2/L3与paper定义错位，以及trial尾批／normalizer切分问题。

版本与身份

固定RoboVerseOrg/RoboVerse@5f3ec0185d2d3bcb59d53b0bd1f5b0f8a6f2ce14（2026-09-08），对应paper 2504.18904v1（2025-04-26）的官方延续repo，而非paper原始实验pin。README如今把MetaSim与RoboVerse分成同tag发行的两套package；trajectory v2/v3、native/config ports与generalization protocol各自记版本。旧usage的RandomizationCfg不可直接作现行DRConfig schema；本轮只选读所列task／data／evaluator。

固定paper为Geng等人的RoboVerse: Towards a Unified Platform, Dataset and Benchmark for Scalable and Generalizable Robot Learning，arXiv:2504.18904v1（2025-04-26）。PDF指roboverseorg.github.io，README 134–141题名、作者与arXiv一致，确认RoboVerseOrg/RoboVerse为官方平台。本文不等于较早同名RoboVerse环境，也不把集成的RLBench、ManiSkill、LIBERO、ARNOLD等数据算成新独立来源。

领域
居家整理与清洁、衣物与洗护、装配与生产作业、通用对象与机动作业
环境
平台把task/robot/scene内容放roboverse_pack，模拟内核在packages/metasim/metasim。已读范例是Franka提起4cm红cube，ScenarioCfg与runtime backend共同决定物理／相机／控制时间；不能赋予全平台单一FPS。eval创建camera0的256×256 RGB/depth并依task选pose。此maniskill.pick_cube是跨simulator config port，该基类文件明分它与*_native/SAPIEN3 official-demo port；未独立验证任何跨引擎parity。
任务
pick_cube alias与maniskill.pick_cube共用一个task，目标cube比reset初态沿z移动>=0.1m，最大250原生步；不要求抓持或放置。traj_filepath指roboverse_data/trajs/maniskill/pick_cube/v2/franka_v2.pkl.gz，下载helper在constructor被调用，本轮未运行。全平台registry条目、object variants、来源task、demo与benchmark trial必须分开；本轮未声称现行registry总数等于paper task数。
题数与数据
legacy v2内容为{robot_name:[{init_state,actions,states?},...]}，init/state是entity→pos/rot/dof_pos；actions支持dof_pos_target/dof_vel_target/dof_effort_target。v3转换只是把state分objects/robots、action包上robot名称；缺states仍可回初态+actions，但不能做state-anchored replay。现行get_traj按内容辨识、拒v1，遇roboverse.episode会要求load_episode另一API，不能只改扩展名。TensorState保存objects/robots/cameras；root/body state为[pos,quat,lin_vel,ang_vel]13维，joint数据与body_names需绑定，部分backend字段可None。另一路data2zarr读demo_NNNN/metadata.json及各camera.mp4（head_camera可退到rgb.mp4），用joint_qpos、joint_qpos_target或robot_root_state/robot_ee_state(_target)生成state/action；EE为robot-local xyz+wxyz+两指共9D，delta_ee另有相对quat。输出data/{camera,state,action}与meta/episode_ends，保留downsample/padding/action-space设置。RobotImageDataset从Zarr抽episode内sequence、相机值除255。未取得外部traj、MP4或Zarr，case数应依实际episode_ends／文件manifest，而非metadata要求处理的num_episodes。
评估方式
DefaultRunner.evaluate→get_task_class→ManiskillBaseTask→get_traj(v2→v3)→env.reset/checker.reset→BaseTaskEnv.step→handler.set_dof_targets/simulate/get_states→_terminated→PositionShiftChecker.check→util.get_pos。正常checker以reset差值z>=0.1m且总位移<=100m回bool，base reward仍为0，timeout另回。runner每个outer step运行joint action一次、EE action两次，仅读最后一次success；SuccessOnce是outer steps上的OR，SuccessEnd是末步，TimeOut只累积不停止个别env；全batch曾成功或max_step耗尽才退出。final_stats为SuccessOnce成功数/总完成数，并保存demo索引、DR level/mode/seed。选取demo靠task_id_range_low/high及max_demo，并没有自动套用paper90/10索引。现行DRManager确为L1 scene+material、L2加light、L3加camera，与paper／旧usage文件的L2 camera、L3 light/reflection不能同名比较。

怎么接入我们的benchmark

可重用

官方native task ID／aliases、ScenarioCfg、typed state/action、v2 parser和v3转换、metadata→Zarr链、具体checker及SuccessOnce/End结果。

需要转换

source保留paper v1与2026 code snapshot；task标config_port或native_port并连回ManiSkill等上游。case保存robot、task、原demo index、asset/初态hash、backend、控制步长及DR实际factor，不只存level数字。明分v2磁盘trajectory、v3内存state、roboverse.episode与IL Zarr四种界面；保留joint名称／单位、wxyz、camera座标及EE local/delta语义。

仍需补齐

PositionShiftChecker 219–221只要cur_pos任何元素NaN就回整批True，沿此task链会被SuccessOnce计成功，需先修补并标版本。尾批demo_end_idx只截到num_demos、不截到要求的low+max_demos，SuccessOnce分母固定num_envs，需核对超额或不满批处理。RobotImageDataset normalizer.fit吃全buffer而非train mask；get_validation_dataset取downsample后train_mask的补集，可能把未选训练episodes纳入val，需固定真正paper split。尚缺2025实验commit/资产/90-10 case清单及旧L2/L3到现行factor对照；v1数据已明示不支持。

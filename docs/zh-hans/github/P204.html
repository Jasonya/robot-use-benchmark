P204 · S-EMBER

S-EMBER: A Large-Scale Benchmark for Streaming Egocentric Memory Retrieval

返回逐篇总表内核内容已核读 benchmark／数据／评测主来源原作 ↗ 用途与原生规模依据

核读快照 2026-10-11。已读范围限所列片段；本轮未运行上游程序。

官方 S-EMBER 已有具体 JSONL reader、五选一 scorer、temporal IoU 与 optional Gemini judge；核读专用 sember task 及两条模型／API 路径。此 commit 预设只回报 MCQ accuracy 或 mIoU，尚未实作 paper v2 的完整 clean／overall／hallucination／R@1／GQ 协定；另有缺片降为纯文字与 judge 异步错配等集成问题。

版本与身份

固定 code 18db1323a60c86f50d9cf91df2083237a9895c50（2026-07-08）早于 paper 2607.02689v2（2026-08-26）。pyproject 标 lmms_eval 0.7.1、task metadata 0.2；Qwen runner 预设 uniform_nframes=768、fixed_frame_pixels=786432，而 paper v2 主表是 open models 128 frames。此读取范围不是整个继承 framework 或所有外部 decoder 已核。

pinned arXiv:2607.02689v2 首页直接指定 facebookresearch/S-EMBER 与 facebook/S-EMBER dataset；README 题名、作者及 arXiv 对应一致。仓库包含 lmms-eval 的其他 task，但本篇只追 lmms_eval/tasks/sember 与其直接调用；没有把 FALCONBench 等继承 task 当成本篇数据。

领域
居家整理与清洁、餐饮与烹饪、零售与购物
环境
613 名用户以 Ray-Ban Meta 录下日常人类第一人称、visual-only 观测。论文的 2,090 fine-grained scenario labels 合并为 33 activity categories，均非可运行场景资产或去重实体场所数。
任务
原生八类为 location_trace、sequential_action、counting_objects_events、visual_detail_recall、temporal_ordering_recognition、time_duration、object_comparison、spatial_aware_reasoning。两个 task entry 是 sember_mcq（五选一）与 sember_grounding（答案＋证据时间段）；同题三种 verbosity 参考答案及 MCQ 变体不产生三倍独立 case。
题数与数据
两个 YAML 以 datasets.load_dataset(path="json", data_files={test: data/sember_*.jsonl}) 加载 test split。程序按 SEMBER_VIDEO_DIR/<video_id>.mp4 取视频，忽略 HF 的 video 路径栏；doc_to_visual 产生 {video_path, video_end: question_time}。MCQ 使用 question_id、question、options、correct_letter（scorer 可 fallback correct_index）、question_category；grounding 使用 answer、answers[].answer_text、answer_start_time／answer_end_time，并保留 memory_recency、answer_range、duration、video_category。question_time、证据区间及 duration 以原片秒为单位；未做跨视频共用时间轴。论文／README 报 9,448 QA、3,141 videos、388 小时，本轮未下载 HF JSONL／视频，未把这些数字宣称为本地验算。
评估方式
MCQ parser 优先接受单一 A–E，否则取第一个独立字母；空白／不可解析为错。aggregate = 100×答对数／所有传入结果，另印每类 accuracy／parsed 数，并非八类 macro。grounding 只解析 Answer: 与 Time:[非负数,非负数]；IoU = max(0,min(end)−max(start))／(max(end)−min(start))，缺 GT、无法解析或 union≤0 均为 0。mIoU = 100×IoU 总和／所有结果，未解析仍在分母，未裁到 question_time／duration。API summary 同样把 FAILURE 留在分母；--max-samples 限制后只对该子集计分。optional judge 收集 answer 与 answers[].answer_text，以任一可接受答案匹配；CORRECT／WRONG／UNPARSED／ERROR 均入 total，仅 CORRECT 入分子。paper v2 的 Acccl、Accov、hallucination union-check、R@1≥τ 及 GQ@τ 并未在上述专用公开 scorer 实作；其论文主表以原始 IoU 0–1 报告，而程序回传 0–100。

怎么接入我们的benchmark

可重用

可重用原生八类、两个 task YAML、JSONL loader、per-question logs、五选一 parser／deterministic IoU 作待修正的原生 evaluator；保留完整／缺片子集与 API／local 路径。

需要转换

source 记 paper v2、repo commit、HF 另行固定的数据版本及 lmms-eval 衍生关系；domain／environment 从 video_category_broad／video_category 分层，不能将 2,090 labels 当 scene assets。case 以 question_id 关联 video_id、question_time、options／answer variants 与多 reference intervals，MCQ／grounding 共用 parent QA。evaluator 各自保存 score unit、全分母、parsed／failed／缺片数、可见 prefix、frame/pixel budget；追加 paper v2 的各分项与同题 joint GQ，保留和旧版 scorer 的差别。

仍需补齐

HF 原生题目／视频 manifest 及数据 revision、有效题数验算、缺片一致处置、strict schema／timestamp validation、judge ID 对齐与 parser 修正、完整 paper v2 metrics 接线。Qwen 的实际解码委派 qwen-vl-utils>=0.0.14，未固定精确版本；需另验证采样时间／外部 reader 的 cutoff，不宣称已完成 runtime 重现。

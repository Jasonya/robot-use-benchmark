EmbodiedMemory-Bench: Benchmarking Embodied Memory for Long-Horizon Embodied Tasks

返回逐篇总表内核内容已核读 benchmark／数据／评测主来源原作 ↗ 用途与原生规模依据

核读快照 2026-10-11。已读范围限所列片段；本轮未运行上游程序。

循官方 project 搬移页确认 ZJU-OmniAI/Embodied-Omni 的 embodied_memory/ 为本篇公开程序，已追 manifest loader、history sanitization、simulator runner、四家族具体 success／ERR 与 macro 分母。HF 有 frozen release，但公开 loader 与发布路径不一致；code 亦将任一 ERR 视为不能成功，与 paper 的可恢复终态 SR 有实质差异。

版本与身份

code 固定 f0409a8ecd858acd1f53c69f6424e0c4af83737b，只核 embodied_memory 子项目。HF 固定 3b45bd3f3a67a23b09b78d27c3ab563a700e832a；README 说公开 episode-level 名称／描述／probe instructions 已英文化并更新 hash，原语言 revision 为 28694bf83b78049ac96ba01c9ffb13aeac7eaef9，不能混用。HF canonical manifest SHA256=6c69644b9fc4755065830e4884a12898e3ed0db32c1825dbecf623c37b9b1bc2 是发布者 metadata 声明，本轮未下载 full2554 逐例重播验算。

pinned arXiv:2609.28236v1 题名及 Lizhou Liang 等作者与 embodied_memory/README 一致。PDF 原始 ZJU-OmniAI project 转址到 Embodied-Omni/EmbodiedMemoryBench，新页直接连官方 monorepo 与 lzLiang/EmbodiedMemoryBench；不将参考文献的 OpenBMB/MiniCPM-V 当成 benchmark。只核本篇 embodied_memory 子树，未扩读同 monorepo 的 reasoner／navigator。

领域
居家整理与清洁
环境
AI2-THOR 单房间组合的多房间脉络与 ProcTHOR 场景；论文 Table 9 报 1,118 个 globally unique source scene IDs、四 room types，不能加总各家族重叠 scene counts。当前 env 以 probe.scene reset，使用 500×500 RGB、visible_objects、agent_state、available_actions 与高级离散目标动作。原生 x/y/z、objectId、rotation_y（0–360）及相机角度须保留；不把 Navigate／PickUp 等界面当连续机器人关节控制。
任务
manifest 四家族 l2_passive、l2_dynamic、l2_interaction、l3_owner_habit 分别对应 Passive Observation、Dynamic Tracking、Interaction Failure、Experience Generalization。probe_retrieve／probe_track_location 要到记忆位置并拾取目标；probe_avoid_failure 要选非已知锁定容器存放物品；owner_habit 以先前 correction 对新对象选择合规 receptacle。construction schema 的 L0–L3 enums 不等于四个发布家族。
题数与数据
data.load_manifest 读 JSONL 的 id、family、source.episode_path、source.episode_sha256；拒绝重复 id，先依 family／per_family 选择，再检查 episode 档与可选 SHA256。run 另以 source.probe_id 精确配对一个 probe。episode JSON loader 是 json.load；schema 含 episode_id/name/difficulty、sessions[].context_trajectory.steps[] 的 step_id/image_path/visible_objects/agent_state/action/feedback、micro_probe 或 macro_probe，以及 hidden_rules／memory_cues／expected_actions／evaluation_hooks。时间原生单位是有序 session／step，非视频秒。paper 与 HF metadata／audit report 同报 2,554=1,036+1,052+263+203、split=all；本轮仅机械清点小型 experience_generalization manifest 的 203 个唯一 id，未重新验证全部 2,554 episodes。
评估方式
实际链为 CLI evaluate→load_manifest→run.evaluate→env.step→EpisodeEvaluator.evaluate_probe。env 为每次 action 尝试记 success／feedback，无效动作及 Done／Stop 也计入 actual_steps；预设 8-step budget 覆盖 schema 的 30／60 预设。success 读 simulator world_state 的持物／parent／状态并核对成功运行的导航或放置；L2 可接受原生指定的同类且同记忆容器对象，owner_habit 保留 executable receptacle alias。ERR 只比对成功动作的 frozen triggers，L2 是先去不同 receptacle type、interaction 是重复已知错误 action–target、owner_habit 是违规放置；每 subtask ERR=min(1,触发数/max(1,required_memory_integration 数))，probe 对 subtasks 平均。run.summarize 以每家族 task_completed 布尔值／已记录 rows 计 SR，再对实际出现家族等权 macro；ERR 同样先家族平均。不能将 smoke 选样或中止前 summary 当 Full-2554。InvalidPhaseOutput 保留作该例失败，infra exception 写错误并中止，不产生新的完整 summary。RAR/AES/MAE 是附带 diagnostics，不等于 paper 主 metric。

怎么接入我们的benchmark

可重用

官方 frozen manifest 身分／family／hash、episode schema、session-step 脉络、模型可见字段过滤、动态 action registry、trace 与具体 state／ERR evaluator 可重用；case、probe、action attempts 需分开。

需要转换

source 同时记 paper v1、GitHub commit 与 HF revision；domain／environment 保留 room type、host simulator、scene provenance 与重用关系。task 维持四家族／probe 规则；case key 用 manifest id 及 episode_id+probe_id，另以 organized_view 建可携 execution_path，不覆写原研究路径或 lineage。history/action/feedback、model-visible context 与 evaluator-only rules 分开映射；evaluator 保存 terminal-state SR 与此版 ERR-veto SR 差异、逐类分母、8-step／80-per-session budget、grounding repair 与实际 world-state。

仍需补齐

修正 published manifest→loader 路径桥接、核对 ERR-veto 与论文 scorer、全 release hashes／素材／scene reset 闭合、完整 runtime 及同一预算重现。单一 nested episode 尝试超过本轮 512 KiB 小文字上限，已停止且保留 receipt；不把该档视为已读或不存在，亦未下载 RGB／模型／simulator。

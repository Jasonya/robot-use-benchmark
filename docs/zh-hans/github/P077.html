P077 · CLIPort

CLIPort: What and Where Pathways for Robotic Manipulation

返回逐篇总表内核内容已核读 benchmark／数据／评测主来源原作 ↗ 用途与原生规模依据

核读快照 2026-10-11。已读范围限所列片段；本轮未运行上游程序。

CLIPort已追到Ravens/PyBullet的bowl／rope任务、示范读写与Task.reward/is_match。mean_reward可含部分分数；bowl文字目标与checker有一对一配对落差，且eval没有按episode seed重设Python random，不能保证完全重建示范语义变体。

版本与身份

本轮固定cliport/cliport@2be5c47b5bb9bb7040ad90693288b87b1e18e7ad（2023-05-22），晚于2021v1；未取得论文实验的逐项commit对照。README承认部分seen/unseen train相同、多任务Google对象训练集较小及旋转augmentation与方向语句冲突。记录的是所列选读区段；不声称全仓库／完整数据／实机实验已验证。

固定论文为 Shridhar、Manuelli、Fox 的 CLIPort: What and Where Pathways for Robotic Manipulation，arXiv:2109.12098v1／CoRL 2021。PDF 的 code-availability 指向 cliport.github.io；仓库 README 1–9 同时吻合题名、三位作者、arXiv 与项目网址，足以确认 cliport/cliport 为本论文官方程式。openai/CLIP 与 Ravens 是重用依赖，不能另算 CLIPort benchmark。

领域
包装、仓储与物流、通用对象与机动作业
环境
PyBullet 桌面 UR5／预设吸盘；agent有三个480×640无噪RGB-D视角，oracle另有俯视图像与segmentation。示范与评测入口将physics设为480Hz，但每笔数据是完成pick/place primitive并等待物体静止后的决策步，不能当480fps视频。工作区x=[0.25,0.75]、y=[-0.5,0.5]公尺；Task bounds的z上限0.3，dataset/action bounds为0.28，需按用途保留。实机Franka结果不等于此UR5环境可直接重播。
任务
任务文件的10个goal-conditioned家族需与seen/unseen/full属性子集及seq流程分开。已读PutBlockInBowl：随机1–3个碗、1至碗数个block、6个distractor，语言指定两种颜色；goal=(objects,matches,target_poses,replace,rotations,metric,params,max_reward)，步数重设为blocks+1。seen与unseen类别在train均取TRAIN_COLORS，unseen只在非train改EVAL_COLORS。AlignRope是20节绳／四种边方向、可正反向匹配；节数、语句变化与生成seed均不能当添加任务数。
题数与数据
RavensDataset把同一episode写成color/depth/action/reward/info五个目录下的{episode_id:06d}-{seed}.pkl；color为uint8、depth为float32公尺。串行元素为(obs,act,reward,info)，最后一笔act=None；reward是到达该obs的前一步回馈。act.pose0/pose1各是(position_xyz公尺,quaternion_xyzw)；info含lang_goal及object_id→(pos,rot,dimensions)特权状态。读入后以3.125mm/pixel融合成320×160×6 RGB+重复三次height，p0_theta固定0、p1_theta为相对负yaw（弧度）。seq以i+1为goal，其他任务用末帧。train seed从0每次+2，val从1、test从10001每次+2；只保存oracle总reward>0.99，实际case数须枚举落地文件，不能用要求生成的n或README估计值替代。
评估方式
callchain：eval.main→ds.load(i)/seed→env.reset（Python random非逐case重设）→最多task.max_steps次env.step→Task.reward→is_match或zone点覆盖。pose逐object在可配对target中找到任一匹配即加max_reward/objects；is_match只看XY距离与对称性处理的z-yaw，不看高度，bowl容差0.05m、rope0.02m。zone算局部座标点落入矩形范围且低于z上限的比例。reward为累计完成度差值，完成当前goal后弹出相应语言；done是goals空或_rewards>0.99，primitive timeout也会直接done=True且reward=0。结果JSON保存episodes=(total_reward,last_info)与mean_reward；预设n_demos=100、n_repeats=1，test_best依val mean_reward选模型（未找到则last.ckpt）。因此不得把done、mean_reward与二元success混用。

怎么接入我们的benchmark

可重用

重用task class与原生属性切分、goal tuple、语言顺序、episode seed、相机与pose-action字段、具体reward/checker。

需要转换

source绑paper edition+commit；environment绑资产／相机／物理设置；task保留家族及seen/unseen/full/seq；case以task+mode+seed+示范文件识别并保存五档引用；evaluator分列delta_reward、total_reward、done及终止原因。把世界座标、公尺、xyzw、heightmap投影和特权info可见性写入profile；同一train数据的seen/unseen别名记reuse关系。

仍需补齐

尚未闭合Google Scanned Objects修改COM后资产、所有case档与实机采集格式。PutBlockInBowl注解要求每block放不同碗，goal也设replace=False，但reward丢弃replace并逐对象独立匹配，不消耗target；加上只验XY，需协调者明列原生checker限制，不能宣称严格一对一装碗或3D落碗验证。val_best只取目录第一个匹配results-val档，且n_repeats共用同checkpoint／case seed，需固定文件与replicate定义才能可比较。另有seed再现性缺口：demos.py同时以episode seed重设np.random与Python random；eval.py只在repeat开始用train_run调用utils.set_seed，逐case仅重设np.random及env.seed，而env.seed只创建self._random。PutBlockInBowl等任务的random.sample颜色未按case重设，因此存下seed不等于已验证同一示范场景／语句；需保存或修订完整RNG协定。

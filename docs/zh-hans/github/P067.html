ManiSkill2: A Unified Benchmark for Generalizable Manipulation Skills

返回逐篇总表内核内容已核读 benchmark／数据／评测主来源原作 ↗ 用途与原生规模依据

核读快照 2026-10-11。已读范围限所列片段；本轮未运行上游程序。

原ManiSkill2网址目前只是搬家说明；实作应固定mani-skill/ManiSkill的v0.5.3。它把episode设置、HDF5轨迹、JSON信息和原生success评测分开保存。 2026-10-11 另补读 ManiSkill2-Learn 的 BC 数据与单程序评测入口，与主 benchmark 的 v0.5.3 契约分开记录。

版本与身份

v0.5.3解析到commit493be361…；最新main是ManiSkill3，因此每个来源链接都带ref/commit。 Learn 固定 e9860aff595da3ad34829d62c923be0b50001427，与主 benchmark v0.5.3 的提交分开；其 README 指明 0.5.0 起改 Gymnasium，较旧环境用 ms2_gym 分支（本次未核读该分支）。README 另说早期 checkpoint／环境 0.3、0.4 的 RGBD camera order 不同，须保留实际 wrapper／观测版本，不把 Learn、ManiSkill2022 challenge 或 ManiSkill3 当成同一版主 benchmark。

领域
居家整理与清洁、装配与生产作业、通用对象与机动作业
环境
SAPIEN任务依env_id、asset模型、reset_kwargs和control_mode创建；柔体另外依赖原作Warp版本。
任务
注册的env/task与原作家族保留其单位；不是每个asset模型、随机seed都增加一个基础任务。
题数与数据
HDF5 traj_id配合JSON episodes/env_info；reset初态使观测／env_states比actions多一笔。depth以uint16保存，原作写入前乘2^10，必须保存这个尺度。 补读 Learn：tools/convert_state.py 依 HDF5 traj 后缀寻找 JSON episodes 的 episode_id/reset_kwargs，逐 state 重建刚体观测，或由 env_init_state 重播动作取得柔体观测；控制模式须先在主 ManiSkill2 转好。输出为 T 笔 obs/actions/rewards，dones 直接来自原 success，episode_dones 仅尾笔为真，next_obs 要加 --with-next。输出 traj_{cnt} 重新编号，须另存原 episode 映射。BC 的 buffer_filenames 范例仍是 SOME_DEMO_FILE；ReplayMemory→FileCacheWorker 实际读 HDF5 groups，num_samples 限制每档前几条排序轨迹，-1 才是全部，不能称为随机 split。
评估方式
Evaluator按episode_cfg的reset_kwargs重建，终止时读info.success等scalar；PickCube示例要求对象放到目标且robot静止。reward、terminated、truncated不互相替代。 补读 Learn 的独立路径：run_rl.py --evaluation／--resume-from→build_evaluation→Evaluation.run；单程序策略预设 mode=eval，BC 范例 num=10、num_procs=1 只是设置值。live step_dict 把 terminated 命名为 dones，以 terminated OR truncated 判 episode_dones；Evaluation 在终止那一步把 dones 记为 finish，statistics.csv 存 length/reward/finish，显示的是 mean(finish) 的「Success or Early Stop Rate」。此 caller 并未直接取 info.success；只有绑定环境的终止契约相符时才能解作成功率。only_save_success_traj 筛存盘、不缩减 statistics 的所有已评 trial 分母；与前述主 benchmark Evaluator 的 info.success 分开。

怎么接入我们的benchmark

可重用

env/task IDs、episode ID、reset kwargs、control mode、HDF5/JSON及原生success。 可另重用 baseline 的 HDF5 视觉转换、ReplayMemory 输入及 length/reward/finish 原生报表。

需要转换

原始T+1观测与T个transition保留对齐；深度尺度、obs mode、state、success、时间上限分栏，不用共通dtype猜单位。 另保存 Learn commit、checkpoint、实际 env_cfg、seed、num/eval_levels、sample_mode 与输入／输出 trajectory ID 映射；原 success、示范 dones、live terminated/truncated/finish 分栏。FileCache 的 purify_items 可补 worker_indices、把 dones 转 bool，并将读取片段末项 episode_dones 设真，不能依训练 buffer 片段另增物理 episode。

仍需补齐

完整资产／示范闭合、共同split血缘与本库eval adapter验证。 Learn 的示范／checkpoint／资产未取得或运行；需替换示例占位路径、保存完整 reset／split 血缘，验证控制模式、观测处理与主 benchmark 的 success／终止关系。converter 的 obs_frame 预设 base，而 make_gym_env 预设 world，数据生成／训练／评测都需显式对齐。

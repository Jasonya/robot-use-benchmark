Real Garment Benchmark (RGBench): A Comprehensive Benchmark for Robotic Garment Manipulation featuring a High-Fidelity Scalable Simulator

返回逐篇总表内核内容已核读 benchmark／数据／评测主来源原作 ↗ 用途与原生规模依据

核读快照 2026-10-11。已读范围限所列片段；本轮未运行上游程序。

这是服装模拟fidelity评测，不是学习policy的task-success榜。已核读98-capture registry、processed CSV／PCD reader、PyBullet fixed-point回放、具体Chamfer／stability计算与两阶段聚合；GarmentDynamics本体仍只有外部import插槽及已发布baseline数字。

版本与身份

固定2026-07-30的5cc3d072。公开来源是evaluation harness加asset子集，不能将paper『Ours／mujoco_style3d』baseline当成此repo可跑的普通MuJoCo。比较脚本扫描所有timestamp run且aggregate时丢robot、按garment/action/simulator/mode平均，重复sample会被重复加权。n_samples亦非处处3。现有cloth params依GarmentDynamics拟合，跨sim使用须保留校准协定。未下载6.7GB数据、checkpoint或运行sim。

arXiv:2511.06434v2（2025-11-12）首页 → rgbench.github.io → hwk0809/RGBench；README的AAAI2026题名与作者相符。网站模板eliahuhorwitz/Academic-project-page-template与Nerfies不算benchmark来源。

领域
衣物与洗护
环境
真实双臂衣物操弄capture与同一动作的cloth simulator配对。公开数据文件列Piper／RealSense D455，固定PDF则描述Piper或JAKA K1／RealSense L515，应保存各版本capture硬件证据。fixed_point以录制末端位置驱动mesh anchors；robot mode包含robot tracking/contact。所读PyBullet wrapper在grasp/fold读取position并把grabber orientation固定identity，不能直接宣称完整6DoF姿态精确重放。普通MuJoCo仅fixed_point；GarmentDynamics不等于普通MuJoCo wrapper。
任务
Grasp、Fling、Fold三种原生动作；native case key=(garment,action,robot,sample_id)。静态解析完整experiment_library得到9 garment keys、98 entries、98个不重复data_subfolder。baseline CSV有105行：fixed_point三动作各21行，robot的fold/grasp各21行，缺robot-fling的21个cells；runner也明示fling只支持fixed_point。baseline只有7件衣物，grey_sunwear／khaki_blazer的数据仍有但未入baseline。PDF6k+ mesh assets=4k+自有工业assets+2k+ ClothesNet来源，不是6,000个task或capture；mesh分辨率variants亦不增加衣物数。
题数与数据
每capture含calibration/world_to_camera_transform.json、两臂joints/*joint_states_and_end_pose.csv、segment_pcds/pointcloud_<absolute_timestamp>_segmented.pcd；mesh另由HF来源供应。实际load_processed_data要求time、pos_1…pos_gripper，或pos_x/y/z、orn_w/x/y/z；文件列header.stamp.secs/nsecs及JSON position/name是另一层ROS输入约定，不可直接喂此reader。pose输出quaternion=wxyz，base_rotation_quat输入给SciPy用xyzw，位置以R_base_to_world.apply(local)+translation组合。PCD由camera_to_world=inv(world_to_camera)转世界座标，timestamp减master_start_time。main逐一遍历PCD，再用target_time+camera_delay+fling_prepare_time+fling_wait_time推进sim；不是重采样成共同FPS。保留原seconds、delay、sim step大小、record/calculation windows与point/vertex数。
评估方式
compute_cost输出单向Chamfer L1 sim→real及real→sim、L2 sim→real、双方向one-sided Hausdorff、sim_stability_score及两点云平均z差绝对值。Chamfer L1是每source point找Manhattan nearest distance后平均；L2用Euclidean距离而非平方距离，单位维持m。CPU/GPU对Nx3路径同义，但batch输入CPU只取[0]、GPU平均batch，不能未验证就扩成batched evaluator。stability实际将同一frame vertices[1:-1]与相邻vertex-index三点均值作L2偏差，再除总vertex数N，并非跨时间稳定性。HD委派point-cloud-utils且未传norm，PDF公式却写L1；pyproject只限>=0.30，本轮未锁定/核读该依赖版本的HD实作，norm一致性列为缺件。record window决定计算哪些frame，calculation window再按sim_time取mean/std；benchmark primary fidelity metric为cd_l1_r2s。空sim mesh frame会跳过，低于z门槛的vertices函数只警告仍原样返回。这些误差不能转成操作success率。

怎么接入我们的benchmark

可重用

98个capture registry／每case时间窗、world calibration、CSV pose与PCD reader、BaseEnvWrapper到具体sim stepping、方向性Chamfer与result schema。

需要转换

source分capture dataset、工业asset subset、ClothesNet重用与code commit；environment保存sim engine/version/mode、robot／sensor、mesh/material；task记动作primitive；case用capture key，simulator/mode/mesh resolution是trial条件。evaluator分direction/norm/unit、raw frame errors、window mean/std及跨sample mean。保存case frame coverage、camera delay与calibration SHA；不要把105列baseline或不同sim run倍增case。raw ROS→processed CSV明示转换，保持wxyz/xyzw与base-transform方向。

仍需补齐

HF capture／mesh与校准档的实际revision及完整性验证；GarmentDynamics本体、完整工业library与不同component条款；HD norm／依赖pin；spatial vertex-order stability的指针命名或实作厘清；数据文件与processed CSV／capture硬件版本对齐；重跑sample去重、mean/std尾列存在性与跳过frame的coverage检查。

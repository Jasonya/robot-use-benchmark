P240 · ANTICIPATR

Rethinking Learning Approaches for Long-Term Action Anticipation

返回逐篇总表内核内容已核读 方法／综述参考原作 ↗

核读快照 2026-10-11。已读范围限所列片段；本轮未运行上游程序。

已沿ANTICIPATR的TSV/feature reader→instance-set预测→timeline／集合前处理→evaluator核读。其future比例以剩余视频为基准，与P236/P237的全视频比例不同；公开commit的scorer链还有会阻止合法计分的变量、shape与case键错误，不能宣称直接重现论文结果。

版本与身份

固定 a7f0af215f50680e6b784df195a17884cb520bbf（2023-04-06）。论文§4与附录A.1.3定义remaining-length protocol及dense重建，与其引用的全长比例benchmark需分项对待。主评测应保留模型提出的instance集合；loss配对不是scorer，loss_segment/loss_siou以跨rank平均target instance数（至少1）范式，不是case成功率。仅核内核source区段与小型原生文字数据，未安装、加载pickle／checkpoint或跑上游模型。

Rethinking Learning Approaches for Long-Term Action Anticipation，Megha Nawhal、Akash Abdu Jyothi、Greg Mori，ECCV 2022；缓存arXiv:2210.11566v1（2022-10-20）。PDF p.3直接连Nmegha2601/anticipatr，README列同题名作者。原生方法是两阶段Anticipation Transformer；不是固定20个verb–noun的Ego4D LTA。

领域
方法／综述参考，未另作来源用途归纳。
环境
脱机人类活动：Breakfast/50Salads第三人称烹饪；EK55/EGTEA Gaze+第一人称厨房。此release的stage2 build_dataset只注册bf与ek，50Salads/EGTEA虽有pretraining名单及论文结果，不能视为stage2已接通。
任务
预测未来action instance集合，每instance是(label,start,end)，query数是最多预测槽数，不是任务数。stage1 snippet anticipation、stage2以冻结snippet encoder配合video encoder/decoder是论文方法关系，本次内核核读以stage2数据／计分为主。Breakfast时间条件dense timeline评测；EK55时间无关future-label presence评测。固定Breakfast词表48类含SIL；EK示例容量125 verbs/352 nouns/3806 actions，many-shot档实际26 verbs/71 nouns，不能照ek.py的旧注解32 nouns。
题数与数据
名为.csv的split实际无header、tab分隔：video_path,start_frame,end_frame,verb_id[,noun_id]；另*_nframes.csv是video_path与全长frame数。DatasetSegmentRecord.num_frames=end-start+1。外部feature pickle是video→frame_index→2048维矢量，reader不载RGB；目前切取range(start-31,end+31)中存在的key，会涵盖观测终点之后至+30的feature index，须验证提特征的时间支持域。局部fps=1只是idx模数，不能解读为1Hz；CLI fps预设60。target含video_id、labels_onehot、instance labels、label_mask、segments、duration、prediction_duration、observation_duration、ratio_idx、prediction_idx、observation_positions、fps；segments=(native_start/end-observation_duration)/prediction_duration，duration以秒存，observation/prediction_duration仍是frame数，单位混用不能抹平。EK action ID依各自CSV中的verb/noun频率另建int_to_idx，可能造成train/val ID漂移。
评估方式
实际入案：只取end<=t的完整past与start>t的future，且各至少3个action；Breakfast future另需end<=pred_t，跨边界action被排除。EK α=.25/.5/.75预测全部remaining；Breakfast α=.2/.3、β=.1/.2/.3/.4/.5，pred_t=t+int(β*(T-t))，论文表只报β=.1/.2/.3/.5。以固定val_S1文字档依相同条件作结构重算（未载features）：Breakfast252视频/1548segments只产生12个窗口、5个video keys；EK67视频/7742segments产生172窗口、60个video keys。这是入案逻辑统计，非成功跑分。模型输出pred_logits[B,Q,C+1]及pred_segments[B,Q,2]；后者实作ReLU+0.1，并未保证<=1或end>=start。get_unrolled_timeline将segment乘prediction_duration，重叠处逐类取最大softmax，去no-action后argmax；却把整个future multi-hot label拷贝到所有时间位置当GT，未重建instance的逐格GT。get_mAP再把timeline presence加总clip至0/1，外层预定调用sklearn average_precision_score macro/micro；get_accuracy预定用1-hamming_loss按class平均×100，不能等同论文的class-normalized逐格MoC。snapshot的get_accuracy写acc[k]但k未定义，get_AP_perclass未初始化preds[k_ap]/targets[k_ap]便append，get_accuracy_perclass对1D数组argmax(axis=1)；所以没有可认定正确的实际评测分母／合法输出。engine更以video name为唯一key覆写不同α/β窗口；单process下前述12/172窗口最多只留5/60笔。

怎么接入我们的benchmark

可重用

版本化TSV与length table、dataset-specific video_id、instance(label,start,end)、观测／future比例及原生query输出界面；普通temporal IoU函数可作原生定义参照。

需要转换

source记paper/commit及EgoTopo/MS-TCN feature来源；domain/environment保留view与dataset；task分instance-set模型、dense timeline与future-label set评测；case键必须包含dataset/split/video/α/β与有效窗口，而不只video。frame、秒、normalized-future座标分栏，native inclusive标注与rasterizer [start,end)保留差异；global action mapping与many-shot mask另版本化。evaluator必须重建合法GT timeline与每类正确/总GT格数，或保存per-case presence及score以计AP；β剩余长度协定不可直接换算成P236/P237表格同一格。

仍需补齐

优先修复criterion/evaluator未定义变量、mask形状、GT timeline与engine窗口覆写，再确认macro/micro／空类／frequent/rare的分母。须固定global action ID，noun分支instance["nouns"]与创建时"noun"也不一致。确认末端+30 feature索引是否越界可见、实际feature pickle及stage1 checkpoint版本、min-three入案排除，并取得50Salads/EGTEA的stage2 reader/scorer。build_matcher永远回GreedyMatcher，CLI hungarian未接；generalized_segment_iou只算普通IoU；greedy将targets依长度排序后未还原原索引，需对照label配对。以上静态疑点尚未运行验证，不可把程序已下载当可重现。

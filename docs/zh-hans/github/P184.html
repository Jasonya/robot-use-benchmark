DLO-Lab: Benchmarking Deformable Linear Object Manipulations with Differentiable Physics

已核读8-task registry、原生RL/DiffRL action与时间约定、coiling/lifting/wrapping的具体reward、trajectory aggregation，以及LeRobot导出／读取。原生episodic return、存活到horizon的diagnostic success及论文视频人工success三者不同；生成示范的过滤也只排除absorbing，不证明任务完成。

领域
装配与生产作业
环境
Genesis衍生的Taichi differentiable rod simulator，ROD material可设E/G、segment radius/mass、接触friction与塑性；场景配Franka、cones/posts、rings等。coiling具体为60个rod vertices、间距0.02 m、radius0.01 m与固定cone，control_idx=[1]在reset直接attached_to_gripper，不能视为已包含自由抓取成功。scene dt=0.001 s、substeps=5；一次policy action跨steps_interval个scene steps，须另保留此数与split，不以视频fps推控制频率。
任务
registry正好8个固定horizon任务：coiling、gathering、lifting、separation、slingshot、unknotting、wiring_post、wrapping。论文第6页另列Letter Art与Wiring-ring，属DLO agent的长时程分解实验，未在此8-task registry中，分开建task来源／协定。grasp候选、rod nodes、posts、robot arms与rollout次数都不是task数；未取得固定case manifest，案例总数不填虚构值。
题数与数据
RL privileged observation按(rope vertices+additional objects)×6+grasp points×14，包含位置／速度、末端pose及arm joints；RL action每control point 6D，先乘_act_magnitude、clip、L2限制，再拆xyz／rotation，Pink controller预设translation=m、rotation=degrees。DiffRL只有每point3D translation并从rope vertex反传，不能共享同一action schema。数据导出另统一为observation.state float32[16]、action[12]、action.joint[18]，单臂左侧zero padding；action排列[right_xyz,left_xyz,right_rot,left_rot]。相机front/wrist_right/wrist_left，单臂wrist_left为黑图，不是第三个真实视角。timestamp=step_idx×scene.dt×n_substeps_per_step；初frame有zero action，之后capture在step之后，末frame action/action.joint又拷贝前frame，必须保留原对齐。导出data/chunk-000/file-000.parquet、meta/info.json/stats.json/tasks.parquet、meta/episodes/...与videos/chunk-*/observation.images.<cam>/episode_*.mp4，split只声明train。filter reader只读consolidated file-000；需保持其前置条件。
评估方式
coiling reward=exp(−0.1Σv||v−(0,0,0.15)||)，是距离proxy而非绕圈成功。lifting reward=5×两环高度和+rope相对抬高项−0.5×rope到两环最近距离−100×末端距环小于0.08 m的penalty；loss_criterion另外含stretch loss，不能当相同分数。wrapping以xy-plane角度和／2π的绝对winding、与1圈的平方误差及到三柱最近距离超出0.015 m的penalty计reward。coiling eval_traj累加substep reward，另回final_reward及forward_time，NaN/failed final用survival_ratio−100；CMA可选cum或final做优化。PPO保存undiscounted return及末reward，diagnostic success_rate=(episode_length==n_outer_steps)，只是未提前失效。论文主表报固定budget内最大episodic return、3 seeds；附录像片人工success用每RL方法15条、GD1条、CMA最佳checkpoint的top15条。这些不是同一个自动success metric。

怎么接入我们的benchmark

可重用

8-task registry、具体reward/loss、scene／material／control-point参数、macro/micro-step约定、LeRobot字段与frame/video reader。

需要转换

source保存此Genesis衍生commit及外部dependency／asset来源；environment按DLO拓朴、材料、fixture、robot/grasp attachment创建；task保存原goal文字与reward program。case保存seed、randomization、grasp indices、horizon、algorithm、sampling budget及checkpoint；evaluator分cum_return/final_reward、simulation-survival及人工task success。数据另记arm_present／camera_present mask、原raw action及缩放后物理action、前后state/action对齐，task名称去重不靠生成episode数。

仍需补齐

assets与Mushroom-RL/Pink等依赖的完整pin／验证；论文视频success rubric／标注及top15选择名册；完整task checker覆盖；LeRobot产生数据的action-time与SHAC格式验证；data generation仅依absorbing过滤且在n_envs>1时用obs0选action后tile给各env，不能直接视为独立闭回路成功示范。

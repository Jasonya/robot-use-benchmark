RoboRecover: Benchmarking Robot Policy Recovery under Execution Deviations

返回逐篇总表内核内容已核读 benchmark／数据／评测主来源原作 ↗ 用途与原生规模依据

核读快照 2026-10-11。已读范围限所列片段；本轮未运行上游程序。

公开程序是 LIBERO／RoboTwin 的恢复起点、固定 split 与回放后推论 overlay。已核读 JSON reader、回放／新推论预算、LIBERO 成功传递与 RoboTwin 入柜任务的具体 checker；完整2,000个 scenario JSON 的托管仍待发布，两个 example 并非完整数据集。

版本与身份

固定 RoboRecover 089b942；LIBERO 延伸核读恰为 lock 指定8f1084e。lock 所有 historical_revision_verified 均为 false；README 指 LIBERO MuJoCo3.3.2／robosuite1.4.x、RoboTwin SAPIEN3.0.0b1，不可用 upstream 最新版代换。RoboTwin FastWAM／LingBot-VA recovery adapters 仍 pending；论文六政策结果不等于仓库六个可用 adapter。

收录论文为 arXiv:2609.28952v1，PDF 第1页直接连至 RUCKBReasoning/RoboRecover；README 的双平台、action-prefix recovery 与论文一致。README 第78行仍使用 CuteClaire/RoboRecover 拷贝网址，保留为别名待确认，不另算来源。

领域
居家整理与清洁
环境
LIBERO 的 MuJoCo 桌面任务与 RoboTwin 2.0 的 SAPIEN 双臂场景各自重用原 benchmark。LIBERO 依 suite/task_id 找 BDDL、episode_idx 找原生 init state；RoboTwin 依 task_name/task_config/seed、embodiment 与 camera YAML 初始化。scenario 是同一任务运行偏离后的起点，不另计为新的 environment 或 task。
任务
论文定义 Recovery Stage=Approach/Contact/Move/Place，Deviation Type=Wrong Target/Wrong Pose/Stage Rollback/Scene Change；实际两个 test CSV 都有9种 stage–type 组合，不是4×4皆存在。静态解析各200个不重复 test sample_id，LIBERO 含38个 task_name、RoboTwin 含34个；论文另述 train 涵盖40／42个任务。2,000是恢复 scenarios，两平台各800 train／200 test，不是2,000项技能。
题数与数据
split CSV 字段为 sample_id/path/sha256/original_sha256/actions/replay_prefix_steps/task_name/s_stage/d_stage；两个 example 的实际 SHA256 各匹配该平台 test 第一列。LIBERO JSON 包含 task_suite_name/task_id/episode_idx/seed、initial_state.xyz/quat/rpy/gripper、actions；RoboTwin 包含 task_name/task_config/instruction、initial_state.joint_vector/left_endpose/right_endpose/left_gripper/right_gripper 及 annotation_meta.frame_index/video_fps。验证器接受 LIBERO 7D、RoboTwin 14或16D action，qpos／ee 应另存 action_type；不可把 gripper 或范式 action 一律当公尺。reader 只在长于 annotated_step+1 时截取，不补短 prefix。LIBERO 模型输入是两视角 RGB、末端位置／axis-angle／gripper state；annotation video_fps=10 的 example 不代表所有控制频率。
评估方式
先以原 reset 重建，再回放 prefix、清空推论历史并给新的 S 步预算；正式设置 post-replay wait=0，prefix 不扣推论额度。LIBERO suite 预设预算 spatial/object/goal/10/90 分别220/280/300/520/400；RoboTwin 以原 task.step_lim 和可选 max_infer_steps 取较小值。LIBERO native done 来自 goal predicates；RoboTwin Base_Task 将具体 check_success 锁存至 eval_success，所读入柜 checker 要求 |dx|、|dy|各<0.05，对象比初高0.007至0.12且对应夹爪张开（原生模拟长度单位）。论文 Overall RSR 是每 scenario 成功数／排定 trials 后等权平均；Macro-9 再对9个 stage–type group 等权平均。程序 build_summary 按 task/error_type 直接累加 trial 并使用 eval_success_at_end，可能包含 replay_already_done；不能原封当成论文 RSR。LIBERO _to_summary 主要输出 status_counts，effective_failure 只加 timeout_failure/env_crash，亦不等于完整失败分母。

怎么接入我们的benchmark

可重用

固定 split／逐档哈希、JSON schema、upstream task/reset 关系、stage–type 标签、replay/infer 分段与具体成功 checker。

需要转换

source 保留两层 commit；environment 指向原生模拟器／资产；task 仍用平台与 native task key；case 用平台+split+sample_id，保存 reset 引用、prefix、原指令及偏离来源；evaluator 另记 step budget、repeat、scheduled/invalid/status。domain 只按任务内容映射。从 results.jsonl 重算 scenario 等权 RSR、Macro-9，将回放已完成与 state mismatch 保留为独立有效性状态。

仍需补齐

完整 scenario archive／数据授权及 simulator assets；各 adapter 完整环境验证；原论文历史 upstream revision 证实；正式排定 trial 名册及 replay_already_done 的统一处置；各 task checker 全覆盖。本轮只核读代表性内核路径，未跑模型或模拟。

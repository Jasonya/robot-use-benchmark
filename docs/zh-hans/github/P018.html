HOT3D: Hand and Object Tracking in 3D from Egocentric Multi-View Videos

返回逐篇总表内核内容已核读 benchmark／数据／评测主来源原作 ↗ 用途与原生规模依据

核读快照 2026-10-11。已读范围限所列片段；本轮未运行上游程序。

HOT3D 官方 toolkit 同时服务完整 VRS 串行与 HOT3D-Clips 子集；已核读 schema、DataProvider 和 BOP 转换，不把工具可读取误写成已完成评测。 2026-10-11 补读官方链接的 hand_tracking_toolkit 提交、GT writer 与实际指针 caller；BOP evaluator 仍未核读。

版本与身份

VERSIONS.md 列 v2 修正 MANO 拇指、v3 更新 visibility，metadata.json 的 version 需随数据保留。Clips README 对 T_world_from_object 的文字方向与字段名不一致，已用实际 converter 确认为 model→world 再转 camera，不直接拷贝文字说明。 官方项目页区分 2024 whitepaper／ECCV 2024 hand challenge 与 CVPR 2025 完整论文；此补读固定 hand_tracking_toolkit@bc628e9286c18444b47a0971a89d075ea6f00747，不宣称今日 snapshot 就是 2024 服务器提交或论文全部实验。README 的 pose 栏名和 run_evaluation.par 与程序的 mano_theta／run_evaluation.py 不同，以已读 caller/writer 为准；数据 v1–v3、论文 edition 与 evaluator commit 分开保存。

领域
居家整理与清洁、餐饮与烹饪、办公与教育、穿戴交互与动作界面
环境
Aria／Quest3 头戴设备记录的手与对象交互；sequence、participant、clip、device、stream 分层。HOT3D-Clips 为同一数据的 5 秒／150 frame 子串行，多个 image streams 不是独立环境。
任务
3D 手／对象追踪与姿态、手形估计；BOP object pose 与手部 pose/shape challenge 使用不同 GT 可见性。动态 object onboarding 只给首影格 GT，静态 onboarding 每影格给 GT。
题数与数据
完整数据用 VRS+CSV providers；clip tar 含 image_STREAM、cameras/hands/hand_crops/objects/info JSON，__hand_shapes 跨 frame 共享。clip_definitions 连原 sequence/device/timestamp；clip_splits 有 train、test_ht_pose、test_ht_shape，test_bop 是两个 test 的联集。相机有 fisheye 模型、projection_params、wxyz quaternion，时间为 ns。 2026-10-11 补读：实际 pose JSON 使用 sequence_name、frame_id、mano_theta[15]、wrist_xform[6]、hand_side（0 左／1 右）；wrist 前三项送 global_orient，后三项是米制平移。shape JSON 用 mano_beta[10]，GT writer 每 clip 只存一份左右手共用 shape。HOT3D README 规定 frame_id=0,10,20…；GT writer 的 --every-n-frames 预设 1，须显式对齐 challenge 抽样。
评估方式
已核公开格式转换及hand_tracking_toolkit所列pose／shape评分链；完整BOP评分器不在本篇列出的阅读范围。BOP converter 实际以 inverse(T_world_from_camera) @ T_world_from_object 得模型到相机姿态，平移乘 1000 成毫米，XYXY 转 XYWH；visib_fract 取 modeled/predicted 可见性的最小值。不在 stream 范围的对象以 -1 pose、空 mask、0 visibility 占位，不能当真实姿态。 Hand tracking的实际调用链为 scripts/run_evaluation.py→evaluate→compute_overall_*→compute_pose_metrics/compute_shape_metrics。pose 用 GT mano_beta 搭配预测 pose／wrist 做 MANO FK，20 点移除 wrist 后评 19 点并乘 1000 成毫米；实际回传 MPJPE、PCK_AUC、FINGERTIP_PCK_AUC，没有 docstring 所列的 MPVPE。PCK 用误差≤阈值，0–50 mm 共 101 点，曲线乘 100 后以梯形面积除 50，保留 0–100 尺度；五指尖另算。pose 依 GT landmarks 列数（手／影格样本，未必是唯一影格数）加权；shape 在零 pose／零 wrist 的左手模型算 MPVPE(mm)，再等权平均串行。未提交某 dataset 的整份结果档会略过，不是零分。

怎么接入我们的benchmark

可重用

VRS/clip schema、对象／手模型、同步时间、GT 可见性 split 与 BOP 转换。 可另接手部提交 writer、原生 19 点／指尖 PCK 和 canonical shape MPVPE；各自保留聚合单位。

需要转换

保留 full→clip→frame→stream ancestry，BOP scene_id 映回 clip_id 而非添加实体场景。座标转换记明方向、米／毫米、相机畸变模型和 visibility 来源；测试缺 GT 依 track 显式标 unknown，不填零。 手部 case 保留 clip/sequence_name、frame_id、hand_side、抽样步长、GT shape 是否已知、PCA pose／wrist 矢量格式及 mm/AUC 尺度；不与 BOP 对象姿态合成共同成功率。

仍需补齐

尚未取得 VRS、tar、对象／MANO 模型、外部 BOP／手评测套件或运行。需为外部 evaluator 另钉选提交，验证相机畸变、时间同步和 -1 占位规则。 更新：手 evaluator 的选定源代码已取得并钉选，但隐藏 GT、MANO 资产、BOP 套件与运行仍未完成。caller 仅按 sequence_name 分组及 frame_id 排序后逐列相减，未显式按 frame_id/hand_side join；接线须验证缺列、重复影格与同影格左右手顺序。本地自选 train 子集也不是官方 validation split。

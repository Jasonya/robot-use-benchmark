CaptainCook4D: A Dataset for Understanding Errors in Procedural Activities

返回逐篇总表内核内容已核读 benchmark／数据／评测主来源原作 ↗ 用途与原生规模依据

核读快照 2026-10-10。已读范围限所列片段；本轮未运行上游程序。

CaptainCook4D 主仓库是入口；已追到官方 annotations 与 error_recognition 程序，核读原始步骤 JSON、mug cake 图、loader 及实际 step/sub-step metrics。

版本与身份

Error-Dataset/annotations 转向 CaptainCook4D/annotations；2023 初版与 2024 最终 baseline／2025 衍生工作分开。主 repo 无 Python 不能推定整项无程序，实作在其明确链接的子仓库。

领域
餐饮与烹饪
环境
真实厨房中遵循食谱或刻意诱发错误的录制。recording、recipe、person、environment split 分别管理；同一食谱多录制是 case，不自动增加独立任务。
任务
error recognition、early error recognition、多步定位／程序学习；task_graph 的 steps/edges 可保留先后与选择限制。loader 另有五类错误 one-vs-rest 标签及 has_errors，未出现／负时间步骤不当作已观察完成。
题数与数据
step_annotations 以 recording_id 连 steps 的 step_id、start/end_time、description、has_errors；error_annotations 另连多个 errors.tag。ImageBind 特征按 2 秒索引，其他 backbone 按 1 秒；floor/ceil 后切片，同一 step 多次出现会串接。early 只取前半特征；recording 12_6 在 ImageBind 分支因无特征跳过。
评估方式
base.py sub-step 以 sigmoid>.5 算 accuracy/P/R/F1，ROC-AUC 用连续分数，但 PR-AUC 实际喂二值预测。step 层取每个 loader batch 的平均分数，再可选全测试集 min-max 范式，以 threshold 判断；GT 平均>.95 才当 error。README 报 step split=.6、recording=.4，core/evaluate.py 目前扫 .5/.6，需固定原作条件。

怎么接入我们的benchmark

可重用

24 份 recipe graph 的路径清单、逐步错误 schema、split 类型及 error／early 的数据流程。mugcake.json 作为已逐项阅读的 task graph 范例；其他 graph 不能据此宣称内容全审。

需要转换

case ID 用 recording+step+occurrence，保留完整秒数、重复片段及合并规则；source 关联原始视频、特征与 graph。error labels、early prefix、step/recording/person/environment split 分栏；评分保存阈值、min-max、batch_size 和二值 PR-AUC 的原始行为。

仍需补齐

尚未取得视频／特征、运行评分或核读 zero-shot/multi_step_localization 全实作。step 切分内 phase=test/val 对应片段命名互换，应以实际索引存盘；batch 必须维持单一步骤，否则 collate 后 batch 被当 step。程序保留作者绝对路径、手选 epoch 表和 start-end>1 条件，均需 adapter 验证与差异记录。

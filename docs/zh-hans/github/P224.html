EMPIRE: Explicit Manipulation Planning as a Learnable Intermediate Representation for Egocentric Hand-Motion Forecasting

返回逐篇总表内核内容已核读 benchmark／数据／评测主来源原作 ↗ 用途与原生规模依据

核读快照 2026-10-11。已读范围限所列片段；本轮未运行上游程序。

已追完EMPIRE的index/episode reader、30→12FPS采样、混合MANO动作表示及best-of-8 joint scorer。公开库有核心程序，但EMPIRE-651K数据与前处理明示尚未发布；650,910训练窗口与111活动标签为论文数字，未由实际dataset逐笔验证。

版本与身份

固定commit bea74bb146baa750b02f291754cafd5ed6cd0bfe。标准StageII配置与predicted_plan ablation使用预测plan；ground_truth_plan另列。直接运行eval_mse的预设K=5、COT_GENERATE_THEN_CONDITION=0，可能使用GT plan suffix；正式shell才设置K=8与online生成，因此两入口不可混同。online分支重读raw image/coarse instruction而不用GT suffix，但数据加载仍依赖reference-plan存在；不能宣称是完全无标注部署封装。所有内容仅静态核读，未运行数据前处理、模型、MANO或评测。

arXiv:2608.22449v1，Wen Wang、Ruibing Hou、Hong Chang、Shiguang Shan、Xilin Chen，EMPIRE: Explicit Manipulation Planning as a Learnable Intermediate Representation for Egocentric Hand-Motion Forecasting。PDF第1页直接连wangwen-banban/EMPIRE，README题名/arXiv一致。VITRA为程序与数据格式基础，EgoDex为母数据，Being-H0为比较baseline，三者不能另算本篇新数据。

领域
穿戴交互与动作界面
环境
EgoDex/Apple Vision Pro的人类桌面操作第一人称视频，RGB、相机内外参、双手追踪骨架转MANO、task caption与per-hand plan。reader在query frame的camera座标表示整段未来姿态；公开FrameDataset只支持human，不提供robot交互环境。
任务
从current RGB、初始双手状态与caption生成操作plan，再预测双手未来motion；plan描述不是可运行robot技能。论文650,910个5秒train windows、6,836个test windows、111个活动标签需分开计数。Part1 ablation另以训练任务重叠定义26 seen tasks/1,247 windows与85 unseen tasks/5,589 windows；并非全五partition训练的预设unseen切分。task summary从episode名称或obj_class/video_name解析label，再对指定training annotation snapshot比对，没有封闭111-task registry。
题数与数据
preferred layout为dataset/episode_frame_index.npz（index_frame_pair[N,2]=episode_index/frame_index、index_to_episode_id[E]）、episodic_annotations/id.npy及statistics.json；legacy .npy字典/processed_episodes_vitra_format也可读。episode含video_name、video_decode_frame、intrinsics、extrinsics及left/right的beta、kept_frames、global_orient_worldspace、transl_worldspace、hand_pose、joints_worldspace、text/anno_type；caption→instruction、plan→cot只是alias。标准设置source_fps=30、target_fps=12，step=2.5，以np.rint取整，并可依此过滤index rows；future=59创建含current的60个window位置，再取next-state而产生60个未来action。OOB虽clip索引，但被mask剔除，60个slots不保证60个有效影格。text范围采[start,end)，plan匹配却允许end且取最近范围。每hand51维为逐步腕平移m、腕旋转xyz Euler-radians及下一步绝对15×3手指Euler；use_rel=false仍保留腕部relative分量。两手102维action补到288；原state122维含betas，padding移除betas后补到296。predicted plan ABI为schema_version=1.0、plans[episode_id:frame_index]，主StageII配置明确读该sidecar。
评估方式
run_full_eval预设REPEAT_TIMES=8、ONLINE_PLAN=1、save_repeated_samples；model config为flow matching 4步。eval_mse先依mask选范式动作MSE最小者，分母为有效action scalar数，这不是论文MPJPE。compute_egodex_metrics优先读sampled_actions[N,K,T,D]，逐候选反范式并recon_traj：累加腕平移、左乘腕旋转、手指使用绝对角，再以MANO重建21关节；beta固定0、左手套轴修正，剔除初始state，只评未来。mask为hand/frame有效性，非独立joint可见性。每window MPJPE=全部有效hand-frame之21-joint Euclidean均值；等价分母21×有效hand-frame数。选该MPJPE最小的同一候选来算wrist joint0与finger-relative（扣wrist后只取其余20关节），不可各指针另挑best。FDE为每个有GT手最后有效frame的joint均值，再对手平均。最终对非NaN windows的metric等权nanmean，再m×1000转mm；num_samples仍包含无有效手而为NaN的records，须另报有效分母。若NPZ没有sampled_actions，scorer把pred_actions当K=1，无法恢复best-of-8。shard merge按sample_positions排序并检查连续性；task summary再分组，并不将总分改成task-macro平均。

怎么接入我们的benchmark

可重用

重用versioned schema/resolver、canonical sample ID、plan sidecar、FPS/mask逻辑、MANO adapter、step重建、best-of-K MPJPE与task provenance摘要；保留EgoDex/VITRA lineage。

需要转换

分开source/domain/environment/task/window/evaluator；case键为dataset revision+episode_id+frame_index，保存source/video/target FPS及np.rint后实际indices。将51维混合action、102有效维、288/296 padding及mean/std明确分层；保留anchor-camera与xyz-radians、公尺/mm转换。evaluator保存K、4步设置、全部sampled_actions、选中best_k、21/20 joint定义、每window有效hand-frame及NaN分母。

仍需补齐

未发布的index/episodes、骨架→MANO拟合与caption/plan前处理、数据/统计/sidecar/weights/MANO资产尚未闭合；不能验证650,910/6,836笔或真正split无泄漏。需核对eval dataset statistics.json与scorer STATISTICS_PATH均使用对应training normalization，避免反范式版本不同。须锁定ONLINE_PLAN、各shard皆保留sampled_actions、真正K与完整case coverage；数据格式称HF-compatible不代表已确认HF dataset repo/revision。

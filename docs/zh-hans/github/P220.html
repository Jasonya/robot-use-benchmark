VISTA: Technical Report for the Ego4D Short-Term Object Interaction Anticipation at EgoVis 2026

返回逐篇总表内核内容已核读 方法／综述参考原作 ↗

核读快照 2026-10-11。已读范围限所列片段；本轮未运行上游程序。

已核读精确VISTA repo的STA reader、split设置、submission串行化与具体Top-5 mAP程序。公开train设置使用train+大部分val，仅24个holdout且每次只跑1个batch的proxy；最终ensemble预设version 2.0，库内scorer却只接受1.0，集成时须显式处理。

版本与身份

读取commit 62e39d137426e12f30fe4efd12122f8c188b4b33。初始prediction writer回传version 1.0；dynamic_metric_head_ensemble与包装shell预设最终version 2.0，而本地validate_results_json拒绝非1.0。ensemble/proxy使用无+1的连续IoU，scorer使用+1像素IoU；ensemble的IoU匹配可含0.5，scorer严格>0.5；论文写TTC<0.25，程序为≤。README的scaffold称呼不代表只有README，亦不代表已完整重现官方submission。

arXiv:2605.20901v1，Qiaohui Chu等人的 VISTA: Technical Report for the Ego4D Short-Term Object Interaction Anticipation at EgoVis 2026，PDF第1页直接指向CorrineQiu/VISTA；README与8张2FPS视频、Faster R-CNN still branch、四prediction heads相符。不是其他同名VISTA项目，也不是FROST-STA。

领域
方法／综述参考，未另作来源用途归纳。
环境
Ego4D v2人类第一人称视频之STA query；数据被预先拆成train／val／test_unannotated sample directories，每例含短片历史影格与最后高解析影格。没有robot rollout或simulation场景。
任务
预测每个query下一交互的active-object box、noun、verb、TTC及score；一例可有多个GT对象。类别不是固定新任务清单：build_label_maps_from_roots扫train+val中有效noun/verb ID，排序重编成连续index，输出时再还原；须保留mapping与母数据taxonomy版本。
题数与数据
reader扫排序后的label.json，读uid、split、video_uid、frame、observation.history_frames[*].file与last_history_frame_highres_file；GT优先future_prediction_target.objects，fallback raw_annotation.objects，读box_xyxy/box/bbox、noun_category_id/noun_id、verb_category_id/verb_id、time_to_contact/ttc。train/val排除空标注与所有框无效的样本；test仍需label.json但不要求GT。history_frames保留既有顺序，超过8取最后8，不足8以前端第一张补齐，并不在reader内由fps重建时间戳。论文/设置为8张2FPS、视频384×384；still short-side train640–800、eval800，max1333。框随图像缩放，dump依orig_size还原xyxy像素，TTC秒不缩放；可改读split/uid.pt的1664维JEPA cache。train_include_val=true时以有效样本排序后前24个作holdout，其余val并train，并非take-disjoint的新split。
评估方式
run_official_metric_only.py是真正本地scorer：以uid对齐，CLI要求所有GT uid都有results（可空list）；无GT对象的query不入评分。IoU面积使用(x2-x1+1)(y2-y1+1)，框须IoU>0.5，TTC条件为绝对误差≤0.25秒。每query按score贪婪一对一匹配各metric的GT；Top-5不是截前5，而是每个metric忽略排序前4×该query GT数的FP。Noun／Noun+Verb／Noun+TTC／Overall皆按noun类别分组：recall分母是全评测集中该noun的GT对象数，AP以precision envelope对recall积分乘100，再只对出现GT的noun做macro平均。compute_proxy_hits则只查score前5，只要任一GT匹配就给该query一个hit，分母为batch中有GT的query；eval.py以batch size加权再跨rank平均，与mAP不同。预设train max_val_batches=1、run_official=false、best_metric_source=proxy；test设置只产生每head最多100个hypotheses，四headensemble再保留100。论文5.40为test server结果，本轮未重跑或证明本地Lite实作与server完全等价。

怎么接入我们的benchmark

可重用

重用STASampleDirItem及label.json reader、noun/verb双向map、UID submission schema、具体STAMeanAveragePrecisionLite与head ensemble参数，保留其来源commit。

需要转换

case键为Ego4D版本+split+uid，video_uid/frame另存；框保留原图像像素xyxy、orig_size与resize比例，时间以TTC秒与实际history-frame串行描述。evaluator分开记proxy query-hit与noun-macro Top-5 mAP，保存FP-budget=4×GT、IoU+1、比较边界与head/top100预算。

仍需补齐

原始视频至sample label.json的可验证制作流程、实际manifest/hash与frame时间戳仍需补齐；未取得数据、features、weights，无法报有效case总数。需固定24个holdout身份并按完整benchmark split评分；须对齐ensemble version 2.0与scorer要求1.0、以边界例核验本地scorer/server差异，不能只改字符串便宣称等价。

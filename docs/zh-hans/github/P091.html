P091 · UniFolding

UniFolding: Towards Sample-efficient, Scalable, and Generalizable Robotic Garment Folding

返回逐篇总表内核内容已核读 benchmark／数据／评测主来源原作 ↗ 用途与原生规模依据

核读快照 2026-10-11。已读范围限所列片段；本轮未运行上游程序。

已核读 UniFolding 的 VR HDFStore、runtime YAML/NPZ/PLY、动作与标注格式、模拟几何计分及真机状态机。真机 SUCCESS 是流程状态：fold1/fold2 条件以最后 action 类型推定，并无成品几何验收；原始论文10步内按折法完成的成功率需另保留评阅证据。

版本与身份

固定2024-10-18 commit，晚于2023论文。核读限Python数据／task／metric与控制流程，未核读所有电机控制／Unity插件底层，未运行上游程序、连接标注数据库／通知或下载模型与大型资产。 已补读VR-Garment c9014f62的收集与回放数据契约；它本是GarmentTracking工具，UniFolding引用作Stage0上游。未使用VR硬件或运行Unity。

README 明示官方 CoRL 2023 程序，完整题名、六位作者与 arXiv:2311.01267 相符。RFUniverse、CLOTH3D、VR-Garment 与 ClothFunnels 各有重用角色，不把框架／母数据集当成本篇新benchmark。

领域
衣物与洗护
环境
模拟是Unity 2022.3 LTS上的RFUniverse，README要求另取得Cloth Dynamics 2.0.9 beta；CLOTH3D衣物依category meta与instance filter加载。真机是双Flexiv Rizon 4、AG-95与Photoneo MotionCam3D＋MindVision RGB。Unity左手系先转Open3D右手系，再转virtual/world/左右robot frames；virtual以z为高度，配置另有particle_scale=100与time_scale=4，不能直接沿用FleX的y-up或将步数当秒。
任务
两种衣物tshirt_long／tshirt_short的展开→fold1→fold2流程；附录C先同时折两袖，再对半折本体，精确抓放点由VR人类示范生成。ActionTypeDef包含FLING/DRAG/FOLD_1/FOLD_2/PICK_AND_PLACE/DONE及恢复／HOME等，是动作enum而非同数量任务。ExperimentVirtual.execute_action只实作FLING，random_fold用于初态，不能宣称runtime模拟提供完整折衣动作集。论文60件真衣物以2:1分割，20件held-out各10trials＝200次测试；2432是训练sample、每sample16次人类偏好比较，不是测试cases。
题数与数据
VR data.h5 的Pandas df以instance_id/video_id/sample_id标识，读pcd_path_frame1→NumPy Nx6 xyz/rgb、nocs_path_frame1、coverage_frame1/2、左右gripper_point/theta_frame1/2、action_type、folding_step、is_smoothed/is_smoothing。raw fold依folding_step映为fold1/fold2；pose内部顺序为左pick、左place、右pick、右place，角度wrap至±π。VR依instance_id打乱切分，所读stage1 config为8/1/1；runtime real/virtual却依sample打乱，不能等同论文对象held-out split。runtime metadata按namespace记pcd.processed.begin、processed_nocs.begin、pose_virtual、reward.begin/end及episode_idx/trial_idx/action_step；NPZ键为points/nocs，real另接受PLY。annotation.action_poses原顺序左pick、右pick、左place、右place，reader重排后将角度全设0；虚拟fling place亦用0占位，应保存validity而非当有效目标。偏好0/1/2/3分别为左对优／右对优／相等／不可比较，经label smoothing后监督分数模型。 VR-Garment补查：PoseData包含dualHandPoses（position／Euler／手势）、localParticles（solver renderable positions／normals）、左右grasp solver indices、solver／actor local-to-world矩阵和Time.time。Record名义每0.04秒调用，应保留实际timestamp而非假设等间隔。JSON录制再回放输出AnimationData及color/depth/mask图像引用的BSON；四个随机相机视角共用同一段示范。
评估方式
虚拟get_deformable_reward以canonical初态粒子覆盖面积作max_coverage，在virtual XY平面用100×100粒子网格；IoU另外把两组XY点共同缩放至0–99并画半径2圆，以点阵交集/联集计算，不是RGB图像mask IoU。reward.py沿用ClothFunnels分解形式，但此版把z归零、同顶点SVD配准5次、镜像取min，距离除sqrt(初态粒子覆盖面积)，stage2权重0.7；与P090用长×宽范式不同。runtime学习用begin−end的l2/icp改善量；VR则用同instance的coverage_frame1最大值范式、stage1以max(tanh(2Δcoverage+coverage_after),0)给fling标签，fold等固定0.8、done为0，均非实测成功率。真机state machine把fold成功设为最后action_type==FOLD_1/FOLD_2，garment_fling_drag_success固定True且有TODO；operable只看mask面积上限、reachable看mask横向均值，没有成品折法验收。step_idx>max_num_steps非全域强制终止，部分转移还要求不可操作，lift与fold前drag循环不按每个物理动作累加。论文要求10动作内按规则完成，这与状态机SUCCESS需分栏。 VR收集工具的开始／清除／保存由手势或按键触发，超过maxFrameCount仅提示；录完不表示通过折叠成功判分。ClothImitation2／AnimationImitation2是录制与回放场景，不能加成两个新任务；四视角不加成四段独立示范。

怎么接入我们的benchmark

可重用

原生动作／观测／annotation dataclasses、frame pairs与偏好、instance与sample索引、模拟几何metric及真机流程状态。

需要转换

source固定commit并标记VR-Garment/CLOTH3D/ClothFunnels重用；environment保存Unity/Open3D/virtual/world/robot座标链；task保存衣物类与两段折法；case保留完整garment/trial/step、checkpoint、split粒度；evaluator分模拟距离、VR训练reward、preference target、真机流程状态及独立成品成功。保留特权粒子/NOCS，勿当真机可观测量；人类VR示范须经primitive与校正adapter才能成为robot命令。 VR原生Unity／solver座标、Euler顺序、BSON/JSON与视角／timestamp对应须保留并校验；不得直接视为米制robot命令。

仍需补齐

VR→UniFolding前处理与data.h5/NPZ/annotation/instance清单闭合；对象held-out真机200trials的逐次成品评阅；严格10物理action budget；pure evaluation入口与网络／barrier相依隔离；Unity付费插件／CLOTH3D／硬件校正取得与运行验证。

P078 · PerAct

Perceiver-Actor: A Multi-Task Transformer for Robotic Manipulation

返回逐篇总表内核内容已核读 方法／综述参考原作 ↗

核读快照 2026-10-11。已读范围限所列片段；本轮未运行上游程序。

PerAct 是使用 RLBench 的方法参考，不另建18任务／249 variations的新任务库。已读replay与keypoint定义，并沿作者peract分支的reader、open_drawer condition、YARR rollout及accumulator闭合一条具体评测路径；test可为每个task加载不同的val最佳checkpoint。

版本与身份

主仓库02fb87681c5a47be9dbf20141bedb836ee2d3ef9（2024-05-09），README明说论文DataParallel改为公开版DDP。补读依赖固定RLBench ad991951bc53e4f3b73b803a75cf4b7d55295cf7与YARR 8d0f2e228b97efa207eeccedfc6dac9334342ba3。P077 PyBullet、P062较新RLBench与本版数据／checker各有版本边界；本轮只审所列区段。

论文为Shridhar、Manuelli、Fox的Perceiver-Actor: A Multi-Task Transformer for Robotic Manipulation，arXiv:2209.05451v2（2022-11-11）。README题名、作者、arXiv与peract.github.io相符；84–109明指MohitShridhar/RLBench及MohitShridhar/YARR的peract分支，不是P062的stepjam/RLBench现行快照。两fork是运行／计分依赖。

领域
方法／综述参考，未另作来源用途归纳。
环境
作者fork的RLBench/CoppeliaSim 4.1／PyRep桌面操作，EndEffectorPoseViaPlanning后接Discrete gripper。policy取front/left_shoulder/right_shoulder/wrist四个128×128 RGB与世界点云；配置不直接输出depth/mask，loader仍读depth产生点云。场景界限[-0.3,-0.5,0.6,0.7,0.5,1.6]为公尺，100³ voxel在此配置每格1cm。Franka真实实验的teleop ZIP及Drive数据是外部附件，未取得／未验证。
任务
18个task是README 232–249手选RLBench subset；249是论文v2的variations，不是task或trial数。已读open_drawer的bottom/middle/top三variation，成功条件为指定joint相对初态位移>0.15m。task、variation_number、语句、demo初态各自存放；其余17个checker未逐一选读。
题数与数据
路径为{split_root}/{task}/all_variations/episodes/episodeN，包含low_dim_obs.pkl、variation_number.pkl、variation_descriptions.pkl与camera/%d.png。24-bit depth除DEPTH_SCALE后以near+depth*(far-near)还原公尺，结合intrinsics/extrinsics产生点云。reader即使仅激活四视角，仍检查全部五相机RGB/depth影格数与low_dim_obs一致。fill_replay按自然序读demo、取第一句description；keypoint为gripper_open改变、末帧或joint_velocities在0.1容差内停止，stopped_buffer=4。action为xyz公尺+xyzw+gripper共8D；保留拼法trans_action_indicies／rot_grip_action_indicies，rotation是xyz Euler+180后5度bin。replay另含ignore_collisions、rgb/point_cloud/矩阵、task、lang_goal、1024D sentence embedding、77×512 token embedding及demo。low_dim_state是gripper_open、两指位置及[-1,1]决策进度。末keypoint的100 reward为合成训练标签；增广replay条目数不能当demo/case数。
评估方式
eval→IndependentEnvRunner→_run_eval_independent→RolloutGenerator→CustomMultiTaskRLBenchEnv→RLBench TaskEnvironment.step→Task.success→open_drawer JointCondition。demo index=eval_from_eps_number+ep，variation与初态自文件恢复。范例checker成功时RLBench回1并terminal，PerAct乘100；reward<1归零，IK／path／invalid-action错误直接失败终止；预设25决策后timeout。SimpleAccumulator对episode累积reward取mean，稀疏0/100协定的eval_envs/return/{task}数值等于百分比成功率，但保留return名称及scale，不泛推到有reward shaping的task。预设每task25 episodes；method seed另记。best模式每task依val CSV独立选现存checkpoint、平手取最后，因此test不保证同一权重。YARR依weight是否dict决定test_data.csv文件名，仍需另核对demo_path实际split。

怎么接入我们的benchmark

可重用

作者fork reader／demo reset、18-task subset、variation/description、keypoint生成、planner与具体condition、YARR return aggregation。

需要转换

source记P078方法与P062 RLBench重用关系并保存三个commit；case以split+task+episode+variation+Demo初态hash识别。raw sensor、policy observation、连续pose与voxel/Euler标签分层；保留原始frame到keypoint的映射、augmentation起点与碰撞旗标。evaluator另存task→checkpoint、decision/trial budget、return scale、error/timeout。

仍需补齐

README只锁peract分支，补pin不能证明是论文实验版本。尚需五相机图像／TTM／Demo资产闭合、其余17 checker核对与实机附件版本。不能套用P062现行RLBench reader。YARR pop只在>1个完成episode时输出，单case试读不保证有CSV指针。

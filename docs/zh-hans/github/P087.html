GarmentLab: A Unified Simulation and Benchmark for Garment Manipulation

返回逐篇总表内核内容已核读 benchmark／数据／评测主来源原作 ↗ 用途与原生规模依据

核读快照 2026-10-11。已读范围限所列片段；本轮未运行上游程序。

已核读 Isaac Sim 场景、Fold／Hang／Bimanual 范例、点云数据管线及 RL fold 的具体 evaluator。公开程序可作来源与部分任务参考，但所读路径未实现论文整套20任务及持续5秒成功验收；多处数据键、split 与计分接线尚未闭合。

版本与身份

固定 2025-03-02 commit，晚于2024论文；READMEs与论文宣称不代表此公开版本已实现所有协定。本次未启动 SimulationApp、未下载 USD/模型，亦未将 template 或文件数当核读完整性。

README 直接链接 arXiv:2411.01200、官方 GarmentLab 页面与同名仓库，BibTeX 题名及作者对应 NeurIPS 2024 论文。LearningBaseline/unigarmentmanip 是本仓库中的基线实作，不另外算新 benchmark。

领域
居家整理与清洁、衣物与洗护、个人照护
环境
Isaac Sim 4.0.0／PhysX；BaseEnv 导入 USD 房间与地面、激活 GPU dynamics／CCD；GarmentConfig 保存 USD、pos、ori、scale、stretch/bend/shear stiffness、friction 和 collision offsets。FoldEnv 使用 Franka、顶视 Recording_Camera 的 depth／point-cloud／segmentation；BimanualEnv 配两支 Franka。原生 Euler／quaternion 与 USD scale 混用，不能直接假定所有输入角度或资产尺寸相同。
任务
README 宣称20任务、5交互群、11衣物类别、20场景及9000+资产，均为不同单位且非本次验证的可运行 case 数。本轮追查 Fold、Hang、双臂展布及 RL fold 子路径；demo 是固定资产／抓点串行。RL fold/config 实际 task_name 为 hang，须由协调者核对任务名称与实验配置，不能仅依文件夹分类。
题数与数据
collector 把 pcd_points／mesh_points 写入 {garment}/p_{index}.npz、另存 rgb_{index}.png；loader 还要求 keypoints_visible_mask、pcd_keypoints_id、visible_mesh_indices，需补前处理来源。loader 回传两份点云与 correspondence 索引，交替产生同衣物跨变形及跨衣物配对，不是 robot episode。get_deformation_paths 先按衣物目录数字排序再切 split；config.train_ratio=1 会把所有衣物给 train、val 为空，不能套用论文 split。BaseEnv 的 .npy record/replay 是 callback 框架，base callback 为 pass，未提供统一有效轨迹 schema。
评估方式
HangEnv.get_reward 读 garment_mesh.get_world_pose() 的 z>门槛（预设0.3，demo传0.5），未检查挂架接触或5秒稳定。FoldEnv 与 FoldDemo 没有 fold success checker。BimanualEnv 以 trial/reference coverage>0.75，但 evaluator 会停止／重设衣物姿态且面积 min/span 使用xy、pos2d却使用xz，必须标为原生疑点。RL fold 的 eval_policy 平均30次 SimEnv.step(...,True) 布尔值；SimEnv 计算抓点到指定粒子的误差，两个 reward_action>0 才成功，误差恰为0.1经非线性分支后仍为正。虽计算0.8×reward_action＋0.2×reward_result，非eval实际回传 reward_action，eval也未用结果形状误差。FoldTask.calculate_metrics 是 Cartpole 范本，不是主 fold evaluator。点云 simple_val 以归一化特征 argmax 找 correspondence，报平均欧氏距离与 distance<threshold 比例；val_score.py 却读 points/keypoints_id、取 train 的0.8子集，而且调用 cal_distance_accuracy 时少了必填 distance_threshold。

怎么接入我们的benchmark

可重用

USD／材料设置、场景与传感配置、固定任务脚本、点云配对结构及已查明的原生 checker。

需要转换

source 绑 commit；environment 绑资产与物理参数；task 对应实际脚本／配置及论文标签；case 需另建 garment_id＋初态＋示范／seed；evaluator 分 geometry matching、抓点成功、挂衣高度、论文持续成功。数据配对数、render frames、衣物对象与30次RL评测不可混算。

仍需补齐

完整20任务 case/split manifest；fold IoU／持续5秒的可运行 checker；原始npz→标注npz→val_score的字段桥接与threshold修正；coverage轴向与state mutation决策；资产、真机benchmark文件及校正尚未纳入可运行接线。

P208 · DYAD

DYAD: A Multimodal Dataset of Co-Located Human Assistance

返回逐篇总表实作尚未确认 benchmark／数据／评测主来源原作 ↗ 用途与原生规模依据

核读快照 2026-10-11。已读范围限所列片段；本轮未运行上游程序。

DYAD pinned paper 将数据与 benchmark code 列为规划中的 controlled-access research release；已收录 PDF／project／GitHub 搜索没有可确认的本篇仓库。已核三个 endpoint 的标注与分母，但没有公开 reader 或 concrete scorer 可读，不能把同名 app builder／其他 dyadic dataset 当成来源。

版本与身份

来源固定为 2609.09023v1 与既有 2026-10-10 discovery/search caches；未确认 repo 就不造 commit 或 source path。851 assistance events、528 step intervals、611 requests、829 mode cases、256 response test pairs、传感影格均为不同单位；数字来自已核 paper，没有本地 release 逐列验算。

核对 arXiv:2609.09023v1（2026-09-08），Akhil Ajikumar、Mahya Qorbani、Sakib Reza、Sean Andrist、Mohsen Moghaddam。paper p.3 Table II 明示 planned release，正文说 will provide annotations/manifests/benchmark code under controlled access；未附本篇 release URL。既有 DYAD co-located assistance 搜索成功回传 0；DYAD 广义搜索前 8／1,197 结果不足以证明全网无仓库。

领域
装配与生产作业、协助、交接与陪伴
环境
单一 gearbox 组装工作站的同地人类 performer–helper 协作；20 名 HoloLens 2 佩戴者各一 session，同一受训 helper 遵循先言语引导、等待自我修正、必要时实体帮助的规则。六 pilot 不计正式 20 sessions／5 小时 58 分钟。人类示范不是已运行机器人协作。
任务
三个分开评测的 reference endpoints：因果组装步骤辨识、已知将有介入时的 verbal／physical mode anticipation、给 oracle 脉络的 helper response generation。八个 step labels 是 Gear on shaft、Bearing in holder、Second holder、First holder、Part search、Shaft assembly in post、Attach crank、Verify rotation。九 trigger labels 是 out of reach、cannot find part、cannot decide next step、wrong part、ordering violation、wrong orientation、wrong screwdriver、stabilization needed、missed screw；null trigger 表示分类外需要，不能当没有介入的负例。
题数与数据
论文 Table II 的观测为 ego RGB 24–30 Hz／896×504、depth 5 Hz／320×288 16-bit、gaze 30 Hz 3D origin/direction、hands 20 Hz 每手 26 joints／4×4 poses、head 30 Hz 4×4 transform、Kinect RGB-D 15 Hz（RGB 1280×720 JPEG）。音频不在规划发布范围，使用去识别逐字稿。三层标注各有 task step（step/objects/tool）、request（utterance/confidence）、assistance（onset/offset、mode、initiation、hard stop、trigger、objects、helper utterance、outcome）。全部转 session-relative clock 并保存 null；两场原始绝对式 hour 栏需保留各自 origin，不能当 elapsed hours。这些是论文 principal fields／单位，尚未核到实际 JSON keys、文件布局、reader 或同步转换程序。
评估方式
mode 的论文清点是 export 852→删一重复 851→有 mode label 850→完整 pre-onset RGB window 829（610 verbal／219 physical）；window=[onset−3.5s,onset−0.5s]。五 fold 各 12/4/4 performers，合并 829 个唯一 OOF events 算 binary macro-F1、physical-class AUPRC，四 seeds 为 0/1/2/42，2,000 participant bootstrap replicates 不能算新 cases。当次 trigger／initiation／outcome／speech／step label 等不得作输入。step track 是 5 validation／15 test sessions，1 Hz 因果 RGB、四 frame lookback；segment F1@IoU0.1、collapsed-sequence edit、temporal mAP@0.1、frame mAP 与 MoF 分别保留，528 intervals 中一笔 null 不能擅自丢成零标签。response 将 request end 前5秒至后15秒内最近的 verbal assistance 配对，376 pairs=120 dev+256 held-out test；oracle 提供先前步骤、10轮真实对话、10次介入及 CAD 图，当次 trigger 不提供。每 query 一次生成、100-token cap；Claude Opus 4.5 依正确性、完整性、脉络相关性、可行动清晰度、简洁度与整体各评0–5，另 BERTScore P/R/F1。以上均为 paper protocol；segment matcher、judge prompt／parser、null／例外处理、aggregation 程序未找到，没有宣称本轮算过成绩。

怎么接入我们的benchmark

可重用

可重用三层事件结构、八步骤／九 trigger 原生词表、单 helper policy、三 endpoint 的信息边界与原生分母；规划 release 与实际可用素材分开记。

需要转换

source 保存 v1 与 controlled-access-planned 状态；domain 记组装／协作，environment 记 workstation、performer、helper policy。case 将 session、step interval、request、assistance event 与各 endpoint 的 eligible sample 建关联，保留原始时钟／session origin／同步率／nullable 栏。evaluator 分开 mode OOF、step sequence／frame 与 response pair，各自保留 split、seed、可见信息及分母，三 endpoint 没有共同成功分数。

仍需补齐

官方 release／access 流程及程序 URL、native annotation／manifest、同步 clock reader、829 OOF IDs、step null-policy、response 配对与评分实作。没有 non-intervention negatives，不能接成 assistance-need detector；827 个有 outcome 标签的事件中 812 个为 effective，这种高度偏态是作者不设 outcome prediction 的原因，不能以所有 851 events 当此 endpoint 分母。

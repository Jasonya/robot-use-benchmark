P080 · DexArt

DexArt: Benchmarking Generalizable Dexterous Manipulation with Articulated Objects

返回逐篇总表内核内容已核读 benchmark／数据／评测主来源原作 ↗ 用途与原生规模依据

核读快照 2026-10-11。已读范围限所列片段；本轮未运行上游程序。

DexArt已追到四个具体RL task的state／success、底层contact、对象annotation reader与paper评测入口。原生success是episode内曾达is_eval_done的比例；bucket的成功比early_done宽松，laptop reset又随机抽对象，不能将eval_per_instance名称当每个对象精确等量试验的证据。

版本与身份

固定d6ab75e1a0b81384d1ac918cbfd4d97b1f230149（2026-05-11），晚于2023v1；README的2023-11checkpoint发布也晚于论文。所读门槛只代表此commit；无论文精确experiment lock或assets版本对照，不宣称重现paper表格。未运行PPO、感知预训练或SAPIEN。

固定论文为Bao、Xu、Qin、Wang的DexArt: Benchmarking Generalizable Dexterous Manipulation with Articulated Objects，arXiv:2305.05706v1／CVPR 2023。README 1–13和171–176吻合完整题名、作者及arXiv，确认Kami-code/dexart-release为官方模拟环境／训练程序；不是同名搜索命中即视为官方。DexPoint及vendored Stable-Baselines3是重用实作。

领域
居家整理与清洁
环境
SAPIEN articulated objects与xArm6腕接Allegro手；create_env预设frame_skip=10，已读laptop scene timestep=0.004s，即该配置每control step为0.04s。policy相机64×64，另外1000×1000的viz_only相机不算policy观测。四task各有point-cloud裁切bound和rand_pos/rand_degree；例如laptop位置扰动为每轴[0,0.1)m、yaw±60度，不是对称±0.1m。基底pose、对象scale、摩擦、handle与joint annotation都是case重建依赖。
任务
四个原生task labels是faucet、bucket、laptop、toilet；TRAIN_CONFIG的seen/unseen ID数分别11/7、11/8、11/6、17/11（共82个配置中的对象ID），不是82个task或实测episodes。*_half只是训练对象子集。laptop reader读assets/sapien/{id}/mobility.urdf与mobility_v2.json的joint字段，结合annotation/laptop_scale.json、laptop_joint_annotation.json中left/middle及robot-relative position。外部asset包未下载，仅核对程序期待的字段，未声称这些JSON内容已读。
题数与数据
BaseRLEnv.step依序控制、update_cached_state、更新robot imagination、读观测、算reward与done。action为[-1,1]的robot.dof矢量：前六维还原Cartesian速度，Jacobian IK得arm速度并裁至±π，再积分成joint target；后段映射到hand joint位置limits，不能当全矢量都是joint velocity。obs含state/oracle_state（所读laptop为joint qpos+palm线/角速度+位置+step/horizon）、instance_1-point_cloud(512,3)、instance_1-seg_gt(512,4)及imagination_robot。点云由camera转robot座标后裁切，少点时重复第一点，空云补零；四mask顺序handle/instance_body/hand/arm。pretrain生成器把512个感知点及96个robot imagination点组成(608,7)样本，保存{task}/{train|val|test}_{id}.npy，再np.load合并；seen同时产生train与val，unseen产生test。其内容是random-action／random-joint-state感知样本，不是成功操作轨迹或固定时间同步action标签。
评估方式
入口examples/evaluate_policy.py→create_env→BaseRLEnv.step→task.update_cached_state→sim contact checker。contact以scene contact的sum(abs(impulse))>=1e-2认定。laptop：progress=1-|q-middle|/(|left-middle|-init_open_rad)，需>0.95且palm距handle<=0.2m、至少两指及palm接触；toilet相似progress>0.95，但距离<=0.1m、两指接触即可。faucet需|hinge qpos|>1.5rad，距离<=0.2m及两指+palm接触。bucket eval需progress>0.7且base-link升高>0.25m；early_done则>0.9、state=3及>0.3m，且is_done实际只看250步horizon。四个task的horizon均250；faucet、laptop、toilet在各自成功条件成立时提早结束。主循环只要任一步is_eval_done为真就锁定episode成功，即使bucket之后落下仍记成功。最终印mean(success_list)，shaped reward另累加但不作该成功率。通用SB3 evaluate_policy回mean/std reward，不能替代此入口。

怎么接入我们的benchmark

可重用

四task checker、contact门槛、native object ID/split、对象annotation loader、robot/point-cloud观测profile与episode-any-success聚合。

需要转换

task记动作目标；environment绑SAPIEN、robot、资产/annotation版本；case记task+object ID+split+初态+seed，不以渲染帧或pretrain样本数当case。evaluator分开is_eval_done、early_done、reward、done、any_step_success及horizon；保留每task不同的角度／progress／接触与高度门槛。点云、seg_gt、imagination及可选previous观测需标示来源与policy可见性。

仍需补齐

外部assets的URDF、scale、joint left/middle及relative-position JSON尚未闭合或验证，须固定asset版本／hash。eval_per_instance预设10、README示例100，总数为该值×instance_list长度；但已读laptop reset用random.randint抽ID，没有逐ID均衡控制或per-ID结果保存，需记实际抽样频数。程序stdout只有总成功率，缺trial明细与失败／落下后状态。BaseRLEnv在horizon处因task.is_done已为True而写TimeLimit.truncated=False，需协调者分离超时与成功，不能把done当成功。

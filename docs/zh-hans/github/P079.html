P079 · FMB

FMB: a Functional Manipulation Benchmark for Generalizable Robotic Learning

返回逐篇总表内核内容已核读 benchmark／数据／评测主来源原作 ↗ 用途与原生规模依据

核读快照 2026-10-11。已读范围限所列片段；本轮未运行上游程序。

FMB有真实Franka数据转RLDS与策略rollout，但环境step固定回reward=0、done=False；成功需依官方实物评测程序另行记录。已追到combined／insert-only builder、ResNet reader与robot action，发现state/peg_id字段不兼容、负ID转uint8、primitive过滤后episode边界未重算等具体集成问题。

版本与身份

固定rail-berkeley/fmb@d4da6ce044a9806f41e58bf7423b5a3c05289925（2024-05-28），早于论文v3（2024-09-03）；不能认定涵盖v3所有实验。官方procedure是以SHA256固定的网站文字快照，无与paper/commit同版的证明。combined、single、multi、insert-only TFDS builders是不同schema／subset，不能仅因均1.0.0合并；本轮选读combined与insert-only。

固定论文为Luo、Xu等人的FMB: a Functional Manipulation Benchmark for Generalizable Robotic Learning，arXiv:2401.08553v3（2024-09-03）。PDF及README均指functional-manipulation-benchmark.github.io，README 136–140列相同作者与arXiv；绑定中的项目Code链接指rail-berkeley/fmb。此repo是控制器／数据builder／baseline，CAD与数据压缩包另行发布。

领域
装配与生产作业
环境
真实Franka Panda、两个侧面与两个腕部RGB-D相机、抓取区、reorientation fixture及插入板。论文单物体位置随机于20×20cm、板于35×35cm；多物体抓取区20×30cm，板固定。控制器预设10Hz；gripper切换会另等待，视频以20fps写出，均不能用来推定原始数据有精确等间隔timestamp。形状／颜色／长短／大小是对象属性，板号或相机数不等于environment/case数。
任务
原生任务含single_object_manipulation及三种multi_object assembly；combined builder的primitive有grasp、place_on_fixture、regrasp、rotate、move_up、go_to_board、insert。论文Table 1的六种分段标签与程序中的过渡primitive不强制一对一合并。22,550为论文统计的分段轨迹（single 15,350、multi 7,200），不等于完整任务episodes：论文另列2,700个single全流程、4,050个额外insert及每assembly150个multi全流程。本轮未下载文件，无实际落地case计数。
题数与数据
combined builder 1.0.0读.npy dictionary：actions(T,7)、primitive[T]、obs/{side_1,side_2,wrist_1,wrist_2及_depth,q,dq,tcp_pose,tcp_vel,tcp_force,tcp_torque,gripper_pose}，single另有object_info。RLDS steps.observation为256×256 JPEG RGB、float32 depth、joint_pos/vel(7)、eef_pose(7)、eef_vel(6)、eef_force/torque(3)、state_gripper_pose及object/shape/color/size/length；episode_metadata保留file_path、episode_task与生成语句，USE embedding为512D。depth仅astype，未提供raw depth到公尺的scale；size/length为类别字符串。action是base-frame xyz增量（m）、左乘的xyz Euler增量（rad）及gripper 0=open/1=close；env裁剪前六维至±0.06m／±0.25rad。builder只有train，ResNet reader预设train[:95%]/train[95%:]，不是对象held-out benchmark split。reward在原始最后步硬设1、discount全1，不能作量测成功标签。
评估方式
callchain：ResNet simulate_policy→rollout→FrankaFMB.step；env固定回(obs,0,False,{})，rollout亦丢弃reward/done、可按Esc停止，只存observation/action与视频。N=100是程序调用参数，不是官方protocol；grasp/regrasp 60步、insert/place_on_fixture 100步、rotate 200步、long_horizon 300步，action chunk可能跨越外层上限。官方procedure另定grasp/rotate/place/regrasp各50 trials（5 seen+5 unseen对象各5次）、insert 45（9 shapes各5次）、single multi-stage 10、每multi-object assembly 10（5初态各2次）。成功依牢固抓持、fixture上斜放、rotate ±15度、底面完全插入正确孔等实物条件；multi-object需全部插入。未找到此路径的机器自动量测或success JSON，必须保留人工／外部判读地位。
原作数字：保留论文的单位与页码

怎么接入我们的benchmark

可重用

raw→RLDS字段、primitive语句与object属性、父轨迹file_path、控制器delta-action定义、官方逐skill初态／trial／成功准则。

需要转换

source同时绑paper v3、repo commit与TFDS dataset名称/1.0.0；task区分完整assembly与primitive；case保留父episode、原始frame index、board/object ID、切分后segment及protocol trial。对象泛化split需另存held-out清单，不沿用95/5切片。把raw depth scale、force/torque frame、gripper及action范式作profile字段；evaluator单列合成demo reward与实物成功判读。

仍需补齐

combined及insert-only builder均无observation.state/peg_id，但ResNet decoder 137–140无条件读state，peg filter/shape_vec又用peg_id；需版本化adapter，不能宣称可直接串接。combined把-1 ID sentinel转uint8后成255，schema文字却仍说-1。insert-only过滤后仍用原始i标is_first/is_last，可能没有first或terminal步。README说旧checkpoint force/torque在base frame、新dataset预期eef frame，不能只按同名字段合并。尚缺深度尺度、物理资产／相机校正、protocol附图座标、实际trial结果与观察者判读记录。

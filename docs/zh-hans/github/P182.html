SoftVTBench: A Deformation-Aware Visuo-Tactile Dataset and Benchmark for Deformable-Object Manipulation

返回逐篇总表内核内容已核读 benchmark／数据／评测主来源原作 ↗ 用途与原生规模依据

核读快照 2026-10-11。已读范围限所列片段；本轮未运行上游程序。

核读的是旧v0.1的四suite task/config、HDF5 reader、具体goal checker、FEM Kabsch变形计算、per-object calibration及正式softvtbench_metrics。它与收录论文的数据规模、asset清单及90th-percentile门槛不同，且runtime禁用了drop termination；本笔是有版本限制的程序核读，不代表已重现4,000示范版DSR。

版本与身份

固定58056111f（2026-07-22）。repo身分由PDF明链与相同作者确认，但README的2607.04234、1,628/33、pi05-only、半最大值calibration都属旧版；PDF为2608.18701、4,000/50+、Diffusion/π0.5/FastWAM、90th-percentile。另有README NoDrop叙述与正式code不一致，以及deprecated global-threshold scorer，全部分开记录。未运行任何模拟或上游模型。

arXiv:2608.18701v1 第1页直接连至此repo，作者与README的Bowen Jing、Mingxin Wang等一致，故为第一方来源。但2026-07-22固定commit的README／项目页仍连2607.04234并使用Safety-Aware旧题名；不能据此改写收录PDF身分或当作新paper版本已完整发布。

领域
通用对象与机动作业、餐饮与烹饪
环境
Isaac Sim／Isaac Lab，Franka Panda及双指GelSight Mini，FEM deformable对象、刚性对照与tactile proxy；与Tabero／LIBERO有重用关系。task JSON分fixtures、objects、regions、robot_base_pos／wxyz orientation、obj_of_interest与tactile_targets，soft／rigid twin及场景variation要各自保留，不将旧LIBERO BDDL文件名当作当前soft task身分。
任务
Object-Soft、Spatial-Soft、Object-Rigid、Spatial-Rigid是2×2 matched suites，内核为pick-and-place。收录论文每suite10 tasks／1,000 demos，另500 ID evaluation episodes／suite（50/task），soft suites各9种单因子OOD条件、每suite/config合计900 OOD trials。程序的generic softvtbench_tasks.json另列libero_10/spatial/object/goal各0–9，不能直接当四个soft/rigid suite mapping。实查object_soft config有10 tasks；task0为取white swirled soft pastry放basket，其asset soft_pastry001与旧alphabet_soup BDDL并存。
题数与数据
PDF宣称4,000 demonstrations、50+ assets；README旧v0.1是1,628 demonstrations（500/500/421/207）与33 assets，均非本轮实际下载数。20 Hz同步第三人称／腕部RGB、左右tactile RGB/marker motion、proprioception、language及binary/continuous gripper；FEM为evaluator-only。所读HDF5使用data/demo_*、actions、obs/eef_pose（xyz+wxyz）、obs/gripper_pos、states/deformable_object/<asset>/nodal_pos_w与soft_extras。assembly保留original_demo_id并按(task_id,demo_id)去重；缺success attr预设True，导入需额外验证。7D converter以xyz+axis-angle+单指gripper为state，接受7D或legacy8D action，13D force-in-action需另一converter；较短视频路径有随机drop state/action再切video的分支，不能宣称与PDF『无重采样』完全一致。模型7D、legacy8D、13D及server padded32D不可混为一种action space。
评估方式
goal checker逐个goals合取xy距离与(|Δz|−height_diff)<height_threshold；IN/ON尚共用此公式，force条件只在enable_force_threshold='True'且sensor存在时激活。task0阈值xy=0.2、height=0.2、force=0.05（原生模拟尺度），soft asset建置会跳过该rigid contact sensor。client预设30次推论×10动作、8连续success steps；但正式JSONL scorer取最后success_now，须核对其与experiment_success一致，且成功／terminated会在debug记录前break。FEM正式metric_id=fem_rms_rigid_aligned_bbox_pct_v1，以首个节点状态作reference，proper Kabsch禁止reflection，D(t)=100×RMS位移／reference bbox diagonal，D_peak=max_t D(t)。程序SafeSuccess=GoalSuccess且D_peak≤tau，未另检NoDrop，harness也禁用*_dropped；不能宣称符合PDF的drop即停。旧calibrator用0.5×max stable peak；例如soft_pastry001 tau=0.44692%，PDF表9的90th-percentile tau为7.6%，差异不是单纯改名。正式scorer重算HDF5 nodes、检JSONL metric ID；goal rate分母是已知goal episodes，safe rate分母是全部episodes，未知safety保留n_safe_unknown且不算safe。strict通过且分母一致前，goal_safe_gap不具有PDF TSR−DSR的精确语义。rigid诊断可令safe=goal，公表仍应保留N/A／适用性。

怎么接入我们的benchmark

可重用

具体task/config、native HDF5与视频索引、policy/evaluator通道分离、Kabsch FEM公式、per-asset门槛及explicit metric ID。

需要转换

source绑PDF v1与程序v0.1两个版本；environment记solver／scene／tactile assets；task以suite+native task_id+asset identity创建；case分demo、ID trial、OOD trial并保存paired seed／initial state。evaluator保留TSR/DSR与程序Goal/Safe label的版本关系，另记tau生成方法、reference nodes、百分比尺度、成功horizon及drop规则。domain依实际pick/place用途映射。附加force的squeeze=2min(|fLz|,|fRz|)，applied-force z扣除成对squeeze，*_max是非零Top5%均值，不映成物理peak。

仍需补齐

对应2608.18701的4,000版release／split manifest、90th-percentile calibration与rescorer、soft_stw_cuboid_hq等新版asset对照；drop termination及300-step协定闭合；terminal debug／sustained goal的对齐；数据与USD／Tabero tactile runtime资产取得验证；原生HDF5 success类型、跨root重复JSONL/HDF5及视频时间对齐。

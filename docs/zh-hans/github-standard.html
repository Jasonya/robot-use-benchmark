先看最简单的结构

我们只维护三层：原作快照 → 共同目录 → 可评测子集。首页仍只回答领域、环境、任务、题数、评估方式。

层保存什么何时算完成
原作快照论文、GitHub commit、子模块、任务／数据／判分原档引用与hash身份和版本可回查；下载与阅读各有纪录
共同目录来源、用途、环境、任务、题目、判分器及它们的关系字段、ID、引用和原生单位通过检查；语义未决保持未决
可评测子集完整输入、初态、可见信息、动作／输出、预算与判分素材、协定、判分正反例、切分及运行范围逐项验证

一本论文可以有多个仓库，同一个仓库也可以支持多篇论文。原作、仓库、版本、原生task、case和trial各有自己的ID，不能共用一个「数据量」数字。

用两个例子走完

步骤CALVIN：操作机器人OpenEQA：看环境后回答
固定原作CALVIN主仓库和它指定的calvin_env子模块OpenEQA固定版本与open-eqa-v0.json
认识环境A–D四个原生场景；D_eval沿用D的layoutepisode_history是观测历史引用，不能直接当作可操作环境
认识任务34个原作子任务定义，例如开抽屉7个信息题型，例如对象位置；不是7个机器人工作
找到一题需绑定实际初态、指令链、观测与动作协定一个question_id连到问题、历史输入、答案与判分协定
真正判分由具体goal checker与整条指令链的完成结果判分依原作开放式回答评审；裁判、prompt与版本一并固定
目前可计什么已取得34条任务定义；不能把文中1,000条链当成本案已取得已取得1,636条问题／答案元数据；完整历史图像另行取得
进入共同格式source→environment→task→case→evaluator，保留原生动作尺度source→history resource→information task→case→evaluator，保留图像可见范围

两个例子共用身份、来源和评测纪录格式，但输入、输出与判分各自保存。对它们添加「指令被打断后恢复」或「不得读取某段历史」时，要写出父任务、变更规则、答案如何产生及添加的评测版本。

目录怎么放

以下为目标目录结构；现有catalog importer保留其0.1版本，不以这张示意冒充全部adapter已实作。

benchmark/
  sources/                  每份來源一張卡：身份、版本、原作入口
  catalog/
    domains.jsonl           用途分類與定義
    environments.jsonl      有身份的場景／layout
    tasks.jsonl             原生任務與共同規格、規則版本
    cases.jsonl             一題的輸入／初態／split／判分引用
    evaluators.jsonl        原生與共同判分契約
  adapters/                 按來源或資料形態讀取、轉換、驗證
  protocols/                模型可見資訊、預算、輸出及切分規則
  releases/                 固定的catalog／evaluation發布清單

视频、HDF5、NPZ、3D资产与大型模型存放在数据保存区。目录保存引用、内容hash和依赖关系；网站直接从同一份目录产生表格和下载。

一篇 GitHub 怎么读

依这个顺序走一遍，每一步留实际文件名、commit、行号和阅读结论。

顺序读什么要回答的问题
1. 身份与版本论文／作者页 → README → tag／submodule这是否该篇的作者程序？是原作版、移植版、新版或只是网站？
2. 任务入口registry、task class、goal DSL、题型或活动表原作的一个task究竟是什么？目标、参数、变体怎么分？
3. 数据入口manifest、dataset reader、纪录器、split设置一笔样本包含什么？时间、单位、座标、label和来源如何对齐？
4. 真正判分运行入口 → wrapper → 具体checker／metric程序实际如何判分？分母、失败排除、候选预算与聚合是什么？
5. 整理与映射来源卡、字段对照与验证纪录哪些原样保存、哪些要转换、哪些仍不足以形成合法评测？

README中的指令只是入口。要沿实际调用链读到数据与判分。例如LIBERO的基底_check_success是占位，真正goal检查在具体problem子类；只读基底会得到错误结论。

每份来源只填一张卡

字段最少要有什么
来源身份paper ID、repo及角色、官方性依据、固定版本、读过的文件
领域原作任务／用途支持的分类；逐任务映射与来源层级标签分开
环境原生scene／workspace／asset或生成规则；视频观测脉络另存
任务native ID、原生单位、目标／规则／必要过程、参数或变体
题数与数据原生split、case/sample单位、输入／标注引用、已取得范围
评估方式实际checker／metric文件、版本、所需证据、聚合与预算
标准化结论可复用、需要转换、仍缺少什么；目前是目录或可评测

字段不明时用null和原因。未找到官方GitHub不表示原作没有数据；只有README或网站的仓库，也不表示评测程序已公开。

统一哪些东西

统一身份、字段意思、数据关系及评测界面。 原生表示保留，转换由adapter完成。

共同项目必须保留的原作细节
身份source、repo、commit、native ID、split、父数据与衍生关系
时间原片秒数、frame index、特征时间格、控制频率、预测截止点与horizon
空间座标frame、世界／相机方向、quaternion顺序、单位与变换参数
动作embodiment、controller、位置／速度／力矩／增量、维数、缩放与夹爪约定
观测与答案数据里有什么，以及此评测允许模型看什么；参考状态／未来／答案分开
成功与误差原生predicate／metric、阈值、时间持续、invalid规则及分母
发布schema／adapter／evaluator／protocol版本与全部依赖的固定清单

相同形状的tensor可能有不同物理意思；不同形状也可以走相同的adapter界面。控制、问答、定位、预测与世界模型保留各自输出类型与native metric。

从已读程序看到的具体原因

原作已核对的程序事实我们要怎么处理
Meta-World现行版基础obs由当前18维、前一观测18维、goal3维组成；部分说明仍写9D由固定程序与数据验证schema，记下stack与goal可见性，不只抄文字说明
Meta-World vs CALVINMeta-World原生4维控制另乘action_scale；CALVIN有两种7维动作，relative另有位置／角度缩放保存原生ActionSpec及转换，不强制把所有数据视为同一个7维矢量
CALVIN主仓库pin的calvin_env不是该仓库的目前main；scene_obs存在数据里但原作政策不使用固定依赖闭合版本，并把保存字段和政策可见字段分开
ManiSkill1/2/3原作2021在Legacy，ManiSkill2在v0.5.3，现行main为ManiSkill3不用同一个main代表三篇；版本与映射各自有证据
ManiSkill2recorder保存T+1个观测与T个transition；depth以uint16并乘2^10写入保存时间对齐和深度尺度；dtype本身不足以解释数据
ManiSkill3training loader裁去最后obs；device分支另对success/fail赋值为terminated/truncated原始保存和training view分开；保留原label，导入adapter需做回读一致性检查
RLBenchcondition可以表示关节、抓握、侦测、顺序或OR；variation还会换目标部位完成条件与必要过程一起保存，不从任务名称推定
CrossTask18 primary与65 related标注资格不同；时间转到1Hz特征格会floor/ceil数据子集、时间格与原始秒数分开；没有GT的活动不自动变成可评题
LIBERO-Plus（P105）分类档有10,030个扰动条目，许多共用底层任务与初态保存base task→variant→case关系；原生level与共同难度分开
EgoDex（P119）ARKit世界座标可能每episode不同；best-of-K只计指定位置点链接episode座标与原片；保存K、padding、所评joint及被略过的旋转分量
WatchAct（P123）Plan SR、完整终态一致与LIBERO物理成功不同；progress还可能扣初态同题可建不同protocol，分别保留原metric与添加规则
Open X（P125）示例可以把tensor形状对齐，原action却可能是位置、速度或增量容器/schema和物理ActionSpec分开验证，保留每个子数据源
AHA（P110）名称为F1的Yes/No脚本实际计算accuracy；模型裁判另有无效输出分母记下原名称与真正公式，保存invalid数与预期题目全集
ALOHA/ACT（P130）两个sim有具体reward规则；real界面的0 reward只是占位原实机评分需另有rubric或checker，不能直接沿用通用rollout日志字段
EggHand／EgoH4（P227／P230）相同父视频被切成不同窗口；target是否含当前帧、缺失关节mask与MPJPE对齐不同父take与时间交集去重，逐协定固定历史／未来与有效分母
SFHand（P228）误差只评匹配、IoU及手别正确的子集合；串流仍取得新图像同时报评分覆盖率与条件误差，标明online observation
OCT／Diff-IP2D（P233／P232）文件可相同，实际caller却不同；OCT wrapper的名称对调不等于Diff-IP2D主路径也如此必须沿入口查到真正调用，保留native名称、公式和修订版
EgoCast（P249）预设分支与forecasting分支不同；预测输入路径有GT变量覆写问题固定两个commit；独立GT、窗口与判分验证通过后才能发布成绩
EgoMAN（P250）程序已公开，但processed data与模型权重未发布；best-of-K还有特定选样规则分开程序可读、素材取得与可评测；不把文件中的219K／3M当作已下载

这些是固定来源的静态核读发现，并非本次跑出的模型成绩。逐篇表提供具体code/hash/行号；涉及可运行行为的问题仍需相应测试。

Adapter只做四件事

read_native(source_snapshot)
    讀原作，保留native欄位與來源身份

map_catalog(native_record, mapping_version)
    輸出共同目錄；未知、未決和不適用分開

build_case(record_ids, protocol)
    綁定相容環境／觀測、初態、輸入、預算與evaluator

evaluate(prediction_or_trajectory, case)
    保留原生指標，輸出分項證據與明確分母

这是共同界面规格，不是宣称所有来源已实作这四个函数。数据源没有原生成功条件时，只能先收目录与示范；添加robot task需要另写goal、规则、可解性和判分。

每次导入留下哪些交付物

交付物用途本次已有什么
来源卡与阅读证据说明读了哪个版本、哪些内容、哪些仍缺少逐篇JSON、固定commit、行段／JSON pointer与内容hash
字段对照表native字段→共同含义→转换→不能推定的内容每篇「可重用／需要转换／仍需补齐」及共同规格
原生数量纪录保留task、layout、sample、frame、trial原单位原文数量摘录、固定ID清单；全库语义联集尚未完成
导入与验证纪录记录成功、失败、缺漏、来源及schema版本现有catalog importer 0.1；不包含所有来源的runtime adapter
发布清单固定要比较的任务、case、资产、协定和评分器来源审阅与目录下载；添加可运行子集另行验收

GitHub commit只能固定程序。Hugging Face数据revision、下载压缩档hash、子模块commit、视频／资产授权和裁判版本仍要各自记录。原作删除或暂停发布的内容保留处理结果；不以同名仓库补位。

广度、规模和难度怎么报

要证明什么可用的数字比较条件
用途更广有任务支持的用途数、用途交集与添加用途同一分类表与纳入范围；来源级与任务级覆盖分开
任务更多去重后语义任务数、保留前作数、添加规则数相同粒度；换初态／颜色不当成新的语义任务
环境更多有版本身份的场景／layout联集共用资产、别名、style组合与程序生成规则分开
题目更多实际case manifest数量及其中可评测数native split、素材与判分资格清楚；train不冒充test
覆盖有效按来源／用途／任务分组的模型结果与缺漏率缺失预测仍留在expected-case清单，不只报成功读到的交集
难度可量化同协定内的baseline反应分布与不确定性真正跑过模型后才校准；不从文献篇数推定难度

难度先记可观测条件：步骤／依赖、容许误差、遮挡、干扰物、材料、历史长度、恢复需求和信息预算。取得模型×case结果后，再于兼容的判分协定内校准成功率／误差分级，依task／scene群聚估计信赖区间。IRT需要足够的反应矩阵与拟合检查，不能借用另一领域的100题设置就宣称机器人难度已校准。

规则扩充要留下「父任务→差异→新判分」：例如同样把对象放入抽屉，添加关门、指定顺序、不可碰倒另一对象或中途滑脱后恢复，分别写出是否改变语义任务，还是只添加评测条件。每个添加规则都要有合法完成与近失败的可核对例子；参数排列数不直接当完成题数。

限速与可续作

先读缓存，再抓必要的小型来源档；所有程序共用请求调度。GitHub搜索至少间隔6.5秒，一般API至少0.85秒，raw档与各网站至少1秒。收到429或rate-limit 403时依Retry-After／reset暂缓，保留deferred状态，不立即重试。这能降低触发限制的概率，不能保证服务端永远不限制。

代理同样采一次一个短批量、完成即保存；遇模型服务429就停止添加代理请求，继续本机整理。来源已完成、待查核和暂缓都有独立纪录，续作不需要把整批重新抓取。

发布前的最小验收

  • 身份与版本：来源、task、scene、case、evaluator能回到原作；子模块／资产版本没有偷换。
  • 数据保留：原始纪录与共同纪录可以回查；时间、单位、座标、T/T+1及label不因loader而丢失。
  • 合法输入：模型看到的字段符合protocol，参考答案／未来／特权状态按约定管理。
  • 判分正确：接受合法完成、拒绝相关近失败，missing/invalid和聚合分母明确。
  • 比较公平：native split保留；新split有血缘核对，候选数、时间／动作／适应预算固定。
  • 计数可重算：论文、仓库、task、环境、case、trial不混加；已取得与已可评分栏。

本研究的规模优势应来自有出处的任务与环境联集，以及清楚定义的新规则。程序仓库数、数据文件数或参数乘积，不能代替这些证据。

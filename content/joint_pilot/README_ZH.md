# 自建聯合資料試作：RGB、數位工具與機器人接觸操作

日期：2026-09-29。資料 release 0.1；執行／判分約定 `joint-dispatch-pilot-0.3`。

這批資料實際在本機產生並驗證。料件影像來自MuJoCo渲染，訂單／庫存是同一工作世界內的合成SQLite資料，機器人透過Meta-World原生Sawyer控制器執行接觸推動。執行開始後沒有直接改寫料件pose。

**這是資料可行性試作，不是完整通用benchmark，也沒有測過學習型VLM／VLA。**

## 規模與計數

| 單位 | 本批實數 | 解讀 |
|---|---:|---|
| 作者工作流候選 | 1 | 依訂單分流料件、保持另一料件的終態位置、再登記出貨 |
| 空間layout／機體／材料形狀 | 各1 | 固定桌面、Sawyer、剛性方塊；兩個顏色標記料件 |
| 實际初態世界 | 15 | 5個開發初態＋10個新驗證初態；不是15個部署領域 |
| 開發測例 | 40 | 5世界×2個SKU×2個出貨區×2故障條件 |
| 驗證測例 | 80 | 10新世界×同樣4目標綁定×2條件 |
| 合計測例 | 120 | 有影像、物件對齊、SQL初態、目標及完整執行資料 |
| 固定程式／診斷控制 | 6 | 不是6個學習模型 |
| 原定方法執行 | 720 | 開發240＋驗證480；失敗不刪除 |
| 額外可解性證據 | 2次 | 只補原來未找到成功witness的兩個測例，不列為第七個競爭基線 |

同一個世界的四種訂單目標使用完全相同的初始影像。不同的SKU、出貨區或回應遺失條件不自動增加G2。正式跨作canonical G2及領域覆蓋仍未裁定。

## 驗證批次的原始結果

每個程式都有80個預先指定的測例。完整保留沒有收斂、找不到目標、越過工具工作範圍、錯誤物理結果或重複寫入。

| 程式／控制 | 物理成功 | 數位成功 | 聯合成功 |
|---|---:|---:|---:|
| 完整RGB＋工具程式 | 92.50% | 95.00% | 92.50% |
| 物件真值位置參考 | 92.50% | 92.50% | 90.00% |
| 回應遺失後改key重試 | 92.50% | 47.50% | 46.25% |
| 只更新資料庫 | 0.00% | 100.00% | 0.00% |
| 有訂單、無影像：強制猜位置 | 5.00% | 100.00% | 5.00% |
| 有影像、無訂單：強制猜目標 | 22.50% | 25.00% | 22.50% |

這是固定程式與低階技能的結果，不能當作VLM能力排行。真值位置參考也是特定啟發式程式，不保證是效能上界。移除必要資訊的兩組控制變得資訊不足，這裡刻意讓其猜測，只作資料與判分診斷；正確的拒答不應被解讀成模型缺陷。

不確定性按10個共享世界區塊重抽樣，同一世界內的目標、故障和方法保持配對。區間只作此設定下的描述；所有區塊相同時不報零寬信賴保證。

## 每個測例的完整資料鏈

1. `public_packet.json`提供文字、初始RGB、相機校準和可用工具。原生39維物件state不在一般程式輸入中。
2. `catalog.list`提供SKU與視覺標記；`orders.get`提供所需SKU／出貨區。兩個資料源不提供料件實際位置。
3. `camera.capture`取得當前實際渲染影像；`vision.locate_parts`用RGB色彩元件和公開相機校準估計位置。它是簡單CV工具，不是VLM。
4. `robot.push_xy`接收位置估計，使用機器人TCP本體狀態作回授。工具回傳TCP移動狀態，不將它當作物件成功。
5. 程式重新觀測並修正，最後呼叫`dispatch.record`。SQLite工具確實寫入資料，不能憑「完成了」的文字過關。
6. 私有evaluator同時判斷物理終態、資料庫終態及登記順序。

初態物件的對應關係與像素定位誤差列於`entity_alignment.json`。相同世界的不同目標／故障／方法不會重複算成新的對齊樣本。

## 判分約定

物理成功要求方塊八個頂點都在指定區域內，底面高度在台面上下6mm內、最高點不超過65mm，最後40個控制步的平移速度低於0.04m/s，另一料件的終態中心位移不超過20mm。這是幾何高度與速度判定，沒有宣稱量到承重接觸力、完整角向穩定或整段零擾動。

數位成功要求恰好一筆正確出貨、正確訂單完成，以及相符的庫存／申報位置。每次有實際寫入的出貨登記，都必須在物理條件成立後才發生。合法替代的工具順序可以通過，不要求照抄一條固定計畫。

SQLite是刻意明訂行為的最小fixture：新的idempotency key會新增一筆申報，相同key與payload才去重。它不觀察物理世界，也不是生產級庫存服務。故障條件會在第一筆SQL commit後丟失回應；這是本機確定性的API故障注入，沒有真實網路故障或外部商業API。

## 真正做過的核驗

- 720次原定執行全部保留，物理動作、影像和資料庫重播均完成；模擬與紀錄錯誤為0。程式例外另列，未藉此刪除測例。
- 2,568個記錄影格重播、1,128次RGB定位重算；所有保存影格與重播影格一致。
- 完整重執行720條工具鏈／7,599次工具呼叫，產生相同的低階動作、物理軌跡和SQLite终態。
- 開發／驗證的world、order ID及初始物理hash不重疊；同世界配對條件的初態和RGB相同。
- 判分反例包含部分超出區域、懸空或近台面懸浮、只改資料庫、重複登記；像素翻轉測試確認定位跟隨影像而非讀取物件真值。

原本的固定程式為驗證集78／80個測例提供成功重播witness。之後只對剩下兩個增加私有物件位置引導的分段推動參考：兩次各1,241控制步，皆完成聯合目標，完整工具鏈亦重播一致。**所有120個測例都有成功操作證據，但原定程式92.5%的成績沒有改成100%。**

## 切分、凍結與工程修正

開發初態seed為501–505；最終新初態驗證為701–710。RGB定位器、動作控制器及六種原定程式在新驗證結果出現前凍結。這是同工作、同資產、同調色盤的初態泛化，不是新任務或新物件類別泛化。

早期工程批次保留在專案內，沒有混入此release：初始化約1e-15的浮點差異會造成多個hash，已固定實際初態精度；判分器補上底面高度上界；訂單ID改用world-keyed隨機流，避免開發／測試重用ID；程式例外後仍保存終態。凍結與修正紀錄附於`registration/`。

後加的兩個可解性參考是測後annotation，不是重新調整六種程式、挑選成功測例或回寫原始成績。

## 重建與使用

安裝包內`code/benchmark`，以及其中記錄的相依版本；本次實際驗證環境為Python3.11、macOS ARM64、Meta-World3.1.1、MuJoCo3.3.0。相同環境的完整影像和動作重播通過，不保證不同GPU／渲染器逐bit相同。

```sh
python -m pip install -e 'code/benchmark[joint]'
python -m robot_use_runtime.joint.validate development --workers 2
python -m robot_use_runtime.joint.validate test --workers 2
```

重新產生一批新初態：

```sh
python -m robot_use_runtime.joint.run \
  --output my-new-run --seeds 801 802 803 \
  --workers 2 --phase development
python -m robot_use_runtime.joint.validate my-new-run --workers 2
```

原始場景／機器人assets仍是Meta-World相依資源，不包含在此包內；場景以可追蹤的recipe重建。資料、工具狀態與物理軌跡都是本批合成／實測的模擬資料，沒有真人影片或真實公司營運紀錄。標為`private`的檔案是公開給研究者的ground truth，不是一般agent輸入。

本包提供資料可行性與重現證據。要成為原定的大規模、廣覆蓋benchmark，還需要更多實質不同的工作、材料／機體／場域、自然影像或人類觀測，以及學習型agent的固定協定實驗。2,000–3,000 G2與2×目標仍待達成。

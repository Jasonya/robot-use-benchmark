整體設計 v0.4：大規模、廣覆蓋、統一評測一起達標

更新：2026-09-22。研究範圍仍是模擬。這是一份整體研發設計，沒有把尚未實作的任務、場景或實驗列為成果。

整個設計改成：完整來源任務庫 → 正規化任務庫 → 廣度約束下的場景實例 → 共用評測平台。

主目標同時要求「真正不同的任務多」、「實際覆蓋的場域與機制廣」和「一套入口能管理與評測」。2,000–3,000 個正規化任務仍是初始研發目標；數量和覆蓋要各自驗收。

3. 「大」和「廣」設成兩道共同門檻

以下數字是本計畫的研發驗收提案，不是文獻公認標準或已完成的結果。在 S1 完成共同分類、參照集與可行性分析後，確認並預先登記；之後若變更要升版本並解釋原因，不能看完 test 結果才改口徑。

驗收項目 v0.4 提案
全球獨立任務數 初始目標 2,000–3,000 個 G2；每個計入者都有有效實例、專家解與判分器審核
相對規模 至少最大可比基準的 2 倍 G2，分母須以同一 task kind、scope、版本與正規化規則取得
相對廣度 至少最大可比基準的 2 倍有效 coverage cells；格子定義見下文
核心場域 起始 12 個共同場域均需要實際覆蓋；若參照集或新任務涉及其他應用，先擴充共同 ontology 再比較
每個核心場域 至少 100 個不同 G2 的有效 task–context 綁定、8 個任務家族、3 類交互／流程機制
有效覆蓋格子 至少由 1 個 G2、3 個不同且有效的 G3 初態／實例，以及專家與判分證據支持
非剛體材料 布料、繩索、顆粒、流體、柔順固體各初步要求至少 20 個適用 G2、3 個家族；實際模型與量測必須有效
機體廣度 至少固定單臂、雙臂／靈巧、移動操作三組執行 track，各有至少 100 個適用 G2；全身／人形繼續擴展
人類觀測 track 初始目標 300–500 個 G2，至少 8 個共同應用場域；來源視角、剪輯方式與實際配對量另報

2,000–3,000 是初始規劃區間，不是硬性上限。若最大可比基準的共同 G2 數量超過 1,500，至少 2× 的目標就需要超過 3,000；先按共同規則完成比較，再上調建置目標。

每個場域的 100 個 G2 可以與其他場域重疊；每個機體的 G2 也可能重疊。這些是廣度支撐要求，不能相加成全庫任務數。機體 track 也不是增加 G2 的理由。

coverage cell 定義為：

共同應用場域 D × 主要任務家族 F × 任務真正需要的交互／流程機制 K

一格必須能回查實際 task/context/instance IDs、有效 reset、可解性和判分證據。相機視角、可額外產生的問答、任意能力標籤或 profile 數不能直接乘進格子數。

同一 G3 可能支持數個真正需要的機制；這些是非互斥覆蓋，仍要保留支撐證據。沒有足夠實例支持的格子列為薄弱／待驗證，不提前計入主張。

與前作比較的共同規則

規模與廣度各自取比較集合中的最大值，可能來自不同工作。比較集合在 S1 凍結，包含大型任務庫、專門機制庫和整合框架；原作的完整資源與正式實驗 subset 分欄。

每項證據區分「原作報告」「公開定義可映射」「有同等實例／專家／判分支持」和「本計畫重跑驗證」。對前作與我們使用同一計入規則；公開資料不足填 unknown，不能當成 0 來拉高倍數。若最大分母仍未知，只報已核對範圍、缺失比例和界限，不宣布 2× 已達成。

同時公布相對每個前作、相對前作聯集的共有／新增／缺失格子，以及 F/K 較粗、主要和較細粒度的敏感性分析。只用一套有利於自己的分類得到 2×，不足以支持穩健的廣度優勢。場域、家族、機制的邊际數量與實際分布也一起報告，不能只留一個總分。

4. 廣度如何落到任務分配

核心場域 應包含的完整工作方向 特別需要避免的薄弱覆蓋
D01 居家生活 整理、取物、布品處理、設備程序、復原 只有桌面取放
D02 餐飲服務 備料程序、擺設、配送、回收、物料處理 只換不同食物名稱
D03 零售門店 揀選、陳列、盤點、包裝、補貨 只有商品辨識
D04 倉儲配送 訂單集貨、裝箱、載荷搬運、多站服務 只有導航到點
D05 辦公行政 文件與物品管理、設備流程、資訊到實體工作 只有數位問答
D06 工坊製造維修 工具、插接、拆裝、緊固、功能驗收 只碰觸零件、不驗功能
D07 實驗室例行物件操作 惰性物品、容器、配量、設備與紀錄流程 宣稱未模擬的化學／生物效果
D08 旅宿洗衣 分類、展開、摺疊、懸掛、收納、周轉 只有單一摺毛巾設定
D09 設施維護 耗材更換、表面處理、設備復位、工具管理 接觸覆蓋被當成實際消毒
D10 園藝戶外 工具、容器、材料、支承、搬運與戶外配置 用植物外觀代替生長或作業效果
D11 非臨床輔助生活 意圖相關取物、交接、等待、協助與協作 將模擬 partner 結果當真實人類體驗
D12 公共場館活動 場地準備、物件整理、服務、共享資源、復原 換場館名稱但任務與條件不變

這 12 類是已有分類的起點，不能靠拆細名稱製造廣度。來源任務若落在真正不同的新應用範圍，就擴充 ontology，並用同一版本重新映射所有比較工作。

場域綁定要有任務相關的環境、流程、資源或角色條件。只有改背景圖、房間名稱或用途標籤，不算新增的有效場域覆蓋。

分布控制

完整任務庫保留所有合格任務，不為了表面均衡而刪除大量已復用任務。任務庫的實際分布、跨場域重疊和來源集中度都公開。

正式結果同時提供：

  • 場域等權 macro 結果：每個核心場域權重相同，再在場域內按預先定義的家族／任務權重聚合。
  • 完整任務庫 micro 結果：保留真實樣本分布，和 macro 分開呈現。
  • 每個場域／家族／材料的覆蓋與成功率：缺項和薄弱項可見。

這避免把「單一場域占比上限」錯套成任務庫刪題規則，也避免大量居家／廚房樣本直接決定整體排名。每個方法實際接受的 eligible 集合先凍結，不能自行只挑擅長的題。

5. 材料、機體與觀測各自管理

材料與機制

六種物理材料模型仍分開：剛體、布料、繩索、顆粒、流體、其他柔順固體。關節、扣件、容器與多零件結構另記，不當成材料。

交互／流程機制先提出九組共同索引，待 S1 與原生任務共同審核：

ID 機制 需要的證據
K01 抓取、放置與支承 物件身份、接觸、位置和穩定性
K02 關節、封口與設備狀態 機構狀態、必要事件、合法轉移
K03 精密接觸、插接、緊固與功能裝配 配合／連接狀態、工具作用與功能結果
K04 形變、層次、拓撲與柔性結構 材料狀態、形狀／邊／拓撲與穩定釋放
K05 物料轉移、配量與可驗證混合 量、殘量、流失與模型有效性
K06 工具作用、表面處理與非抓取操作 任務相關接觸或作用結果
K07 導航、載荷與移動操作 到達、載荷保持、交付與路徑事件
K08 交接、共同支承、時序與角色協作 partner 協定、共同結果與干擾
K09 由歷史或數位查詢決定實體目標 合法資訊、身份／版本指涉與實體結果

K 是交互／流程索引；不是九種材料，也不取代原有 C01–C34 能力標籤或 T1–T8 模組。只有任務真正需要且有證據的機制才參與 coverage 計數。

純設備狀態機可支持程序評測，但不冒充熱學、化學、清洗或其他未模擬的物理效果。材料覆蓋需由對應模型、量測與有效性檢查支持。

機體

保留六個候選 profile，先建立三組明確可執行 track：

  • 固定單臂：以 R1 為起點。
  • 雙臂／靈巧操作：以 R2／R3 為起點，依不同控制與手部介面分層。
  • 移動操作：以 R4／R5 為起點，底座與手臂的控制約定固定。

R6 全身／人形可以繼續擴展。每個被宣稱支持的 profile 都須有真實 adapter、可解性與結果；不能只靠 ontology 中有這個名稱就算覆蓋。

觀測

保留文字、頭戴、胸前／身體、外部／多視角、VLOG／剪輯、robot 示範、多 session 歷史等來源。相機安裝、agent origin、剪輯、語言、history 與 sensors 分欄記錄。

人類觀測 track 必須真的有人的觀測與合法 goal pairing，不能以 robot 模擬影片補數。沒有校準的影片仍可作語義測試，但不宣稱有度量 3D 標籤。

6. 任務怎麼建出來

任務來源分為三類：

  1. 直接復用：原生任務、初態、控制與判分對得上，通過同介面驗證。
  2. 移植或修改：保留來源與改動清單，重新檢查 simulator、assets、controller、目標與判分。
  3. 補足新任務：針對廣度矩陣的真實缺口，建立新目標、必要流程或互動機制，再對照已有任務聯集確認增量。

新增候選可以取材自人類程序與活動文獻、具體部署工作流、既有資產的合理重組。但只改名稱、顏色、位置、相機、seed 或不必要的步驟，不能自動增加 G2。

每個 G2 必須保存完整的合併／拆分理由。共同規則先固定，對我們與對照工作一致套用；抽樣隱去來源做獨立覆核，避免為了讓數字好看而採不同粒度。

一個完整工作也不應只因有多個控制動作就多算多個任務。主要 task bank 收錄有獨立使用者目標與完整 outcome 的規格；僅作控制校準或子技能診斷的項目另列。原生、短組合與完整工作流的分布仍須分開報告。

7. 平台架構改成可替換的模組

同一個研究／評測入口
    ↓
Task Registry + Source/Dedup Ledger
    ↓
Task–Context / Execution Binding Builder
    ↓
Observation & Dataset Builder
    ↓
Simulator Adapter ↔ Policy Adapter
    ↓
Evaluator + Event/Trace Recorder
    ↓
Coverage / Statistics / Result Package
    ↓
網站、下載與核驗排行榜

Task Registry 是共同核心。Backend 可以不同，但每次執行必須固定 robot、action、觀測、資料、時間與介入條件。

每個 backend adapter 至少要提供 reset、step、允許觀測、evaluator 私有狀態、介入、snapshot 和 trace。Policy adapter 負責不同模型的輸入與動作約定。共同格式不表示跨引擎動力學或 action space 相同。

可以審核復用 RoboVerse、EAI 及各原生環境的接口與組件，但需要保留原作的角色與限制。真正的增量要由任務庫、覆蓋與可重現結果證明。

網站已能公開閱讀與搜尋，正式執行服務尚未實作。未來採下載自行執行或平台代跑，皆使用同一 release／case／trace 格式；核驗狀態明確區分。

8. 評測核心保留，改成全庫與模組分層

T5 完整執行與 T6 恢復是機器人使用能力的主體。 T1 理解、T2 記憶、T3 預測、T4 規劃、T7 協作、T8 世界模型連到同一 task／instance，在資料足夠時產生合法 packets。

不是每個任務都自動有八種測例。每個模組報告自己的適用 G2、instance、資料來源與有效測例數。

主結果保留：

  • GoalSuccess 與 CompliantSuccess，分別看終態與完整明訂要求。
  • 成對目標成功與影片／文字／單幀／無影片對照；資訊不等量時清楚解讀。
  • 完整 episode 成功、介入施加率與條件式恢復；snapshot replanning 另報。
  • 時間、動作、允許詢問、禁止介入與副作用。
  • oracle goal／state／plan 的瓶頸診斷。
  • 按 task family、場域、機制、材料、profile 與條件的 macro 分布及不確定性。

完整 task bank 的正式 T5 評測不能只跑原 100–140 個案例，卻宣稱全部 2,000 個都經過比較。每個方法／track 都公布完整 eligible G2 與實際執行集合；昂貴的影片或專門診斷子集另外報告。

資料仍先按來源活動／錄製 session／資產家族切分，再生成 clips、QA、plans 或其他衍生標籤。凍結、離線適應、few-shot、online 和 continual learning 分開；公開預訓練未知的情況如實記錄。

難度先保留十維設計描述，再以固定 agent panel 和 contract 校準。場景多、步驟多或影片長本身不等於經驗難度。

難度如何在大題庫中量化

先替測例記錄任務鏈、精度、遮擋、形變、記憶等設計條件，用它們檢查分布和抽樣。這些描述不直接決定「難／易」。

正式難度以同一評測模組、輸入／控制約定和固定方法群下的成功率估計：

D_empirical(case, contract) = 100 × (1 − 加權平均成功率)

方法權重、重複次數和不確定性估計先固定；共享 checkpoint 的方法不當成大量獨立證據。任務層只在預先定義的 instance 分布上聚合。可依凍結的校準集劃分四個難度區間，實際邊界由 S3 pilot 校準並在 S5 前凍結；目前不替 5,020 筆來源紀錄虛填難度級別。

全方法失敗先檢查專家解、reset、資訊充分性和判分器，再判定是否高難度。難度、評測鑑別力和任務的重要性各自報告；換方法群或 control contract 後，要重新檢查量尺。

9. 同時做大和做廣後，預算怎麼算

新增場域和機體會增加實作與測試量，但不必增加 G2。因此 v0.4 明確分三種集合：

N_task = 全球唯一的 G2 task specs
B_context = 不同 (task, context) 有效綁定
B_execution = 不同 (task, context, profile, backend contract) 執行綁定

一個純規劃示例：

層級 假設 規劃數量
G2 全球去重任務 2,400
Task–context bindings 部分任務在多場域使用 2,800
Execution bindings 部分場域再支援另一機體／contract 3,000
G3 assignments 每執行綁定 10 個不同有效初態 30,000
G4 assignments 每實例 2 種有效資訊條件 × 2 種介入 120,000
G5／完整相容模型 每固定 case 3 次 policy repeats 360,000
8 個完整相容方法 主執行量，不含訓練和額外消融 2,880,000

這個例子仍只有 2,400 個 G2 任務，不能因為有 2,800 個場域綁定或 3,000 個執行綁定而改報成更多任務。

各模型未必適用全體 bindings，資訊與介入也不一定每題都適用。實際預算應對合法 eligible records 加總，不把乘法當已去重的實績。單位時間、人力與計算成本由 pilot 量測，沒有假設既有 24 週示例可以直接交付全量。

11. 論文最後要怎麼呈現

主表同時列出：native counts、正規化 G2、有效場域／家族／機制格子、材料與機體支撐、G3、typed G4、實際 G5，以及資料來源量。

與對照工作的完整資源、可取得部分、已實例化部分和實驗 subset 分欄。原生 task、資料 episodes、影片 QA 和 benchmark wrappers 不能直接混加。

論文的主實驗須回答：擴大的任務庫與覆蓋是否帶來穩定、可解釋的新評測證據；哪些領域、材料、流程與來源仍是瓶頸；新增任務相對原作聯集有何真正差異。統一接口本身已有相關工作，不單獨當作新穎性。

# 共同比較與任務作者手冊 v1.0

日期：2026-09-25。此版本固定開發期標註／作者規則，供來源審核與任務實作共用；尚未宣稱完成全庫獨立覆核。規模目標仍為 2,000–3,000 個 G2，必要時依共同參照上調。

## 1. 三種分類各回答不同問題

| 層 | 單位與用途 | 不代表什麼 |
|---|---|---|
| 文獻 taxonomy | 資料、理解、預測、操作、恢復、世界模型等研究類型 | 不能按篇數比例配題 |
| 共同比較家族 CF01–CF16 | 依主要使用者終態分組，供所有前作與我們共同映射 | 不是 16 種任務，也不是全庫任務上限 |
| 原作者家族 F01–F48 | 180 個設計種子的工作流模式，保留為較細層模板 | 不是已完成跨作正規化的 48 類 |
| 機制 K01–K09 | 任務真正必需的互動／流程要求 | 不是材料、機體或可任意附加的能力標籤 |

採用 coarse CF → workflow pattern → typed G2 → execution binding → G3 → typed G4 → G5 的明確欄位。原生 task、activity、schema、instance、episode、QA 與 demonstration 仍分開保留。

## 2. 共用家族與邊界

| ID | 家族 | 納入條件／例子 | 排除或優先規則 |
|---|---|---|---|
| CF01 | 定位與關係配置 | 主要終態是物件或一組物件的位置、朝向、支承／相對配置。 例：單物件放置、推至目標、物件排列與堆疊。 | 若主要目的為分類、容量裝箱、連接或協作，優先用對應家族。 |
| CF02 | 選取、搜尋與取回 | 主要終態是找到並取得被指涉的物件，包含必要的搜尋或存取條件。 例：從遮擋處取物、依歷史定位物件、工具取出受限物。 | 單純移到已指定目的地用 CF01；純回答物件位置用 CF15。 |
| CF03 | 分組、盤點與補足 | 主要終態是集合的分類、完整性、數量或庫存規則成立。 例：按規則排序分組、盤點後補貨。 | 物件數量是同一規則的參數時不新增 G2；容量／保護式包裝用 CF04。 |
| CF04 | 裝箱、存放與容器工作 | 主要終態是物件集合以指定容量、容器、保護或封存規則完成存放。 例：按清單裝箱、打開容器存入後關閉。 | 只打開空容器用 CF05；只放在已開放目標區可用 CF01。 |
| CF05 | 機構與設備狀態 | 主要終態是關節、封口、按鈕、閥或設備程序達到要求狀態。 例：開關抽屜、轉動閥、執行面板設定。 | 位姿插接以形成連接用 CF06；設備熱學／化學效果須有另外物理證據。 |
| CF06 | 連接、裝配與拆卸 | 主要終態是配合、連接、緊固、拆離或功能驗收成立。 例：插銷、插座配合、螺絲、拆裝零件。 | 普通穩定堆疊不是功能裝配；只碰觸零件不代表連接成功。 |
| CF07 | 柔性構形與拓撲 | 主要終態是柔性物的展開、摺疊、懸掛、套合、穿線或繫結關係成立。 例：摺布、晾掛、繩路佈設與打結。 | 僅移動一塊已摺布而不要求構形用 CF01／CF04；永久分割用 CF10。 |
| CF08 | 表面處理與散落物收集 | 主要終態是表面作用、接觸覆蓋或非抓取式散落物收集完成。 例：擦拭覆蓋、刷掃、推集碎片。 | 不能由接觸覆蓋宣稱消毒；容器間倒粒子用 CF09。 |
| CF09 | 物料轉移、配量與混合 | 主要終態是物料的轉移、容量、比例、配量或可驗證混合要求成立。 例：倒顆粒／液體、量測回饋配量、攪動程序。 | 只搬移封閉容器用 CF12／CF01；狀態旗標不等於真實流體或化學模型。 |
| CF10 | 材料分割與成形 | 主要終態是材料分割、切削、壓縮或指定成形結果。 例：切分材料、壓入模具、軟物成形。 | 可逆衣物整理通常用 CF07；接觸到切割工具不代表真的分割。 |
| CF11 | 導航、通行與跟隨 | 主要終態是 agent 到達、通過或保持對目標的跟隨關係。 例：導航、清出通道後通行、跟隨指定對象。 | 運送載荷為主要要求用 CF12；出現人類不自動算協作。 |
| CF12 | 載荷搬運與交付 | 主要終態是載荷在移動／搬運約束下送達目的地或完成多站配送。 例：保持載荷姿態、移動配送、大型物搬運。 | 多末端協調不等於多 agent；需要合作方交接／共享支承時另判 CF13。 |
| CF13 | 合作、交接與輔助 | 主要終態依賴合作方角色、時序、共享資源或共同結果。 例：交接物件、共同支承、輪流使用、依意圖協助。 | 只有同場影片或雙臂不算合作；必須有 partner／role 條件與相應證據。 |
| CF14 | 複合工作流與狀態復原 | 使用者要求多個同等重要結果或跨類條件分支，沒有單一更具體主家族；或復原明訂歷史狀態。 例：完整場所復原、跨類準備工作、條件式實體流程。 | 不能把所有長任務都塞進此類；若整體目的仍為裝箱、配送或分類，優先 CF04／CF12／CF03。 |
| CF15 | 資訊取得、理解與預測 | 主要產物是回答、記憶檢索、預測或規劃資訊；可包含主動觀測。 例：影片 QA、Ego forecasting、主動場景問答。 | 與物理 robot_control 的 G2／G4 分型計數；推論正確不代表完成操作。 |
| CF16 | 運動控制與校準診斷 | 主要終態是機體自身的姿態、速度、平衡、末端位置或控制校準。 例：無外部工作成果的 reach-to-pose 或平衡診斷。 | 保留原生 benchmark 單位，與有外部使用者工作結果的任務分欄；兩邊採相同 pool 規則。 |

只有 task 的主要請求結果決定 primary CF；工具使用、記憶、動作步驟或場景背景不另創 primary family。若一個完整工作仍清楚是裝箱／配送／分類，使用相應家族，不能因為長就全部標 CF14。

## 3. 必需機制的正反例

| ID | 機制 | 納入 | 不納入 |
|---|---|---|---|
| K01 | 抓取、放置與支承 | 需求涉及物件取得、支承、釋放或位置关系。 | 只因所有任務都在重力中，不把支承一律加入。 |
| K02 | 關節、封口與設備狀態 | 要求機構／設備的合法狀態轉移。 | 裝飾性轉動動畫或未參與任務的按鈕不算。 |
| K03 | 精密接觸與功能配合 | 要求插接、緊固、配合或功能連接結果。 | 普通低精度物件靠近不算功能配合。 |
| K04 | 形變、層次與拓撲 | 要求柔性形變、層次、穿繞、結或套合關係。 | 物件是布但僅當剛體搬運，不直接算形變能力。 |
| K05 | 物料流動與配量 | 要求物料轉移、量、比例或可驗證混合。 | 容器外觀有水、裝飾粒子或 equipment flag 不直接证明流體。 |
| K06 | 工具與非抓取作用 | 要求工具傳遞作用、表面作用或非抓取控制。 | 場景中放了一把工具但可忽略時不計。 |
| K07 | 導航與載荷路徑 | 要求 agent 移動、通行或載荷路徑條件。 | 只改相機或把桌面放入倉庫背景不算移動操作。 |
| K08 | 角色、時序與共同結果 | 要求與另一個 agent／partner 的角色或時序交互。 | 雙臂屬同一 agent 時不能自動計作社會協作。 |
| K09 | 歷史／查詢決定物理目標 | 有效物理目標必須由合法歷史或數位查詢來確定。 | 僅多給一段無關歷史，或把明示目標重述成文字不算。 |

## 4. 何時新增 G2，何時只新增 instance／case

| 變更 | 預設處理 |
|---|---|
| 顏色、外觀、位置、相機、seed、同義指令 | G3／G4 或資料變體；不直接新增 G2 |
| 同一工作在家中與旅館，有真正任務相關場景條件 | 新增 context binding／覆蓋；G2 全球只計一次 |
| 固定单臂換成雙臂／移動平台 | 新 execution binding；需重新驗證，不增加語義任務數 |
| 取左側物件改成依上次 session 的身份取物 | 引用規則改變；保留 reference program，由共同規則判斷 G2 差異 |
| 摺好布品改成摺好且存入指定位置 | 使用者終態／必要程序增加，可成不同規格；需對照舊庫聯集 |
| 加入不必要的步驟，或把合法替代計畫列成新 task | 不增加 G2 |
| 兩個原生 task 的 goal hash 一樣 | 只列候選重疊；仍查引用、必要過程、角色／機制與完成語義 |
| 未知資訊被直接填 0 或「無」 | 拒絕；未知必須保留與說明 |

G2 定義欄位是 task_kind、roles、goal_program、reference_program、required_process、required_mechanisms 和 completion_semantics。穩定 spec ID 只表示規格內容可識別，不代表已完成跨作去重、可解性或正式 release 驗證。

參數化必須保留固定的邏輯規則、指涉方式、必要流程與完成意義。可換目標座標、物件身份或固定規則下的數量；不能把任意 goal predicate／完整程式塞進 instance 參數，把所有工作壓成一個『執行輸入程式』任務。相反地，也不能把同一排序規則的每個物件數量拆成新 G2。粗／細粒度差异必須同樣套用前作並報敏感性。

## 5. 來源審核與支撐證據分開

review_state 記錄是否索引、讀過原文、讀過特定任務定義、重跑或經獨立覆核。support_state 記錄原文明示、任務定義、實例／trace、部分／相鄰、只有資料、不屬該端點或仍未知。讀過但無足夠證據，仍可以是 unknown；不可把 review completion 當成新 coverage。

每格保存 source ID／版本、章節或程式行定位、可核对陈述、原生單位／scope、審閱方式與保留事項。正式有效 coverage cell 另需至少 1 個 G2、3 個有效 G3，以及 reset／expert／evaluator 證據。每域 8 家族和 3 機制不自動代表 24 個交叉格子。

## 6. 資訊、資料與難度

觀測的 agent origin、camera mount、view pairing、temporal packaging、language、history scope、sensors 分欄；頭戴影片也可被剪成 VLOG。人類影片、robot 合成影片、只有文字和 oracle labels 不能換名補數。來源群組先切分，再產生 clip／QA／plan／pair。

難度依固定方法群、輸入與控制條件計算，保留不確定性；來源名稱、步數與 native 難度層只作描述，不是跨 benchmark 共用分數。現在已有 scripted／random／zero 和兩個任務專用 BC 開發方法，仍不能當完整 VLA 校準 panel。

## 7. 實作與發布門檻

順序為來源規格 → 實際執行綁定 → 可解 reset → 專家／合法替代 → 判分器正反例 → 分層基線與重現。程式索引、goal fingerprint、reviewed cell 和實際 robot trial 各有單位，不能互相替代。

目前本機已能產生 Meta-World 原生任務的 MuJoCo 執行證據；其 state＋goal contract、reset 同步修正、原生判分與開發控制組均明列。它不構成 2,000–3,000 個新任務或全部材料／場域的已驗證覆蓋。

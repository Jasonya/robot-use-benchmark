# 主設計 v0.7：全面盤點前作，建立任務聯集，再擴充任務與規則

更新：2026-09-29。這是目前主設計。v0.4／v0.5的配額和容量數字保留為歷史規劃；v0.6的小型聯合試作移到工程附錄。研究範圍由來源與任務決定，本機目前能跑哪些環境另列進度。

## 1. 計畫要完成的三件事

1. **全面收集過去相關的 benchmark、含評測的資料集與任務套件。** 涵蓋機器人操作、導航／移動操作、柔性物、協作、恢復、從人類觀察到操作，以及 Ego／body camera／VLOG 的理解、記憶、規劃、預測和世界模型評測。模擬與實體前作均收錄；本計畫的執行平台以模擬為主。
2. **像 survey 一樣分類，把各來源的領域與任務整理成聯集。** 原作的任務名稱、類別、規則、場景、機體、觀測、數量和版本必須能查回。整合後保留前作的互補範圍，按多個粒度展示規模和廣度。
3. **在來源任務上擴充定義與規則。** 增加目標、約束、條件分支、過程要求、組合工作與觀測條件，形成可追溯的擴充規格和測例。

論文主體是「survey 支持的綜合任務庫＋任務／規則擴充＋統一評測」。復用、整合、分類與標準化都可以是貢獻；無須把每一題都說成從零發明。

## 2. 從前作聯集取得規模與廣度

```text
相關前作的完整來源清單
        ↓
研究類型 taxonomy ＋ 原生領域／任務／規則
        ↓
保留來源的任務聯集 U_base
        ↓
目標擴充 ∪ 規則擴充 ∪ 工作組合
        ↓
綜合任務目錄 U_total
        ↓
按相容平台建立場景、觀測和可執行測例
        ↓
分 track 評測，再報共同與分項結果
```

在相同分類和計數口徑下，完整保留各來源的聯集，範圍不小於其中任一來源。若來源提供互補的領域、任務或規則，聯集便會更大、更廣。最後以「共有、只在某來源、整合後增加、我們再擴充」四種數量展示增量。

這是本計畫取得規模優勢的主要方法。單一小型試作的成功率不決定這條主線。原先2,000–3,000任務、12場域、240 layouts等數字作容量參考；完整來源清单和實際聯集決定下一版規模，不以舊預算封頂。

## 3. 收集必須覆蓋哪些類型

| Survey 分支 | 收集內容 | 整合後可提供什麼 |
|---|---|---|
| 一般操作與靈巧控制 | 取放、排列、工具、設備、裝配、連續目標、多步操作 | 任務定義、物件／機體、控制与判分 |
| 柔性物與材料 | 布料、衣物、繩索、袋、顆粒、液體、柔順固體 | 材料專屬任務、狀態與成功條件 |
| 導航與移動操作 | 導航、搜尋、載運、跨房間、跟隨、移動操作 | 場景、路徑／存取約束、載荷與操作流程 |
| 協作與輔助 | 多機器人、交接、共同操作、人機協作 | 角色、依賴、時序、資源與共同目標 |
| 恢復、穩健與過程評測 | 擾動、錯誤、重試、復原、過程限制 | 規則、介入條件與失敗判分 |
| 人類觀察到操作 | 人類示範、模仿、觀察後執行 | 影片／任務關係、目標指涉與轉移條件 |
| 人類影片與動作資源 | Ego、身體相機、VLOG、教學、外部／多視角 | 活動、程序、物件、領域與觀測資源 |
| 理解、記憶與推理 | QA、空間、歷史、意圖、程序理解 | 資訊型任務與可接到操作的中間目標 |
| Ego／行為預測 | 動作、物件、接觸時間、手／身體／路徑、互動 | 各預測目標、輸入時間窗與答案型態 |
| 世界模型 | 狀態轉移、動作條件預測、影片／物理未來 | 模型預測與規劃／執行的分項評測 |
| 通用策略與整合平台 | 資料聯集、跨機體、模擬接口、綜合評測 | 任務來源、接口與資料相依關係 |
| 評測方法與延伸工具 | 統計、難度、multimodal tool use、數位／物理工作 | 評测規則與可選工具擴充 |

主要分支使用既有十二類作索引，次分類與來源原生分類繼續擴充。專門場域與尚不能本機重跑的資源仍留在來源庫。純方法论文可保留於 survey 的 related works；其所使用的父 benchmark 另連結，避免把方法本身當成新增任務庫。

## 4. 分類欄位要足以回查任務

每個來源至少有下列欄位：

| 軸 | 記錄方式 |
|---|---|
| 來源身份 | paper／dataset／benchmark ID、原名、年份、版本、官方入口、父來源 |
| 資源角色 | benchmark、含評測資料集、任務／平台、資料來源、方法、survey；可複選 |
| 研究 taxonomy | 操作、預測、理解、恢復等主要／次要分支 |
| 應用領域 | 保留原作者的領域名稱，再映射共同 domain；共同分類可以擴充 |
| 任務家族 | 導航、裝配、摺疊、選取、倒注、協作等，多粒度保留 |
| 原生任務 | task／activity／schema ID、原始指令、goal、必要過程、參數範圍 |
| 物理與環境 | 材料、機構、scene／layout、物件、機體與動作接口 |
| 觀測與任務型別 | 文字／影像／影片／state／歷史；控制、QA、規劃、預測、世界模型分型 |
| 數量 | 原作數字及單位、全庫／訓練／測試subset、已提取的原生定義量 |
| 收集進度 | 已登記、已讀來源、已取得原生清單、已完成共同映射 |
| 執行進度 | 資產取得、adapter、可解性、判分、模型測試；獨立於收錄狀態 |

先完成來源與原生任務盤點，保留原作者的細分類；共同 taxonomy 可逐步細化。已有107篇原始書目被標記含benchmark貢獻，與68項詳細比較交集之外尚有75篇來源先前未進比較表；它們現在全部接到來源總目錄，來源層標記與逐任務審核狀態仍分開。

## 5. 任務目錄與執行子集分開管理

| 集合 | 收錄依據 | 需要本機先跑通嗎 |
|---|---|---|
| 來源總庫 | 確認前作身份、範圍、角色與出處 | 不需要 |
| 原生任務庫 | 原作者的task／activity／schema定義與ID | 不需要 |
| 共同任務目錄 | 對齊目標、規則、家族和來源关系 | 不需要 |
| 擴充規格庫 | 有明確父任務、修改內容與判分需求 | 不需要先有執行結果；標為規格 |
| 可執行任務／測例 | 實際資產、adapter、合法初態與有效判分 | 需要 |
| 模型結果庫 | 固定方法、條件與預算下的實際執行 | 需要 |

因此，某個布料或導航套件需要其他硬體時，仍可以先納入其任务與规则，完成survey和任務目錄。部署和實驗進度由執行表呈現。物理控制、影片QA和預測在同一平台中使用各自的task kind、輸入與分數。

## 6. 任務定義與規則怎麼擴充

每個擴充都保存 `parent_source_ids → base_task_id → variant_spec_id → change → evaluator_requirements`。以下是可以實際採用的擴充方向：

| 擴充方式 | 具體例子 | 計數位置 |
|---|---|---|
| 增加終態目標 | 摺好布品，再按規格收納 | task spec／規格變體，另保留父任務 |
| 改變成功規則 | 放進容器，且不得突出邊界、不得混入其他類別 | 規則變體 |
| 增加必要順序 | 先檢查，再封箱；取物後關回櫃門 | 過程規格／規則變體 |
| 條件分支 | 尺寸不合則换容器；庫存不足則改配或詢問 | 條件式任務規格 |
| 複合工作 | 揀選→裝箱→配送→交接 | 組合工作規格，連結所有子任務 |
| 歷史與指涉 | 找回上一次使用或移動過的物件 | 指涉／觀測規格；是否改變base task另記 |
| 資源與容量 | 同時滿足訂單、載重、容器容量與工具可用性 | 約束規格 |
| 協作規則 | 交接需對方接穩才釋放；多人依序使用工作站 | 角色／時序規格 |
| 恢復與復原 | 中途掉落後續作；完成後恢復指定狀態 | 恢復task／介入測例，分欄 |
| 數位工具 | 查到有效訂單或版本後才執行；登記需與物理結果一致 | 可選工具／過程規格 |
| 觀測與泛化 | 同規則換視角、物件、場景或初態 | instance／case；原生粒度另保留 |
| 預測／資訊輸出 | 同一活動加入下一物件、接觸時間、後續步驟的預測 | 對應資訊task kind與題型 |

規則本身可以是研究設計的擴充。相同終態但不同必要過程，可以有不同的有效解集合；保存這個差異，不把它一律壓成同一個ID，也不把所有規則變體稱為全新任務家族。

生成器從有適用條件的任務與規則組合產生候選，再檢查定義、資訊充分性和判分可行性。實際執行後的通過數另列。目錄可保留完整的容易、中等與困難任務；難度分層是後續分析。

## 7. 比較表必須同時列多個尺度

| 比較尺度 | 本計畫怎麼報 |
|---|---|
| 來源數 | benchmark／資料集／版本／方法分欄；保留衍生關係 |
| 領域 | 原生域＋共同域，列出聯集帶來的新增範圍 |
| 任務家族 | 粗分類與細分類並列，所有前作使用同一層 |
| 原生任務量 | 忠實列原作者task／activity／schema數與scope |
| 共同base task | 跨來源對齊後的任務核心數；保留重疊關係 |
| 擴充規格 | 目標、規則、流程和組合變體數；與base分欄 |
| 場景／物件 | layouts、配置、mesh、資產類別及來源 |
| 測例／資料 | 初態、episodes、QA、預測樣本、影片和示範各自列 |
| 實際評測 | 支持的backend、完成測例、受測模型與執行量 |

來源整合的增量、任務／規則擴充的增量與執行完成度，都應有各自的表和分布圖。任務定義充分時，目錄可先報語義規模；正式模型成績報可執行集合與覆蓋比例。

## 8. 搜集與分類的完成條件

目標是全面盤點，清單保持開放。每個survey分支保存查詢、資料庫、引用追查與官方task-list入口；逐筆標記已納入、衍生版本、相關方法、待查與排除理由。

當前250篇書目、68項詳細比較與原5,020筆來源是起點。新增來源繼續進同一目錄；不能把已有書目數当作「搜尋已完成」。對每個已納入benchmark，分別記錄「是否取得完整原生任務清單」和「該清單還有多少定義未分類」。

本輪重新接起既有書目和比較表，並補抓官方VIMA、ARNOLD、COIN、CrossTask任務定義。這些來源拓展的是既有任務聯集；原始人類影片和模擬執行不在這次讀取動作中。

## 9. 現在的工作順序與論文圖表

| Milestone | 主要交付 | 完成依據 |
|---|---|---|
| U0 全面來源總庫 | 原作、版本、角色、taxonomy、搜尋與引用追查清單 | 每支都有來源／待查表，未收齊者可見 |
| U1 原生任務聯集 | 每benchmark完整task list、native分類、goal／規則、資產入口 | task ID可追溯，缺失清單可量化 |
| U2 共同分類與分布 | benchmark×domain×family×材料／觀測矩陣、多粒度計數 | 顯示共有／互補／衍生來源與映射依據 |
| U3 任務與規則擴充 | 規格語法、適用條件、父任務、例子與擴充清單 | 每個規格有修改說明和判分要求 |
| U4 平台整合 | 各backend adapter、資產與執行子集 | 按來源／家族報可執行比例；保持完整目錄 |
| U5 分層評測 | 各track基線、難度與泛化、規則消融 | 在固定條件和有效測例上比較 |
| U6 論文／發布 | survey、完整聯集、規則增量、平台與實驗 | 題名和主張對應實際交付與覆蓋 |

U0–U3是当前主線；已有工程元件支援後面的整合。論文先用「來源全景圖、taxonomy分布、benchmark逐列比較、task聯集與重疊、規則擴充譜系」說清楚大與廣，再以執行實驗支持可用性。

## 10. 既有工程結果放在哪裡

50個Meta-World原生任務的執行器與基線，保留作為一個已實作backend的證據。120個合成聯合測例、720次固定程式試驗和92.5%結果，保留於工程附錄，用於檢查影像、工具、物理和判分的資料鏈。

它們提供可復用的程式與測試，研究題目仍由前作聯集、分類結果與擴充規格決定。下一個主要交付是更完整的benchmark／task目錄和規則庫。
